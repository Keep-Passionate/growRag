## 如何审图

- 图 1：确认我们目前是在首检之后做追加查询修复，而不是纯 query-only 检索前层；BASE/FRESH/REUSE 的区别能否一眼看清。
- 图 1：历史仅到候选检索/改写，不能直接给 Reader 提供当前事实；训练 gold 不进入在线选择；评价题不更新经验库。
- 图 2：步骤 1 已完成、步骤 2 可执行、步骤 3 等待的判断是否清楚；不把未知大学用源题值补全。
- 图 2：下方双分支是离线实验，而非部署时必须双跑；例子不是数据集结果；现有代码仍每支至多一次修复。
- 方法不是已确认原创。QCR、RRM、AMA-Agent、AWM 等已覆盖很多组件；图审是锁定假设，不是承诺发表结论。

## 生成与可复现资料

- 使用内置图像生成工具；未调用用户 Qwen 接口。
- `figure_briefs.md`：每张图的主张、构图、边界和核验清单。
- `architecture_prompt.txt` / `method_prompt.txt`：人工整理的具体要求。
- `*_compiled_prompt.txt`：工程绘图技能模板编译后、实际用于初次生成的提示词。
- `*_revision_prompt.txt` 和 `method_revision2_prompt.txt`：对语义箭头进行定向修正的完整提示词。
- 交付为 PNG **讨论稿**，不是可编辑矢量源；确认后再按论文版式重绘 SVG/PDF。不能把 AI 栅格稿称为已完成投稿级矢量图。
- 原始生成文件保留于绘图工具目录；项目只交付选定修正版，不把错误箭头版本作为正式架构。

## 语义核验

- 架构初稿发现 Frozen memory 被误连到 Reader，已定向修正为只到 Candidate retrieval；选定稿不保留该错误连线。
- 方法初稿发现步骤与表格的映射箭头错位、ready 行绕过 q1 的旁路。最终稿改为整体步骤检查与明确的“实例化 READY 步骤”标签，只保留 q1 → R → E1 两条执行箭头；可视核验通过。
- 两张选定稿均为 1536×1024 PNG。语义检查通过仅指图与讨论方案一致，不是算法可靠性或新颖性得到验证。
- 不新增性能数值、不模拟 API 结果、不执行工程测试或算法实验来为示意图背书。
