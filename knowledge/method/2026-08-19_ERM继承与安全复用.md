# ERM 继承与安全复用

更新日期：2026-08-19  
用途：方法概念说明；当前仍是候选设计

## ERM 做了什么

ERM（Evolving Retrieval Memory）把一次查询中得到的有效扩展，逐步融合进检索索引的文档 key。直观上，它让文档不只由原始文本表示，还能记住过去用户用过、且被判断为正确的表达方式。

其思路可以简化为：

1. 当前查询经过扩展或改写；
2. 检索器和/或生成器验证这次结果是否正确；
3. 若通过成功门，把扩展拆成更小单元；
4. 只把能增加某些已检索文档相似度的单元归因并写入对应 key；
5. 后续查询直接在演化后的索引上检索。

ERM 的优点是持久、累积且后续查询不必重新生成同一扩展。它也比“整段提示永久保存”更克制。

## ERM 留下的关键问题

### 1. 绝对成功不等于相对改进

ERM 的成功门关注扩展后的检索或生成是否被判断为正确，但没有强制要求：

> 扩展结果必须比原查询 `DIRECT` 更好。

如果原查询本来就能答对，扩展也答对，这条扩展未必有必要写入；更糟的是，它可能在未来问题上制造噪声。

我们的升级是**成对写入门**：

``
\Delta U_{\text{source}} = U(q') - U(q)
``

只有 `\Delta U` 超过预先确定的最小增益，且关键指标不退化，才进入候选经验区。

### 2. 来源题成功不等于跨题可信

一条扩展在产生它的那道题上有效，只能证明 `source-valid`。真正的历史可信度应来自它在**独立目标题**上的迁移记录。

因此建议状态为：

`candidate → active → quarantine → retired`

- `candidate`：来源题上有成对增益；
- `active`：在若干独立目标题上表现稳定，且伤害置信上界可接受；
- `quarantine`：出现明显伤害、环境不匹配或证据不足，暂停自动使用；
- `retired`：语料/检索器版本不兼容或长期失效。

### 3. 写入可信不等于当前适用

对于经验 `e` 与当前问题 `q`，必须分开估计：

- `reliability(e)`：这条经验过去是否可靠；
- `applicability(e,q,env)`：它是否适合当前问题和检索环境。

前者来自独立使用历史、来源和伤害记录；后者来自 query 结构、实体/关系类型、相似度、检索器、语料版本等当前特征。

接受规则最简单可以写成：

``
\text{REUSE}(e,q)
\iff
\text{reliability}(e) \ge \tau_r
\land
\text{applicability}(e,q) \ge \tau_a
``

否则保持 `DIRECT`。两个分数不能合成一个不透明的“总 trust”后就不再区分，因为这样无法判断失败到底来自经验本身还是当前匹配。

### 4. 写入索引后缺少读取时拒绝

ERM 的 key 一旦演化，就会影响后续所有相似查询。我们的第一版不直接改索引，而保存可选择的 query-side record，因此每次都可以拒绝复用。

后续若实现索引版，应保留：

- immutable base key；
- versioned delta/overlay；
- 使用条件与来源；
- 可回滚日志；
- 每次检索是否启用 overlay 的决策。

## 第一版经验记录建议

第一版不保存答案正文和完整 CoT，建议保存：

| 字段 | 作用 |
|---|---|
| `source_query` | 经验产生时的原问题 |
| `source_direct_query` | 原始送入检索器的查询 |
| `transformed_query` | 成功后的查询或子查询集合 |
| `atomic_units` | 新增、删除、替换的最小语义单元 |
| `transformation_type` | 消歧、补实体、补关系、分解、限制时间等 |
| `source_outcomes` | DIRECT 与变换后的成对指标 |
| `provenance` | 数据集、题号、生成方法、验证方式 |
| `environment` | corpus、retriever、index、prompt/model 版本 |
| `transfer_history` | 独立目标题上的收益、伤害和成本 |
| `state` | candidate / active / quarantine / retired |

这里的 `atomic_units` 可以借鉴 ERM 的细粒度归因；`transformation_type` 可以借鉴 ReFormeR 的显式模式，但不能把二者写成我们的原创概念。

## “Do-No-Harm”具体测什么

对同一道目标题，固定检索预算、生成器和上下文预算，分别运行 `DIRECT` 与 `REUSE`。

设达标为 `good(·)`，定义：

- **Benefit**：`DIRECT` 不达标，`REUSE` 达标；
- **Harm**：`DIRECT` 达标，`REUSE` 不达标；
- **Both-good**：两者都达标；
- **Both-bad**：两者都不达标。

其中最重要的是：

``
H = \mathbf{1}[\text{DIRECT good} \land \text{REUSE bad}]
``

它是非对称风险，因为“把原本正确的系统改错”通常比“本来就错且仍然错”更不可接受。

每个结果同时报告：

- answer EM/F1 或任务成功率；
- supporting evidence recall / qrels 指标；
- benefit rate；
- harm rate；
- reuse coverage；
- 在已接受复用中的 selective risk；
- retrieval / generation token、延迟和调用次数。

## 风险—覆盖率

门控阈值越严格：

- 自动复用的问题越少（coverage 下降）；
- 被接受复用中的伤害通常也应下降（risk 下降）。

因此不能只报一个阈值。需要画出不同阈值下的 risk–coverage 曲线，并和以下方法比较：

- never-reuse（全部 DIRECT）；
- always-reuse；
- random history；
- nearest-neighbor history；
- 只看 historical reliability；
- 只看 current applicability；
- reliability × applicability；
- oracle upper bound。

这能直接回答：为了把伤害压到某个水平，需要放弃多少复用机会。

## 无 gold 时怎么办

强化学习不会自动创造正确奖励。没有人工答案或相关性标注时，可以使用 proxy，但必须先在有 gold 的开发集上验证它和真实收益/伤害的关系。

可测试的 proxy 包括：

- pre-retrieval QPP；
- 检索分数间隔、文档多样性和结果稳定性；
- query 与候选经验的结构匹配；
- 引用是否真正蕴含答案；
- 多个独立 verifier 的一致性；
- 用户的延迟反馈或下游任务是否成功。

正确顺序是：

1. 在有 gold 数据上同时计算 proxy 和真实成对标签；
2. 测 proxy 的区分能力、校准误差和跨域稳定性；
3. 冻结规则；
4. 在测试时隐藏 gold，只让控制器看 proxy；
5. 测试结束后才揭示 gold 评价。

## 不是当前创新点的组成部分

- 查询重写本身；
- 从成功 query pair 抽取 pattern；
- 检索前 query variant selection；
- “经验是可选资源”；
- 历史 usage / decay / feedback；
- EMA；
- `DIRECT / REUSE / FRESH` 动作命名；
- 本题内证据不足后再改写。

这些可以组成系统或作为基线，但主贡献必须落到尚未被充分回答的可检验问题上。

## 暂定系统流程

``
当前问题
  ├─ 候选经验召回（只看运行前可见信息）
  ├─ 历史可靠度筛选
  ├─ 当前适用性估计
  ├─ 风险门
  │    ├─ 不通过 → DIRECT
  │    └─ 通过   → REUSE
  ├─ 统一预算检索与回答
  └─ 有反馈时更新迁移记录；EMA 仅作可选近期平滑
``

第一阶段会在离线条件下同时跑所有动作，以获得 oracle 上界和真实成对标签；部署选择器本身绝不能看到这些事后结果。
