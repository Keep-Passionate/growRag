# GrowRAG v1.1 代码审阅清单

更新日期：2026-08-19

## 1. 先审概念边界

- `QueryTransformation.transformed_query` 是否始终表示来源题的 `q_s'`？
- `PreparedReuseCandidate.transformed_query` 是否始终表示当前题的 `q_t'`？
- 是否有任何地方把来源实体、历史答案或历史证据正文直接复制给当前回答？
- `diagnosed_failure/gap_categories` 是否明确标成来源经验，而不是伪装成当前题证据缺口？

重点文件：`src/growrag/models.py`、`src/growrag/rewrite/application.py`。

## 2. 审数据泄漏

- 查询时 gate 的输入中是否出现 target gold、最终答案、检索结果或 paired outcome？
- test split 是否可能更新经验状态、阈值或热记忆？
- 独立目标题是否与来源题、来源 group 重复？
- risk–coverage 阈值是否只在 calibration/dev 选择，并在 test 前冻结？

重点文件：`src/growrag/experience/ledger.py`、`src/growrag/selection/gate.py`、`src/growrag/evaluation/selective.py`。

## 3. 审三道门是否分开

- 来源题成对改进是否只获得 candidate 资格？
- active 是否来自独立目标题上的多次观察，而不是一次成功？
- 当前 applicability 是否与历史 reliability 分开记录和拒绝？
- 禁用条件命中时是否保持 DIRECT？

重点文件：`src/growrag/experience/ledger.py`、`src/growrag/selection/applicability.py`、`src/growrag/selection/gate.py`。

## 4. 审衰减与 Top-K

- priority 是否只影响 hot/cold/expired，而不修改统计真值和生命周期？
- 是否只有新验证反馈才能刷新 `last_validated_step`？
- 缺少活动时间的经验是否 fail closed 到 cold？
- 容量外和 expired 经验是否仍保留审计记录？
- cold/expired 是否有独立的周期性 shadow 再验证，避免永久反馈饥饿？
- `priority_base` 启发式是否适合最终任务；是否需要与 mean gain、repair rate、成本联合做消融？

重点文件：`src/growrag/experience/portfolio.py`。

## 5. 审环境兼容

- 主实验是否使用 strict？
- corpus、index 和 retriever identity 是否始终是硬约束？
- tiered 的软差异和扣分是否完整写进 trace？
- unknown/UNSET 是否一律拒绝？
- 查询应用器及 prompt 版本是否单独与历史验证版本匹配？

重点文件：`src/growrag/selection/environment.py`、`src/growrag/selection/gate.py`、`src/growrag/config.py`。

## 6. 审安全力度

- 是否同时报告 coverage、benefit、harm 和条件破坏率，而不是只报平均 F1？
- 门变严时收益覆盖损失多少，门变松时 harm 增加多少？
- 是否存在一个质量非劣、成本下降的操作点？
- quarantine 阈值与逐题读取阈值是否被错误混成同一个参数？

重点文件：`src/growrag/evaluation/paired.py`、`src/growrag/evaluation/selective.py`、`configs/pilot.example.toml`。

## 7. 审可复现性

- schema v1 能否读取，重新保存后是否升级为 canonical v2？
- 未知字段、重复 JSON key、NaN、未知版本是否 fail closed？
- 相同输入是否稳定产生相同候选顺序和决策？
- DIRECT/REUSE 是否使用相同检索次数、top-k 和上下文预算？

重点文件：`src/growrag/experience/snapshot.py`、`src/growrag/runtime_io.py`、`src/growrag/selection/candidates.py`。

## 8. 当前最该质疑的未完成部分

1. 当前 query signatures 仍由请求文件提供，自动抽取方法尚未确定；
2. 真实 query-variant application 仍是预生成 plan，不是完整 rewriter；
3. 尚未接入 HotpotQA/2Wiki 和真实 BM25/E5；
4. portfolio 活动时间尚未进入文件化 CLI 协议；
5. risk–coverage 已有计算接口，但尚未有真实 calibration 结果；
6. 路线 C 的当前题 gap item 与二次检索闭环尚未实现。

审阅时应优先挑战这些未完成接口，而不是被 toy demo 的 REUSE 结果说服。
