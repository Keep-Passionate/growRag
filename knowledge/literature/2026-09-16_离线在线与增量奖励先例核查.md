# 离线／在线记忆与增量奖励：先例核查

日期：2026-09-16。用途：研究边界和后续基线候选，不替代实验结果。

## 最需要掌握的三点

1. **离线收集经验、在线复用并不新。** ExpeL、AWM、ReFormeR 都提供了直接借鉴；我们采用这种架构是合理的工程选择，不是单独的论文贡献。
2. **“有记忆减无记忆”的收益用于学习也已有先例。** Trainable Graph Memory 用此差值训练图权重；UMEM 用邻近问题上的增量效用训练记忆优化器。不能声称第一次提出净收益奖励或用强化学习学记忆。
3. **我们还可以研究更窄的问题：** 在检索前能够观察到什么条件，能否据此选出优于同预算强 FRESH 的经验，并减少原本正确的问题被改坏？这是待检验命题，不是本次检索已保证的新颖性。

本次为有边界的原文核查，不是穷尽检索。采用已核对的版本和章节；未找到最终录用来源的论文只标“本次未确认”，不推断“未投稿”。

## 1. 架构分别从哪里吸收

| 工作 | 原文支持的机制 | 我们吸收什么／不能说成什么 |
|---|---|---|
| [ExpeL，AAAI 2024](https://ojs.aaai.org/index.php/AAAI/article/view/29936) | 训练任务上积累成败经历、提炼洞见，评价任务中回忆并使用；无需更新 LLM 权重。 | 支持“离线探索更充分、上线复用”；不是要求应用阶段也跑完所有探索。 |
| [AWM，ICML 2025](https://proceedings.mlr.press/v267/wang25bx.html) | 支持先从训练样例归纳 workflow 的 offline 设置，也支持逐题形成 workflow 的 online 设置。 | 程序性经验库及两种学习协议已有；不应把“离线库＋在线库”当必需的两个物理数据库。 |
| [ReFormeR，§2–3.1](https://arxiv.org/html/2604.01417v1) | 从更优的历史改写归纳模式，再根据新问题及首次检索上下文选择模式，约束生成。 | 学习模式库与生成分开；我们 q-only 选择不能冒充原方法，因为它允许读取首次检索文档。 |
| [Adaptive-RAG，NAACL 2024](https://aclanthology.org/2024.naacl-long.389/) | 用实际运行结果和数据集先验构造标签，训练问题复杂度分类器，部署时在不检索／单次／多次检索之间路由。 | 学习“提前选策略”，不是研究历史经验增量；其复杂度分类器不是 TF-IDF 分类器。 |

注意词义：offline／online 这里主要表示**学习、维护、应用发生的阶段**，不是是否联网。调用 API 收集训练轨迹也可以属于 offline 学习。可以保留一个可审计经验仓库，并发布冻结版本给 online 使用。

## 2. 最接近的增量收益与更新先例

### A. 真正将收益差用于参数优化的直接先例

**[From Experience to Strategy: Empowering LLM Agents with Trainable Graph Memory](https://arxiv.org/html/2511.07800v1#S4.SS2)，§4.2。**

其图包含查询、规范化决策路径和策略节点。对新问题比较带某个策略的运行与不带策略的运行，得到 `ΔR = R_with − R_without`，用 REINFORCE 优化策略选择相关图权重。它还研究记忆辅助 agent 的 RL 训练。**因此“经验增量→强化学习”已有明确公式，不只是评价消融。** 本次未确认最终会议录用，不能据匿名投稿 PDF 或二手消息标为 ICLR 正式论文。

**[UMEM](https://arxiv.org/html/2602.10652v1#S4.SS2)，§4.1–4.2，公式 2–4。**

对源问题的相似邻居，比较采用候选记忆更新与不采用该更新的正确性；两边都正确时，另奖励轨迹缩短。邻域平均增量加格式奖励，用 GRPO 训练记忆提取／管理模型。**reference 不一定是完全空记忆，更不是我们指定的强 FRESH。** 它优化记忆生成与维护，而不是固定 RAG 下的 q-only 改写动作选择。ICML 2026 [官方节目下载页](https://icml.cc/Downloads/2026) 列有该标题，链接为 Poster `/virtual/2026/poster/65616`；本次正文核查采用 arXiv v1，不声称逐字核对了最终会议版。

### B. 用任务回报更新记忆价值，但不是配对 FRESH 差值

**[MemRL](https://arxiv.org/html/2601.03192v1#S4.SS3)，§4.1–4.3，公式 4–8。**

条目包含意图向量、经验、效用；先按相似度召回，再综合效用选记忆。实际使用后用 `Q_new = Q_old + α(r − Q_old)` 更新；LLM 参数冻结。该式等价于 EMA，但论文这里的 `r` 是执行回报，不能改述成“论文已采用 memory−FRESH”。这种标量更新也不等于训练一个读取问题特征的线性回归模型。本次只确认预印版本。

**[Memory-R1](https://arxiv.org/html/2508.19828v1#S3.SS2)，§3.2–3.3。**

以 PPO／GRPO 训练记忆管理及答案 agent。v1 奖励公式为最终答案 Exact Match；GRPO 的组内优势归一化不是单独跑无记忆对照再相减。它是“记忆操作可由结果监督”的先例，不能直接当作增量 FRESH 奖励先例。本次固定 v1 核查，未把它的主张当作领域绝对第一。

### C. 已做增量评价或生命周期更新，但不能等同 RL

| 工作与定位 | 做了什么 | 不能混淆的边界 |
|---|---|---|
| [RRM：方法与表 2](https://arxiv.org/html/2607.28156v1) | 无历史的本题修复 OQR → OQR＋历史经验 → 再加生命周期维护；反馈、使用与衰减控制经验。 | 已区分现场修复与历史增量；正文这组差值是递增消融，并非用该差值训练 q-only 选择器的证据。 |
| [QCR：§5.1、§6](https://arxiv.org/html/2608.12847v1) | 显式报告 `U = S_memory − S_no-memory`；固定候选和选中轨迹，比较完整轨迹／摘要／目标绑定笔记。 | 主要隔离“选中以后怎么呈现和执行”；效用是评价量，并未据此训练 RL 选择器。 |
| [ReMe：§3.4](https://arxiv.org/html/2512.10696v1#S3.SS4) | 初始探索形成经验；后续成功后录入，按历史召回和成功效用筛除不良条目。 | 成功使用率不是对某条经验的反事实因果归因，也不是必然优于无历史修复。正式版本见 [Findings ACL 2026](https://aclanthology.org/2026.findings-acl.829/)。 |

## 3. 对 GrowRAG 的设计约束

- `memory − BASE` 回答“整条改写路径比原问题好多少”；`memory − strong FRESH` 更接近“历史信息额外贡献多少”。两者都留，不把差值定义包装成首创。
- 单次运行差异会混入生成随机性、检索变化、回答器变化。需固定底座、提示版本和预算，足够样本时用重复种子／配对统计；不能称数学意义证明。
- 第一阶段用离线全信息配对监督选择器，最易调试。先不加 RL；只有数据表明序列决策、探索或长期信用分配确有价值时再考虑。
- EMA 可维护某条卡的近期经验效用；预测“当前题适不适合”的模型则还需要当前题特征。历史平均好用，不等于这道题好用。
- 在线不必死守一轮：默认一次，必要时最多追加一次可审计修复。另设固定两轮无历史、同预算强 FRESH，避免把额外计算当经验收益。
- 若加入 q-only 路由，其输入只允许检索前可见内容。离线教师获得的中间实体、支持句、gold 答案只能生成监督结果，不能作为在线学生输入。
- 冻结评价与流式先预测后更新分别报告；正式测试不能边看 gold 边暗中修经验再报告同题成绩。

## 5. 关于“描述”字段的准确理解

[AWM §2.2](https://arxiv.org/html/2409.07429v1#S2.SS2) 将高层功能描述和 workflow 步骤分开：描述可以由规则提取或 LLM 总结，不要求把原问题与完整轨迹全压进去。

我们的设计建议：`description` 只说明该模式解决哪类需求；`rule` 才规定如何修改及不修改什么；`examples` 给代表例或来源指针；原始轨迹留在审计记录中。每个字段是否有用仍需固定候选动作的删字段实验，而非字段越多越好。
