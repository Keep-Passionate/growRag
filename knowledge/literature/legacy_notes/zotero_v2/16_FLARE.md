# Active Retrieval Augmented Generation（FLARE）：读前导读

## 一句话理解

普通 RAG 在回答前检索一次；FLARE 先试写下一句话，发现其中有“不确定的词”时才检索，并利用新证据重新生成这句话。

## 前置知识与已读论文

先回忆 01 ReAct：ReAct 把检索放进动作空间，但通常依赖模型显式生成 Search；再回忆 09 Self-RAG：它通过训练模型学习是否检索和如何评价证据。FLARE 位于两者之间——同样把检索变成生成过程中的动态动作，但不训练模型，而用下一句话的 token 概率触发检索。读完后接 17 CRAG：FLARE 解决“什么时候检索、检索什么”，CRAG 解决“检索内容不可靠怎么办”。

## 论文在解决什么

一次性 RAG 适合事实型短答案，但长答案的信息需求会在生成过程中逐步出现，最初的问题无法提前表达所有后续需求。FLARE-direct 在第 t 步先不加入新文档，生成临时下一句。若所有 token 概率都不低于阈值 θ，就接受这句话；只要有 token 低于阈值，就认为模型可能缺知识，用临时句构造查询，取得文档后重新生成正式句子。论文还提供 FLARE-instruct：用少样例让模型主动输出 `[Search(query)]`，但实验显示这种显式指令并不稳定。

查询不能直接使用整句，因为临时句可能已经包含错误假设，搜索引擎会顺着错误检索。论文提供两种处理：把概率低于 β 的词遮掉，用剩余句子作隐式查询；或者针对低置信片段生成一个可由它回答的问题。前者便宜，后者可解释，表现相近。第一句仍用原问题做初始检索；以后每一步先试写一句。系统只保留当前轮检索结果，不累计此前所有文档，以控制上下文长度。

## 关键证据

2WikiMultihopQA 上，无检索、单次检索、问题分解和 FLARE-direct 的 EM 分别为 28.2、39.4、47.8 和 51.0；FLARE-instruct 只有 42.4，说明贡献来自“前瞻句＋置信度触发”，而不是简单教模型输出搜索命令。直接使用下一句检索相较上一句，在 2Wiki 上由 39.0 提升到 48.8，在 ASQA-hint 上由 42.5 提升到 45.9。2Wiki 在检索超过约 60% 的句子后趋于饱和，StrategyQA 超过约 50% 后反而下降，说明检索不是越多越好。遮掉低置信词后，2Wiki EM 从 48.8 最高升到 51.0，也说明错误草稿会污染查询。

## 局限与阅读警惕

低 token 概率不必然意味着缺少外部知识，也可能只是存在多种措辞；模型也可能高置信地生成错误事实。方法依赖可访问且相对校准的 token 概率，现代闭源聊天 API 未必开放。临时句仍可能把错误前提带入查询，遮词只能部分缓解。实验主要使用 text-davinci-003，每个数据集最多约 500 个样本；在 Wizard of Wikipedia 和 ELI5 上没有显著增益。反复试写、检索和重生成会增加延迟与费用。

## 对 GrowRAG 的帮助

FLARE 最大的启发不是“用低概率检索”，而是经验记忆也应按需介入 Thought，而不是每题固定塞入若干经验。GrowRAG 可以先形成下一步 Thought/Action 草案，再根据任务不确定性、计划缺口或工具选择冲突决定是否检索经验；查询应描述“即将做什么”，而不只是复制当前问题。每次经验注入后还应记录 Thought 或 Action 是否改变，这正是检验经验 Observation 是否真正发挥作用的证据。

不可照搬的是把 token 概率当作经验价值。FLARE 判断当前生成是否不确定，不判断某条经验是否正确、可迁移或有长期价值。GrowRAG 的写入价值仍需通过结果验证、反事实增益和跨题复用判断；使用阶段则可以借鉴动态触发、前瞻查询和低置信片段遮蔽。

## 精读时追问与关键页

为什么“即将生成的句子”比“已经生成的句子”更适合作查询？若草稿本身错误，检索为何不会形成确认偏误？论文证明的是检索时机有效，还是查询写得更好？GrowRAG 有什么黑盒信号能替代 token 概率？关键页为 PDF 第 2 页总流程，第 4—5 页触发与查询，第 7—9 页主结果、消融和局限，第 14—16 页初始检索、调用频率与阈值配置。
