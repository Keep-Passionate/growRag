# Astute RAG：读前导读

## 一句话理解

Astute RAG 不默认检索结果永远比模型可靠，而让模型分别摆出“自己记得什么”和“外部证据说什么”，保留来源，合并一致信息、隔离冲突信息，最后按来源、交叉印证与完整性选择答案。

## 前置知识与已读论文

最合适的顺序是 16 FLARE → 17 CRAG → 09 Self-RAG → Astute RAG。FLARE 解决何时再检索，CRAG 纠正低质量检索，Self-RAG 判断证据相关性和支持度。Astute RAG 进一步指出：检索结束后，外部信息仍可能不完整、错误或恶意；此时不能只过滤文档，也不能盲信模型内部知识，而要处理两类知识冲突。GrowRAG 还会增加第三种来源——历史经验账本。

## 论文在解决什么

论文在 NQ、TriviaQA、BioASQ 和 PopQA 各抽取问题，每题用 Google Search 检索 10 个网页段落，发现约 70% 的段落不直接含正确答案；Claude 3.5 Sonnet 上 19.2% 的样本出现无 RAG 与有 RAG 回答冲突。冲突样本中，内部知识正确占 47.4%，外部检索正确占 52.6%。两边胜率接近，因此固定“总信检索”或“总信模型”都不可靠。

## 完整方法

Astute RAG 是免训练、黑盒模型可用的后检索方法。第一步生成内部知识段落：模型根据问题生成至多 m 条可靠、相关、不重复的知识，不确定时允许说不知道，甚至不生成。它们不是绝对事实，而是待核验的内部来源。

第二步做带来源的迭代知识整合。把外部段落与内部生成段落放在一起，保留内部/外部标签和原文档编号；模型将一致内容聚合压缩，把互相冲突的内容保留为不同组，删除无关信息，每个新组继承来源。第三步对每个信息组产生候选答案和置信度，再综合来源可信度、跨来源印证、频率与完整性选最终答案。最后一次整合与回答可以合并进一个 prompt；主实验使用 t=1、m=1、温度 0。

它不只是 context filtering。过滤只问这段是否相关；Astute RAG 还问相关段落之间是否冲突、每种说法由哪些来源支持、冲突双方谁更可信。这是它相对 CRAG 的核心新增。

## 关键实验

Claude 上 No RAG、普通 RAG、Astute RAG 整体准确率为 54.5、55.5、61.7，最强可比基线 InstructRAG 为 58.8。Gemini 为 51.3、53.7、59.2，最强 Self-Route 为 57.6。Mistral-Large 上 Astute RAG 为 59.9、USC 为 59.5，但 USC 约耗三倍 token；Mistral-Nemo 上 Astute RAG 51.3、Self-Route 51.2，小模型增益很小。

普通 RAG 并非总有帮助：Claude 在 NQ 从 47.1 降到 44.4，TriviaQA 从 82.0 降到 76.7；BioASQ 从 50.4 升到 58.0，PopQA 从 29.8 升到 36.0。RGB 最坏设置中 5 篇检索文档全为负例，普通 RAG 约 21%，No RAG 约 78%，Astute RAG 约 76%，是唯一接近 No RAG 的 RAG 方法。冲突样本中，当内部与外部一对一错时，Astute RAG 约 80% 能选中正确方。

相比普通 RAG，平均 token 增加不到 5%，整体改进超过 11%。t 从 1 到 2 有收益，第三轮接近饱和；内部段落上限从 1 到 2 时，实际平均生成量从 0.69 到 1.24，准确率仅从 61.71 到 62.00。Gemini 上去掉来源标签由 59.2 降到 58.6，仅 0.6；说明来源意识有帮助，但主要增益还来自冲突分组和整合。单纯过滤内部＋外部知识为 57.9，完整方法 59.2；CompAct 压缩反而在 Claude 从普通 RAG 的 55.5 降到 48.4，而 Astute RAG 为 61.7。

## 局限

方法依赖较强的指令遵循与推理能力，小模型增益很小；未覆盖更长上下文，规模变大后冲突发现、分组和来源追踪更难。所谓内部知识其实是同一个 LLM 临时生成的文本，不等于直接读取参数知识，仍可能幻觉和自我确认。生成、整合、置信判断与最终回答常由同一模型完成，错误可能相关而非独立。主结果 t=1、m=1 并未展示很深的迭代推理；中间整合正确率 98.2%、置信度正确率 95.0 来自 LLM-as-a-judge，不是人工真值。

## 对 GrowRAG 的帮助

GrowRAG 应把历史经验作为第三种明确来源。经验注入必须携带来源题、原始证据、验证方式、时间和版本，不能把总结文本变成失去出处的普通 prompt。冲突时不应直接覆盖旧经验或多数投票，而应保留冲突候选组，比较当前语料证据、跨题重复支持、来源可靠性和时间，再采用、降权、隔离或废弃。

验证门要分成写前与用前：写前门判断本题轨迹是否可靠，决定能否进入账本；用前门在新题中重新比较旧经验、当前证据与模型判断，因为写入时正确的经验在新题上仍可能不适用。经验价值应随复用更新：一致且提升就提高可信度；冲突则记录适用边界；多次误导就降权或废弃。

可直接构造经验冲突四象限：经验和当前语料都正确、只有经验正确、只有语料正确、两边都不完整；比较总信经验、总信语料、简单路由和来源感知整合。再做 10%/30% 污染，区分完全无关、局部噪声和直接冲突；消融 provenance、整合轮数和 top-k；固定 token 预算比较过滤、压缩和来源感知整合。
