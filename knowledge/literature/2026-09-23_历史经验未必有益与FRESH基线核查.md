# 历史经验未必有益：问题来源与 FRESH 基线核查

日期：2026-09-23。用途：支持本轮方案和代码选择，不是实验结果报告。

## 先记住这四点

1. 如果你记得“正确经验经过反复整合，反而让以前会的题做错”，最可能是 **Useful Memories Become Faulty**。
2. 如果你记得“强模型反而更少调用经验，经验应该是可选资源”，则是 **Zhao 等的 ExpWeaver**。注意：另有一篇不同作者、不同机制的同名 ExpWeaver，不能混引。
3. 本轮先跑通 **S2G-inspired GAP2** 与 **Reflective-inspired 自由缺口修复**，同一 Qwen、同一底座、最多两轮。两者都是注明差异的适配，不冒充原论文完整复现。
4. 历史收益、选择性调用、适用条件、具体轨迹与摘要的对比均有先例。我们研究的是：**在同预算强现场修复对照下，历史是否仍提供有价值的动作，以及检索前是否能选中它。**

## 一、究竟是哪篇文章

### 1. Useful Memories Become Faulty：经验可能在整合中变坏

**我们最需要它的一点：好经验不等于好记忆；存得更久、改得更多，也不保证更有用。**

[Useful Memories Become Faulty When Continuously Updated by LLMs，作者正文 v2](https://arxiv.org/html/2605.12978v2)<!--ref:useful_memories--><!--anchor:section:4.2-->比较具体情节记录、一次抽象与持续整合；在所测设置中，持续更新可能损害原有能力。§4.2 给出 episodic-only 对照，§6.4 和附录 L.2 进一步区分抽象、读取旧记忆、覆盖旧记忆等影响。

它支持我们保留原始执行来源、冻结正文、追加反馈，并把原始记录作为对照；**不支持“所有抽象都不好”或“最多改三层就安全”**。后者只是可实验的工程限制，不是论文定理。

最相关的阅读顺序：§3 实验设置 → §4.2 具体经验对照 → §6.2 干扰 → §6.4 更新操作 → 附录 L.2。正式会议/期刊接收状态本次未确认；按预印本引用，不能写“未投稿”。[arXiv 书目页](https://arxiv.org/abs/2605.12978)<!--ref:useful_memories_metadata--><!--anchor:section:Submission history-->

### 2. Zhao 等的 ExpWeaver：经验不应强制进入每一步

**我们最需要它的一点：先承认当前决策可能不需要经验，再研究何时调用。**

[Rethinking Experience Utilization in Self-Evolving Language Model Agents](https://arxiv.org/html/2605.07164v1)<!--ref:expweaver_zhao--><!--anchor:section:3.2-->保持已有经验构建和更新方式不变，将经验暴露为推理时可选的资源。§5.1 观察不同任务、不同模型的调用频率；强模型在部分设置下很少调用。§5.2 已比较移除被调用经验与随机安排调用位置，不能说它没有研究调用的作用。

这不是“经验普遍没用”的论文：其选择性调用在实验中获得收益。它没有直接替我们回答“同预算强 FRESH 已经修复后，历史查询动作还增加多少”。最值得读 §3.2、§4.1、§5.1–5.2。

此处作者是 **Weixiang Zhao 等**，编号 **2605.07164**。本次只确认预印本，不能因为看到另一个同名条目的 ICML 标记就替它升格。[arXiv 书目页](https://arxiv.org/abs/2605.07164)<!--ref:expweaver_zhao_metadata--><!--anchor:section:Submission history-->

### 3. QCR：相关历史找到了，也未必会用

**我们最需要它的一点：历史中的可迁移程序，与必须重新确认的当前实体和事实，要分开。**

[Beyond Retrieval: Query-Conditioned Reuse of Long-Horizon Agent Trajectories](https://arxiv.org/html/2608.12847v1)<!--ref:qcr--><!--anchor:section:5.1-->固定历史候选和选中轨迹，对比无记忆、具体轨迹、通用摘要和当前目标绑定笔记。§5.1 已使用有记忆与无记忆的成功率差；在线生成支持笔记的费用也计入成本。

因此，“净收益差值”和“固定来源比较表示”不能单独宣称首次提出。我们可以借鉴它的变量控制，但本轮主要改变的是**选择器所见信息**，选中后仍执行同一个规范动作；QCR 的重点在选中之后怎样交付历史。本次仅确认预印本。[arXiv 书目页](https://arxiv.org/abs/2608.12847)<!--ref:qcr_metadata--><!--anchor:section:Submission history-->

## 三、本轮先采用怎样的 FRESH

FRESH 是**不读取跨题历史经验、只利用当前问题和允许的当前证据进行修复**。它不是“随便让模型重写一句”，也不等于不能使用结构化状态。

### 1. S2G 的可借鉴部分与原始实现

[S2G-RAG，ACL 2026 主会长文](https://aclanthology.org/2026.acl-long.1185/)<!--ref:s2g_publication--><!--anchor:section:Abstract-->把充分性判断、缺口表达、证据抽取和检索明确分开。其附录 E 给出判断器和证据抽取提示；完整方法包含训练过的判断器，而非只有一句提示。

本次核对 [作者仓库](https://github.com/nianaaa/S2G-RAG) 的提交 `5d842a67a0a99a7b545bbad0dc402ceaae0e5eff`，重点为 [inference_bm25.py](https://github.com/nianaaa/S2G-RAG/blob/5d842a67a0a99a7b545bbad0dc402ceaae0e5eff/inference/inference_bm25.py)<!--ref:s2g_code--><!--anchor:section:build_query_from_missing-->：

- 判断器读取原问题和累计证据，给出是否充分及缺口列表。
- 缺口包含类别、目标、缺失属性/关系和说明。
- `build_query_from_missing` 优先将最多三项 `target + slot` 接到原问题后；字段不足才用说明。它并非每次另外调用模型自由改写。
- 抽取器输出真实句子 ID，再从来源文本恢复证据，不能自由编写“证据”。
- 默认轮次上限为四；首次空证据若被误判充分，代码仍要求至少检索一次。

### 2. GrowRAG 本轮 GAP2 的明确差异

当前选择的是 **S2G-inspired GAP2**，不是完整 S2G-RAG：

1. BASE 首检索产生当前真实证据。
2. 冻结提示词的 Qwen 判断证据缺什么；当前最小接口使用缺口的**文字描述**，尚未完整采用原版 `target/slot` 结构。
3. GAP2 以固定规则将缺口描述补入检索查询，不增加一轮自由改写调用。
4. 最多进行第二次检索，累计、去重后交给同一回答器。

“用描述构造查询”“以 API 判断器替换训练判断器”“最多两轮”“使用我们的索引和证据预算”都必须记入适配清单。以后可在同一批状态上单独比较描述与 `target/slot`，不能把它们现在混称同一个实现。

### 3. 同场对照：Reflective-inspired 自由缺口修复

给它与 GAP2 **同一原问题、同一首轮证据、同一判断器输出的缺口**，让 Qwen 生成下一查询，随后执行同预算的第二次检索。区别只有“机械组合缺口”与“模型自由组织缺口查询”；额外生成调用单独记账。

这条对照能回答：自由改写是否改善了检索表达，还是引入了实体替换、关系遗漏或更多成本。它不是历史经验组；两条 FRESH 都不能读取跨题卡片。

建议首批逐题记录：原查询、首轮证据 ID、充分性判定、缺口、新查询、是否保留原问题约束、第二轮新增证据、答案及 EM/F1、每个模块的调用数和费用。**本文件不报告尚未核验的运行结果。**

## 四、为什么不直接照搬 ReflectiveRAG 的停止公式

[Verma 等 ReflectiveRAG，EACL 2026 Industry](https://aclanthology.org/2026.eacl-industry.27/)<!--ref:reflective_publication--><!--anchor:section:Abstract-->包含自反思检索 SRR 和噪声过滤 NR。它是已审稿的工业轨论文，不能写成主会研究长文。

[正式论文](https://aclanthology.org/2026.eacl-industry.27.pdf)<!--ref:reflective_paper--><!--anchor:section:A-->中，正文 §3.2、实现说明及附录之间有需要澄清的细节：正文提到每轮最多三个改写候选，附录提示要求五个；正文讨论边际停止，附录 C 伪代码仅以充分性终止；附录生成提示列原问题输入，正文条件式生成则还使用当前检索信息。

因此可以吸收“足够就停、不要无限修复”的思想，但不能把自行设定的轮次、候选数、阈值包装成论文原设置。本轮使用明确的二轮硬上限；充分停止、重复/无新增停止、预算停止应记录不同原因。达到预算上限**不代表证据已充分**。NR 未实现时，也不能把 SRR 局部适配叫完整 ReflectiveRAG。

## 五、ReFormeR 暂作下一阶段历史模式基线

[ReFormeR，ECIR 2026](https://doi.org/10.1007/978-3-032-21300-6_30)<!--ref:reformer_publication--><!--anchor:section:Abstract-->是最接近我们的显式历史模式参照，但不要求本轮把所有基线同时接入。

[论文 §2–3](https://arxiv.org/html/2604.01417v1)<!--ref:reformer_paper--><!--anchor:section:2-->描述：从更优查询对归纳模式；读取首轮检索上下文选模式；按模式生成改写；最终拼接原查询与新表达再检索。其监督选择器描述、查询生成条件、实际模型和数据都要与公开代码分别核对。

本次核对公开提交 `72e52450a922bc0051b5b39c3a6307186a555137` 的 [core/reformer.py](https://github.com/aminbigdeli/ReFormeR/blob/72e52450a922bc0051b5b39c3a6307186a555137/reformer/core/reformer.py)<!--ref:reformer_code--><!--anchor:section:select_best_pattern-->：

| 核查项 | 公开代码可见内容 | 我们需要怎样说明 |
| --- | --- | --- |
| 选择位置 | 首检索后，取前三篇文档帮助选模式 | q-only 是单独消融，不能当原版 |
| 选择方式 | 提示调用现成模型 | 不能称已完成论文所述监督训练 |
| 生成输入 | 原问题、规则、示例；此函数不再传文档 | 论文公式包含检索上下文，两条口径需注明 |
| 异常兜底 | 部分异常返回第一模式 | 若改为 BASE，应记为我们的适配 |

ReFormeR 的原实验面向 TREC 检索评价；迁移到 HotpotQA、统一 Qwen/检索器后得到的是**同底座迁移结果**，不能直接与论文表格绝对分数混排。

接入顺序：先让两种 FRESH 的共享输入、证据积累和成本记录跑通；再实现 ReFormeR-style POST 对照，之后才比较 PRE 信息限制。**现有六张 PRE 候选经验不可以改个标签当成 POST 经验**；需要现场证据的动作必须从独立来源按相应协议构建。

## 七、围绕三条问题，哪些可以研究、哪些不能声称首次

| 用户确定的问题 | 本轮可检验的表述 | 已有工作限制了哪些说法 |
| --- | --- | --- |
| 历史是否提供 FRESH 没有的机会 | 同模型、同候选数、同执行预算下，历史动作是否增加有效检索/回答机会 | 不称“FRESH 永远做不到”；一次采样没找到不等于能力不可能 |
| 有机会时，PRE 能否选中 | 只给检索前真实可见信息，预测哪个动作有额外收益 | ExpWeaver 已有选择性调用；ReFormeR 已有模式选择 |
| 真正有效的是什么 | 固定来源和规范动作，仅改变选择器看到的条件；另控提示长度、候选数量、检索次数和实体信息 | QCR 已有表示与净收益评价；Useful Memories 已比较保留与整合 |

我们的潜在贡献不是“三个模块都存在”，而是**在更严格的信息与成本边界下，识别历史查询修复什么时候有独立价值、什么条件让它可选，以及何时应该承认需要首轮证据**。只有实验支持后，才能把这个问题写成方法贡献。
