# S2G 改进切口核验：先证明瓶颈，再决定改什么

核验日期：2026-09-26。状态：有界文献核查与实验建议；**不是新颖性保证，也没有执行新实验**。本文件不修改数据、经验库或基线实现。

## 最值得先记住的结论

1. **ReFormeR + S2G + 二选一路由，目前只是可用的工程起点，不是充分的论文贡献。** 换了两个组件的名称，不等于改变了已有的“按需使用经验”科学问题。
2. 可以先改 S2G，但不能把它已经做过的查询格式、缺口数量、Judge 替换或抽取句数实验重新包装成创新。
3. 我建议先测出：错误到底在“没有取到证据”“取到了却被压缩丢掉”“缺口或查询方向错了”哪一层。随后优先考虑**缺口保真改写**：研究哪些约束在缺口转成查询时被丢掉，以及怎样在相同预算下保留它们。历史记忆最后接入，不提前承担没有证明的贡献。

## 1. S2G 作者承认了什么；哪些不是我们发现的

以下是原文意旨的精简转述，不是逐字翻译。

| 原文位置 | 已有内容与边界 |
|---|---|
| Limitations | gap 表达对多实体连接、时间及组合关系有限；句级压缩可能丢跨句/消歧信息；充分性偏保守；可探索面向系统目标的学习优化。 |
| A.2 / Table 6 | 已比较自然语言 gap 与结构化 gap，以及使用 1/2/3 个 gap。只换成自由改写或多加几个字段不够。 |
| 4.5.5、A.3、A.5 | 已做 teacher / student / 未训练 Judge 对照、另一种小模型 Judge、抽取句数变化。替换 Qwen 或调整句数是复现配置，不自动是贡献。 |
| 4.5.2 | 用累计检索标题覆盖 gold 支持标题作为 Truth，而不是直接标注压缩后上下文是否充分。 |

来源：[S2G 正式论文记录](https://aclanthology.org/2026.acl-long.1185/)、[作者论文全文及附录](https://arxiv.org/html/2604.23783v1)。S2G 的 ACL 正式发表身份已由 Anthology 核实。

**我们的推论：**不能把标题已经覆盖、Judge 仍说不足的所有情形都叫“Judge 误拒”。标题正确，不代表答案所需句子真的进入了 Judge 看见的上下文。一个看似停止判断的问题，可能实际是抽取问题。需要分层核验后，才能确定训练哪个模块。

## 2. 与 ExpWeaver、ProactAgent 的区别究竟在哪里

| 工作 | 它已经做了什么 | 我们可以不同的地方 | 不足以主张新颖的说法 |
|---|---|---|---|
| ReFormeR | 从更好的改写中归纳模式，用当前检索上下文选模式，再指导改写。 | 研究多轮缺口状态下的约束保留与模式适用边界；不只是新数据集分数。 | “把成功改写变成模式”“按上下文选规则”。 |
| Zhao 等 ExpWeaver | 保持既有建库/表示/更新不变，把经验当作可选资源，在推理中触发调用；也探索 GRPO 学习调用行为，并含 HotpotQA。 | 将动作缩小为下一条检索查询；固定相同缺口、检索器、答案模型，对表示和执行的作用分别归因。 | “不用经验也可以”“训练一个调用经验的开关”。 |
| ProactAgent | 把经验检索作为动作；同一前缀比较调用/不调用经验的后续轨迹，并结合任务收益和成本训练。 | 固定 FRESH 为竞争动作，研究查询执行前可用的信息能否预测条件性收益；不联合改变整套智能体。 | “经验减去无经验”“配对分支奖励”“加成本惩罚”“记成功和反例”。 |

来源：[ReFormeR](https://arxiv.org/html/2604.01417v1)、[ExpWeaver](https://arxiv.org/html/2605.07164v1)、[ProactAgent](https://arxiv.org/html/2604.20572v1)。后两者本轮只核实到预印本，不暗示已被顶会录用。

上表“可以不同”只是**研究范围差异**。范围不同不自动是贡献；需要给出新的机制、可靠的经验发现或能推翻既有常见做法的实验。

还有一个概念需要统一：ReFormeR 的公开十种模式是文本规则库，不是可直接当作 GrowRAG 历史库的已训练权重。如果只使用固定模式库，论文中应写“模式辅助”，不能写成系统已经具备了持续跨任务学习。

## 3. 推荐主切口 A：缺口保真改写

**09-27源码核验补充：**作者3.3及 `build_query_from_missing` 会保留原问题，再追加target/slot；不能声称它把原问题所有限制词直接删掉。以下“丢失”应指检索执行时关系绑定、目标消歧或注意重点没有被正确表达/利用的待检验现象，不是已确认的字符串删除。只有开发轨迹呈现此类失败，才推进这个假设。字段更多本身不是贡献。

### 科学问题

> 同一个正确的信息缺口，转换成查询时丢失关系方向、实体绑定或限定条件，是否是失败的重要来源？在不增加检索次数的情况下，是否能学会选择保留这些条件的查询？

通俗例子：题目问“电影 A 的导演出生在哪个国家”，第一跳出现多个人名。下一条查询不能仅仅出现“出生国家”；必须保留“谁是 A 的导演”这个绑定。又如“甲比乙更早”不能改成只查甲的年份。这些例子用于说明机制，**不是已经观察到的实验样本**。

### 为什么不是“多加几条规则”

研究对象不是一个更长的 JSON，而是**查询变换应保留的语义约束**。我们可以暂用极小中间表示：

```text
待查目标：变量或实体
待查关系：具体缺口
已绑定条件：这个目标为何是本题要查的目标
条件来源：原问题中的约束 / 当前证据中的句子指针
未确定部分：仍待检索，不允许自动补成既定事实
```

每个字段必须有可删除的消融和可观察的失败类型。不要先实现时间、否定、排序等十几个专门处理器；先选择自然开发题中确实反复出现的一种绑定错误。`unknown` 不是“不适用”，也不凭空把不确定桥接实体写成事实。

### 最小实验 A1：机会是否存在

在冻结的 S2G 开发轨迹中抽取不足状态，每个状态固定问题、已取原文、抽取证据、Judge gap。只替换下一条查询：

1. 作者的原查询构造。
2. 相同 gap 的普通自然语言改写。
3. 约束保留候选：保留目标绑定及其可追溯来源。

每个分支均只执行**一次相同 top-k 检索**，后续抽取器和回答器相同。候选文本生成也计入费用。先报告 gold 支持句增量，再报告答案变化；二者不互相代替。

训练侧少量人工纠正的 gap 可以作为诊断上界，但只用于标记“有可修空间”，不能作为上线输入，也不能混入测试。模型对同一状态的两次随机生成也可能不同：初筛可以确定性设置，关键结论仍需重跑或报告随机变动。

### 最小实验 A2：机制而非更长提示

固定候选文本/规范动作后，比较选择器看到：

| 表示 | 回答的问题 |
|---|---|
| gap 本身 | 最短形式是否已经够用？ |
| gap + 等长无关/重排控制文本 | 收益是否仅来自长度或额外关注？ |
| gap + 当前绑定条件 | 条件能否帮助排除错误目标？ |
| gap + 条件 + 来源指针 | 指针有用，还是只增加上下文？ |

选择器先用固定 Qwen 做可行性探针；若有稳定机会，再用 train 内配对结果训练小型排序器。**不给每种表示重新生成不同候选**，否则无法单独解释“更会选”来自哪里。

### 成功与否决标准

- 支持：相同检索预算下，条件保留减少意图漂移，且改善支持句覆盖或答案，不只增加查询长度；跨实体分组后仍有效。
- 否决：正确 gap 本来很少；普通同成本改写已同样好；或效果只来自旧答案/实体重复。出现这些情况，应改研究对象，不继续堆字段。
- 代价：需少量高质量状态标注与对照候选；比直接加路由更费分析，但仍不要求一开始训练 7B。

**最近相关风险：**ReFormeR 已做上下文模式选择；[HCQR](https://arxiv.org/html/2603.19008v1) 已用结构化假设指导不同目的的查询。因此“结构化指导改写”并不新。本切口需要证明的是特定约束的保留机制与独立作用，且仍需继续检索其最近邻。

## 4. 备选切口 B：先判断“该再搜，还是该恢复已经搜到的证据”

### 科学问题

> 当压缩上下文不够时，哪些状态真的需要新查询，哪些只需要恢复已检索但未保留的证据？能否在相同预算下减少无效重搜？

维护两种本题材料：原始检索缓存 R，送给 Judge 的短上下文 C。R 是审计/候选源，C 是执行上下文；不把所有原文都塞给答案模型。

### 第一项实验应是诊断，不是训练分类器

对同一个本题状态，比较：

- 标准路径：由 gap 产生新查询，再检索。
- 恢复路径：不新检索，只从 R 中补回覆盖缺口的原句/相邻句。
- 预算匹配控制：随机补同样多的句子；以及同 token 上限的一般重抽取。

离线记录支持句是否“在 R 中但不在 C 中”。这是标注可见的诊断信号，不许作为上线模型能直接读取的特征。上线只看到 q、C、R 的有限摘要/候选、当前 gap 和已有动作。

若存在稳定的可恢复状态，下一步才学习预测“重搜的额外收益”。标签来自 train 内冻结状态的配对执行，模型可先是小分类器/排序器。收益应展示准确率与成本的 Pareto 曲线，不靠任意调整一个权重掩盖损害。

**优点：**诊断清楚、容易看到逐题案例，能与用户要求的真实轨迹直接对应。

**缺点：**需要访问检索后的原文缓存，不再是严格的纯检索前层；更接近 RAG 外部控制器。若作者抽取本来已保留必要证据，这条路可能空间很小。

**已有相似路线：**[ACL 2025 RAG-Critic](https://aclanthology.org/2025.acl-long.179/) 已基于错误分类安排纠正动作；[AdaGATE](https://arxiv.org/html/2605.05245v1) 已研究 gap、微查询与 token 约束下的证据选择；[D2R-RAG](https://arxiv.org/html/2606.29377v1) 已研究预算内诊断与自适应修复。故“先诊断再修复”本身不是新意。本题只是在明确条件下检验**检索缺失与压缩丢失的区分价值**，不是声称已经填补无人研究的空白。

## 5. 后置切口 C：历史动作的适用边界，而不是二选一路由本身

只在 A 或 B 已经有可复用的成功动作之后开展。

### 科学问题

> 将同一修复动作迁移到新问题时，哪些条件决定它比 FRESH 好？删掉哪些条件会造成有害复用，哪些字段其实可以省略？

冻结一批规范动作和候选集合，表示版本建议只比较四种，避免组合爆炸：

1. 原问题 + 原改写示例。
2. 名称 + 通用变换规则（静态模式基线）。
3. 规则 + 触发条件。
4. 规则 + 条件 + 不适用反例。

所有版本选中同一个动作编号时，执行器收到完全一样的动作；历史答案不进入答案提示。实体分组和跨数据集检查用来区分“学会适用性”与“记住词”。

主对照必须包含 FRESH、静态模式、相似度挑经验、按需触发经验，以及不受上线条件约束的离线最好候选上界。没有上界机会，就没有训练路由器的理由。上界有机会但便宜特征预测不了，也应明确报告。

配对净收益只作为实验归因，不宣称“首次提出”。真正需要证明的是：**条件表示使相同选择器更少误用，同时没有因永不复用而虚假变安全。** 因而同时报告修复题数、损害题数、复用比例、漏掉的机会、API/检索/延迟成本。

这条线与 ExpWeaver 和 ProactAgent 重合最强，适合后续机制研究，不推荐当前先做一个笼统 router 后期待自然形成论文。

## 6. 执行阶段和放大条件

| 阶段 | 做什么 | 为什么 | 不能据此声称什么 |
|---|---|---|---|
| S0 | 8 道 train 题跑通 Qwen API 迁移；保存真实请求、响应、检索、句指针、费用 | 查接口、停止条件、可观测性 | 不能声称复现原权重成绩或方法更强 |
| S1 | 新的 32–64 道 train 开发题；逐状态区分检索/抽取/gap/生成问题 | 决定 A 或 B 哪个瓶颈值得做 | 不能把所有未答对都归因于改写 |
| S2 | 针对主要瓶颈做冻结状态配对，限定候选数和相同执行预算 | 先证明有改善机会，再学习选择 | 不能用 oracle 标签充当线上输入 |
| S3 | 独立 train 子集训练/调参；对题目及衍生状态分组 | 防止同题多轮记录串入两侧 | 不能把随机切状态等同独立迁移 |
| S4 | 冻结方法后使用官方保留 dev/test，扩到其他数据集/模型 | 检验泛化与稳定性 | 不能根据评测题结果继续建卡再报同一分数 |

32–64 是诊断样本建议，不是统计功效计算结果。是否扩到 200–500 或更多，应依据误差比例、配对差异和置信区间决定。任何计划中的 API 调用仍受项目批准累计费用上限约束；本文不增加预算授权。

## 7. “能投 SCI 几区”的诚实判断

不能用组件数量预估分区，也不能承诺“做出路由就能发二区”。分区属于期刊及其学科/年份，不是给一个方案的固定质量标签；SCI/SCIE、JCR 分区和国内所说的中科院分区也不是同一件事。[Clarivate 对期刊分区的解释](https://clarivate.com/academia-government/blog/a-primer-on-ties-in-the-jcr/)

当前判断：

- 只有 ReFormeR + S2G + 开关及少量提分：创新证据不足，不能可靠预期任何分区录用。
- 有明确失败机制、针对机制的实现、同成本强基线、跨数据集验证、损害与成本报告：具备形成完整论文的基础；届时再核对具体期刊当年分区和范围。
- 若能给出可迁移的新机制并对最近邻做严格复现，当然可以考虑高水平投稿，但这是结果后的目标，不是现在的保证。

简单机制不等于低级；**无法区分“为什么有效”的复杂系统才更危险**。不应为了看起来高级而先上强化学习或多个大模型。

## 8. 检索与证据边界

本轮使用 academic-research-suite 的来源核验与研究设计指导，直接查阅 S2G、ExpWeaver、ProactAgent、ReFormeR 原始论文页面，核验 ACL 正式记录，并以“RAG-Critic hierarchical retrieval”“RAG evidence compression loss adaptive repair”“ReFormeR context selector”等组合进行反向最近邻检索。不是穷尽式系统综述，没有给出“所有文献都没做”的结论。

S2G / RAG-Critic 的正式会议身份已核验；其他新增近邻本轮只按预印本证据处理。未使用跨模型审稿、没有人工精读认证，也没有付费训练或实验。所有上文实验均为待执行建议；任何收益都必须由真实记录产生。
