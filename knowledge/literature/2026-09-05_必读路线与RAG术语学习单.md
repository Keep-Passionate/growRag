# GrowRAG 必读路线与 RAG 术语学习单

日期：2026-09-05。目的：把历史 86 篇参考文献收敛为能支撑研究判断的阅读路线，而不是继续扩大“全部必读”的清单。发表状态见同日的四批阅读包复核；当前研究方向见同日项目路线。以下是建议，不假定用户已经读完某篇。

## 1. 先明确读完要能回答什么

我们的研究对象不是“生成更好看的改写”，而是**新问题出现证据缺口时，是否应该使用过去的查询修复，以及该用哪一条**。

读完核心路线后，应能独立回答：

1. 检索 query 与最后要回答的原问题为何不是同一个对象？
2. 文档相关、证据充分、答案得到支持、答案正确，为何是四种判断？
3. 本题内 FRESH 与跨题 REUSE 各多用了什么信息？
4. RRM、ReFormeR 已覆盖了我们哪些设计？
5. 成功经验在新问题上失效，为何不等于来源经验是假的？
6. 不看当前 gold 的选择器，如何通过独立数据学习/校准，而不是提前知道结果？
7. 多搜一轮、提高模型强度、拒答更多，是否冒充了记忆收益？

这里“精读”指摘要、引言的问题定义、方法、主实验、关键消融和局限逐句理解；公式中的变量逐一解释，实验中每个 split 的用途核对清楚。附录的证明、全部 prompt 与复现超参数，等对应模块实施时再深入，不要求为了形式把无关附录全部背下来。

第 1–6 篇建立 RAG 闭环术语，第 7–10 篇建立最接近的查询/经验方法边界，第 11–12 篇检验“记忆一定有益”的假设。后两篇虽不是纯文本 RAG，但直接决定我们的立意，不能因未正式发表而忽略它们。

如果第 1 篇的 RAG 基础已能准确讲明白，可以快速复核；不要因此跳过第 7、9、11、12 篇的近邻比较。用户此前说已读部分文献，本表是顺序与学习目标，不要求机械重读全部。

## 3. 三组配套阅读：有明确用途，不继续塞进主队列

### 3.1 查询变换对照课

在第 2 篇之后对照读 [HyDE](https://aclanthology.org/2023.acl-long.99/)（ACL 2023）和 [Query2doc](https://aclanthology.org/2023.emnlp-main.585/)（EMNLP 2023）的机制与实验设置。

- HyDE：先生成假想文档，再编码成向量检索真实文档；假想文本是检索表示的中间产物，不能作为事实证据。
- Query2doc：用 LLM 生成的伪文档扩展查询，观察 sparse/dense retrieval 的影响。
- 我们首版不同时优化全部变换；把它们当可执行候选或基线。若使用 HyDE，检索接口需要接受相应表示，不能声称对每种 retriever 完全无适配。

读完要能区分：paraphrase 是换表达、expansion 是补词/上下文、decomposition 是拆子问题、HyDE 是以假想文档构造检索表示。LLM rewrite 是实现手段，不是和这些形式并列且互斥的一个分类。

### 3.2 开始数据实验前必须读的数据课

[HotpotQA](https://aclanthology.org/D18-1259/)（EMNLP 2018）、[2WikiMultiHopQA](https://aclanthology.org/2020.coling-main.580/)（COLING 2020）、[MuSiQue](https://aclanthology.org/2022.tacl-1.31/)（TACL 2022）。

MuSiQue 是四批清单中核实到的正式期刊论文。精读其问题构建、连接性、捷径排除、MuSiQue-Ans / Full 与不可回答样本设计。三篇都要看实际数据示例和字段：gold answer、supporting facts / evidence、候选段落、官方 split。不要将题目附带的候选段落设置叫成 fullwiki 全库检索。

### 3.3 仅为对应模块选读

| 触发条件 | 选读 | 不要过早做什么 |
|---|---|---|
| 要确定 FRESH 的停止实现 | [Verma 等 ReflectiveRAG](https://aclanthology.org/2026.eacl-industry.27/)，EACL 2026 Industry；AIR / HALT 作边界核对 | 不把“收益很小就停止”包装成新贡献 |
| 要做记忆置信度与在线更新 | [GAM-RAG](https://icml.cc/virtual/2026/poster/65843)，ICML 2026；[ReMe](https://aclanthology.org/2026.findings-acl.829/)，Findings ACL 2026 | 不把 Kalman-inspired gain 直接叫 EMA；不在冷启动时同时训练索引、记忆和 controller |
| 要比较自适应控制层 | [Adaptive-RAG](https://aclanthology.org/2024.naacl-long.389/)、[C-3PO](https://proceedings.mlr.press/v267/chen25an.html)、[SPARKLE](https://aclanthology.org/2026.acl-long.1793/) | 不把“简单题走简单 RAG”当新机制 |
| 要检查最新经验 RAG 重合 | [LivingRAG](https://arxiv.org/abs/2608.25960)，08-26 新预印本 | 不混淆支持度、写入新颖性与未来迁移收益；它不是纯 query 字符串复用 |

## 4. 随读随查的术语表

| 术语 | 通俗含义 | 本项目易混淆处 |
|---|---|---|
| corpus / index | 文档集合 / 供检索的数据结构 | 经验库不是基础文档库；测试所需文档可按基准公开，测试答案不能进经验 |
| chunk / passage | 被检索的文档片段 | 片段切法一变，旧 evidence ID 的含义可能变 |
| retriever / reranker / reader | 先找文档 / 对候选重排 / 据文档作答 | 首版冻结这些组件，研究查询决策 |
| BM25 / sparse retrieval | 基于词项匹配及权重的经典检索 | 通常不能直接匹配无词面重合的同义表达；dense 依靠向量相似度，也不保证语义判断正确 |
| dense retrieval | 把查询与文档表示成向量后匹配 | 不代表一定优于 BM25，取决于问题和语料 |
| query variant | 同一信息需求的一个检索表达版本 | 原 query 也可作为候选；不是一个新的 gold 问题 |
| query drift | 改写偏离原问题意思 | 文档可能支持偏离后的问题，但不支持原问题的答案 |
| multi-hop / bridge entity | 多步证据连接 / 连接两步的实体 | “文字很长”不等于需要多跳 |
| relevance | 文档与问题相关 | 相关不意味着已找到所有必要信息 |
| sufficiency | 当前证据是否足以回答原问题 | 不是问 LLM 自己知不知道答案 |
| support / faithfulness | 某个回答论断是否由所给证据支持 | 不自动等于满足原问题或外部世界完全正确 |
| correctness / gold | 按参考标准答对 / 参考标注 | Gold 可能只标答案或局部证据，不天然有改写好坏标签 |
| gap | 明确缺少的实体、属性、关系、约束或桥接证据 | 状态中既要保留已满足项，也要指明残余缺口 |
| FRESH | 本题内、不看跨题历史的现场修复 | 不等于“任何新生成的 query”；REUSE 也会生成新 query |
| REUSE | 借用跨题历史指导当前修复 | 历史不是答案证据，最终答案仍针对 q0 和当前检索文档 |
| reliability / applicability | 过去表现如何 / 现在条件是否适合 | 分开很合理，但这种区分本身已有近邻，不算已成立创新 |
| negative transfer / harmful reuse | 过去有用的经验对新问题产生负作用 | 不是只指记忆内容本身事实错误 |
| paired comparison | 同一题上实际运行两个或多个方案后对照 | 不能只见 REUSE 答对就归功于记忆 |
| oracle | 看完所有候选真实结果后作出的事后最好选择 | 仅作离线上界或训练标签，不是线上全知路由器 |
| calibration | 用独立数据选择/检验置信分数与门限 | 不是在测试集上挑一个最好看的阈值 |
| memory-build / model training | 建立外部经验库 / 更新模型权重 | v1 需要经验来源数据，不要求梯度训练 |
| frozen / held-out | 实验中保持不变 / 未用于开发的留出数据 | 冻结 prompt 只控制变量，不保证判断正确 |
| reuse coverage / answer coverage | 调用经验的题目比例 / 实际作答的题目比例 | 不调用经验仍可以 FRESH 或直接回答，两者不是同一个覆盖率 |
| QPP | 在没有当前 gold 排名时预测查询检索效果 | pre-QPP 不看候选检索结果；post-QPP 要先检索并计入成本 |

## 5. 每篇只写一页笔记，但关键边界必须具体

建议统一记录七项：研究问题；输入/输出；会训练或改动什么；保存什么记忆；何时读取/写入；反馈与数据划分；与 GrowRAG 的“已覆盖部分 / 可检验剩余问题”。

最后加两个手工例子：一个它理应有益的情况，一个它可能失败的情况。找不到失败例子时，优先检查是否把“有机制”误读成“有保证”。文献综述不是为每篇挑缺点以证明我们更好，而是找到一个现有强对照仍没有解决、且可以测量的具体问题。
