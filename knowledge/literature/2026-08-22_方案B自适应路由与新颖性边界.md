# 方案 B：Adaptive / Agentic Routing 与新颖性边界

更新日期：2026-08-24
证据口径：优先论文官方页、ACL Anthology、PMLR、AAAI Proceedings 与 arXiv 原文
结论性质：定向检索范围内的新颖性评估，不是对未公开工作的绝对保证

## 1. 结论先行

可以参考 adaptive routing，而且方案 B 在具备状态观察、动作选择、再检索和停止后，可以称为轻量级 Agentic RAG。

但是以下组合在 2026 年已经非常拥挤：

```text
不改基础 RAG
+ 轻量控制器
+ 问题/场景分析
+ 显式 gap
+ query rewriting
+ experience memory
+ strategy routing
```

GrowRAG 不能再以这组高层组件作为创新。当前更可守的中心是：

> **带不可变来源的单-query repair episode，如何晋升为长期修复经验；调用时如何把历史可靠性、当前适用性和 BASE 正确→REUSE 错误的风险分别建模并允许拒绝。**

## 3. 为什么不直接预测“简单/复杂”

更好的预测对象是 `intervention need`：离开当前 BASE 是否值得。

原因：

- 短问题可能含实体歧义、时间条件或指代；
- 多跳问题可能被 GraphRAG 的一次调用直接解决；
- 查询与当前语料/检索器的匹配程度，比长度或 hop 数更重要；
- 历史经验本身还有可靠度、适用性和额外成本。

### v1 路由

首版采用 BASE-first。第一次检索后，实际证据比表面复杂度更可靠：

```text
BASE evidence
  -> sufficient                  : ANSWER
  -> insufficient + trusted fit  : REUSE_REPAIR
  -> insufficient + no safe fit  : FRESH_REPAIR
  -> no progress / no budget     : STOP_ABSTAIN
```

### 后续训练标签

在 train/dev 对每题完整执行候选动作，得到 full-information oracle。标签不是“single-hop/multi-hop”，而是：

> 在达到答案/证据阈值的动作中，哪一个成本最低且不造成 correct-to-wrong harm？

这样训练出的小控制器直接优化我们关心的决策。

## 4. Query Transformer、Query Rewriting 与 HyDE

“Query Transformer”在 RAG 工程里通常是一个接口/总称，不是唯一公认的同名核心论文。它可以包括 rewrite、expand、compress、multi-query、step-back 与 HyDE。如果指特定论文，需要提供准确题名。

### 必读的查询算子论文

1. [Query Rewriting in Retrieval-Augmented Large Language Models](https://aclanthology.org/2023.emnlp-main.322/)，EMNLP 2023 Main：Rewrite-Retrieve-Read；prompt rewriter；用 reader feedback + RL 训练小 rewriter。
2. [Precise Zero-Shot Dense Retrieval without Relevance Labels](https://aclanthology.org/2023.acl-long.99/)，ACL 2023 Long：HyDE；先生成假想文档，再用 dense embedding 找真实文档。
3. [Query2doc](https://aclanthology.org/2023.emnlp-main.585/)，EMNLP 2023 Main：生成 pseudo-document 并与原 query 拼接，可用于 BM25 和 dense。

GrowRAG 对它们的使用方式：

- 都作为 `FRESH_REPAIR`/经验卡的 operator 或强基线；
- 不主张发明新 query transformer；
- 研究哪种修复在什么 gap、什么 BASE 环境下能够安全复用。

HyDE 与 Query2doc 的重要区别：HyDE 主要把假想文档变成稠密向量；Query2doc 将 pseudo-document 拼回原 query，因此保留原始词并可直接用于稀疏检索。

## 5. 失败经验是谁做过

### [RRM](https://arxiv.org/abs/2607.28156)

最直接。它维护成功库 `M+` 和失败库 `M-`：

- 失败轨迹不原样复用；
- 只抽取异常、缺失证据和调整方向；
- 只有没有适用成功经验、且失败诊断与当前异常匹配时才考虑失败经验。

### [ExpeL](https://ojs.aaai.org/index.php/AAAI/article/view/29936)

AAAI 2024 正式论文。它利用成功与失败轨迹抽取自然语言 insight，推理时回忆 insight 与成功经验。适合学习“对比成功/失败后提炼经验”，但不是文本 RAG 专用。

### [Reflexion](https://proceedings.neurips.cc/paper_files/paper/2023/hash/1b44b878bb782e6954cd888628510e90-Abstract-Conference.html)

NeurIPS 2023 正式论文。同一任务失败后生成语言反思，放入 episodic buffer 供下一次尝试使用；这更像本题内 trial-to-trial 修正，不是跨问题可信 query-repair 库。

### GrowRAG v1 选择

- 所有完成的失败 episode 冻结并隔离保存；
- 不把失败轨迹或失败卡注入在线回答；
- 只有 verified beneficial success 可以晋升 active；
- 失败只作为 harmful reuse 统计、审计和后续 controller 负例。

这比“彻底不存失败”多一个审计档案，但 serving memory 仍是 success-only。

一个关键缺口是：**成功门控不等于配对增益门控**。某次 REUSE 答对时，BASE 也可能本来就答对；因此它只能算无害使用，不能自动给经验记功。GrowRAG 必须在相同环境与预算下保留 BASE/REUSE/FRESH 的成对结果。

## 6. GAM-RAG 结构与我们的差异

GAM-RAG 的经验单位是 corpus sentence：

```text
sentence -> task vector + time vector + 两个不确定性项
```

成功检索后由 LLM judge 给 sentence support，Kalman-inspired gain 调整向量和更新力度。它擅长让历史上有用的证据句以后更易激活。

GrowRAG 的单位是 query repair：

```text
query episode -> gap -> repair operator/query -> evidence change -> paired outcome
```

所以 GAM 的 gain/EMA 可以以后用来更新卡片优先级或近期信任，但不是我们的 memory schema，也不能证明当前适用性。

## 7. 当前最可守的差异

不是单个新模块，而是一套可证伪协议：

1. 每次 query repair 保留不可变 episode；
2. 具体 q→q' 与抽象 operator 双表示，卡片反向引用来源；
3. 成功、相对 BASE 有益、跨题可信分三级；
4. 历史 reliability 与当前 applicability 分开；
5. 相同 BASE/预算下测量 `P(REUSE bad | BASE good)`；
6. 风险高时拒绝历史经验，回到 BASE 或 fresh repair；
7. 报告 risk–coverage、benefit、cost，而不只报最终平均准确率。

最危险的审稿意见仍然是：

> “RRM + S2G/SPARKLE + Useful Memories 的系统组合。”

必须用以下消融回答：raw episode vs abstract card vs dual；覆盖式合并 vs 版本化晋升；reliability-only vs applicability-only vs joint；有/无 harm gate；BASE/REUSE/FRESH 配对；同文档与跨文档迁移。

## 8. 推荐精读顺序

### P0：读完才能审方案

1. Adaptive-RAG：理解复杂度路由已经做到哪里，以及标签怎样自动产生。
2. C-3PO：理解“不改底座 + 轻量代理”已经不是空白。
3. SPARKLE：理解显式 reasoning gap→targeted query 和 plug-and-play controller 的上限。
4. S2G-RAG：理解可审计的 sufficiency/gap state。
5. RRM：理解 query-only 程序经验、适用条件、成功/失败库和生命周期；它是最近方法基线。
6. ReFormeR：理解历史 query-reformulation pattern 已经如何抽取与选择。
7. MemCon：理解旁路 controller、NoOp 和记忆操作已覆盖到哪里。
8. Useful Memories Become Faulty：理解为何保留 raw episode、为何不持续覆盖卡片。
9. Experience-RAG Skill：篇幅短但危险，理解经验驱动插件路由的重合边界。

### P1：实现和实验前读

10. Query Rewriting in RAG：标准 fresh rewrite/operator。
11. HyDE：假想文档与 dense retrieval。
12. Query2doc：pseudo-document expansion，稀疏/稠密均可。
13. Skill-RAG：typed failure→skill routing；当前只有预印本，但与方案 B 很近。
14. SegMem-RAG：已审稿的经验记忆路由与 episodic/procedural/semantic 划分。
15. State-Aware RAG：当前题 working memory 与冻结底座。
16. QPP Query Variant Selection：检索前/后 variant 选择及 retrieval-generation utility gap。

### P2：扩展时读

17. MBA-RAG：bandit 与成本奖励；训练控制器再读。
18. GAM-RAG：在线 gain 与 sentence memory；EMA/优先级模块再读。
19. ExpeL、Reflexion、ReMe：失败经验和正负经验的通用 Agent 处理。
20. ERSkill：训练 router、经验 trie 和双 frontier；研究技能演化时读。
21. RAGRouter-Bench：未来跨 Vanilla/Graph/Hybrid/Iterative BASE 验证时使用。
