# 已覆盖方向、不能单独声称的创新与共同缺口

更新日期：2026-08-19  
检索边界：截至本日期的已发现正式论文与预印本；提交前必须再次查重

## 一句话判断

“历史成功查询变换 + 检索前选择 + 生命周期管理”这几个高层组件都已有相近工作。仍有价值的切口不是重新命名这些组件，而是：

> 对跨题查询变换复用做严格的成对因果式评价，将历史可靠度与当前适用性分别校准，并把 `DIRECT 正确 → REUSE 错误` 的风险作为显式约束。

这是一项**检索范围内的新颖性判断**，不能承诺世界上绝对没有重合工作。

## 相关工作做了什么、没有做什么

| 工作 | 已经做了什么 | 与我们相关但没有完成什么 | 对 GrowRAG 的结论 |
|---|---|---|---|
| ERM / RAG without Forgetting | correctness-gated 查询扩展持久化；原子归因；更新文档 key | 未要求相对 DIRECT 有净增益；无新问题级读取拒绝；未把 paired harm 单列 | 写入思想基线，不宜直接当纯检索前代码底座 |
| ReFormeR | 从 `q→q'` 对抽取、聚类显式 reformulation patterns；按当前 query 与初检结果选模式 | 不是纯 query-only pre-retrieval；无跨题 trust 校准与 DIRECT 伤害约束 | “typed delta / pattern 复用”本身不是创新 |
| QPP Query Variant Selection | 在完整 RAG 前预测哪个 query variant 更好；比较 pre/post-retrieval QPP | 不保存历史成功经验；不控制 base-correct→rewrite-wrong；主题数小 | 适用性估计与选择强基线 |
| Query Rewriting in RAG | 用 LLM 反馈训练 query rewriter | 不研究跨题经验记忆与读取拒绝 | 改写生成基线 |
| RaFe | 用排序/反馈信号训练或评价改写 | 不解决历史经验是否适合当前题 | 反馈式改写基线 |
| RQ-RAG | 学习 rewrite/decompose/disambiguate 等细化动作和轨迹选择 | 需要训练；不做历史经验的 paired trust | 训练型强参照，不是第一版底座 |
| ReflectiveRAG（Verma 等） | 判断当前证据是否充分，不足则迭代 reformulation；无需 policy training | 每题现场修复，不持久化跨题经验；不是纯检索前 | 检索后 FRESH/repair 基线 |
| S2G-RAG | 本题内搜索到生成的自适应/反思流程 | 不针对历史查询变换的安全复用 | 路线 C 基线 |
| RRM | 从历史轨迹抽可迁移检索知识；记录适用条件、失败模式、可靠度和生命周期；query-level guidance | 多模态长视频、异常后触发；未做文本 RAG 的 calibrated paired harm/risk–coverage | “trust 与 fit 分开”概念不新；定量安全验证仍有空间 |
| GAM-RAG | training-free 经验积累；收益和不确定性共同更新，降低重复成本 | 不是标准 EMA；未聚焦 DIRECT 原本正确却被复用改错 | 不确定性更新基线，不能把 EMA 当新意 |
| ExpWeaver（Zhao 等） | 把经验视为可选资源，允许选择是否调用 | 仍缺查询变换的成对安全协议 | “经验可选”本身不是创新 |
| ExpWeaver（Feng 等，同名） | latent RAG、交叉注意力与 RL 学经验利用 | 不是轻量 query-side safe reuse | 需在 Zotero 中与上一项消歧 |
| MemCon | contextual bandit 控制 retrieve/inject/consolidate/forget 等记忆动作 | 工程/训练重；没有专门解决查询变换的 paired harm | Agent 控制后续参照，不在第一版实现 |
| Useful Memories Become Faulty | 揭示记忆反复抽象/覆盖可能逐渐错误 | 不提供查询复用的风险门 | 支持保留原始记录、不可变 provenance |
| Not All Queries Need Rewriting | 直接展示改写可能伤害，简单 gate 可能很弱 | 不使用历史可信经验；非主会正式论文 | 重要反证，要求先做 oracle 止损 |
| SelectiveNet | 用 coverage 与 selective risk 评价/学习拒绝 | 非 RAG、非历史经验 | 风险—覆盖率评价基础 |
| Counterfactual Harm（NeurIPS 2024） | 形式化“基线本来正确、辅助后错误”的反事实伤害 | 非 RAG；不研究查询变换 | Do-No-Harm 定义的理论参照 |
| SegMem-RAG | training-free 多语料记忆与路由，含失败计数 | 对象是 source routing，不是历史 query transformation | 记忆路由相关但非同一问题 |
| CoEvo-Mem | route-specific rewrite、在线路由和 memory bank 共同演化 | 未做校准安全复用；负干扰仍是风险 | 最新训练/在线路线威胁，暂列跟踪 |
| MERIT | oracle 验证正负经验和 typed delta，用于失败后的 Text-to-SQL 修复 | 依赖 oracle；非文本 RAG 检索前；无 calibrated applicability | 正负经验/原子归因近邻 |
| QCR / Beyond Retrieval | applicability conditions、decline reuse、verification guardrail | 长程 Agent 轨迹复用，非 RAG query transform；非检索前 | “允许拒绝”也不是单独创新 |
| GroundedCache | 用相似性、证据重叠、版本/支持检查控制答案缓存复用 | 复用对象是答案而非查询变换 | 安全复用设计的邻域参照 |

## 不能单独作为创新点

- 记住成功查询或查询改写；
- 把 `q→q'` 抽象成 typed delta / pattern；
- 检索前从多个 query variant 中选择；
- 经验可选、允许 no-op；
- success/failure memory；
- usage、decay、feedback、EMA；
- 多级记忆队列；
- 检索后判断证据不足再 reformulate；
- 历史 CoT/轨迹压缩成笔记；
- `DIRECT / REUSE / FRESH` 三动作本身。

这些仍然可以是实现模块、消融或组合创新的组成部分。

## 目前发现的共同欠缺

### 1. 来源成功与目标迁移混为一谈

很多工作验证经验产生时是否成功，却没有在独立目标题上测：

``
U(\text{REUSE})-U(\text{DIRECT})
``

来源题成功只是进入候选库的资格，不是“trusted”。

### 2. 平均提升掩盖非对称伤害

平均 nDCG、EM 或 F1 可能提高，但仍可能把一批原本正确的问题改错。该风险很少被作为独立目标和约束。

### 3. Trust 与 Fit 多为启发式描述

RRM 已经在概念上包含 applicability/reliability，但现有工作通常没有分别测：

- historical reliability 是否校准；
- current applicability 是否校准；
- 两者各自错误会导致何种 harm；
- 跨 retriever/corpus/domain 后是否仍成立。

### 4. 缺少风险—覆盖率回答

系统通常报告一次性平均分，却不回答：

> 若要把复用伤害控制在某个水平，必须拒绝多少问题？

### 5. 无 gold 时的“正确性”容易循环自证

LLM 产生改写、检索结果，再由同一或相似 LLM 判断结果正确，容易产生确认偏差。RL 也无法在没有奖励来源时凭空知道正确性。

### 6. 环境变化与回滚不足

经验通常和 corpus、retriever、index、prompt/model 版本绑定。局部历史成功不保证换环境后仍有效；不可逆全局更新会放大污染。

## 候选切口对比

| 切口 | 新颖性风险 | 工程难度 | 建议 |
|---|---:|---:|---|
| Safe-ERM 写入门 + 读取门 | 中 | 中 | 推荐做系统主干 |
| Do-No-Harm paired risk | 中低至中 | 中高 | 推荐做论文主张 |
| Trust × Fit ledger | 中高 | 中 | 做核心模块，不能独立成篇 |
| Reversible conditional key delta | 中 | 高 | 第二阶段 |
| 无 gold verifier | 高 | 高 | 先在 gold 上校准，后续研究 |
| 压缩 CoT 检索笔记 | 很高 | 中高 | 相关工作拥挤，先作表示消融 |
| Contextual-bandit Agent | 很高 | 很高 | 设备与阶段都不适合现在做 |

## 推荐组合

首篇优先组合：

1. ERM 式、但更严格的 paired improvement write gate；
2. 历史可靠度与当前适用性分开；
3. 不确定时 `DIRECT`；
4. 主评价为 benefit / harm / coverage / cost 与 risk–coverage；
5. 先用 gold full-information oracle 判断天花板；
6. 成立后再做无需大模型训练的轻量 gate。

## 阅读优先级

1. ERM：看写入门、原子归因和 key 更新；
2. ReFormeR：看已经覆盖的历史变换模式；
3. QPP Query Variant Selection：看不运行完整 RAG 如何做前置选择，以及 utility gap；
4. RRM：看 applicability/reliability/lifecycle 已经做到哪里；
5. Counterfactual Harm + SelectiveNet：看 harm 与 risk–coverage 的严谨表达；
6. Not All Queries Need Rewriting：看负结果与 oracle 天花板；
7. CoEvo-Mem / MERIT / QCR：只作最新前沿跟踪。
