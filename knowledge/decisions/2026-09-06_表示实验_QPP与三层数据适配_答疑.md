## 1. 两个方向用一句话区分

- 经验选择：当前这道题，使用哪条历史经验比不看历史重新改写更值得？
- 经验笔记写法对比（此前称“表示实验”）：同一次成功经历，怎样写成笔记，更能帮助上述选择以及实际改写？这里不是训练向量表示，也不是仅比较 JSON 格式。

S2G 的 gap 是当前这道题尚缺什么信息，是修复的输入状态；不是跨问题经验卡。S2G 可提供共享的当前状态设计和无历史 FRESH 对照；只参考其 prompt/结构、未使用训练后 Judge 时，称 S2G-inspired，不称完整复现。[正式论文](https://aclanthology.org/2026.acl-long.1185/)

### 一个教学例子（不是实际实验结果）

历史问题：“《作品甲》的作者出生在哪个国家？”首检只找到作品介绍，并有证据确认作者甲；下一条查询改为“作者甲 出生地 国家”，随后取得缺失证据。

同一条来源经历可以写成三种笔记：

| 写法 | 给模型看到什么 | 可能优点 | 可能代价 |
|---|---|---|---|
| 具体例子 | 原 query → 成功的下一条 query；原样实体与角色化实体另作对照 | 操作具体，易模仿 | 复制旧实体、把偶然案例当通则 |
| 抽象规则 | 从作品切换到相关人物，查询所缺属性 | 短、容易跨题复用 | 容易丢掉“人物已被证据确认”等边界 |
| 例子＋最少前提 | 角色化改写示例；必须已确认人物；还缺出生地；不能把出生地换成国籍 | 同时表达怎么做、何时不该做 | 多占 token；前提抽取也会出错 |

用新问题“《作品乙》的作者出生在哪个国家？”检查：如果还不知道作者是谁，直接套用“作者→出生地”就可能猜人；如果已经知道作者，此经验才具有执行前提。先有前提也不保证一定比 FRESH 好，仍要实测。

要分清两个实验：

1. **我们内部的受控比较**：同一源步骤、同一目标题/首检证据/候选 ID、同一模型与预算，只换笔记视图。先比较这些视图支持改写的效果，再固定候选池比较它们是否帮助选择；前者单独不能证明“更容易选择”。
2. **完整方法对照**：随后在统一语料、数据划分、模型、预算下重跑 ReFormeR、S2G 等。不同论文的公开总分不能直接相减；改动过方法的版本必须明确标 inspired/adapted。

## 2. “接通配对实验”不是对比分数文件

配对＝让同一道题、在同一个出发点走不同路线，再比较实际结果。

```text
原问题 q0 → 首次检索 → 冻结同一份已有证据和 gap
                         ├─ BASE：不继续检索，用当前证据回答
                         ├─ FRESH：不读历史，现场写下一条 query → 检索 → 回答 q0
                         └─ REUSE：读指定历史笔记写 query → 同一检索器 → 回答 q0
```

所有分支始终回答原问题，不以“下一条查询写得漂亮”替代答案效果。FRESH 也能看完整的当前结构化 gap，不能故意削弱为只看到一句原问题。首个实验每支最多增加一次检索，不同时研究完整多轮。

离线研究为了比较会真的运行各支。线上选择只能使用执行前信息，不能先看哪支答对再称自己预测成功。BASE 与 FRESH 是不同对照，旧 `direct_score` 不能改个名字就当 `fresh_score`。

### 同一道题的直观报告

每题并排展示：原问题、共同证据、当前缺口、来源经验 ID、可见笔记、实际新 query、新证据、最终答案、答案/证据评分、调用与 token 成本。保留错误和超时，不只挑成功案例。

除了平均答案分数，还汇总：

- FRESH 错、REUSE 对：经验真正救回的题；
- FRESH 对、REUSE 错：经验造成的退化；
- 两者都对：是否同样正确但更费，或节省搜索；
- 两者都错：经验是否没有补上真正缺口。

“救回率”分母为 FRESH 错的题，“伤害率”分母为 FRESH 对的题，另报告全体样本数与调用覆盖率；不能混用分母。EM 是标准化后答案完全匹配，F1 是预测与参考答案词语重合的综合分数；它们应按数据集官方脚本计算。

还可报告：新补回的 gold 支持句、已知证据重复率、旧实体误复制/问题目标偏移、笔记长度、相同答案质量下的总费用。完整结果先冻结，再从预设类型选案例，避免挑图讲故事。检索排名/QPP/LLM 判断只是代理信号，不能替代人工 gold 的最终评价。

## 3. QPP 能加入，但必须讲清预测发生在哪里

QPP（Query Performance Prediction）是“查询效果预测”。它本来就是信息检索中的研究方向，不是新造术语。查询变体选择论文区分查询/语料统计与检索结果信号，并指出检索效果更好未必让最终回答更好。[QPP query-variant selection](https://arxiv.org/html/2604.22661v1)

| 位置 | 已经知道什么 | 可以预测什么 | 不可以声称什么 |
|---|---|---|---|
| 改写生成之前 | q0、首检证据、当前 gap、候选经验 | 是否值得尝试某条经验；需专门选择规则/模型 | 不存在的改写已有传统 QPP 分数 |
| 生成 FRESH/REUSE 两条 query 后，执行第二次检索前 | 两条具体 query 与上述状态 | 用检索前 QPP 选择下一条 query | 免费省掉了两次候选生成 |
| 对新 query 检索之后 | 新结果及排名分数 | 检索后 QPP，可用于后续读答选择/评价 | 仍是没有执行新检索的提前预测 |

原查询第一次检索的结果可以免费复用为“当前状态”的信号（首检费用仍计入整题），但不是尚未执行的新 query 的检索后分数。

建议最小顺序：先把配对结果和执行前特征对齐记录；加入轻量 QPP-only 对照；再比较“仅经验条件”和“QPP＋经验条件”。两条 query 先生成再选，是第一种易解释的 QPP 诊断协议，独立报告生成费用；最终线上是否采用先选经验再生成，待成本数据决定。首轮不训练神经选择器。

关键例子：一直搜“作者介绍”可能取得很相关的段落、QPP 也很高，但如果作者已知、真正缺的是出生地，它对当前缺口未必有帮助。我们的候选问题是“当前剩余信息需要下，历史提供的操作是否有额外价值”，不是笼统宣称“我们首创预测有用性”。

本轮新核的边界文献：

- [Predicting Retrieval Utility and Answer Quality in RAG](https://arxiv.org/abs/2601.14546)：已研究检索带来的相对收益及答案质量预测，结合检索、阅读模型等信号；[Springer 官方页确认 ECIR 2026](https://link.springer.com/chapter/10.1007/978-3-032-21289-4_24)。主要信号需已检索上下文，不能当尚未检索的预测。
- [Predicting the Benefit of Retrieval Augmentation in Open-Domain QA](https://arxiv.org/abs/2604.07985v3)：已研究是否使用检索增强及不同预测时点。v3 已改名，作者给出 CIKM 2026 论文集信息与 ACM DOI，本次出版端尚未独立核验；不要称未投稿，也不要写已官方确认。v3 的内部状态预测器也已获得文档，不等于免费省去检索。不要把旧 v1 标题当另一篇。

它们不是历史查询修复选择器，但使“预测相对收益”本身不能成为首次声明。上面论文只作为本轮相关工作边界补充，不要求用户立即加入全部逐字精读队列。

## 5. 数据能否支撑三层？你的担心成立

### 主实验：HotpotQA，之后 2Wiki，再之后 MuSiQue

- [HotpotQA](https://github.com/hotpotqa/hotpot#json-format)：一题包含问题、答案、带标题的段落/句子，以及哪些句子是支持证据。它像“跨资料找两步证据”的问答题，适合首检缺口和跨题经验。
- [2Wiki](https://github.com/Alab-NII/2wikimultihop#dataset-contents)：类似多跳问答，另有关系证据，适合检查桥接实体和关系条件。
- [MuSiQue](https://aclanthology.org/2022.tacl-1.31/)：有组合式多跳问题和支持段落，适合作更困难迁移。分解和子答案是 gold，不可当免费在线输入。

这些数据不是现成的经验卡库，QueryEpisode 由系统实际做题得到，ExperienceCard 从来源题轨迹生成。不同题可能共享文档，但没有保证每篇文档拥有多道相关问题，更没有天然的文档内学习顺序。

Hotpot distractor 已给少量候选段落。若全部交给模型，测的是阅读/证据选择，不能包装成开放全库检索收益。调试的小语料实验必须标 debug；正式语料、切块、索引和题号另行冻结。

### 文档层：推荐 QASPER 单独诊断

[QASPER，NAACL 2021](https://aclanthology.org/2021.naacl-main.365/) 按论文组织：paper_id、分章节全文、多个问题、人工答案与 evidence。它支持“同文档多个问题”的结构，但不能保证有大量重复别名/歧义；先抽样审计再确定能否突出文档层。

建议的 DocumentSession 只保留三类局部内容，均附原文位置和来源题号：

1. 已实际读到并确认的术语/别名对应：帮助把用户说法对齐本文说法；只在该文档版本有效。
2. 章节与段落导航：例如评价指标定义在哪一节；帮助定位，不复制问答答案。
3. 歧义定位与避坑记录：例如某缩写在正文与附录指不同对象；帮助保持当前解释边界。

局部 action 收益统计等扩展字段暂缓。不把成功经验卡、全文摘要、旧答案又存一遍。

我们提出的评价协议，不是 QASPER 原论文原生协议：

- 训练/测试按论文 ID 隔离；同一文档固定文本版本。
- 按预注册顺序逐题，再用其他顺序重复；原数据无真实时间，不能把存储顺序当时间顺序。
- 固定段落切块并通过检索访问；不提前读后题、后题 gold 或全篇后再声称从问答积累导航。
- 每题完成冻结 QueryEpisode；文档层在文档内逐题更新，整篇结束冻结；测试只允许此明确的局部在线适配，跨文档长期库仍冻结。
- 同一道目标题用“没有之前局部记忆”和“只有之前可合法获得的局部记忆”配对。绝不允许从该目标题未来结果中建立其输入记忆。
- 比较：无局部记忆、已读原文缓存、局部导航记忆；另用同预算静态文档地图排除只是预处理收益。长期库开启/关闭可后置交叉对照。
- 统计答案/证据质量、token 与检索次数；看同文档后续题的配对增益，不能直接把后面题更简单解释为学习。误差区间按文档分组。

如果导航记忆不胜过简单缓存或静态文档地图，不能声称三层整体有必要。保留 DocumentSession 接口并不强迫论文必须证明每层都创新。

doc2dial 有同文档多对话，但上下文承接会混入代词消歧收益；QMSum 主要是会议摘要。暂不增加首批工作量。

## 6. 哪个关键点值得证明？

当前“结构化 gap＋三层＋QPP＋EMA”还是架构组合，不能靠模块清单支持高创新判断。值得试的窄问题是：

> 历史经验的价值不仅取决于问题像不像，也取决于当前已知哪些事实、还缺什么。能否在短笔记中保住决定可用性的必要前提，帮助系统选择比 FRESH 更合适的修复？

须正视 ReFormeR 的模式抽取与当前情境选择、RRM 的适用条件、QPP 的查询选择、Useful Memories 的抽象失真；这些不是前人没考虑的问题。我们尚无已证实的独创算法，更不能保证不存在类似研究。

最小证据链：

1. 现象：控制题目相似度/来源经验后，经验相对 FRESH 的结果随当前已知/缺失证据不同而变化。
2. 原因：删除某一必要前提后，选择错误和修复退化增加；保留不相关描述不应取得同样收益。对照删除长度相近的无关内容，排除只是长度变化。
3. 方法：在固定可见信息与预算下，紧凑笔记＋当前状态匹配胜过具体示例、现有抽象模式/条件卡以及 QPP-only。只是增加条件字段但不优于 RRM 风格条件匹配，不能算已解决新问题。
4. 泛化：在独立题和另一数据集成立，不依赖旧人名、答案泄漏、更多调用或大量强模型特权。

可另做“同一问题但可见证据不同”的压力测试，检查某个前提缺失/存在时的行为；修改的是系统允许看见的证据状态而非 gold，也不能人工指定哪支应该赢。此为诊断，不能替代自然数据主结果。

停止标准：若经验没有额外收益、条件不影响结果，或普通 QPP/已有匹配已完全解释收益，应缩小/改选问题，不继续堆模块。负结果可以指导路线，但不承诺一定构成可发表论文。

## 7. 代码到底基于谁？

当前 `external/` 只有说明，没有已克隆的上游；GrowRAG 是自己的原型，不是已经 fork 某篇完整系统。现有 `paired.py` 只整理输入分数，不实际做题；候选召回为词集合 Jaccard，不是 BM25；改写读取预生成计划，没有真实 LLM 调用。

建议：**成熟检索/模型组件＋我们自己的薄配对实验层**。不从头实现搜索引擎，也不整体搬来三套框架后再难以控制变量。

- [QPP-4-RAG](https://github.com/Narabzad/QPP-4-RAG)：参考查询变体、分阶段评估和 QPP；[MIT LICENSE 已核](https://raw.githubusercontent.com/Narabzad/QPP-4-RAG/main/LICENSE)。涉及 Java/Pyserini 与模型/API 依赖，不是零成本 Windows 即插即用。
- [ReFormeR](https://github.com/aminbigdeli/ReFormeR)：最直接的历史改写方法对照。README 有 MIT 声明，但本轮未核得许可证正文；搬代码前继续确认。演示接口与实际类方法也要逐一核验。
- [S2G-RAG](https://github.com/nianaaa/S2G-RAG)：参考证据状态/缺口接口；完整 Judge 基线需模型权重与运行环境。本轮未核得 LICENSE，不宣称已有完整复制许可。

不存在所有 memory-agent-RAG 论文必须遵守的统一工程范式。我们遵守可复现实验规范：配置/数据划分/上游 commit 固定；输入与 gold 评价隔离；共享首检快照；独立分支日志与成本；失败可见；固定 prompt/模型版本；保留原始来源；小型单元与集成测试。完整对照依据论文而不是仅凭脚本名称：QPP 上游某 oracle 说明把最高预测分也称 oracle，不能照搬为“真实结果上界”。

## 8. 最小实施与待决定项

建议逐步验收，不一次落地三层闭环：

1. 共同数据合同＋假模型测试：一份首检快照可分叉；答案标签只进评价器；各支互不污染。
2. 一次真实 repair 的 FRESH/具体经验/具体经验＋最少前提，附 BASE 参考；抽象笔记视图作为下一项低成本扩展，不预选最佳来源。
3. 生成逐题对比页及改好/改坏/费用总表；先看经验是否真的值得使用。
4. QPP-only 与经验条件选择对照，再组合。此时才决定是否值得训练一个便宜小选择器。
5. 单独接 QASPER 文档层，最后才考虑多轮、EMA、自动合并/遗忘。
