## 一句话方向

> 先运行一次不受影响的基础 RAG；只有证据不足时，才显式说明缺什么，并在“可信历史修复、现场新修复、停止并弃答”之间选择。

这是一层可绕过的查询修复控制层，不修改基础 RAG 的索引、检索器或生成器。基础系统可以是普通向量 RAG、BM25/稠密混合 RAG 或 GraphRAG，但每次实验必须冻结其中一种作为 `BASE`。

## 为什么不是“按简单/复杂问题路由”

Adaptive-RAG 已经用小分类器把问题路由到不检索、单步检索或迭代检索；后续工作也已经研究了 bandit、代理模型和多种 RAG 范式之间的路由。因此，“简单问题走简单 RAG，复杂问题走 Agentic RAG”不能作为 GrowRAG 的创新。

GrowRAG 的路由目标改为：

> **这一次离开 BASE 策略是否值得，以及历史经验会不会把原本正确的结果改坏？**

问题表面复杂度只是特征之一，不是最终标签。一个长而复杂的问题可能恰好被当前 GraphRAG 解决；一个很短的问题也可能因为实体歧义而必须改写。

## 首版采用 BASE-first

首版流程冻结为：

```text
原问题 q
  -> BASE：使用原查询运行一次冻结的基础 RAG
  -> 证据充分？
       -> 是：ANSWER
       -> 否：输出结构化 gap 和进展状态
              -> 有可信且当前适用的历史经验：REUSE_REPAIR
              -> 没有：FRESH_REPAIR
  -> 再检索
  -> 证据充分：ANSWER
  -> 没有新增证据或预算耗尽：STOP_ABSTAIN
  -> 否则继续下一轮
  -> 回答结束后冻结 QueryEpisode
```

这个版本仍是 adaptive routing，但不是在检索前猜“难不难”，而是基于第一次真实检索后的证据状态决定是否升级。检索前 `PROACTIVE_REUSE` 保留为后续消融：只有当一条经验的预期收益很高、配对伤害很低时，才测试能否省掉第一次 BASE 检索。

## 这算不算 Agentic RAG

更常用的英文是 **Agentic RAG**，而不是 agentive RAG。

- 如果只是固定规则与冻结 prompt，可准确称为“带 agentic 修复循环的自适应模块化 RAG”；
- 当控制器根据当前状态自主选择 `ANSWER / REUSE_REPAIR / FRESH_REPAIR / STOP_ABSTAIN`，它可以称为“轻量级单控制器 Agentic RAG”；
- 它不需要多 Agent，也不以“多 Agent”作为贡献。

## 已确认的记忆单位

1. `QueryEpisode` 是核心局部单位：一次问题从原查询、每轮检索和修复，到最终回答或弃答的完整轨迹。
2. `DocumentSession` 只是可选容器：把同一文档或同一工作阶段的多个 QueryEpisode 归组；它不是第二套会反复改写的经验。
3. `ExperienceCard` 是跨问题长期程序记忆：从已经验证有增益的 QueryEpisode 晋升而来。
4. 每个完成的 QueryEpisode 都冻结。正确性决定能否晋升，而不是决定是否保存。
5. v1 在线服务只调用成功且验证有增益的长期卡；失败 episode 只进入隔离审计档案，不注入回答。

## 长期记忆采用具体—抽象双表示

不在“保存历史改写”与“保存经验卡”之间二选一：

- 冻结的 QueryEpisode 保存具体 `q -> q'`、动作、证据指针和结果；
- 长期 ExperienceCard 保存去实体化的适用条件、禁用条件、修复算子和证据契约；
- ExperienceCard 必须指回来源 episode/turn，任何合并都生成新版本，不能覆盖原始证据。

## Query Rewriting、Query Transformer 与 HyDE 的位置

GrowRAG 不把“发明新的改写器”作为首版目标。首版把已有方法视为可执行的修复算子：

- `REWRITE`：参考 Rewrite-Retrieve-Read；
- `EXPAND`：参考 Query2doc；
- `HYDE`：生成假想文档并用于稠密检索；
- `DECOMPOSE`：把组合问题拆成子查询；
- `DISAMBIGUATE / ADD_CONSTRAINT / BRIDGE_ENTITY / EVIDENCE_FOCUS`：由结构化 gap 选择。

“Query Transformer”在工程框架中通常是 query transformation 的统一接口，不是本项目需要继承的唯一论文模型。如果项目负责人指的是某篇特定同名论文，需要补充准确标题；当前默认对应 Ma 等人的 Query Rewriting 及其扩展家族。

HyDE 已明确参考，但它只是算子和强基线，不是记忆机制。它更适合稠密检索；对 BM25 不能直接把假想文档 embedding 的做法原样套用。

## 冻结 prompt，之后再训练小控制器

首版先冻结三个 prompt：

1. `state_judge`：判断证据充分性并输出结构化 gap；
2. `fresh_repair`：从 gap 生成现场修复 query；
3. `experience_apply`：把长期卡的修复算子填充到当前实体、关系和约束。

等完整轨迹和 gold 结果积累后，再训练轻量控制器。控制器不是改写器；它只选择下一步动作。

离线训练标签来自同一问题、同一 BASE、同一预算下实际执行所有可选动作后的结果：

- BASE 已达标且最便宜：`ANSWER/BASE`；
- BASE 失败而可信复用成功：`REUSE_REPAIR`；
- BASE/REUSE 失败而现场修复成功：`FRESH_REPAIR`；
- 所有动作无收益或风险过高：`STOP_ABSTAIN`。

若多个动作都达标，选择成本最低且不会造成 `BASE 正确 -> 干预后错误` 的动作。首版先用规则和逻辑回归/树模型，不从强化学习开始。

## 当前论文立意

暂定研究问题：

> 能否在不修改基础 RAG 的条件下，把经过验证的单问题查询修复轨迹，以保留来源的方式晋升为长期经验，并通过历史可靠度、当前适用性和 BASE→REUSE 配对伤害来安全决定是否调用？

暂定简单标题：

- 中文：**检索增强生成中的跨任务查询修复可信复用**
- 英文：**Safe Cross-Task Reuse of Query Repairs in RAG**

## 可以争取、但仍需实验守住的贡献

1. 不可变的单 Query repair episode，以及具体 `q -> q'` 与抽象修复卡的双表示；
2. 来源可追溯、版本化的晋升，不采用持续覆盖式总结；
3. 将“答对”与“相对 BASE 有增益”分开；
4. 分开估计历史可靠度、当前适用性与环境兼容性；
5. 把 `BASE 正确 -> REUSE 错误` 作为一等风险，允许拒绝历史经验并退回 fresh repair；
6. 在 BASE、REUSE、FRESH 的相同预算配对协议下报告 benefit、harm、coverage 和 cost。

## 不能声称的创新

- 首次 adaptive RAG 或按复杂度路由；
- 首次不修改 retriever/LLM 的可插拔控制层；
- 首次 Agentic RAG、轻量 proxy 或 learned controller；
- 首次结构化 gap 后重写 query；
- 首次 query rewriting、HyDE、query expansion 或 decomposition；
- 首次 episodic + consolidated 双记忆；
- 首次经验记忆、applicability conditions、成功/失败双库或生命周期衰减；
- 首次用经验选择检索策略。

## 方案 A 和 C 的处理

- 原方案 A 不再单独作为首篇论文；其 reliability/applicability/harm gate 被吸收到方案 B，成为历史复用的安全部件。
- 原方案 C 不作为主线；充分性、无进展和预算停止只作为方案 B 的必要控制，不主打新的 stopping 方法。

## 最近实施顺序

1. 先实现 QueryEpisode、VerificationEvent、DocumentSession 与 ExperienceCard 的稳定 schema；
2. 接入一个固定文本 BASE RAG 与有 gold 的小数据，跑 BASE/FRESH 的成对轨迹；
3. 冻结 S2G 风格 state/gap prompt 和已有改写算子；
4. 只把 verified beneficial success 晋升为 candidate card；
5. 加入 REUSE 与 trusted gate，完成 BASE/REUSE/FRESH 三臂 oracle；
6. 证明确有跨题收益且可控制伤害后，再训练小控制器；
7. 最后在另一种基础 RAG 上验证 sidecar 可迁移性，而不是首版同时路由多种 RAG。

## 新颖性声明边界

截至 2026-08-22 的定向检索已经发现多个非常接近的 2026 工作，无法诚实保证“全球绝无重复”。当前结论只能表述为：在已检索的一手来源范围内，上述成对伤害、可追溯晋升和可靠性/适用性分离的组合，比泛泛的 adaptive + memory + rewrite 更有可守性；正式投稿前必须持续查重并以实验反驳“只是 RRM + S2G + Useful Memories 的组合”。
