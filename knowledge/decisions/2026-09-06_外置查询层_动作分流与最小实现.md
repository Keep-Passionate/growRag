# 前置查询层＋RAG 外循环：动作分流与最小实现

日期：2026-09-06。状态：用户已认可此前图的总体方向，并明确授权最小编码、本地测试与训练；覆盖此前“先图审、暂停编码”的阶段限制。本记录不把工程实现升级为已验证的论文创新。

## 1. 本轮结论

采用一个薄的外置控制层：进入 RAG 前可保持原查询或改写，得到 RAG 的回答和可见证据后，外层决定停止还是再调用一次。RAG 内部的检索器和回答器不由控制层改写。

首版仍是单题状态＋跨题经验。DocumentSession 后置；不启用 EMA、自动合并、分解子查询、强化学习或完整 agent 框架。

## 2. 是否需要类似 AWM 的状态机

需要简单的显式流程，但不需要先引入重型状态机库。

状态描述“现在到哪一步”；动作描述“接下来做什么”；经验描述“某种做法在什么条件下可能值得借鉴”。三者分开，避免把每条经验变成必须按顺序执行的脚本。

```text
观察当前状态 → 选择 BASE / FRESH / REUSE
             → 必要时生成查询 → 调用独立 RAG
             → 收集反馈 → 停止，或回到选择动作
```

AWM 的核心是从历史轨迹归纳可复用工作流，再提供给 agent 引导执行；不能直接把 AWM 等同于一套显式有限状态机。我们借鉴“工作流经验”，外部循环是自己的简单工程实现。工作流、状态机本身都不作为新贡献。[AWM，ICML 2025](https://proceedings.mlr.press/v267/wang25bx.html)；[作者方法全文 §2、§5](https://arxiv.org/html/2409.07429v1)。

当前用一个有上限的循环实现，不引入 LangGraph 等框架。控制规则和将来的学习策略由一个小的 policy 接口隔开，之后更换选择器不必重写 RAG。

## 3. 改写怎样统一，又不把所有问题解释成“缺信息”

“形式、目的、来源”是三个不同维度，不能混成一串平级类别。

| 维度 | 表达什么 | 首版内容 |
|---|---|---|
| 是否改写／经验来源 | 不变，或改写时是否参考历史 | BASE；FRESH 不用历史；REUSE 参考一条已选经验 |
| 改写形式 form | 查询文本怎样变 | paraphrase 语义改写；expand 扩写；decompose 拆分先保留接口、禁止执行 |
| 改写目的 intent | 为什么要这样变 | 术语对齐、消歧、补关系线索、改变检索表达等简短说明 |
| 适用前提 | 做法何时可用 | 当前问题／已见证据应满足什么；什么情况应避免 |

例如“谁创办了 A”变为“A 的创始人”：问题并没有缺失实体，只是表达改变。它是 paraphrase，目的为术语／表达对齐；同一种形式既可以 FRESH，也可以借鉴历史 REUSE。反之，消歧有时靠重述，有时靠扩写，不能硬绑定为唯一形式。

ReFormeR 已研究明确查询改写模式与情境选择；RQ-RAG 已覆盖改写、拆分、消歧。因此“多种动作统一调度”是必要实现，不是独立首创。[ReFormeR §2](https://arxiv.org/html/2604.01417v1)；[RQ-RAG §2](https://arxiv.org/html/2404.00610v1)。

建议经验卡采用统一外壳，而不是每种改写维护一种数据库。外壳保存 ID/版本、动作形式与目的、适用与禁用条件、具体例子引用、验证记录；动作正文有区别：语义改写存替换模式，扩写存可补入的术语类型，未来拆分才存子问题依赖。

统一结构不等于每条卡填满全部字段。缺口 gap 可为空：没有观察到证据，不得编造结构性缺口。能从问题本身判断的条件用于首次前置选择；必须看文档才能判断的条件，在首次检索前应记为未知。

实施范围：新 RewriteDecision 已分离 action/form/intent，且语义改写不要求 gap。它复用现有 MemoryView 接口；旧 ExperienceCard 全量字段迁移及自动条件匹配尚未做，不能把新动作接口说成新记忆库已全部上线。

## 4. 分流怎样简单而有依据

候选流程为“少量候选 → 检查必要前提 → 比较预期价值”，不是先造几十个专家分支。

1. 先排除明确冲突：篡改原问题目标、时间、否定、实体关系方向；把历史实体当当前事实；当前题引用自己的经验等。
2. 再判断适用性：条件已满足、未知、明确不满足。未知不是逻辑上的失败，可选择 FRESH 或先 BASE 获取证据；不要为了高精度把所有未知都硬过滤。
3. 在可行候选中比较：BASE、同种形式的 FRESH、同种形式的 REUSE。软评分可以包含 QPP、条件匹配与来源验证；具体权重与阈值不能凭感觉宣称有效。

目前只完成选择接口和透明回退策略：默认第一次 BASE，外部反馈允许继续时再 FRESH。调用者可以指定首次改写；自动找历史、自动选择最佳形式和训练后的门控还没有接通。

经验可靠性回答“这个版本过去在什么条件下有效”；当前适用性回答“这道题是否符合那些条件”。RRM 已有适用条件、证据需求及维护机制，不能把有条件字段说成我们首次提出。[RRM 作者全文](https://arxiv.org/html/2607.28156v1)。

## 5. 压缩以后必须重新看待适用范围与置信度

同意用户意见，但不是“压缩一次，置信度统一乘 0.9”。压缩可能去掉噪声，也可能删掉决定适用性的前提；方向不能预先断言。

例子：原笔记“已确认作品作者后，搜索该作者的出生地”，若压成“搜索人物出生地”，就丢失了人物绑定前提。新版本可能在表面相似的新题上误用。

首版规则：旧版本和来源不覆盖；内容压缩／规则修改生成新的 candidate；明确提交新版适用条件和成本估计；新版已验证试验数归零、验证时间为未知。旧成绩保留在父版本，但不冒充新版亲自通过的验证。

已实现 `ExperienceCard.revised_candidate()` 并测试以上边界。它只是创建待验证新版本，**不是自动压缩器，也没有自动证明新范围合理**。原卡仍可保留使用，不必让服务等待新卡验证。

以后可研究：哪些必要前提必须保留？新旧版本在哪类问题上等效，在哪类问题上边界改变？只有拿到独立、配对验证才更新该版本的统计。EMA 可用于近期收益／退化趋势，不能代替重新验证；被调用得多也不自动提高可信度。

## 6. QPP 的时点与我们当前真正训练了什么

QPP 包括检索前和检索后两类。检索前可用 query 与已有索引的统计，不需先获得该候选的排名；检索后则利用排名分数等信息。已有工作直接比较两类 QPP 选择查询变体。[Can QPP Choose the Right Query Variant? §3.6、§4–5](https://arxiv.org/html/2604.22661v1)。

三个问题要分开：

- 原查询预计检索得怎样？这是当前小模型的目标。
- 新生成的查询预计比原查询好多少？需要候选和差值目标；生成候选已花费成本。
- 历史改写是否比本题独立 FRESH 更好？这是经验的额外价值，不能由“原查询难”自动推出来。

若新候选尚未生成，对它的预测更准确地叫“动作价值预测”，不是已存在候选的传统 QPP。上一轮结果可以做状态特征，但不能当未执行候选的检索后分数。

### 本地训练记录

实际使用现有 Hotpot official train 前 200 条便利样本的冻结散列划分。21 条 selector_train 拟合，16 条 calibration_dev 作内部误差检查；其余 163 条 memory_seed 未用于本模型拟合。未使用官方 dev/test。内部开发题以前也可被用于工程诊断，不应称为未见最终测试。

模型是 scikit-learn 的 StandardScaler＋Ridge 回归（alpha=1，svd），不是大模型微调。5 个特征：查询长度、去重词比例、平均／最大 IDF、未出现在候选语料中的词比例。只用每题允许的候选文本统计，无 gold 特征；预处理参数仅在 21 道训练题拟合。

标签通过离线实际运行 BM25 top-4，计算检索到的 gold 支持句比例获得。训练生成标签需要检索；未来模型预测时不需要先执行候选排名。这里是每题给定 distractor 候选集的句级诊断，不是 fullwiki，也不是完整 Hotpot 答案评价。

| 内部开发集 16 题 | MAE：平均绝对预测误差，越小越好 |
|---|---:|
| 总是预测训练集均值 0.75 | 0.270833 |
| 小型 Ridge 回归 | 0.261906 |

差别很小，样本很少，没有显著性或外部泛化结论。不做超参搜索，不据此设路由阈值；模型未控制在线动作。预测值不是答案正确概率、充分性，也不是改写／记忆收益。

## 7. 低耦合的真实边界与终止条件

接口输入：原始问题＋检索查询。原始问题始终给回答器，改写只给检索器。接口输出：回答、可选的本轮证据、调用审计。经验不直接进入 RAG 的事实上下文。

如果第三方系统只接收一个字符串，不能分别表达原问题与检索查询，则无法无损满足此接口；需要它已有的自定义检索查询能力或一个适配器。如果只返回回答、不返回证据，则运行一次并标记未验证，不假装完成证据充分性闭环。

外层累计观察是按稳定证据 ID 去重的 Evidence 记录序列，供下一次查询生成使用。现有适配器每轮回答器只读当轮检索证据；它不会自动联合阅读跨轮证据。以后需要累计阅读时，必须检查底座是否接受外部 context，不能偷偷改变“完全黑盒”的假设。

已有停止条件：正向充分性信号；最大 RAG 调用数（默认 2）；重复查询；没有收益信号／没有新证据 ID 的代理（默认容忍 1 次）；证据不暴露；未配置判断器；生成、RAG 或判断器发生调用错误。

“没有新 ID”只在没有明确收益结论时作便宜代理。即使文档不变，新回答也可能正确利用了证据，因此明确 useful_gain=True 时不能用 ID 未变强制停止。默认次数是工程初值，后续只在独立内部开发集比较 1/2/3 次的质量—费用曲线，不能在最终测试上挑次数。

停止不等于正确。首版保留原始回答和 stop_reason，不把达到预算时的回答标成 supported。最后一轮也不一定是最佳一轮，尚未实现可靠的答案择优或“最好已验证答案”回退机制。

完整 RAG 外循环会重复回答器调用，因此可能比仅追加检索更贵。后续必须同时报告检索次数、生成／判断 tokens、延迟，不以低耦合冒称零额外成本。

## 8. 最小实现、验证与未实现部分

| 文件 | 本轮职责 |
|---|---|
| `src/growrag/outer_loop.py` | 独立 RAG 接口、外循环、停止规则、原问题隔离、费用与错误审计 |
| `src/growrag/query_actions.py` | BASE/FRESH/REUSE 与形式分离；单查询语义改写／扩写的固定 prompt API 适配器 |
| `src/growrag/preflight_qpp.py` | 5 个检索前特征、独立划分检查、离线标签及小模型拟合 |
| `scripts/train_preflight_qpp.py` | 本地训练入口 |
| `src/growrag/experience/cards.py` | 在现有模型上增加“新版候选不能继承旧版验证成绩” |

没有直接复制 AWM/ReFormeR 上游代码；复用项目现有数据、检索与受审计 API 接口。借鉴 QueryGym 的统一查询改写接口思路，不声称这里是官方代码复现。[QueryGym 方法接口](https://querygym.readthedocs.io/en/stable/user-guide/methods-reference/)。

测试：完整 382 passed（此前 336，新增 46），改动 Python 文件 Ruff 检查通过。独立只读审计发现的 4 个问题均修复并有回归测试：Reader 失败漏记先前检索成本；judge 失败丢回合及费用；mock/real 来源冲突；新 ID 代理覆盖明确正收益。

单元测试中 RAG 与语义改写使用可控测试替身，证明流程约束，不证明模型质量。实际 QPP 拟合和 BM25 标签生成在本地 CPU 执行。本轮无付费 API，无读取密钥，无 GPU 训练；新改写 prompt 仅做模拟传输契约测试，尚未实测其真实质量。

外部 assessor 的普通 Feedback 返回值被约定为纯本地检查，不得藏 API；真实模型 judge 必须返回带费用与传输审计的 CallResult。接口中的 real 标记本身不是实际 API 调用证明，必须核对底层传输日志。

尚未实现：自动经验条件选择、受校准的安全门、真实充分性 judge 接入该新循环、经验压缩器、QPP 差值／REUSE 增益训练、拆分多查询、跨轮累计阅读、EMA、文档层、正式数据集比较。旧首轮 8＋8 API 结果不能移作新外循环的效果。

## 9. 模块创新先想清楚，再做消融

不要求每个模块都有创新；一篇论文应有一个清晰可证伪的主机制，其余模块构成公平、透明的实验载体。

| 模块 | 已有工作／工程性质 | 我们要证明什么 |
|---|---|---|
| 外循环、状态控制 | AWM 等工作流思想；迭代 RAG 已有 | 工程可替换、成本透明，不主张新颖 |
| 多形式查询改写 | ReFormeR、RQ-RAG、QueryGym | 固定动作族的公平基线，不主张新颖 |
| QPP 前置预测 | 已有直接查询变体选择研究 | 作为便宜强对照，不能因加入 QPP 就称贡献 |
| 适用条件／历史选择 | RRM、QCR 等已有条件化经验 | 有限笔记长度下，哪些前提确实影响新题的相对收益 |
| 经验压缩与改版 | 丢失前提有害已有直接近邻 | 新旧表示的适用边界能否被有效检测、保留与重新校准 |

建议主假设（尚未证明独创）：在相同操作形式与预算下，保留并检查最少的必要适用前提，能否使经验在适用新题上优于 FRESH，同时避免在表面相似但前提不符的新题上有害复用？压缩前后版本的边界变化是这个问题的一种强测试，而不是另一套大系统。

验证不是只看总分：同题列出 BASE/FRESH/REUSE 的查询、新增支持句、答案、是否跑偏、成本；区分“确实不用经验也会成功”和“经验带来额外支持”。QPP-only、相似度选择、RRM/ReFormeR 风格选择须为直接对照。已有 QCR/AMA 等重叠约束仍见上一轮复核，不保证“没有类似工作”。

下一步建议只做一件事：在固定单次语义改写形式上，接通同状态 FRESH 与一条候选 REUSE 的配对记录，让适用／不适用的具体案例与增量标签可检查。先不同时加入拆分、自动合并、多轮训练。这个标签集才支撑后来“什么时候值得用经验”的小模型，而不是拿本轮绝对召回预测冒充它。
