# 两层记忆：具体存什么、为何这样分、哪些优势尚待验证

## 最需要掌握的三点

1. 本题记录保存“这一次真实发生了什么”；跨题卡保存“以后可尝试什么、何时适用、有什么验证记录”。临时不等于必须删文件，持久保存不等于自动参与后续回答。
2. 两层、规则、适用条件、版本化都不是天然创新。当前研究目标是：在同预算强FRESH面前，哪些最少可观察条件真正改善选择，减少有害复用而不过度拒绝。
3. 用户2026-09-19确认离线/在线分开、最多两轮。下面区分设计定稿、已有代码和待接通部分；两轮不保证比一轮好。

## 1. 层次与用途定稿

- QueryEpisode：一题一份，不是一篇文档一份。运行时暂存当前问题、证据、尝试、判断和消耗；结束后冻结为审计记录。不会仅因答对就直接加入执行记忆。
- ExperienceCard：跨题程序性记忆。可以被候选召回和选择器读取，指导查询变换，但历史答案和整段历史文档不直接喂给当前Reader。
- DocumentSession：保留旧设想，不进入本轮核心、不新增第三层。
- 离线/在线是阶段，不是两座必须分开的数据库。审计与执行是访问用途，也不额外算两层学习架构。

transient 指本题工作状态在本题后退出运行上下文；persistent 指未来查询能实际检索到并依赖的记忆。审计文件可以长久保留，但不属于默认可调用经验。归档不是销毁，也不是模型遗忘的数学保证。

在线：原q → PRE选择BASE/FRESH/REUSE → RAG1 → 检查证据 → 足够则结束，否则允许POST FRESH/REUSE → RAG2 → 有支持的回答或说明不足。第一组POST实验将PRE固定为BASE来隔离变量，最终PRE入口仍保留。

## 2. 本题记录：六组必要信息

| 组 | 具体内容与现有对应 | 为什么在本题层 |
|---|---|---|
| 身份与目标 | episode_id、original_query、run_context_id、comparison_group_id；新运行时是LoopState.question | 防止改写后换了题；同题不同实验分支可配对；全局配置只存指针 |
| 每次实际动作 | BASE/FRESH/REUSE、实际query、operator、目标gap ID、卡的精确版本 | 区分提出过与真正执行过的动作，识别重复搜索及历史来源 |
| 本题真实证据 | doc/unit或evidence ID、来源、内容指纹、轮次；运行缓存持真实文本 | 支持累计、去重和引用校验；事实只对这道题的当前语料有效 |
| 当前判断 | sufficiency、gap、进展、下一动作与停止原因 | 指导下一轮，但判断可以错，不能当gold |
| 成本 | 检索次数、模型调用、输入/输出token、耗时；金额由账本附加 | 判断是否继续，区分采集总支出与某策略部署支出；未知费用不能写0 |
| 终局与反馈 | 最终答案/证据指针、停止原因；之后追加反馈来源和对照分数 | 运行事实不被后来judge改写；gold、人工、judge、代理反馈分开 |

真实代码：src/growrag/episodes/models.py 的 FrozenQueryEpisode、EpisodeTurn、GapItem、EvidenceRef、VerificationEvent。旧存档只存证据指针；运行时 src/growrag/outer_loop.py 的 LoopState.observed_evidence 保存本题真实文本。这不是矛盾，而是缓存与存档用途不同。

全局 RunContext 存语料/索引政策/检索器/生成器/prompt/judge/预算版本，episode只引用它。每题候选文档池另记hash用于配对复现，不要求不同题使用完全同一份候选段落，否则Hotpot跨题迁移会被错误禁止。

### 2.1 下一步必须补的小状态，而不是长CoT

建议新增明确标为v1的观察结构：

- requirements：原问题需要回答的对象、属性、关系、时间或比较要求。是模型对问题的解释，允许错误。
- support_links：每项要求对应的已检索证据ID，以及支持/冲突/未知标记；程序先检查ID确实存在。ID有效不代表语义判断必然正确。
- gaps：未支持的要求、类别与目标；关联requirements。保留OTHER以涵盖词汇不匹配、描述不充分等，不把所有修复强行归成“缺实体”。
- previous_attempts：query、命中文档ID、是否重复；引用已有轮次，不重复存长文本。
- decision：停止/修复，以及短理由；不需要保存隐藏推理链。
- query_constraints：不能换的问题目标与已显式给定的约束；不能把推测出来的答案当约束。

当前旧GapItem有category/target/slot/description，但没有完整“要求→支持句”的映射；旧充分性是sufficient/insufficient/unknown，冲突可用contradiction gap表示。新字段是待实现设计，不声称现有模型已可靠填出它们。

第二轮Reader必须看到去重、有长度上限的真实累计证据，而不是只看到第二轮片段。首版可固定每轮top4、累计最多8句和冻结的总token上限；token上限具体取值先用无gold文本长度预检确定并记录，不以字符冒充token。超限需确定性选取并记录被删证据，不能假装保留全部。冲突证据不能无声丢弃。

## 3. 跨题卡：统一外壳，动作正文与历史统计分开

| 组 | 真实字段 | 用途/为什么不放本题正文 |
|---|---|---|
| 身份与版本 | card_id/version/schema_version/created_at/parent_versioned_ids | 追踪哪版被执行；修改后回到候选，不继承原有验证 |
| 适用范围 | activation.stage/query_pattern/gap_pattern/preconditions/contraindications/required_retriever_capabilities | 保存稳定的条件规则；这次题满足多少条件由选择器另算 |
| 程序性动作 | repair.operator_type/action_body/intent/evidence_contract，旧版slot_template | 描述可迁移操作与希望补到的证据，不记“这题答案就是某城市” |
| 来源 | provenance的episode-turn引用或PRE source引用、代表例、独立来源数 | 抽象可回查到真实q→q′，不靠摘要自己证明自己 |
| 验证 | validation的配对次数、收益/中性/损害次数、均值、反馈事件及来源等级 | 全局历史效用可重算，不能把一次来源成功误当跨题可靠 |
| 使用与状态 | serving.expected_cost/use_count/last_used_at；candidate/active/quarantine/retired | 选择时估成本，维护时停用；使用多不代表因果上更有效 |

真实代码：src/growrag/experience/cards.py。名称、描述、规则、示例是读给人/选择器的逻辑视图，当前并非都已经是ExperienceCard的同名顶层字段。新增展示视图时复用query_pattern、intent、action_body及provenance，不为了凑四字段复制同样信息。

reliability（历史可靠程度）来自跨题验证；applicability（当前适用性）来自当前q/证据与条件的匹配。二者分开能表达“以前很好用，但这道题不适用”，却不能仅凭分开字段就自动判断正确。

旧默认激活策略的“两题/两文档/两次配对、损害率上限0.1”等是工程门槛，不是统计安全保证；2次没损害不等于未来风险低于10%。本轮不放宽门槛凑活跃卡。离线验证可有显式候选池，不能偷偷绕过生产ACTIVE权限。

### 3.1 压缩与生命周期

- 不改写旧来源；新规则/压缩产生新版本并重新验证，旧版保留。
- 首版只使用原始来源加一次抽象；不实现自动反复合并。用户倾向最多两三层抽象，超过后回原始来源重提取或停用；目前尚无可靠自动深度管理实现。
- 成功动作可成为候选；失败/无收益记录用于审计、验证和调整范围，不作为“执行失败动作”的默认经验。
- 评价时冻结卡库。测试gold不写回。以后若做流式更新，必须先预测后获得合法反馈，再更新下一题可用记忆。

### 3.2 教学示例（虚构，不是实验结果）

问题：“影片T的导演出生在哪个城市？”
本题第一轮找到带ID的句子“T由甲执导”，缺口是“甲的出生城市”。第二轮可查询“甲 出生城市”，Reader仍回答原问题。

长期经验不应保存“T答案是Y”。可保存：
- 描述：已确定桥接人物，但目标属性未覆盖时，进行人物—属性检索。
- 条件：桥接人物来自本题已检索证据；关系确为导演而非编剧；没有互相冲突的人名。
- 规则：用有来源的人名加原问题属性构造query，不更换人物角色、不推测答案。
- 例子：真实来源q→q′的指针。
对新题“编剧出生地”不能机械套入导演；条件能否避免此误用，就是要测的假设。

## 4. 前人共同面对的矛盾，不是“他们全都没做”

| 研究张力 | 已有工作做到了什么 | 我们可检验的更小目标 |
|---|---|---|
| 来源成功≠目标适用 | ReFormeR已有上下文选模式；RRM已有适用条件与证据要求 | 同动作池下，哪些条件减少选错、同时保留有益复用？ |
| 压缩省token但可能丢边界 | QCR已有目标绑定笔记；Useful Memories已研究抽象漂移与保留情节 | 信息相同时结构是否有用？删哪类边界会增加损害？ |
| 多检索补证据也可能引入噪声 | S2G/ReflectiveRAG已有充分性、缺口与多轮控制 | 同一首轮状态、同最多两轮预算下，历史比强FRESH多什么？ |
| 组合模块容易混淆收益来源 | QCR固定选中来源比较表示；S2G固定组件做消融；AWM研究离线+在线组合 | 把“选得好”“改得好”“多算了一轮”拆开评价 |

文献定位：
- [ReFormeR §2](https://arxiv.org/html/2604.01417v1#S2)：q和初检Dk选模式，再生成并检索。不是答案后反思循环。
- [RRM](https://arxiv.org/html/2607.28156v1)：已有OQR、本题/历史区分、查询级复用、答案隔离和生命周期；不能称我们首次。
- [QCR §4–6](https://arxiv.org/html/2608.12847v1)：选后表示对照，§6未逐字段隔离；我们的第一实验针对选择器看到哪些字段。
- [Useful Memories v2 §5–6](https://arxiv.org/html/2605.12978v2)：具体情节有时可匹敌/超过双存储，不预设双层稳赢。
- [S2G-RAG §4.5.4–4.5.5](https://aclanthology.org/2026.acl-long.1185.pdf)：证据压缩与轮数分别消融。
- [ReflectiveRAG §3](https://aclanthology.org/2026.eacl-industry.27.pdf)：反思与停止控制。
- [AWM](https://proceedings.mlr.press/v267/wang25bx.html)，[方法及附录C](https://arxiv.org/html/2409.07429v1)：工作流及offline+online，组合并非自动相加获益。

希望解决的不是“前人没有可靠性”，而是识别可迁移条件的独立价值。可证伪目标：
在相同来源、候选、执行动作和预算下，最少的可观察适用条件，是否改善相对强FRESH的选择质量与损害—覆盖权衡？

## 5. ReFormeR 的POST：借鉴接口，不急于微调参数

论文：q → 初次检索Dk → 模式选择 → 改写r → q与r拼接 → 再检索。它主要评价检索，不等于已包含我们的回答、充分性judge和两轮停止协议。首轮检索不应被误算成“已做一次检索+回答”。

公开核心：[作者实现](https://raw.githubusercontent.com/aminbigdeli/ReFormeR/main/reformer/core/reformer.py)。本轮只读核查，main分支可变，复现必须固定提交：
- select_best_pattern读q、模式及前三篇检索文档；
- apply_pattern读q、规则、示例，未将文档传入；
- 用现成Qwen提示调用，与论文写出的训练选择器/生成损失不等同；
- 失败默认第一条模式，不等于安全NOOP；适配时改变回退必须披露。
未确认源码许可前不原样复制。采用独立方法适配，先不微调LLM。完整ReFormeR复现和同底座适配版分开命名。

## 6. 当前代码的四处断层：下一位模型不能误读

1. 运行时LoopState/RoundRecord与FrozenQueryEpisode未自动统一。旧episode强制BASE-first和prior-gap，不能硬塞PRE-first语义改写。
2. outer_loop中的Reader仍只读当轮证据；旧PairedRunner有累计阅读可参考，但它依赖外部给定状态，不是自动闭环。
3. 旧VerificationEvent/TransferObservation/CardValidation以DIRECT/BASE为对照；独立报告已有REUSE−FRESH，但不能把FRESH分数写进direct_score。
4. 六张09-11 PRE来源卡仍是候选，不自动变成POST卡或可信卡。新POST小实验单列来源与协议，旧6卡和原8/24名单不改。

本轮仅审计和规划，未实现新schema或新闭环、未运行模型效果实验。
