# GrowRAG 方向决策与启动计划（讨论稿）

更新日期：2026-08-19  
当前状态：方向讨论中，尚未进入正式实现  
当前优先路线：检索前历史查询改写的安全复用  

> 本文记录本轮讨论后较可信的方向和止损条件，供后续共同确认。它不是已经证明成立的结论。
> 2026-08-19 之前的 A1、M1/M2、v2、v2.1、项目说明和对话总结均视为历史方案；旧代码也不再约束新设计。

## 一、当前建议

第一阶段不做“新的 RAG 范式”，也不同时做在线 Agent、EMA、CoT 压缩和检索后闭环。

建议先回答一个窄而清楚的问题：

> 在第一次文档检索之前，RAG 能否从历史上验证有效的查询变换中，提前选出一条适用于当前问题的经验；如果不确定，就保持原查询不动，从而减少有害改写并节省每题现场改写的成本？

暂定工作名：**GrowRAG：历史查询改写的安全复用**。

第一版只有三个概念：

- `DIRECT`：不改写，直接使用当前原问题检索。
- `REUSE`：选择一条历史查询变换，并把它应用到当前问题后再检索。
- `FRESH`：不使用历史经验，为当前问题现场生成一个新改写。它也是改写，但来源是当前即时生成；第一版先把它作为强比较基线，而不是放进主控制器。

## 二、最重要的概念拆分

“这条经验可信”和“它适用于当前问题”不是同一件事。

| 判断 | 通俗含义 | 何时能够知道 | 第一版如何处理 |
|---|---|---|---|
| 历史可信度 | 这条经验过去是否真的帮过忙，而不是偶然成功 | 使用当前问题之前 | 只接收来源清楚、在独立问题上有正收益记录、且检索器与语料版本匹配的经验 |
| 当前适用性 | 过去的办法看起来是否适合眼前这个问题 | 检索前只能预测 | 根据当前问题与经验的语义、结构、实体关系及适用条件打分；不确定时拒绝复用 |
| 当前实际成功 | 用完以后是否真的比原查询或现场改写更好 | 必须执行检索并获得评价后 | 离线实验中用于检验选择器；部署时依赖可获得的反馈更新后续经验 |

因此，用户提出的疑问是正确的：**在执行以前不可能百分之百知道改写是否成功。** 检索前层能做的是风险受控的预测，而不是证明。

这也形成了本项目的第一个止损条件：如果执行前可见的信息无法预测哪些历史经验会帮助当前问题，那么纯检索前路线就不成立，应转向检索后修复路线。

## 三、新颖性边界

截至 2026-08-19，以下高层想法已经被覆盖：

- **ReFormeR（ECIR 2026）**：从历史上更成功的原查询—改写查询对中抽取可迁移模式，再为新查询选择模式。它已经覆盖“保存并复用历史查询变换模式”。
- **Can QPP Choose the Right Query Variant?（SIGIR 2026）**：在运行完整 RAG 以前，用检索前预测器选择查询变体。它已经覆盖“检索前选择较好的查询版本”。
- **RRM、MERIT、Beyond Retrieval/QCR**：分别覆盖历史检索轨迹、已验证正负修复经验、轨迹压缩后的适用条件和验证要求。
- **CoEvo-Mem（2026-08 预印本）**：已经联合更新 route-specific query rewrites、轻量路由器和 memory bank；因此“路由＋记忆在线共同演化”也不能作为宽泛创新。

因此，不能声称：

- 首次记住成功改写；
- 首次在检索前选择查询变体；
- 首次把历史经验作为可选资源；
- 新的记忆化 RAG 范式；
- EMA 本身是创新。

目前仍可能成立、但需要进一步查证和实验证明的差异是：

1. 把**历史可信度**与**当前适用性**明确分开，而不是给经验一个全局分数；
2. 在纯检索前、跨问题复用的设置中，允许 `DIRECT` 拒绝经验；
3. 用严格无泄漏协议研究原本正确的查询被历史经验改坏的风险；
4. 在没有测试标签时，验证轻量代理信号能否预测真实收益，而不是直接把代理分数当正确答案；
5. 报告质量、复用覆盖率、有害复用率和真实成本之间的边界。

更准确的论文核心不是“给可信经验更高分”，而是：**估计某次历史查询变换迁移的条件化伤害风险；风险过高时拒绝干预。**

这是一个“受控问题研究＋轻量方法”，不是全新范式。任何“首次”表述都必须在最终投稿前重新检索确认。

## 四、路线 A 与路线 B

### 路线 A：检索前主动适配（当前先做）

流程：

`当前问题 → 找历史查询经验 → 判断是否适用 → DIRECT 或 REUSE → 只执行一次正式检索 → 回答`

优点：

- 结构简单，可以作为旁路接入现有 RAG；
- 不必先支付一次失败检索再修复；
- 容易测量是否节省现场重写调用、token 和延迟；
- 不修改索引、切块或生成模型。

困难：

- 看不到当前检索结果，只能估计适用性；
- 与 ReFormeR 和 QPP 的重合风险很高；
- 若问题之间没有可迁移结构，历史经验只会退化成近重复缓存；
- 如果生成候选改写的成本与现场改写一样高，“复用更便宜”的主张就不成立。

### 路线 B：首次检索后的可靠修复闭环（暂缓）

流程：

`原查询检索 → 判断证据是否充分/缺什么 → 必要时调用历史经验或现场修复 → 再检索 → 验证 → 回答`

它确实与 Self-RAG 有共同思想：都让系统评价检索或生成是否需要调整。但二者不是同一个研究对象：

- Self-RAG 训练一个模型生成特殊反思 token，控制本题内是否检索、文档相关性、答案支持性和答案效用；
- 路线 B 更接近 ReflectiveRAG 和 S2G-RAG：先看本题检索到的证据是否充分，若不足则明确诊断缺口并改写下一次检索；
- 如果 GrowRAG 将来做路线 B，可能的新增部分只能是跨题历史修复记忆、可信读取、拒绝和回滚，而不是“证据充分性判断”本身。

路线 B 的优点是判断依据更强、闭环更可靠；缺点是至少多一次检索/判断，结构和成本都更重，且近邻工作更多。它保留为路线 A 失败时的后备方向或第二阶段扩展。

## 五、没有 Gold 时怎么办

`Gold` 指数据集中由人工或可信流程提供的参考答案、相关文档或 supporting facts。它不是模型自己生成的分数。

没有 Gold 不意味着必须使用强化学习。强化学习也需要奖励；如果奖励只是错误的代理指标，它只会更努力地优化错误目标。

建议分两步：

1. **科学验证阶段使用有 Gold 的数据集。** 先确认哪些代理信号真的与真实收益相关。如果在有标签环境中都无法验证，就不应直接部署到无标签环境。
2. **现实部署阶段使用经校准的弱信号。** 候选包括检索器/重排器分数、证据覆盖与互补性、引用蕴含、答案一致性、用户确认和下游任务是否完成。它们都只能叫代理信号，需要在有 Gold 的开发集和少量人工抽查中验证。

第一版不使用 RL。只有当可观测反馈明确、简单规则或小分类器不足，并且在线探索的风险可接受时，才考虑强化学习或 bandit。

## 六、EMA 的位置

EMA（指数移动平均）可以理解为“更重视最近反馈的平滑平均”。它适合做两件事：

- 当语料或问题分布变化时，让近期成功/失败更快影响经验优先级；
- 为经验的热、温、冷或暂时隔离提供一个辅助信号。

它不能直接解决：

- 当前问题是否适合某条经验；
- 没有反馈时如何知道成功；
- 一次偶然成功是否可信；
- 语料版本已经不匹配时是否应立即失效。

现有论文也并非都用 EMA：RRM 使用频率、复用反馈和时间衰减；GAM-RAG 是受 Kalman 思想启发的收益与不确定性更新，并非标准 EMA；ERM 是正确性门控的持久写入；MemCon 使用学习型控制。故 EMA 暂时从核心贡献中移除，等在线生命周期阶段再作为普通基线。

## 七、基线和代码策略

### 研究基线

- **主选择基线：Can QPP Choose the Right Query Variant?** 它最接近“检索前判断哪个查询版本更值得执行”。
- **主经验表示基线：ReFormeR。** 它最接近“从历史成功改写中抽取可迁移模式”。
- **基本对照：** `DIRECT`、随机经验、最近邻经验、always-reuse、每题 `FRESH` rewrite。
- **训练型强参照：RQ-RAG。** 第一版不必训练或完全复现，但若以后扩大动作空间或训练控制器，必须比较。
- **路线 B 对照：ReflectiveRAG、S2G-RAG。** 只在进入检索后闭环时使用。

没有一篇论文能够单独作为全部代码基础，因为 GrowRAG 处在 ReFormeR 的经验模式和 QPP 的检索前选择之间。

### 代码选择

推荐采用“公开评测骨架＋薄增量模块”，而不是两个极端：

- 不继续重构旧 GrowRAG 主流程；
- 也不从零重写所有检索和 query rewriting 方法；
- 以 **QPP-4-RAG** 公开仓库作为主要检索、生成、QPP、oracle 和端到端评价骨架；它已经包含原查询、六类改写、BM25/稠密检索、RAG 生成和 nugget 评价；
- 使用 **QueryGym** 补充查询改写、提示词版本和跨数据集方法复现；
- 单独实现很薄的历史经验库、候选召回、`DIRECT/REUSE` 选择和评价层；
- 按论文复现 QPP 特征，并包装 ReFormeR/RQ-RAG 的公开实现或结果，而不是 fork 一个庞大的 Agent 仓库。

QPP-4-RAG 的 TREC-RAG 只有 56 个主题，适合复现和原型，不足以可靠训练历史迁移门。正式实验仍需更大的 source/calibration/test 查询集合。

旧代码暂不删除，统一视为 legacy。新实验跑通后再决定归档或删除；只复用经过检查的通用检索、日志和评价代码。

## 八、阶段计划与止损门

### Gate 0：完成危险近邻精读并冻结主张

完整精读：QPP Variant Selection、ReFormeR、统一改写复现实验、RQ-RAG、SelectiveNet。

输出一张逐项对照表，确认现有工作是否已经同时具备：纯检索前、跨题历史经验、实例级选择、允许不用经验、无 Gold 反馈、对 DIRECT 的伤害评价。

### Gate 1：历史经验是否真的能迁移

先不做控制器、EMA、Agent 或复杂记忆。保存最简单的“历史原问题—历史成功查询—来源与环境”。

在有 Gold 的 support/test 划分中，为相同目标题离线比较 `DIRECT`、`FRESH` 和若干 `REUSE`。使用事后知道每条路径结果的 oracle 只测量理论空间，不作为可部署模型。

停止条件：最好的历史经验也只能帮助近重复题，或相对 `DIRECT/FRESH` 几乎没有稳定增益。

### Gate 2：执行以前能否选出来

只做简单的相似度、结构兼容性、环境版本过滤和拒绝阈值；暂不训练。

停止条件：真实规则明显选不出 oracle 能找到的经验，或为了减少少量失败而拒绝了几乎所有经验。

### Gate 3：最小完整方法

Gate 1、2 成立后，才实现可校准的轻量选择器，并加入不同检索器、不同问题族和分布变化。主结果同时报告答案质量、检索质量、复用覆盖率、有害复用率、token 和延迟。

### Gate 4：无 Gold 与在线生命周期

验证代理信号与真实收益的相关性，再加入弱反馈、少量人工抽查、经验降级/隔离和可选 EMA。RL/bandit 仍不是默认选择。

### Gate 5：路线 B 或 Agent 扩展

如果路线 A 因适用性不可预测而失败，转向首次检索后的证据缺口修复；如果 A 成立，再研究 A/B 混合、在线 Agent 控制或 CoT 检索笔记。

## 九、推荐阅读顺序

用户已读的 8-13 九组论文不重复列入新 RDF。接下来按下列顺序阅读：

### 定方向前必须完整精读

1. **Can QPP Choose the Right Query Variant?**：学习如何在不跑完所有检索与生成路径时，提前选择 query variant；重点看其 oracle 和“检索最优不等于答案最优”。
2. **ReFormeR**（已在 8-14 包中）：学习历史成功 query pair 如何被抽成显式模式；重点查明与我们的直接重合。
3. **A Reproducibility Study of LLM-Based Query Reformulation**：学习公平实验协议及 retriever 依赖性。
4. **Not All Queries Need Rewriting**：学习纯检索前改写何时会伤害检索，以及简单 gate 为什么可能无效。它是 workshop 论文，认可度低于主会，但对止损最直接。
5. **RQ-RAG**：学习 rewrite/decompose/disambiguate 的动作空间及训练型强方法。
6. **SelectiveNet**（已在 8-14 包中）：只重点学习拒绝、coverage 和 selective risk。

### 方案确定后定向阅读

7. **Query Performance Prediction: From Ad-hoc to Conversational Search**：补 QPP 基础。
8. **Q-PRM**：仅在考虑训练型逐步改写时精读。
9. **Masking or Mitigating?**：开始做稠密检索器泛化时精读。
10. **Controlling Counterfactual Harm...**：主打可信/安全复用时，借鉴如何定义“原本正确，却被辅助系统改坏”。
11. **Beyond Retrieval/QCR**：作为最新预印本跟踪其“适用条件＋验证要求”的经验笔记表示，不能当成熟结论。
12. **CoEvo-Mem**：作为最新预印本查重，重点确认路由器、query rewrite 和 memory bank 如何共同在线更新。
13. **QueryGym**：论文快速阅读，重点看工具和公开接口。

### 暂时不读

- Bandit、LinUCB、Doubly Robust：只有进入在线控制时读。
- 大量 CoT/轨迹记忆论文：只有“压缩检索笔记”升为主贡献时读。
- 检索后修复与 rollback 论文：路线 B 启动时再读。
- 数据集原论文：实验协议确定后读对应章节。

## 十、还需要共同确认的决定

建议下一轮只确认下面四项，不继续扩范围：

1. **第一版经验表示**：推荐保存具体 `原问题 → 成功查询` 和最小适用元数据；抽象模式只作 ReFormeR 基线或后续消融。
2. **第一版动作空间**：推荐主系统只做 `DIRECT/REUSE`，`FRESH` 作为强基线；三者同时路由留到第二阶段。
3. **第一版反馈设定**：推荐先用有 Gold 的 support 集构建和验证经验，再做无 Gold 代理版。
4. **第一版任务与数据**：推荐先做开放域多跳 QA，因为可获得 supporting facts，随后再用 BEIR/TREC-RAG 检查结论是否只在 QA 场景成立。

只有在这四项和 Gate 0 的新颖性边界确认后，才正式开始实现。
