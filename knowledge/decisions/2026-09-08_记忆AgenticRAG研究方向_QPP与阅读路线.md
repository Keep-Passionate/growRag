# GrowRAG：哪些问题值得研究，而不是继续堆模块

日期：2026-09-08。状态：供用户选择的研究方向，不是已确认的新算法或论文结论。

本轮使用 academic-research-suite 的定向文献比较与 citation-management 核验元数据。承接已有研究框架，不重新启动从零选题问卷。本轮只查文献、读代码、制作阅读包和更新记忆；没有改变 RAG 运行代码，没有读取密钥、收费调用、训练或新成绩。

## 1. 先给结论

建议保留四个方向，但不要把四个方向都塞进一篇首轮论文：

1. **优先：历史经验能否帮助我们少跑几次完整 RAG，仍选对改写？**
2. **紧密配套：经验怎样记，才能判断“这题适用，那题不适用”？**
3. **独立备选：哪些经验值得长期留下，什么时候不再继续压缩或改写？**
4. **后续系统环节：证据不足时，怎样选择下一步修复并及时停止？**

前两项延续用户已经认可的“选择＋表示”方向；第三项保留上一轮关于长期持有和浅层派生的构思。第四项先作为已有方法基础上的支撑模块。不是沿用早期架构 A/B/C 的编号。

我更推荐将第一项作为主问题，第二项只实现回答主问题所必需的最小表示。是否选择这条路线，仍由用户决定。本轮新检索不能保证不存在重复工作，也没有证明我们的办法更优。

## 2. 三类问题：并非三种互斥题型

下面的例子是概念说明，不是新实验结果。

| 现象 | 通俗解释 | 合理处理 | 不应采取的捷径 |
|---|---|---|---|
| 词汇不匹配 | 用户和文档说的是同一件事，却用了不同词 | 同义表达、领域术语对齐；有时删去冗余，比不断扩写更好 | 看见难题就增加一堆词 |
| 意图漂移 | 查询变得好搜，却已经偏离原任务 | 保留实体角色、关系方向、时间、否定与比较要求；核对动作目标 | 只因为 QPP 高就接受 |
| 查询描述不充分 | 搜索表达缺少必要线索；或者用户本来就没说清要什么 | 前者从当前证据补线索；后者澄清或明确保留多种解释 | 从历史经验猜一个条件，并当成当前事实 |

例如“谁更早出生”与“谁更晚出生”使用同样的人名，却不是同一个任务；但二者都可能复用“分别检索出生日期”的操作。**适用性不能只看表面相似，也不能机械地见到比较方向变化就整卡拒绝。** 是否可复用取决于卡片究竟是“找两个日期”，还是连“取较小日期作答案”的决策也一起保存。

另一个例子：“这部电影的导演在哪里出生？”若当前证据已经查明导演，下一条查询可以只问该导演的出生地。它不需要逐字重复原问题，但必须服务原问题中的子目标。原问题 q0 始终保留，不能让局部搜索问题悄悄替代最终任务。

因此建议沿用：**统一经验外壳、不同动作正文**；诊断可同时有多个标记，动作可以是保留、语义改写、扩写、压缩、拆分。不要先强行分为三个类别，再给每类固定一个改写器。

对应文献不是空白：Query Rewriting/Query2doc/HyDE 提供变换基础；Q2EI 强调领域实体导向的压缩；RAQG-QPP §7.3 同时讨论偏题和“意思未变但词形不适合语料”的情况。[Query Rewriting](https://aclanthology.org/2023.emnlp-main.322/)；[Q2EI](https://aclanthology.org/2026.findings-acl.1791/)；[RAQG-QPP](https://arxiv.org/html/2604.27244v1#S7.SS3)

还应区分**用户主动变更意图**与**系统误改固定意图**。RECAP 研究前者所在的多轮对话理解；我们当前研究固定原问题 q0 的查询控制，不照搬它的任务定义。[RECAP](https://aclanthology.org/2026.findings-eacl.105/)

## 3. QPP：可以借鉴，但要准确说它预测什么

QPP 是 Query Performance Prediction，查询性能预测：在不知道当前问题真实相关性标签的情况下，估计一个检索表达可能搜得怎样。它可以训练，也可以使用无需训练的统计量；“推理时不需要 gold”不代表训练与评价也不需要标签。

需要区分三个问题：

- **检索质量**：搜到的文档是否相关、排名是否合适？
- **答案效用**：这些文档是否帮助回答原问题？
- **记忆增量**：这些帮助是否是历史经验额外带来的，而不是现场改写本来就能做到？

三个量不能合成一个未经验证的“置信度”。QPP 研究已经发现检索目标与最终生成目标不总一致。[QPP Query Variant Selection](https://arxiv.org/html/2604.22661v1)

### 3.1 “多写几个候选”与“多跑完整 RAG”成本不同

设生成 K 条候选，其中只执行 r 条候选的检索，最后让回答器生成一次。简化账本为：

```text
候选生成 + 经验读取/选择 + QPP计算
        + r次文档检索 + 实际发生的重排 + 1次最终回答
```

对照“每条候选都跑完整 RAG”，后者有 K 次检索和 K 次回答。这里不假定各次 token 长度相等，也不保证前者一定便宜。

| 筛选发生在何时 | 候选检索是否已经发生 | 可能减少什么 |
|---|---|---|
| Pre-QPP：候选检索前 | 未逐条排名；可以读取预计算索引统计 | 未选候选的检索、重排和回答 |
| Post-QPP：候选检索后 | 已经发生，必须记账 | 未选候选的后续重排/回答，具体看接口 |
| 完整 RAG 后按真实效果挑最好 | 已经全部运行 | 只能作离线诊断，不是免费部署策略 |

候选可能在一个批量请求中生成，但输出 token、延迟、重复候选仍有开销。在线全库统计重算也不是免费。只减少回答调用不代表一定明显降低总费用：在我们当前小型 BM25 环境，成本结构与云端重排/大上下文系统不同，必须实测。

### 3.2 本轮发现的三条直接边界

1. **QPP 论文已有 QSD(Pre)**，使用历史近邻查询表现。“QPP 加一点历史”不是新贡献。
2. **RAQG-QPP 已从历史查询检索变体，再辅助生成变体**，并有跨语料评价。其目标主要是 QPP 预测质量，不是持久修复卡的生命周期或额外 QA 收益。[TOIS 正式记录](https://eprints.gla.ac.uk/385540/)
3. **ReformIR 已研究多改写的漂移与预算分配**：原问题锚定排序反馈，轻量替代模型指导昂贵重排。其预算主要在重排端，不能把它说成所有候选都不检索的纯 PRE 方法。[SIGIR 正式书目](https://research.tudelft.nl/en/publications/when-more-reformulations-hurt-avoiding-drift-using-ranker-feedbac/)

另有 RAG-QPP 根据检索后特征预测质量、调节深度，且适配黑盒生成器；已确认 TOIS 44(6) 正式期刊登记。此次核验到摘要与作者代码，未完成全文精读。[出版社 DOI](https://doi.org/10.1145/3827605)；[作者代码](https://github.com/APARAJITA1997/RAG_QPP_JH_2026)

## 4. 四个方向：分别研究什么、如何推翻自己

### 方向一：经验辅助的低成本查询选择——建议优先

**直观问题：** 原查询、一条现场改写、几条历史指导的改写都摆在面前，能否在少量执行预算下，挑出真正值得跑的一条？

建议候选主张，而非已证实创新：

> 在固定底座和预算下，历史动作的适用条件与独立迁移反馈，能否提供普通 QPP 尚未利用好的信息，帮助选择相对 FRESH 更有价值的查询，同时减少改坏题目？

历史不是只提供一句“建议加出生日期”，而是提供：什么动作、哪些观察条件下用过、相对无历史修复有哪些收益/无增益/退步。部署时这些都是此前独立问题的记录，不读取新题 gold。

**先做什么：** 在独立训练问题上采集小型候选池的真实配对结果；冻结候选生成器、Reader、索引和预算。首版可用少量统计或规则选择，不立即训练大模型。

**必须对比：** 原查询、FRESH＋纯 QPP、历史查询示例/历史表现 QPP、ReFormeR/RRM 风格复用、相同库＋相似度选择、相同库＋拟议选择器。ReformIR 作为检索后强参照单独交代成本界面；移植版本只能标为适配复现，不能冒称作者原成绩。

**证明标准：** 在相近答案效果下少花总成本，或在相近成本下多救回问题且没有过高退步；报告整条质量—成本曲线，不挑有利单点。必须显示实际复用覆盖，排除“从不用历史”的退化。

**失败条件：** 同候选池下普通 QPP 已经足够；历史没有额外价值；或者读取和判断历史的开销吃掉全部节省。出现这些情况，应缩小任务/改表示，不继续堆路由模块。

**必读：** QPP Query Variant Selection、ReformIR、RAQG-QPP、ReFormeR、RRM。

**选读：** EPR、Adaptive-RAG、WeWrite、Q2EI；Query Rewriting 是基础，Query2doc/HyDE 按动作补读。

### 方向二：保留适用边界的紧凑经验——与方向一配套

**直观问题：** 一条笔记不仅让系统“照着做”，还让系统知道“哪些情况下不能照着做”。

最小对照不是“我们加结构，所以比自然语言好”，而是固定相同来源、候选卡和读取预算，比较：

1. 具体 q→q′ 改写对；
2. 一段通用摘要；
3. 动作＋必要前提＋必须重新获取的当前对象；
4. 第 3 项再加入独立迁移中观察到的边界反馈。

运行卡不必塞全部记录。完整来源、成功和失败审计可以外置；执行时只送与当前选择有关的程序信息。无反馈的卡写“未知”，不能由模型臆造已验证条件。

**候选创新位置：** 不是发明一种卡片字段，而是从受控的成功/反例中，找出对“用还是不用”真正有区分力的最少条件；证明它比通用摘要或模型自述前提更能识别适用范围。

**直观检查：** 词换了但任务/动作不变，能否仍然复用？人名没变但要求变了，能否正确改变动作或拒绝？这些是诊断，不保证每个反向比较都应拒绝。干预后的问题若变了任务，不能继续沿用原 gold。

**已有覆盖：** RRM 已有适用条件；QCR 已有当前对象重绑定和核查要求；ReMe 已有场景适配。我们的目标是独立验证这些条件如何形成、保留和影响迁移，而不是宣布前人都没有适用性。[RRM 方法](https://arxiv.org/html/2607.28156v1)；[QCR 方法](https://arxiv.org/html/2608.12847v1)

**失败条件：** 保留更多字段只有提示长度优势；换个选择器收益消失；或只在人为构造的诊断题上有效，真实未见问题没有增益。

**必读：** RRM、QCR、ReFormeR、Useful Memories v2。

**选读：** ReMe、EPR、AWM、When Continual Learning Moves to Memory。

### 方向三：长期持有与稳定更新——独立备选

**直观问题：** 本题成功的经验，什么时候值得占据未来经验库的位置？新的总结什么时候值得替换旧版本？

保留上一轮设计：临时工作上下文退出后续执行；审计可保留；候选卡与正式执行卡不同。操作正文冻结、反馈追加；改写正文或扩大适用范围都要重验。浅层派生上限是工程假设，不能拿“两三层”本身当发现。

建议分开两类实验：

- **表示实验：** 同一来源集，逐条经验 vs 一次性抽象。
- **更新实验：** 同一来源流，追加原卡 vs 持续改写摘要 vs 从原始来源重新提炼并验收。

对持有价值再问：同样容量下，这张卡是否提供其他卡或 FRESH 不能替代的帮助？不能只保留最热门 top-k，否则稀有却关键的卡可能被淘汰。删一张没有损失，不代表几张互相替代的卡可以一起全删。

**已有覆盖与张力：** Useful Memories 研究持续更新导致损坏；When Continual… 比较表示与跨任务复用。前者不证明摘要永远不好，后者不证明反复改写永远安全；任务与干预不同。ERM 将验证信号写入文档 key，GAM 按收益与不确定性更新，也不是静态相似度方法。[Useful Memories §6.4](https://arxiv.org/html/2605.12978v2#S6.SS4)；[When Continual…](https://arxiv.org/html/2604.27003v1)

**证明标准：** 固定探针上的旧能力、独立新题迁移、库容量/检索延迟/维护成本，随任务流共同报告。禁止探针写回；看探针分数调方法后，它就属于开发集而非盲测。

**失败条件：** 只不过减少了写入次数或总 token；同预算对照没有长期优势；收益只来自重复测试越来越熟悉的问题。

**必读：** ERM、Useful Memories v2、When Continual Learning Moves to Memory。

**选读：** GAM-RAG、ReMe、MemCon、AWM、可选经验调用的 ExpWeaver（2605.07164）。

### 方向四：证据驱动的有限修复循环——先作支撑模块

**直观问题：** 已经搜过一次了，证据缺什么？下一步是换说法、找桥接实体、拆问题，还是停止？

S2G 已有结构化 gap；ReflectiveRAG 已有当前证据驱动的修复；SMR 已有 REFINE/RERANK/STOP；QPP 与 Agentic RAG 搜索轨迹的关系也已有分析。不能把一个有限状态机包装成新范式。[S2G](https://aclanthology.org/2026.acl-long.1185/)；[SMR](https://aclanthology.org/2025.findings-emnlp.371/)；[IR-RAG workshop 正式目录](https://ceur-ws.org/Vol-4199/)

**仍可问：** 相同初始证据和剩余预算下，历史是否帮助选对下一种动作，而不是只多搜一次？若要把这一项做主贡献，需要逐轮动作价值的强对照，代价显著高于首版 PRE 选择。

累计证据保存真实文档/句子引用与获取轮次；摘要是辅助视图，不能变成新来源。停止原因至少区分：证据足够、边际新增信息小、查询/证据重复、预算到限。后三者不代表可以无条件自信回答；是否部分回答/拒答另按证据决定。

**必读：** ReAct（基础）、Sufficient Context、S2G-RAG。

**选读：** Self-RAG、Verma ReflectiveRAG、SMR、Am I on the Right Track?、RRM。

## 5. 怎样避免把候选生成和候选选择的贡献混在一起

本轮重点推荐以下配对，而不是只报 GrowRAG 高于 BASE：

```text
FRESH − BASE：现场修复有多少作用
REUSE − FRESH：历史经验额外增加了多少作用
REUSE − BASE：整套方法有多少作用
```

差值需要相同起点、实际执行、分支隔离和独立评价；单次差值会有噪声，不是每张卡的数学因果证明。无适用卡时，REUSE 是未执行，不能抄 BASE/FRESH 的分数冒充一次复用。

但**整套路由策略必须在全部留出题上评价**：无卡时实际执行预先规定的 BASE/FRESH 回退，这次结果与成本计入策略总分，只是不计入复用次数。复用子集的效果用于分析，不能替代全体题目的策略评价；也不能只在成功触发的题上宣称收益。

再做一个 2×2 对照：

| 候选如何生成 | 选择器只看查询/QPP | 选择器再看历史迁移反馈 |
|---|---|---|
| 不读程序性经验生成候选 | 基本参照 | 历史能否只帮助选择？ |
| 历史指导生成候选 | 历史能否只帮助生成？ | 完整方法 |

每行比较时固定完全相同的候选池。若比较两行，固定候选数量、调用预算、解码设置与选择策略；最后还要报告真实总成本，因为等条数并不等 token。

若候选池包含历史生成的候选，而选择器看不到历史，它只能叫“无历史选择器”，不能叫“整套无记忆 FRESH”。QSD/RAQG 已利用历史查询信息，也要单独标记，不混入纯无历史组。

QPP 对原始查询文本可做一级廉价筛选；若允许对少数候选试检索，那是另一个有检索成本的分级策略。不能在评价时偷偷让“纯检索前”选择器看到候选检索结果。

### 应共同报告的量

- 修复了多少 FRESH/BASE 原本错误的题；
- 损害了多少 FRESH/BASE 原本正确的题；
- 实际使用经验的覆盖率，以及错误/未知/未执行各多少；
- 答案 EM/F1 与证据指标分开；支持引用可追溯不等于语义蕴含；
- 候选生成、读记忆、预测、检索、重排、Reader 的实际成本；离线建库和线上成本分账。

比较同样调用率下的伤害、同样成本下的收益，有助于避免靠大量拒绝复用得到好看的“安全率”。不能预先挑只会受益的题作最终测试。

| `querygym/qpp/run_qpp_querygym.py` | NQC/WIG/Clarity 与排名输入 | 只能在有真实排名时计算；属于 Post-QPP |

| `scripts/convert_to_ragnarok_format.py` | 查询、文档、分数转换接口 | Reader 问题取决于传入文件，不能假定永远使用改写后的问题 |
| `querygym/run_RAG_on_prepared_files.py` | 检索与回答分离 | 当前默认 top-k=3，而论文主设置为 top-5，需显式统一 |

上游一个候选生成脚本的默认模型、候选数和温度，也不等于论文全部实验设置。代码可用不等于一键复现。借用应保留许可证、固定提交、记录函数改动，并单独做数值一致性测试。[固定提交代码](https://github.com/Narabzad/QPP-4-RAG/tree/306d3da6477b046754512889ebd215610760aa78)

我们的现有 `src/growrag/preflight_qpp.py` 只是预测原查询在本地 BM25 top-4 下的支持句召回的小型诊断，不是改写收益模型，也不是已接通的经验选择器。下一步若确认方向一，只需要薄接口：索引统计缓存 → 候选特征 → 可绕过选择器 → 分项成本记录；不重写完整框架。

## 9. 共同点、共同挑战与我们真正可争取的贡献

所读工作总体都在处理：**从当前任务/历史中取信息 → 改变下一步行为 → 用反馈评价 → 决定继续、停止或更新。** 它们的“记忆”并不是同一种对象：用户兴趣、历史查询、文档 key、证据向量、程序性卡片与行为轨迹不能混为一谈。

跨文献可归纳的挑战是：**相似、源题成功、当前适用、证据有增量、答案正确、跨题长期有用，彼此有关，但不能互相替代。** 不准确的说法是“所有前人都忽略这些问题”；准确说法是“各篇覆盖不同界面，指标与成本往往不能直接横比”。

可争取的候选贡献，按收敛程度排序：

1. **面向实际执行选择的条件化经验价值估计**：历史反馈能否在相同候选池中补足 QPP，以更少完整执行保持有用修复？
2. **从迁移支持/反例形成最少适用边界**：不是多存字段，而是说明哪些条件对迁移选择必不可少，并有真实未见题验证。
3. **保持迁移质量的浅层持有/替换规则**：控制相同来源、容量和成本后，何时保留、重建或替换更稳？

每项都需与已列近邻对比。当前更像在成熟范式内提出可检验方法改进，而不是已经创造新范式；这不妨碍做出有价值的研究。
