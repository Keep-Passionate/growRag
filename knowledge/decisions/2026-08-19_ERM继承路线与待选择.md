# ERM 继承路线与待选择事项

更新日期：2026-08-19  
状态：讨论稿；用于下一轮共同拍板，不等同于最终论文方案

## 先给结论

用户所说的“EMR”按 **ERM（Evolving Retrieval Memory）** 理解。ERM 很适合作为我们的**思想基线**，尤其值得继承它的三点：

1. 只有通过正确性检查的查询扩展才有资格持久化；
2. 尽量把收益归因到较小的查询扩展单元，而不是把整段生成内容都写入；
3. 记忆随任务流逐步积累，而不是每道题都从头学习。

但不建议直接把 ERM 当成最终架构照搬。ERM 主要把成功扩展融合进文档 key，写入后会全局影响后续查询。它缺少我们最关心的**读取时门控**：对于一个新问题，系统不能单独选择“使用这条历史经验”或“保持原查询”。

因此当前最推荐的组合是：

> **ERM 式写入控制 + 检索前读取控制 + 成对伤害评估。**

也就是：先严格判断“什么值得记住”，再单独判断“这次是否值得使用”；不确定时保持 `DIRECT`。

## 三条可选路线

### 路线 A：Safe-ERM 查询侧边层（推荐先做）

**研究对象**

索引外保存的、历史上验证过的查询变换记录。每个新问题在第一次正式检索前，在 `DIRECT` 与 `REUSE` 之间选择。

**相对 ERM 的改动**

- 把 ERM 的“扩展查询正确即可写入”，改为“相对原查询有成对净增益才进入候选区”；
- 来源题上成功一次只表示 `candidate`，不表示可以普遍复用；
- 用独立问题上的复用记录建立历史可靠度；
- 当前题的适用性单独估计；
- 只有“经验可靠”与“当前适用”同时过门，才执行 `REUSE`；
- 把 `DIRECT 正确 → REUSE 错误` 作为一等风险，而不是藏在平均分里。

**优点**

- 与用户偏好的“轻量级、纯检索前补充层”一致；
- 不改基础索引，容易回退和做公平消融；
- 第一版不需要训练大模型；
- 可以先做很小的完整反事实实验，快速判断课题是否成立。

**缺点**

- RRM 已经概念性地区分可靠度和适用性，单靠这两个名词没有足够创新；
- ReFormeR 已经从历史成功改写中抽取查询变换模式；
- QPP 工作已经研究检索前 query variant 选择；
- 因而论文创新必须落在**成对伤害、风险—覆盖率、可校准拒绝、严格跨题验证**，而不能只说“记住成功改写”。

**预计难度**：3/5；若追求形式化风险保证则 4.5/5。  
**建议定位**：首篇论文主线。

### 路线 B：可回滚、条件化的 ERM 索引

**研究对象**

保留不可变的 base index，同时把 ERM 写入保存成可开关、带版本的 overlay/delta。每个新问题先决定是否启用某一组增量 key。

**优点**

- 更直接改进 ERM 的全局污染与早期错误强化问题；
- 比纯 sidecar 更接近一个完整的持续学习检索器；
- 写入可审计、可撤销，适合研究语料更新和分布漂移。

**缺点**

- 索引工程复杂，稀疏、稠密、late-interaction 检索器的实现不同；
- 可能失去 ERM 所强调的“后续零额外推理开销”；
- 读取门、版本管理、回滚和重排耦合在一起，不适合用来做第一周的可行性验证。

**预计难度**：4/5。  
**建议定位**：路线 A 证明有迁移空间后的第二阶段，或第二篇论文。

### 路线 C：可靠的检索后修复闭环

**研究对象**

先按原查询检索；证据不足时再从历史经验中选择修复，失败则现场生成新修复，并把经验证的结果写回。

**优点**

- 能看到首轮文档、分数、覆盖和冲突等信息，通常更容易判断“为什么需要修复”；
- 更符合真正的 repair 闭环；
- 能处理第一次从未出现过、无法仅凭 query 判断的问题。

**缺点**

- 与 ReflectiveRAG、S2G-RAG、ReFormeR 以及 RRM 的触发位置更接近；
- 至少多一次检索或充分性判断，成本更高；
- 想声称“新架构或新范式”反而要面对更多强基线，创新并不天然更容易。

**预计难度**：4/5。  
**建议定位**：若路线 A 的 oracle 迁移空间很小，转向路线 C；否则作为 A 的失败回退。

## 当前推荐的论文问题

暂定主问题：

> 在文本 RAG 中，能否在第一次正式检索前安全复用历史上验证过的查询变换；在保持有用复用覆盖率的同时，显式抑制“原查询本来正确、复用后反而错误”的伤害？

这个问题同时包含：

- **写入问题**：什么变换值得进入经验库？
- **历史可信度问题**：它在过去独立目标题上是否稳定有效？
- **当前适用性问题**：它是否适合当前问题和当前检索环境？
- **拒绝问题**：证据不足时是否保持原查询？

它不包含“首次提出查询改写记忆”“首次检索前选择”“首次用 EMA”之类已经站不住的主张。

图片把“论文基线”和“代码底座”分开，这个判断是正确的。

### 图片中的论文基线

- **ReFormeR**：最接近“从历史成功改写中得到可迁移模式”的方法基线；
- **QPP Query Variant Selection**：最接近“检索前从多个 query variant 里选一个”的选择基线；
- **DIRECT / 随机历史 / 最近邻历史 / always-reuse / 每题 FRESH**：不可缺少的基本对照；
- **RQ-RAG**：训练型查询细化强参照；
- **ReflectiveRAG / S2G-RAG**：只有进入检索后修复路线时才是直接基线。

### 图片中的代码建议

- **QPP-4-RAG** 适合作为复现实验参考，因为它已经覆盖 query variants、QPP、检索与答案评价；
- **QueryGym** 适合作为改写方法和提示词实验工具；
- **ReFormeR** 适合作为完整方法基线；
- GrowRAG 自己只实现历史经验库、候选召回、信任/适用性估计和 `DIRECT/REUSE` 决策。

需要修正两点：

1. TREC-RAG 只有 56 个主题，适合复现和冒烟测试，不足以训练或验证可靠的跨题信任门；
2. 我们不应在尚未跑通 oracle 可行性之前，把三个上游仓库拼成重型系统。先统一数据接口与预计算结果，再决定复用多少代码。

## 下一轮需要用户拍板的四件事

### 选择 1：首篇论文主对象

- **A1：查询侧 Safe-ERM + Do-No-Harm（推荐）**  
  工程较轻，能尽快验证；新意依赖严格风险定义和实证。
- **A2：可回滚条件化 ERM 索引**  
  更像完整架构，但周期和工程风险显著增加。

### 选择 2：第一版经验表示

- **具体 `q → q'` + 原子扩展单元（推荐）**：最可审计，最适合找出伤害来源；
- ReFormeR 风格 typed pattern：迁移覆盖可能更高，但抽象错误更难归因；
- 压缩 CoT/检索轨迹笔记：信息丰富，但相关工作拥挤、成本高，暂作消融或后续支线。

### 选择 3：在线动作空间

- **`DIRECT / REUSE`（推荐第一版）**：最清楚地测安全复用；
- `DIRECT / REUSE / FRESH`：更接近完整 Agent，但会把“经验是否适用”和“是否应现场修复”混在一起。

离线 oracle 阶段仍会把 `FRESH` 作为强对照运行，即使它不进入第一版在线控制器。

### 选择 4：风险承诺强度

- **先做经验风险—覆盖率与校准（推荐）**：可落地，先回答现象是否存在；
- 直接做 conformal 风险上界：理论更强，但要求交换性、校准集稳定等假设；在流式漂移下很难一开始就站住。

## 当前默认选择

若用户暂时不改变，工程将按以下默认推进：

1. 路线 A；
2. 具体 `q → q'` 与原子扩展单元；
3. 在线 `DIRECT / REUSE`，离线加入 `FRESH`；
4. 先经验风险控制，不提前承诺形式化保证；
5. 第一项正式实验是 full-information oracle 可行性，不是训练路由器。
