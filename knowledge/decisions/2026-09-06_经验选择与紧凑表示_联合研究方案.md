## 1. 本轮用户确认与尚未确认

用户明确认为“什么时候值得复用历史”和“一条经验到底存什么”两个研究方向都值得做，要求继续细化研究及编码方向，同时自己阅读论文。

确认的是两个研究问题的价值，不是某个具体算法已经获认可，也不是已有实验结果。本轮交付研究方案、实现路线与补充阅读；不修改运行代码、不安装依赖、不调用付费模型、不提交或推送 Git。此前 9 月 8 日 22:50 的单次文献跟进仍保留，不重复创建。

建议将两个问题放进同一条主线：

> 在原检索已有明确缺口时，保留哪些历史修复信息，才能帮助系统判断何时值得借用经验，而不是直接现场改写？

通俗名称可先叫“查询修复经验的精简与选择”。不使用 amortize 等术语，也暂不称新范式。

这是方法型增量研究候选：以现有查询改写和记忆方法为强对照，研究具体的表示与决策。不是从零发明 RAG，也不需要先把完整 Agent 系统搭大。

## 2. 为什么两个方向应当一起研究，但分开做实验

“存什么”决定选择器能看到哪些适用前提；“何时用”决定这些信息在新题上是否有实际价值。二者相互影响，不能只比较最终大系统平均分。

先固定历史来源与选择规则，比较三种表示；再固定表示，比较不同选择规则；最后交叉验证。这样可以区分：更好是因为内容更有用、选择更准，还是仅仅多给了 token 或换了历史候选。

工作假设：

- H1：在相同当前证据与后续检索预算下，某些历史修复确实与无记忆 FRESH 互补，且去掉近重复题后仍存在。
- H2：紧凑地保留修复前提与具体修改，比单纯自由摘要更少丢失迁移边界；但不预设一定超过具体 query-pair。
- H3：当前已知/未知状态与来源修复前提，能在语义相似度之外增加选择能力。
- H4：较好的表示能让便宜选择器更容易判断何时复用，而不是只能依赖更强、更贵的模型。

H4 是两方向最有价值的联系，但仍是待测假设。若三种表示差别不大，就让经验表示回到工程选择，不硬凑第二个贡献；若相似度选择已经足够好，就不能声称复杂状态选择必要。

## 3. 保留已讨论的总体位置

首版仍采用 BASE-first，不重新打开已经讨论过的全部架构选择：

```text
原问题 q0 → 原查询检索一次 → 固定当前证据与缺口
                             ├─ 证据足够：据当前文档回答
                             └─ 需要修复：选择 FRESH 或一条 REUSE
                                             ↓
                                     产生一条检索 query
                                             ↓
                                     再检索一次并回答 q0
```

- FRESH：只用本题信息现场生成下一条 query。
- REUSE：同样的本题信息，加选中的历史修复笔记，生成下一条 query。
- 两支使用相同 rewriter 和 reader；第一轮研究最多再检索一次。
- 经验只进入查询生成，不作为答案证据进入 reader。当前检索文档才支撑最终答案。
- 不修改底层索引、检索器或回答模型参数，但确实改变外围执行流程，因此不是“完全不改变原 RAG 执行流程”的纯前置层。
- 这里是首轮检索之后、下一轮检索之前的查询侧决策；不是还没看到任何文档就能准确知道缺口。

完整多轮、DocumentSession 在线作用和动态记忆后置。关闭经验仍可跑同一套 FRESH，关闭整个修复层才回到单次 BASE，这两个开关要分开。

## 4. 方向二：具体保存什么

### 4.1 先分清“归档保存”与“每次给模型看”

不为三个实验版本复制三套长期库。保留同一份不可变来源记录，按实验设置生成不同读取视图。视图就是从同一记录中挑出哪些字段展示，不是新的一层记忆。

| 位置 | 内容 | 为什么放这里 |
|---|---|---|
| QueryEpisode / 其修复步骤 | 原问题、当时实际 query、修复后实际 query、修复前已支持项与缺口、证据 ID、执行成本、反馈事件指针 | 保存事实经过，防止压缩后无法追查；一个 episode 可以包含多次修复步骤，但同题多步骤不算独立样本 |
| DocumentSession | 继续保留严格单文档版本的导航、别名和局部歧义设计 | 它解决“这一篇里怎么找”，首个实验暂不参与选择，以免引入另一套增益来源 |
| ExperienceCard / 读取视图 | 从来源步骤挑出的修改做法、必要前提、边界与简短例子 | 服务跨题查询修复；是否需要抽象、抽象多少由实验决定 |
| 独立验证账本 | 来源是否正确、相对 BASE/FRESH 的配对效果、数据角色、模型/索引版本、反馈时间 | 统计可以追加重算，不能被写成永远正确的自然语言信条，更不能把目标测试题结果提前喂入选择器 |

环境配置集中在 RunContext，一条记录只保存其 ID。完整文档正文留在文档库，经验中保存证据指针。答案标注与评价信息留在隔离反馈侧，不能进入在线记忆视图。

### 4.2 首轮比较三种表示

| 表示 | 模型看见什么 | 优点 | 风险 |
|---|---|---|---|
| 具体查询对 | 历史检索 query → 当时成功修复 query | 最少人为抽象，容易复核具体变化 | 不说明为何可用；可能照搬旧实体，或包含源题答案线索 |
| 抽象卡 | 简短修改规则与必要适用说明，不给具体 query-pair | 易迁移、通常更紧凑 | 抽象不准确或过宽，可能丢掉决定成败的前提 |
| 实例＋最少前提（建议候选） | 角色化 query-pair、修复前已知/未知状态、适用前提、必须保留的约束 | 能示范怎么改，也能判断当前能不能这样改 | 可能比抽象卡长；条件生成有误时同样会失效 |

“角色化”指把源题人名换成“当前已定位作者”等角色，运行时只能用当前问题/证据中的对应实体填入。它是候选表示，不预先认为一定最好。

为了避免把去实体化的效果误当作条件字段的效果，还需一个小型对照：原始 query-pair vs 角色化 query-pair。然后以角色化 query-pair 为底，逐项加入状态、前提和约束。

旧决策曾默认长期在线卡不读取具体 q→q′；本轮因用户认可表示研究，将其改为“允许在明确标注的受控实验中比较具体与抽象视图”。完整来源永久保留不变；是否让具体查询对成为最终默认尚未决定。

### 4.3 建议的紧凑笔记只保留四组在线内容

1. **修复前状态**：已确定什么、还缺什么。防止在不同推理阶段机械照搬同一种操作。
2. **具体变化**：原检索表达如何变成下一条表达，尽量用一个短 query-pair 表现。没有必要再用长篇文字复述相同操作。
3. **必要前提**：这次变化要求哪些实体、关系或证据已经存在。前提最好能指向当前证据，而不是“适用于复杂问题”这种空泛描述。
4. **不能丢的约束**：原问题的时间、否定、比较对象、目标属性等；只保留对该修复确实相关的项，不每张卡塞全套规则。

经验 ID、来源、验证次数等放在旁路元数据中；选择器可读取允许的历史特征，但无需把整个账本发给改写模型。第一轮不要同时加十几种“安全分”。

关键时间边界：来源“已支持项”必须指向修复发生前已检索到的证据，不能在成功后把新文档事实回填成“当时已知”。提炼出的必要前提分为“来源当时有证据满足”与“事后提出、尚待验证”；不能把后者当作已验证事实。目标题的状态/gap 同样不能用 gold supporting facts 补全。

预期证据类型首版可由目标 gap/关系推导，避免单独重复一大段 evidence contract；确实不能推导时再作为消融字段加入。最小表示是要测的，不是手工宣告四组一定最优。

### 4.4 一个纯示意例子（作品和人物均为占位，不是事实）

来源问题：某小说作者毕业于哪所大学？首轮已经定位作者，只缺作者的毕业学校。

```text
已支持：作品 → 创作者
仍缺失：创作者 → 毕业学校
修改前：[作品] 作者 毕业大学
修改后：[已定位创作者] 毕业大学
必要前提：创作者身份可由当前证据唯一定位
保留约束：原题若有年代或身份限定，不能删除
```

新问题问某电影导演的毕业学校：若当前文档已确认导演，可以把“已定位创作者”绑定为当前导演，再查询学校；若当前连导演是谁都没有确定，就不满足前提，应先 FRESH 查导演，而不是猜一个名字填入。

这说明“两个题很像”和“目前能用同一种修复”不同。但条件判断本身已有 RRM 等工作；该例只是解释我们要测试的信号，不能作为新颖性证据。

### 4.5 不保存哪些内容

- 不把完整自由文本推理过程或长篇 CoT 作为默认在线经验；只保留可观察的缺口、修改和证据关系。
- 不复制历史答案、源文档全文或整段评价说明到在线卡。
- 原始查询本身可能含源题答案线索，因此“没放 answer 字段”不等于已防泄漏；要审计实体重合与近重复问题。
- 正确来源的经验可以在新题上失败；记录这类使用结果不等于开始从失败源题提炼建议。两件事分开，仍保留“先只用成功来源”的选择。
- 冻结实验中不合并、晋升或淘汰；EMA 留作后续近期趋势，不因频繁调用就上调真实性。

## 5. 方向一：如何判断现在值不值得用

### 5.1 目标不是“这条经验过去成功过”

要预测的是：在当前这道题、当前证据状态下，选择该经验后，比不看历史的 FRESH 是否更有帮助。

离线用同一状态实际执行两支，获得：

```text
相对收益 = REUSE 的回答分数 − FRESH 的回答分数
```

这只是离线训练/评价标签，不是线上输入。线上不知道当前题的两支答案分数，只能根据过去独立试验归纳出的关系作预测，所以不可能预先保证每次都判断正确。

两支都答对，不给记忆虚构正确率增益；可能有成本差异，另记成本。某条经验来源正确也不表示这道目标题一定有正收益。

### 5.2 首版在线过程

1. 用当前问题和缺口召回固定数量的候选经验。先将“找到候选”与“决定采用”分开；召回不直接宣称可信。
2. 检查必须能确定的边界，例如实体槽位是否有当前证据、时间约束是否明显冲突、检索器能否执行该操作。
3. 在候选中挑一条，或选择 FRESH。第一轮实际只给改写器一条经验，避免同时引入多条经验相互干扰。
4. 选择器输入包括当前 q0、已支持项、gap、当前证据片段/指针、候选视图，以及允许的历史验证特征；输出动作、经验 ID 和简短的可审计依据。

明确矛盾或无法执行可硬拒绝。普通相似度低、少观测、某个非必要前提未知，不应一律硬拒绝；作为软特征或退回 FRESH。未知不等于已经证明不可靠。

“证据充分”是另外一个问题：负责决定是否还需要修复，而不是直接决定某张历史卡是否有益。Judge 使用冻结提示词控制变量，但其结果仍会误判，须在开发数据抽查。

### 5.3 按从简单到复杂比较选择器

| 选择策略 | 看到的信息 | 作用 |
|---|---|---|
| 固定 FRESH | 本题状态，不读历史 | 无记忆强参照 |
| 随机/最近邻 | 固定候选池中的随机项或原问题相似度 | 测选择到底是否必要 |
| 历史表现优先 | 允许的历史成功/迁移信息 | 检查“历史好就优先”是否足够 |
| 当前条件匹配 | q0、gap 与前提 | RRM/ReFormeR 启发的必要强对照，不贬低成仅语义相似 |
| 冻结 prompt 联合判断 | 当前证据状态＋经验表示＋历史信息，允许 FRESH | 首版拟比较方法，不训练模型参数 |
| 后续小选择器 | 用独立开发题的配对效果学习上述特征 | 数据足够才训练；训练后应明确称为 learned selector |

另做 q-only、q+gap、q+证据+gap 对照。后两者若无增益，就不能把“状态感知”列为中心贡献。历史特征在冷启动时允许缺失，不能造一个漂亮的置信度；影子样本也不能把自己的结果计入自己的输入特征。

QPP 保留为候选检索效果特征/基线。当前首检的分数分布属于可见状态；某个新候选 query 的 post-retrieval QPP 必须先检索它，不能偷偷用于声称“只执行一条”的选择器。若选择发生在改写生成前，只能使用当时确实存在的查询/状态特征。

## 6. 哪些属于前人已有，哪些才是我们的待验证空间

| 原始工作 | 已覆盖、不能重称创新 | 本项目可测的剩余问题 |
|---|---|---|
| [ReFormeR](https://arxiv.org/html/2604.01417v1)，ECIR 2026 | 成功改写对提炼模式、当前检索上下文选择及受控改写 | 在文本 QA 的相同状态与预算下，历史相对 FRESH 的取舍；具体/抽象表示对这种取舍的影响 |
| [RRM](https://arxiv.org/html/2607.28156v1)，已核实预印本 | 当前任务修复、适用条件、证据要求、query-only 复用与生命周期 | 用独立配对效果检查条件匹配是否足够，并比较保留具体编辑的信息；不是声称前人没有条件控制 |
| [Useful Memories v2](https://arxiv.org/html/2605.12978v2)，已核实预印本 | 具体经历与整合摘要的对照、持续抽象可能失效 | 针对查询修复定位哪类前提丢失会导致误迁移，检验短表示是否同时改善选择与执行 |
| [When Continual Learning Moves to Memory](https://arxiv.org/html/2604.27003v1)，已核实预印本 | harmful reuse、原已成功/原失败分组、具体/抽象与访问粒度对照 | 在本文本检索问题中用明确方法改善已有诊断指标，而非发明同名指标 |
| [EPR](https://aclanthology.org/2022.naacl-main.191/)，NAACL 2022 | 以模型的下游表现信号训练示例检索，而非只依赖相似度 | 相对“无历史现场修复”的增量标签，以及当前检索证据状态；不是发明效用学习 |

本轮是围绕上述近邻的定向核查，不是全领域系统综述，不能保证不存在更接近的论文。较强的论文论证应是：明确展示某类适用前提丢失→错误选择/错误修复；一个紧凑表示与选择方法在受控对照中缓解它。仅有模块拼接和平均分提升，论证仍偏弱。

## 7. 第一组实验怎样同时支撑两个方向

### 实验 0：先验证记忆真的存在额外价值

从独立来源题收集正确修复，冻结经验库；在影子开发题的同一首检状态下，分别执行 FRESH 与固定候选经验。离线 oracle 是已尝试候选集合中的最好结果，不是全库理论最优或线上算法。

注意：多候选取最大值天然受试验次数和模型随机性影响。补充等次数多次 FRESH 的候选集对照，并对部分样本重复生成，检查“记忆上界”是不是多抽几次造成。该实验的费用是离线发现费用，不能伪装成部署费用。

若在固定候选、有限预算和去近重复检查下几乎无互补，先检查召回覆盖及表示；不能凭一个很小候选池就断言所有经验都无用。若多次检查仍没有质量或成本空间，不继续堆生命周期模块。

oracle 仅作诊断；训练配对按预先规定的候选抽样产生，不能把“尝试很多次后的单次赢家”直接视为稳定正例。若确需最佳经验标签，用额外独立生成复核或做正收益样本稳定性审计，并保留平局/不确定标签。额外复核费计入离线费用。

### 实验 1：先只改变表示

同一来源经验、同一目标状态、同一候选 ID、同一选择规则，比较具体查询对、抽象卡、实例＋前提。先每次读取一条，避免“表示变了”同时变成“选了更多条”。

这里要固定的是每条配对实际使用的 `source_step_id`，不只是候选池相同；先选定来源步骤再渲染三个视图。若改变表示导致重新排序、选中了不同来源，那属于后面的端到端组合实验。

分别做：

- 同一条来源记录的自然长度比较：报告实际 token，不能将其当作等 token 实验。
- 固定 token 上限的比较：用预先固定的渲染/压缩规则，不临时截掉某种表示的关键条件；记录截断和无法容纳率。
- 小规模字段消融：在同一角色化 query-pair 上逐项添加/删除状态、前提、约束，另做源实体原样/角色化对照。

不比较来自五次经历的抽象卡与来自一次经历的具体例子，然后把差异归因于抽象。跨来源合并留到后续。

### 实验 2：固定表示，只改变选择

比较最近邻、历史优先、条件匹配、联合判断和 FRESH。使用相同候选召回缓存，不给某个方法额外独占候选。另测条件门过严时丢掉了多少实际有益经验。

### 实验 3：小型交叉验证

将三种表示与“最近邻/条件匹配/联合判断”组合，观察二者是否交互。第一次可只完成“具体 vs 实例＋前提”与“最近邻 vs 联合判断”的 2×2 对照，抽象卡随后补齐。

每一步都保留同预算 FRESH。完整矩阵不是要求一上来跑完所有组合，而是避免最后只挑最好组合讲故事。

## 8. 评价、数据与训练

建议首阶段质量优先：回答 F1/EM、相对 FRESH 的得失、相对 BASE 的退化，以及全部实际成本。不要先把多个指标随意加权成单一 R 并隐藏权重。

```text
经验破坏率 = FRESH 答对而所选方案答错的数量 / FRESH 答对数量
经验修复率 = FRESH 答错而所选方案答对的数量 / FRESH 答错数量
```

同时以 BASE 重算一组。分母为零记不可估计；拒答按既定基准规则计分并报告覆盖率，不能以少回答换来“低风险”。另报告被触发修复子集，避免简单题稀释伤害。

成本包括候选召回、Judge、选择器、改写、检索、回答、重试与回滚。REUSE 不预设比 FRESH 便宜。既给定相同最大资源预算，又记录实际消耗；不强行让早停止的 BASE 浪费调用以伪造相等。

两种公平口径单列：①相同改写/检索机会，用于隔离历史内容的作用；②相同总成本上限，用于判断实际效率。②应允许 FRESH 利用省下的选择/记忆开销做额外候选生成或自检，具体使用方式预先固定。只完成①不能宣称同计算预算优势。

数据继续采用既有协议，不因本轮讨论重切已经约定的角色：

- HotpotQA 为第一站；优先从官方 train 中开发桥接实体/关系修复。是否 fullwiki 取决于实际索引，不把 distractor 候选段落称为全库检索。
- 官方 train 内既有工程初值：1,600 来源建库、1,400 影子迁移/未来选择器训练、1,000 校准；40/35/25 不是文献标准比例。
- 先在上述各自固定子集中做少量排错/成本测量，不触碰计划作为留出的官方 dev 500 题来调 prompt。样本量是否足以支持结论要根据开发方差和成本另估；不能以排错几十题给论文结论。
- 2WikiMultiHopQA、MuSiQue-Ans 后续检验跨题/跨分布迁移。共享文档与严格跨文档分别标注；官方 split 不自动证明文档不重合。
- 测试期冻结经验、阈值、prompt、索引与模型版本。建库题、影子题和测试题都要去近重复；同题多个修复步骤不算多个独立观察。

v1 可不训练神经网络，但仍需要来源与独立验证数据。后续小模型用开发题上实际执行 FRESH/REUSE 获得的标签训练；gold 只在训练/评价侧使用。无需从强化学习或 bandit 起步。

推断结果按 query 或预定义相关题组做配对统计，不能把候选卡行当独立问题放大样本。先报告差值、区间与成本曲线，不承诺某个固定百分比的统计安全保证。

## 9. 需要用户选择的三个内容

这些是建议，不改变“两个方向都值得研究”的确认。

| 选择项 | 推荐 | 另一个可行选择 | 取舍 |
|---|---|---|---|
| 实验先后 | 两方向联合立意，先做表示配对实验，再做选择 | 先固定一种表示，优先开发选择器 | 前者更容易解释记忆内容，后者更快接近实际调用策略，但可能受坏表示拖累 |
| 第一类问题 | 先桥接实体/关系修复 | 先实体消歧与时间/属性约束保留 | 前者贴近 HotpotQA 多跳且有证据标注；后者易手工解释，但自然发生率和标注需先核查。两类同时起步更全面也更难归因 |
| 主目标 | 质量增益为主、破坏率和成本作约束 | 质量接近时节省成本为主 | 前者适合先证明经验有用；后者要求真实测得经验便宜，不能从名字推断 |

我推荐“联合立意、先表示 → 桥接修复 → 质量优先”。无论选择哪个顺序，都先建立同状态配对执行器。三个视图作为实验对照保留，不需要现在强行决定唯一赢家。

冻结 prompt、成功来源优先、单 query episode 和三层职责都是已有偏好，本轮不要求用户重新选择。

## 10. 这轮补充阅读，不打乱原 20 篇主队列

1. [Learning To Retrieve Prompts for In-Context Learning（EPR）](https://aclanthology.org/2022.naacl-main.191/)，NAACL 2022：接在 ReFormeR/QPP 后读。学习如何把 gold 条件概率形成正负例，训练推理时不用 gold 的检索器。条件概率是代理，不等于实际答对率；它证明效用导向示例选择已有工作。重点方法与训练反馈部分。
2. [Compositional Exemplars for In-context Learning（CEIL）](https://proceedings.mlr.press/v202/ye23c.html)，ICML 2023：暂存后读，等考虑一次多条经验时再看。学习整组示例的互补与冗余；DPP 可先理解为兼顾相关和不重复的集合模型，不是本项目必需实现。

两篇都是正式会议论文，均不是纯 RAG 查询修复方法。它们用于补齐选择方法的思想与查重，不替代 RRM、ReFormeR、Useful Memories 的近邻阅读。无当前引用次数核验，不附虚构高引数字。
