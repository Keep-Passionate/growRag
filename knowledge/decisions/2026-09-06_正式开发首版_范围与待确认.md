## 1. 已确定的主线，不重复让用户选择

- 保留原 RAG 底座，外置查询层；先实现首次检索前适配，完整首尾循环留后续。
- 统一经验卡外壳、不同动作正文；跨题经验优先，DocumentSession 后置。
- Hotpot 起步；不以官方 dev/test 建库或反复调参。
- 先冻结大模型和 prompt；之后有配对标签再训练小选择器。
- 开发分支与研究标签保留可回退版本；原始运行和密钥不进 Git。

本轮目标不是重写项目，而是接通“真实来源操作 → 候选经验 → 独立问题对照 → 可选择/可绕过的经验层”。497 项已有测试说明工程合同通过，不说明方法有效。

## 2. 正式开发前发现的关键缺口

现有 `episodes/models.py` 强制第一轮 BASE，repair 又必须引用上一轮 gap；`experience/query_views.py` 要求卡的来源指向已归档 repair。这个合同适合检索后修复，不能诚实表示首次检索前、空证据开始的独立 FRESH 分支。

不能为了兼容旧结构，先独立跑一个 BASE，再伪造 FRESH 读过 BASE 证据的轨迹。也不能把旧 POST 经验的 stage 改成 PRE 就继承成功。

首项开发：允许来源引用表达**独立分支操作**，保留问题、决策时已知信息、实际改写、底座/模型版本、结果和来源指针。实现时优先小型来源引用扩展，不再复制一套卡片系统。独立 BASE 是离线对照，不能成为 PRE FRESH 的运行输入。

旧 POST 经验保留；跨阶段迁移只能另建版本、说明前提、重新验证。首批优先重新积累 PRE 来源。

## 3. 分三个可验收的增量开发

| 增量 | 主要开发内容 | 验收标准 |
|---|---|---|
| D1：真实经验可追溯 | PRE 来源记录、来源 BASE/FRESH 对照、候选卡构建与冻结 | 每张卡能追到真实操作；运行时不读 gold；不伪造证据顺序；没有好来源时如实报告冷启动 |
| D2：批量真实对照 | 新清单/运行入口、共享总预算、独立分支适配器、逐题持久化、批量报告 | 可重复执行预定题集；所有失败/无卡题保留；成本包括建库与目标；不会覆盖结果或悄悄补调用 |
| D3：最小可绕过选择层 | query-only 候选匹配、阶段/来源约束、可审计的适用性信号、返回使用/不使用决定 | 对所有目标都有结果；不强制挑卡；分别对照近邻复用、总是复用和无历史 FRESH |

D1 的来源验证与 D3 的目标适用性分开。来源一次改善只能得到 candidate，不能自动成为 trusted。源题证据增量与答案增量分开记录；门限在运行前版本化，不依据目标结果回调。

D3 先有简单词面匹配基线，不能把已有的 QPP 原查询支持召回预测器改名为“经验收益预测器”。真正预测 REUSE−FRESH 的小模型，要在独立 selector_train 题上产生标签后另训。实验运行三支是为了比较，部署选择后只运行选定路径，费用口径不同。

## 4. 建议默认值，以及原因

- **先固定语义改写**：运行前统一 form/intent，不从选中的卡取目的。扩写接口保留，之后作为独立实验加入；避免同时变动作、表示和选择策略。
- **找不到合适经验时默认 BASE**：维护轻量、可绕过的首版。FRESH 仍在研究对照中运行，用来检查历史是否有额外作用；以后才让控制器按状态选择 FRESH。
- **来源库在目标批次中冻结**：保存目标反馈但不在线回灌、不根据目标 gold 更新 reliability。动态可靠度/EMA 是另一份在线协议，不能混进冻结评测。
- **沿用已连通过的固定模型设置**：不因进入正式开发而采购新服务或切换模型；执行前核对快照可用性和当前价格。若不可用则报告，不静默换模型。
- **第一批最多 32 道来源＋16 道开发目标**：来自现有 Hotpot train 内合法角色，只用于开发排错，不保证得到 32 张卡，不把 16 题称为统计充分样本。这是建议规模，不是已生成清单。
- 现有校准题已有旧试跑/QPP 检查曝光，重新跑它们是回归测试，不是新盲测。接通后再预先抽取更大的独立内部开发批次，必要时扩展官方 train 本地数据；正式 dev 继续保留。
- 首批仍是每题候选池中的 BM25 检索，不是 fullwiki。正式开放检索主张必须之后补固定语料的真正检索实验，不能直接拿候选池结果和全库论文混比。

## 5. 研究目标与评价

待验证的问题：经验保留的操作和适用前提，能否帮助挑出对当前问题比 FRESH 更有价值的改写，同时减少错误复用？这是待证假设，不宣称“前提字段＋QPP＋记忆”即新算法。

- 首看 REUSE 相对 FRESH 的答案 EM/F1、胜/平/负与成本；BASE 提供不改写对照。
- 分开看新增支持、答案变化、正确变错误、正确变弃答、无卡率和实际经验使用率。
- 不以低错误率单独判成功：永远不使用经验也可能错误率低，必须联合报告使用覆盖与收益。
- 先人工逐题检查小批次，不用 16 题证明一般优越性；正式批次再预定样本规模、按题配对的不确定性分析与必要重复。
- 不根据是否为正结果挑题、扔掉失败或偷偷更换 prompt。若 REUSE 不优于 FRESH，先定位问题，不靠扩张系统掩盖负结果。

2Wiki 是后续域内验证；MuSiQue 保留冻结迁移；QASPER 是文档层专项。本轮不重新决定数据比例，沿用 `knowledge/datasets/2026-09-06_正式数据协议与阶段划分.md` 的官方切分与 train 内角色。

## 6. 运行边界与真正需确认的事

建议为整个首批来源建库＋目标比较设**累计估算 API 预算 5 元**，不是每个分支各 5 元，也不是预估一定花完。此数是建议授权上限，不是厂商报价；尚未确认，不执行收费调用。

预算保护还须限制总请求数、输入/输出长度和运行时间；所有独立组件共享同一总账。当前应用层估算不是厂商结算保证，价格/usage/模型不明时停止新增调用。不自动重试。恢复只重用完整、版本匹配的已落盘结果；未知的中断调用需要核对，不能自动重发。

API 内容范围仅为本次所选公开 Hotpot 问题/候选文本及生成的来源过程；不发送本地私人研究笔记或凭据。

当前没有可直接声称存在的新版批量启动命令、冻结 ID 清单或真实产物。D1/D2 编写完成后，先打印不含密钥的启动计划并通过本地替身测试，再在预算明确后真实运行。

不用用户逐项批准函数名、卡字段和测试用例。已有路线内的编码可以推进；真正需要明确的是**新真实批次的总预算**，以及用户是否反对本节所列默认的单步/语义改写/无匹配回 BASE 范围。

本轮仅核查和保存规划，没有修改业务代码、运行训练、读取密钥、发起付费实验或推送 GitHub。
