## 1. 两张图表达什么

文件目录：`figures/2026-09-06_design_review/`。

### 图 1：整体架构

用途：说明历史进入哪一步、模型看到什么、训练与评价如何隔离。

上半部分是训练期：来源问题 → 单题轨迹 QueryEpisode → 离线来源审核 → 经验卡 ExperienceCard → 冻结经验库。

下半部分是新问题：原问题 q0 → 原有检索器首检 → 当前证据 E0 和缺口 → 候选经验与待定选择器 → BASE / FRESH / REUSE → 当前证据回答原问题。

- **BASE**：不追加改写，用首检证据回答，不等于不做 RAG。
- **FRESH**：不使用跨题历史，但会根据本题信息生成新查询。
- **REUSE**：让来源经验指导新查询，再用同一检索器找当前证据。
- QueryEpisode 是本题审计记录；ExperienceCard 是跨题程序知识。DocumentSession 不参与当前最小主线，仅保留为后续文档专项。
- 历史指导“如何寻找”，不能直接替代当前答案的事实证据。训练参考答案只进入离线审核，不流入目标题选择器。
- 蓝色实线表示组件已接通；琥珀虚线表示未实现的证据感知选择和语义支持检查。整体路由尚未实现，不能因部分模块是实线就称系统已完成。
- 当前真实代码运行三个配对分支，目的是收集比较结果；未来部署才只选择一个动作。源库在评价期间冻结，目标题日志不回写它。
- 来源审核通过只说明值得进入候选库，不等于跨题永久可信。
- 图中方法位于**首次检索之后、追加查询之前**。这是现阶段已有配对实验的时点，不应再称“完全检索前、只看 query”的方案。后者仍可作为轻量变体，但没有 E0，就不能直接检查当前证据前提。

中文图注草稿：GrowRAG 的训练期经验构建与新题查询修复。来源轨迹被提炼为程序性经验，评价前冻结；经验只参与查询生成，答案来自当前检索证据。BASE 保留首检路径，FRESH 与 REUSE 分别表示无历史和有历史的修复。虚线模块是待确认机制，图不表示安全性或收益已得到证明。

### 图 2：候选具体方法——只用当前有依据的经验步骤

用途：把“适用”从一句判断变成可以逐项审查的动作约束。**这是候选设计，不是已确认原创算法。**

虚构示例：问“《Silver River》作者就读的大学是哪年建立的？”当前证据 e1 只说明作者是 Mira Chen。

| 来源程序的步骤 | 当前题能确认什么 | 下一步 |
|---|---|---|
| 作品 → 作者 | 已由 e1 得到作者 | 不重复查这一步 |
| 作者 → 就读大学 | 输入作者有 e1 支持，输出大学未知 | 可以用当前作者实例化这一搜索动作 |
| 大学 → 建校时间 | 大学还没有确认 | 暂不执行，不能拿源题大学顶替 |

未知输入可用 FRESH 查证；出现相互冲突的输入则核验或弃用。**有依据并不等于值得执行**：成立的操作也可能多余或无收益，仍需费用与增量比较。未知前提也不等于经验永远无效，故不是把所有不确定卡全部过滤掉。

离线条带从相同 q0、E0 和候选历史出发，比较同预算 FRESH 与局部 REUSE；分别测新支持、答案变化、调用和 tokens。FRESH 对照不读取该历史；“固定候选历史”是指所有记忆写法/策略共用同一候选，避免选到了不同的好卡。

未来循环只在预算允许时重新检查。停止条件包括：支持充分、没有新的有用支持、查询重复、预算耗尽。证据没补齐却达到停止条件，应弃答或说明限制，不能把“停了”标为“正确”。**当前实现仍是每个分支最多一次追加检索**；图不授权增加轮次。

中文图注草稿：当前证据约束下的局部经验复用候选。历史程序保留步骤依赖，变量必须从当前问题或证据重新确认。已完成步骤不重复执行，输入有依据的步骤可实例化，缺少必要输入的步骤等待查证。离线同状态对照用于识别经验相对现场修复的额外价值。示例为人工虚构，不是 HotpotQA 实验。

## 2. 官方划分：不是“测试集训练完再测试”

测试题不能被用于积累经验、挑 prompt、调阈值或训练小选择器。现在的“训练期”主要是**建经验库**，并不更新基础 LLM 参数。

Hotpot 官方有 train、dev 和 test；公开 fullwiki test 不含答案与 supporting_facts。官方 dev 可以本地评分，但论文须准确写 official dev。distractor 是每题候选段落设置；fullwiki 是全语料检索任务，二者不能混报。官方旧评测服务本轮只核对说明，没有验证当前可用性。[Hotpot 官方协议](https://github.com/hotpotqa/hotpot#data-download-and-preprocessing)

继续沿用已经记录的数据设计：

| 用途 | 建库、训练、校准 | 冻结后评价 | 决定理由 |
|---|---|---|---|
| 起步 / 第一域内主实验 | Hotpot train 内独立角色 | Hotpot official dev；后续有条件再提交 hidden test | 有答案和支持句，先解释证据缺口与效果 |
| 第二域内主实验 | 2Wiki 自己的 train 内独立角色 | 2Wiki official dev / 后续隐藏 test | 关系链标注可辅助离线查错，不进入运行输入 |
| 迁移实验 | **只用 Hotpot 来源库和已冻结选择器** | MuSiQue-Ans official dev | 先测跨数据集可迁移性，不用 MuSiQue 调规则 |
| 可选域内扩展 | MuSiQue 自己的 train | MuSiQue dev / 后续隐藏 test | 与上一行分开，不称零适配 |
| 文档层后续专项 | QASPER train，按论文分组；dev 调整 | QASPER test | 验证同文档多题，不用三层数量当贡献 |

各数据集的结构/完整数量和公开标签见 [正式数据协议](../datasets/2026-09-06_正式数据协议与阶段划分.md)。2Wiki、MuSiQue 也有官方划分；QASPER 是按论文组织多道问答。[2Wiki 官方](https://github.com/Alab-NII/2wikimultihop#dataset-contents)、[MuSiQue 官方](https://github.com/StonyBrookNLP/musique#data)、[QASPER 官方加载器](https://huggingface.co/datasets/allenai/qasper/blob/main/qasper.py)

**先分别建库，不把所有数据混起来训练。** 复用同一个固定 LLM 和代码，不代表各数据集共用一个不加区分的经验库。以后可以联合多个 train 建库，但需另设实验行、记录各数据集来源预算，并审计重合。

对上表以 official dev 为冻结评价集的 Hotpot、2Wiki 和域内 MuSiQue 协议，train 内约 80% / 10% / 10% 仍分别作为来源池、选择器训练池和内部校准池。这是我们的选择，不是官方比例或某论文最优定理。官方 dev 首次正式评分前冻结方法；如果之后据其结果改方案，需披露它已成为开发依据，并使用真正未见评价。**QASPER 是另一套合法协议：train 建库、official dev 校准、official test 冻结评价，不套用前述“官方 dev 不调参”的约束。** 无需把来源池全部跑完，小规模成本曲线更合理。

跨库联合还须防范 MuSiQue 的单跳来源泄漏。其官方公开了 dev/test 来源 ID 排除提醒，不能因为多跳题 ID 不同就认定未见。[MuSiQue usage caution](https://github.com/StonyBrookNLP/musique#data)

## 3. “不用经验”和“怎样 rewrite”不是同一个问题

一个问“需不需要历史、哪条历史有帮助”，另一个问“下一条检索句如何生成”。例如证据缺作者，但库里只有地名消歧经验：可以不用历史，仍用 FRESH 去查作者。

“简单题不用经验、难题用经验”也不充分：复杂题可能没有适用历史；简单题可能恰有高价值别名操作。QPP（查询效果预测）可以当辅助特征/对照，但预测 query 的效果不自动等于预测历史相对 FRESH 的增量。

可先按下列顺序阅读控制思想：

1. **Adaptive-RAG（NAACL 2024）**：从不同策略的离线结果学习低成本路由，不只是凭长度猜难度。[L1]
2. **RRM（本轮确认 arXiv 版本）**：本题修复与历史经验分开；按适用条件、证据要求和失败模式选择经验。[L2]
3. **ExpWeaver，Zhao 等（本轮确认 arXiv 版本）**：经验可在需要时通过工具请求，而非强制注入。[L3]
4. **MemCon（本轮确认 arXiv 版本）**：将 NoOp 与检索、维护等动作纳入轻量策略。[L4]

正式发表的强近邻还包括 **ReFormeR（ECIR 2026）**：成功改写抽象为模式，再按当前问题与检索上下文选择；不能把我们的这条通路叫首次。[L5]

## 4. 按记忆 Agent 工作流找切口，而非堆模块

| 工作环节 | 已有能力 / 不能直接当创新 | 仍可收缩检验的问题 |
|---|---|---|
| 产生轨迹、写入 | 成功来源提炼经验、失败诊断、来源保留，已有 RRM 等 | 哪些动作对独立目标题仍有净帮助，而不仅是来源成功 |
| 提炼与表示 | 结构化规则、前提、目标变量重获、短摘要，已有 ReFormeR/QCR | 压缩是否改变经验可用/不可用的边界，而不只是语义相似 |
| 召回与选择 | 不只相似度；条件、任务效用、选择性调用都有先例 | 在相同当前缺口和预算下，经验能否优于 FRESH |
| 实际执行 | 子程序、依赖、前提检查、失效后重规划都有 AWM/AMA-Agent | 对检索动作部分适用时，能否更细地复用并减少无根据的查询限定 |
| 反馈与记功 | 新证据反馈、删记忆重答、阶段信用已有 RRM/Hindsight/TreeMem | 历史改变了检索到的支持，还是只改变了回答器猜测/弃答行为 |
| 合并与遗忘 | 去重、衰减、NoOp、预算控制已有 MemCon 等 | 维护时能否保持适用边界；首版不为完整性加维护模块 |

**以上右栏是研究问题，不是已经空白的领域。** 更换到 RAG 数据集、换一个卡片名字或叠加几项能力，都不能自动产生核心贡献。

### 方向 1：局部适用的查询经验（候选方法主线，中高难度）

目标：同一经验只有部分前提成立时，保留有效步骤，将未知部分交给本题查证。

具体单位不是整张卡的单一置信度，而是“检索操作＋输入变量＋依赖＋当前依据”。待执行器输出某一步可执行/已完成/待查证/冲突；所有实例化值要能指向当前问题或证据。只有能减少错误绑定且不靠更多检索预算取胜，才有价值。

最强近邻：QCR 已有目标条件化笔记与重绑定；RRM 已有查询经验条件；AMA-Agent 已有前提依赖与失效重规划。**因此，画出步骤状态机本身依然不够新。** 差异必须落到检索动作上的可执行机制、适用状态干预及同预算收益上。[L2、L6、L8]

最低比较：整卡复用、整卡条件门、QCR-style 笔记、结构化 gap 的无记忆 FRESH、局部复用。固定候选、LLM、证据和预算；QCR/AWM 的跨任务适配需标为 adapted baseline，不冒称原论文官方完整复现。

可证伪条件：强条件基线已同样避免错误；或优势只来自多轮/更多 tokens；或普通 gap 拆分不看历史也完成同样动作。出现这些情况，就不把局部状态机写成主要方法创新。

### 方向 2：把真正增加支持的操作记下来（建议与方向 1 配套，中等起步 / 深入较难）

问题：来源成功不说明历史在新题有用；目标答对也不说明经验有功。

先做同状态 FRESH/REUSE 比较，再区分两层：

- 检索层：目标缺的支持有没有增加？不是只统计文档数量。
- 回答层：同样证据与同一个回答器下，答案正确性和弃答行为怎样？引用到了文档不等于内容被文档支持。

必要时再做训练侧的操作消融：去掉某个查询限定、桥接或拆分步骤后重检索，检验其贡献。每个探针都要计算成本；几次随机 LLM 结果不等于普遍因果效应。

RRM 已有新证据后记功；Hindsight 已有条目删除干预；HiMPO/TreeMem 已研究局部信用。我们的潜在差异必须是**相对同预算 FRESH 的查询操作贡献，并验证这种贡献能指导跨题选用**，不能只换一套评分和日志。[L2、L7、L10]

当前 8 题结果只提供做此诊断的动机，不提供主假设的正证据：FRESH/REUSE 各 6 题正确，且后者有前者弃答、后者错答的案例。不能通过挑出有利题来“证明”记忆有效。

### 方向 3：压缩时保留适用边界（后置候选，中高难度）

目标：一条经验缩短后，面对原本适用的题仍允许使用；面对只改变一个关键条件而不适用的题仍能拒绝。

需要少量成对边界题，如改变时间约束、关系方向或证据中的身份绑定。构造和人工审核使用 train；不得用官方 test gold 反向设计经验。人工干预数据另称诊断集，不冒充未修改的 Hotpot 官方测试。

QCR 已保留前提；DeltaMem-lite 已有 pre/anti-conditions；AMA-Agent 已说明摘要可能丢前提。因此“摘要里加条件”不是差异。只有可测的边界保持目标、压缩机制及对照结果，才可能形成独立论文问题。[L6、L8、L9]

### 当前推荐，不是定稿

方向 1 做候选方法，方向 2 做必要的价值验证，方向 3 暂不同时实现。不要同时加 QPP、EMA、训练、三层联动、自动合并和长期在线更新，把负结果原因掩盖掉。

也不要把“经验不够新”误解为必须重新发明整个范式：基于强基线做一个能清楚检验、确实有效的增量方法，可以是合理研究；前提是贡献边界和反例要诚实。

## 5. 文献证据与精读位置

本次主要追加读 L6（QCR）和 L8（AMA-Bench 方法部分），再读 L7 的记功范围。它们比再加一批泛 RAG 论文更能帮助判断我们是否重复。L1/L5 为正式发表的控制与改写基础。

- **L1 Adaptive-RAG**，NAACL 2024：[正式论文](https://aclanthology.org/2024.naacl-long.389/)。读复杂度标签构造与策略选择：监督来自离线策略实际结果。
- **L2 RRM**，arXiv:2607.28156v1：[方法全文](https://arxiv.org/html/2607.28156v1)。读 Reflective Experience Memory / Reflective Retrieval Control / Online Memory Lifecycle Management。并非只看问题相似度；已区分成功与失败程序、OQR 和跨题经验。不将其长视频结果直接搬作文本 Hotpot 对照数字。
- **L3 ExpWeaver: Rethinking Experience Utilization…**，Zhao 等，arXiv:2605.07164v1：[全文 §3.2–3.3](https://arxiv.org/html/2605.07164v1)。这是经验工具调用工作，**不是另一个同名的 Latent RAG 论文**。
- **L4 MemCon**，arXiv:2607.13591v1：[全文 §3.1–3.3](https://arxiv.org/html/2607.13591v1)。状态条件化控制、NoOp、记忆维护及折扣反馈；不能将轻量控制器视为首次。
- **L5 ReFormeR**，ECIR 2026：[正式章节](https://link.springer.com/chapter/10.1007/978-3-032-21300-6_30)，[作者全文](https://arxiv.org/html/2604.01417v1)。读模式提炼、聚合、上下文选择；它已经高度接近“成功改写→经验模式→选择→新改写”。
- **L6 Beyond Retrieval: Query-Conditioned Reuse of Long-Horizon Agent Trajectories**，arXiv:2608.12847v1：[§3.4、4.2、5.7、6、附 D](https://arxiv.org/html/2608.12847v1)。四字段涵盖工作流、重获变量、适用前提、验证；固定历史对比表示。其作者承认只评成功单条历史及受控目标变体，未隔离所有字段。这个边界不等于我们自动获得新颖性。
- **L7 Hindsight Memory-PRM**，arXiv:2608.29605v1：[§3.2–3.6](https://arxiv.org/html/2608.29605v1)。检索/引用痕迹及删除后重答得到操作性信用；其 scope statement 明确条目存在效应不等于历史写入动作的完整因果效应。
- **L8 AMA-Bench: Evaluating Long-Horizon Memory for Agentic Applications**：[v4 方法及附 H.3 Table 21](https://arxiv.org/html/2602.22769v4)，[ICML 2026 官方名单](https://icml.cc/Downloads/2026)。不仅有基准，还包含 AMA-Agent：保留前提与动作依赖，状态变化后弃用失效分支。因此“用因果图/状态机保存前提”不宜单列创新。相关 ICLR workshop 版本不可误标为 ICLR 主会。
- **L9 DeltaMem-lite / Store Less, Reuse More Safely: Guarded Delta Patches for Train-Free Lifelong LLM Agents**：[官方论坛](https://openreview.net/forum?id=oA6kKQe58G)。本轮仅核对官方 PDF 搜索缓存摘要/首屏，标 Anonymous ACL submission；直开遇验证，**没有读完全文，不能标已录用**。已见最小补丁、前提/反条件、top-1 或 NONE，足以触发查重警报，不足以穷尽其方法边界。
- **L10 TreeMem**，arXiv:2605.04811v1：[§3.1–3.3](https://arxiv.org/html/2605.04811v1)；**HiMPO**，arXiv:2606.16285v1：[§3.2–3.4](https://arxiv.org/html/2606.16285v1)。分别涉及树状阶段信用与固定状态下的新旧记忆比较；“细粒度记功”非空白。
- **L11 Agent Workflow Memory**，ICML 2025：[正式论文](https://proceedings.mlr.press/v267/wang25bx.html)、[作者正文 §3.2.1](https://arxiv.org/html/2409.07429v1)。工作流子程序复用已有正式基础；作者也讨论不适合时难以偏离旧工作流。把查询操作画成若干步骤不自动区别于技能复用。

额外正式近邻：**Voyager，TMLR 2024** 已将技能代码、当前状态和新生成程序组合，并依据反馈修改；混合 REUSE/FRESH 并非新概念。[正式记录](https://openreview.net/forum?id=ehfRiF0R3a)、[方法 §2.2–2.3](https://arxiv.org/html/2305.16291v1)。**ExpeL，AAAI 2024** 已从成功/失败轨迹提炼规则辅助后续任务；本文不声称它已实现逐操作依赖检查。[正式论文](https://ojs.aaai.org/index.php/AAAI/article/view/29936)

发表状态补记：**Can QPP Choose the Right Query Variant?** 已有 SIGIR 2026 正式记录，DOI `10.1145/3805712.3808571`，不能继续仅标预印本。[作者出版记录](https://people.eecs.berkeley.edu/~matei/publications/)、[官方论文 PDF](https://openreview.net/pdf?id=PwPwoa9SzG)。没有在本轮更改历史 RDF；后续合并包时更正。仅确认 arXiv 的论文不等于确认“未投稿”。

## 7. 图审后才做什么

用户先看三件事：①接受当前“首检后、追加检索前”的时点吗；②最小方法是否采用逐步适用，而非一个全局 confidence 分数；③是否以超出 FRESH 的支持增量为主要机制证据。

这些确认之前，只完善图和研究说明。之后先落实一个可审查步骤机制和对应对照，不立即训练小模型或扩大数据集。若与 QCR/AMA 等强基线无可检验区别，继续收缩问题，而非靠增加模块宣称新范式。
