# GrowRAG 重新评估：项目路线与贡献边界

日期：2026-09-05。性质：基于本轮原文复核的路线建议，不代表已经获得实验结果，也不把建议自动记成用户确认。用户当前请求是重新审阅与规划；本轮不推进运行代码。

## 1. 必须修正的旧判断

1. “可插拔、冻结基础模型、经验只用于查询”已有直接近邻。RRM 已覆盖 query-level guidance、当前证据回答、适用条件、现场修复和生命周期；ReFormeR 已覆盖历史改写模式的提炼及按当前检索上下文选择。不能把这些写成我们的首次贡献。[RRM](https://arxiv.org/html/2607.28156v1)，[ReFormeR](https://arxiv.org/abs/2604.01417)。
2. “原本对、用了记忆后错”的诊断也不是新发现。Hu 等的 *When Continual Learning Moves to Memory* §2.3 已按无记忆 baseline 的成功/失败子集报告 retention/new learning，并分析 harmful reuse。本轮新增它为必读近邻。[原文](https://arxiv.org/html/2604.27003v1#S2.SS3)。
3. 8 月 26 日新增的 LivingRAG 已做 Graph RAG 上的经验存储与复用，并用 grounding/novelty 控制写入。它会影响图检索激活和回答提示，并非只改 query 字符串。[原文](https://arxiv.org/abs/2608.25960)。
4. “有 supported/reliable 判定”与“限制相对基线的质量退化”是不同对象，但仅把两者区别说清楚也不构成方法创新。当前安全机制尚未在真实 QA 实验中证明有效。
5. 40%/35%/25% 是旧助手提出的工程初值，不是任何论文规定的标准比例。保留作为待试验的默认值，不给它虚构论文依据。
6. Findings、Short、Industry、Reproducibility 都是正式出版类型，不能仅凭赛道机械推断论文技术质量。arXiv 页面存在也不表示论文未被正式接收；必须查官方会议记录。

本轮文献调查使用 AI 辅助检索与原文比对，检索范围以既有四批阅读包及直接近邻为主；不宣称穷尽所有文献，也不宣称首次。

## 2. 项目问题重新表述

建议使用简单名称：**RAG 中的查询修复经验选择性复用**，英文暂用 *Selective Reuse of Query Repairs for RAG*。在得到实证前，标题不强调“保证安全”。

研究问题：当当前检索有明确缺口时，能否根据当前证据状态和过去迁移结果，判断一条历史查询修复是否值得使用；在保持回答质量的同时，相比无记忆的现场改写减少错误迁移或总成本？

三个需要测出来的问题：

- RQ1：在新的问题上，是否存在 FRESH 没做好而某条历史经验做好的情况？这种互补能否在去近重复后保留？
- RQ2：仅靠语义相似度、成功次数或 QPP，能否区分有益经验和有害经验？状态/条件信息是否增加可预测性？
- RQ3：在相近修复收益、经验调用率或总成本下，选择性复用能否减少相对无经验基线的退化？

“新的系统范式”暂不作为定位。首篇更适合是清楚的问题定义、选择方法和受控实证。论文层面的增量必须由实验支持，不能由模块命名支持。

### 2.1 最值得先试的具体方法候选

不是再加一个含糊的“可信分”，而是把选择目标改成**相对无记忆 FRESH 的额外价值**，同时观察对 BASE 的破坏。此处是方法假设，不宣称其他领域没有类似选择学习。

1. 来源题 A：BASE 没做好，现场 FRESH 修好；保存具体 query 变化、修复前缺口及约束，形成候选经验。
2. 独立目标题 B：从同一检索前缀出发，分别运行 FRESH 和候选经验引导的改写；执行完成后用 gold 对照。FRESH 和 REUSE 都答对，不给记忆虚构准确率增益；若记忆更省成本，单独记成本优势。
3. 选择输入只使用执行前可见信息：当前 gap/原问题约束、经验操作及条件、当前与来源的结构匹配、历史迁移结果、低成本 QPP。不能把 B 执行后的得分当成 B 的输入特征。
4. 首版用冻结 prompt/规则比较这些特征；后续才用 B 类配对样本训练小选择器，预测“值得复用 / 走 FRESH”。在策略总体层面用独立 Calibration 选门限，不要求每张卡先积累数百个独立正确题。
5. 相同候选库、相同模型和预算下比较：只按语义相似、只按历史成功率、只看适用条件、QPP、联合选择。只有联合信息确实增加可预测性，才有超出模块组合的实证依据。

Shadow 中一条样本的输入历史统计不能包含它自己的结果；用时间前缀、leave-query-out 或预先规定的交叉拟合生成训练特征。之后在 Calibration / held-out 上使用由全部允许开发历史产生的冻结统计，角色要记录清楚。

若 oracle 有互补、简单选择器却无法识别，说明目前信号不可预测，不能称已经有可用方法。若只有抽象卡好看的案例而平均不胜具体 query pair，也不把“抽象经验卡”保留为必须优越的立论。

## 3. 可插拔的精确含义

必须区分三件事：冻结 LLM 参数、保持 retriever/index 的实现与内容、保持原有执行流程。加入循环 controller 会改变执行流程，即使底座组件没有改动。

GrowRAG 的接口主张应当是：**不修改文档索引、检索器和回答模型的参数；通过公开检索与生成接口组织查询修复；关闭经验后可运行同一无记忆管线。**

ERM 更新 document keys，GAM-RAG 有自己的层级索引与句子记忆，因此二者是重要机制参考，却不是相同的 query-only 黑盒插入点。S2G-RAG 本身也不要求修改搜索引擎或重训 generator；其模块性已经公开说明。[S2G-RAG](https://aclanthology.org/2026.acl-long.1185/)。

## 4. “安全”要如何成为可以检查的结果

这里的安全指经验引入的回答质量退化，主要观察三项：

```text
破坏率 = 原本答对、干预后答错的题数 / 基线答对题数
修复率 = 原本答错、干预后答对的题数 / 基线答错题数
成本 = 检索 + Judge + 候选改写 + 经验检索/应用 + 回滚/FRESH 的总花费
```

分母为 0 时报告不可估计，不能写成风险为 0。除逐题 EM 的对/错转移外，还报告 F1 等分数的下降幅度，避免二值阈值掩盖变化；逐题 EM 本身是二值，不称连续分数。

必须有两个无记忆参照：

1. **BASE**：原问题的一次检索与回答。
2. **FRESH**：相同问题、相同已检索证据和同样预算下，使用结构化 gap 的无经验修复闭环。

只优于单次 BASE 不能证明历史经验有用，因为收益可能全部来自多搜了一轮。只有对照同预算 FRESH 才能把历史经验的作用分离出来。

supported Judge 检查证据/答案关系；可靠性评分检查过去表现；适用性评分检查当前条件。三者都可能判断错。部署时不能看到当前 gold，也不能保证预先知道一条改写是否有害。

一个具体例子：原问题问某机构 2009 年的负责人，历史扩写规则错误删掉时间约束，检索到 2024 年的负责人。生成内容可能被 2024 年文档充分支持，但仍不满足原问题。相反，适用性检查只凭语言模型自评也可能漏掉这种错误，因此必须在盲测上量化。

不能把更多拒答当作更安全的证据。报告完整回答正确率、回答覆盖率、拒答率，以及“基线能答对却被系统拒答”的机会损失；在相近覆盖率/收益下比较破坏率。BASE-first 模式还必须单独报告被路由到修复的子群，防止大量未干预的简单题稀释风险。

回滚只表示恢复干预前的候选证据/状态。它不能撤销已经花掉的 token，不能自动知道 BASE 答案正确，也不是数学安全保证。

## 5. 对原先逐卡高置信门的修订建议

现有代码的最少 2 个观测、风险上界 0.70 属于脚手架默认参数，不能作为低风险结果或部署承诺。

逐卡样本非常稀疏。即使观察到零次伤害，常用双侧 95% Wilson 区间的上端在 n=2 时约为 65.8%；要压到 5% 附近需约 73 个相关独立观测，到 1% 附近需约 381 个。这里 n 是基线已答对的独立复用试验数，不是随便调用卡片的总次数。这是公式演算，且依赖二项独立观测假设；选择偏差、重复问题与动态更新会破坏简单解释。

建议首版：

- 保留逐卡原始验证记录，少样本标记为“未充分验证”，不混为“已证明不可靠”；
- 将卡片次数、收益/伤害估计、最近表现作为选择器特征；
- 在策略整体或少量明确的动作/缺口类别上评估风险和覆盖率，先避免每张卡都要求数百次验证；
- 先做冻结的离线记忆，EMA 与在线晋升单独放到后续实验；
- 不能将普通 Wilson 上界宣传成对自适应在线策略的正式保证。

若以后确实研究统计保证，需要独立校准数据、固定选择策略、清楚的风险定义和采样假设。可参考 [Safe Policy Improvement with Baseline Bootstrapping](https://proceedings.mlr.press/v97/laroche19a.html) 与 [Conformal Risk Control](https://proceedings.iclr.cc/paper_files/paper/2024/hash/f3549ef9b5ff520a7e41ff3cc306ab2b-Abstract-Conference.html)，但它们的理论条件不能直接套到动态 memory 上；本阶段不把 RL 或 conformal 当必修前置。

## 6. 三层记忆保留，但首个实验减少活动模块

用户喜欢并已确认的三层概念继续保留：

| 层 | 保留的作用 | 首个实验如何使用 |
|---|---|---|
| QueryEpisode | 单问题的具体查询、证据引用、动作和最终验证轨迹 | 必做；完成后冻结，用于复现与错误分析 |
| DocumentSession | 精确单文档版本的术语、导航位置、局部歧义 | 保留设计与来源接口；先不作为第二套在线决策器，后续单独消融 |
| ExperienceCard | 跨题可复用查询操作、适用/禁用条件、验证记录 | 必做，但先冻结一个小库 |

首版在线卡建议只暴露六组信息：问题/缺口模式、操作模板、前置条件、禁用条件、预期证据类型、验证统计与来源 ID。具体历史 q→q' 和答案评价留在离线 episode，避免旧实体/旧答案进入新问题。

累计证据的原文账本与紧凑视图仍有价值，但 NeedSupportGraph 首版用简单列表/映射实现即可，不先引入图数据库或复杂合并服务。每个额外模块只有独立增益证据后才进入完整系统。

## 7. 基线与代码底座

| 角色 | 建议 | 使用边界 |
|---|---|---|
| 无记忆修复基线 | S2G 风格结构化 gap + FRESH | 如果只用冻结 prompt，必须命名 S2G-inspired；不能说复现了其训练后的 S2G-Judge |
| 历史改写基线 | ReFormeR | 尽量复用公开 pattern 方法；转到 QA 时统一 retriever/reader，说明与原 IR 实验的差别 |
| 经验控制基线 | RRM 的文本化机制对照 | RRM 原任务为视频/多模态，不把文本移植结果冒充官方端到端复现 |
| 简单强对照 | 不复用、最近邻经验、成功率门、适用性门、QPP、固定 FRESH | 对照候选、模型、预算和停止规则一致 |
| 查询算子实现 | QueryGym | 用作算子实现参考，先核对接口/许可和固定版本 |
| 评估参考 | QPP-4-RAG | 学习 variant oracle 与 IR/生成效用差异，不因 TREC 主题少而强行训练经验门 |

继续使用当前 GrowRAG 脚手架作为实验记录与接口，不为了适配旧代码而选择研究问题。真实 retriever/LLM 尚未接入、现有主要是合同/离线选择与测试，不能说系统已经完成实证。[S2G 代码](https://github.com/nianaaa/S2G-RAG)，[QueryGym](https://github.com/ls3-lab/QueryGym)，[QPP-4-RAG](https://github.com/Narabzad/QPP-4-RAG)。

## 8. 推荐实施次序与继续/调整条件

### 阶段 0：先冻结可比较的最小切片

一个文本语料、一个 retriever、一个 reader、同样的 Judge 与 FRESH prompt。只保留少数明确操作，例如消歧、补关系、拆出桥接问题。保留原 q0 作为回答目标，检索 query 的改变不改变回答问题。

运行 BASE、FRESH、最近邻经验、随机经验、ReFormeR 风格模式和 oracle。前期每次仅比较一个修复决策；多轮闭环随后接入，避免状态误判和经验误匹配同时变化无法归因。

### 阶段 1：验证历史经验的额外价值

从独立 source 子集获得经验证的候选卡；在影子子集运行固定 top-k 卡和 FRESH。oracle 是执行完后知道真实得分的离线上界，不是可以部署的选择器。各方法共享同一候选池；oracle 尝试所有候选的巨大成本不能算成在线系统成本。

继续条件：历史经验在去近重复样本上有可复现的额外质量或成本优势；不能只靠例子或全部来自共享答案的样本。

调整条件：如果相同预算 FRESH 已达到相同或更好的质量且更便宜，停止增加 memory 生命周期复杂度，先调整经验表示或缩小适用任务。

### 阶段 2：研究选择，而非继续发明改写

以当前 q/gap、来源模式和过去验证统计预测 REUSE 相对 BASE/FRESH 的增益/退化。首版先用可解释规则与冻结 prompt Judge；比较 query 相似度、gap+action 匹配、historical-only、current-only 与联合特征。若后续加入训练过的逻辑回归、树或排序模型，它本身已经是 learned selector，必须标明训练数据，不能再称整个选择层 training-free。

继续条件：在相近经验调用率、修复收益或总成本下，联合选择比简单门控有稳定优势。阈值统一在 calibration 确定，测试时固定。

### 阶段 3：才接多轮控制与执行后核验

把已验证的选择器嵌到 BASE-first 的 FRESH/REUSE 循环。保留最大 3 次 repair 和连续 2 轮无进展的开发初值；只能用 calibration 比较其他上限。单独消融执行后 contract、回滚和停止，每个分支的调用都计费。

### 阶段 4：外部验证与训练小模型

先 HotpotQA，再 2Wiki/MuSiQue；第二个模型强度或 retriever 做泛化检验。模型强时调用经验少本身可以是合理结果，重点看相同预算的质量。规则选择与 oracle 差距明显、标签足够时再训练小 controller；如果阶段 2 已加入训练过的简单选择器，这里属于模型升级/蒸馏，而非首次训练。文档层、EMA、在线流式更新分别增加，不与主实验证据混合。

## 9. 数据协议的出处与初值

IRCoT 的 HotpotQA/2Wiki/MuSiQue/IIRC 实验支持多跳 QA 的选择；数据集论文支持 gold 与官方划分的定义。[IRCoT](https://aclanthology.org/2023.acl-long.557/)，[MuSiQue](https://aclanthology.org/2022.tacl-1.31/)。

ERM §5.1 用不重合的查询做适配/冻结评估并考察多个适配比例；RRM 在同视频预测结束后再揭示反馈，让经验只影响后续视频；二者提供建库与未来评价隔离的依据，但都不规定我们的三段百分比。具体原文和完整数据集矩阵见 `knowledge/datasets/2026-09-05_历史论文数据集总表与划分依据.md`。

可继续使用官方 train 内 40%建经验、35%影子迁移/未来训练、25%调参校准，官方 dev 作为 held-out。比例分母只是 train，dev 没包含其中。标准切分保留，额外报告跨实体/文档的严格子集；不把共享文档的全连接分组强加到主结果上，也不把 yes/no 等常见答案的重复等同于泄漏。

MuSiQue-Full 的不可回答标签依赖缺少必要段落的给定候选上下文。如果开放全库检索重新找回必要段落，该标签不再能当作当前系统不可回答的 gold。主开放检索用 MuSiQue-Ans；Full 只在遵守原上下文条件的缺证据/拒答诊断中使用。

首个预算切片可从 HotpotQA train 抽 4,000 题，分为 1,600/1,400/1,000；官方 dev 抽 500 题作一次性 pilot 留出评估。先运行其中 200–500 题排错，不能看 held-out 错例反复调 prompt。pilot 结果不冒充 fullwiki 全规模结果。语料库可按标准基准包括测试可检索文档；测试问题、答案标签和修复经验不得进入建库。

## 10. 下一轮可直接承接的工作

先完成真实 BASE/FRESH 与小规模配对数据采集，再决定是否需要完整 Schema v1 的所有字段。当前用户授权是规划与文献审查，具体运行实现留待下一次编码请求。此前用户“每轮记录精华”的要求继续有效：新论据/反例先写审计与决策建议，再更新项目记忆，不让旧助手的推断逐轮变成既成事实。
