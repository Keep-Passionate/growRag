# 两条主线对齐：经验怎样记，才能知道这次值不值得用

日期：2026-09-08；本日后续讨论。状态：研究设计候选，尚未选定优胜表示，未开始新实验。

## 1. 对齐上一轮的四个方向与本轮的两个研究问题

上一轮把“研究问题、使用场景、长期扩展”平铺为四个方向，容易使阅读分类与主线不对应。本轮改为以下层次，不把四个方向同时启动：

| 层次 | 本轮定位 | 对应上一轮 |
|---|---|---|
| 研究问题一：经验怎样记 | 核心：保留哪些信息，有助于判断当前是否适用、是否值得执行 | 原方向二 |
| 研究问题二：经验怎样用 | 配套：结合当前问题、经验和 QPP，少执行候选仍作出好选择 | 原方向一 |
| 使用场景：证据驱动的有限修复循环 | 保留 Agentic 特征；每轮观察、选择、执行、检查、停止。不是第三个平行创新 | 原方向四 |
| 后续：长期持有与稳定更新 | 待表示和复用收益明确后再做，不在首轮同时改变经验池 | 原方向三 |

这不是放弃低成本选择。我们把“经验表示是否提供有用决策信息”作为研究对象，把“选择更好、成本更低”作为验证结果；有限修复循环是将来更丰富的使用环境。是否以此写论文仍待用户阅读讨论后确认。

一句话候选问题：**同一批历史经验，保留哪些最少信息，能让系统保留有益复用、拒绝有害复用，且比现场修复更值得？**

不承诺一定有统一最优卡，也不承诺相似工作不存在。可能得到的结论是不同动作/阶段需要不同表示；也可能简单动作模板已足够。

补充两个类别：

- **最近的已审稿查询模式工作**：[ReFormeR，ECIR 2026](https://link.springer.com/chapter/10.1007/978-3-032-21300-6_30)。从高效改写对抽取模式，并根据检索上下文选择。不因为 ECIR 不同于 SIGIR 就跳过这篇；但也不把它标成 SIGIR 顶会。
- **必须排重的预印本**：[RRM](https://arxiv.org/html/2607.28156v1)、[QCR](https://arxiv.org/html/2608.12847v1)。前者已有适用条件、证据要求、查询级复用；后者已有操作不变部分、当前对象重取、适用条件、执行核查。我们不能靠换字段名超越它们。

### 三个容易混淆的对象

S2G 在每题维护当前证据和 gap，输出 `category/target/slot/description`；GAM 将经历写进句子级向量状态；我们拟保存的是“如何修改查询”的程序性经验。三者可以借鉴，但不是三种同质卡片。[S2G 方法 §3](https://aclanthology.org/2026.acl-long.1185.pdf)；[GAM 方法 §3](https://arxiv.org/html/2603.01783v1)

ERM 则把扩展单元与贡献写入文档 key；并非我们的查询旁路。它已研究录入、单元贡献与限容量，不能简写成“答对就全存”。[ERM §4](https://arxiv.org/html/2602.05152v1)

### 最接近的已有覆盖

ReMe 已做关键点与轨迹、不同检索键的比较，也报告修复与引入错误；ExpeL 已做示例与 insight 消融；QCR 已控制来源并比较等篇幅摘要。因此“首次比较摘要/轨迹”“首次存适用条件”“首次报告伤害”均不成立。更窄的机会仍需检验：**在 RAG 查询操作中，条件的可观察性与最少信息保留，是否有实际决策价值。**

## 3. 我们研究的是信息选择，不是 JSON 排版

区分两条正交轴：

- **动作种类**：同义改写、扩写、压缩、拆分、消歧等，即“改什么”。
- **经验表示**：具体对、摘要、模板、状态、条件、按需读取，即“怎样记”。

同一种语义改写动作可以有六种表示；“条件卡”不是新增一种 rewrite action。同理，不能把所有语义改写强行写成实体/关系缺失。

统一外壳先只承担管理：ID、版本、源记录指针、可使用阶段、动作族、正文类型。来源环境指纹与完整反馈留在审计层；执行或选择器只读取预先规定的视图。

**关键实验约束：**若外壳已给所有组完整适用条件与核查项，就无法再通过正文对照判断这些信息是否有用。实验变量放在不同正文/视图中，公共字段保持相同。生产卡的安全合同不因实验而放松。

## 4. 六种经验卡候选

以下是设计草案，不是现有系统已经采集的卡，也不是哪种更好的证据。

共同示意来源：曾处理“周澄与林沐谁年长？”，实际搜索改为“周澄 出生日期 林沐 出生日期”。人名与轨迹均为虚构教学例子，没有真实日期、得分或成功次数。真实实验必须使用实际运行的独立来源；缺失记录不能补造。

### M1：具体改写对——记住发生过什么

```text
源问题：周澄与林沐谁年长？
实际检索词：周澄 出生日期 林沐 出生日期
```

保留明确词汇操作，便于审计；无需先相信模型归纳的规则。缺点是系统要自己推断为何有用，可能照抄旧实体，跨词汇迁移较弱。该组不携带历史最终答案；具体实体只能是示例，不能变成新题事实。可另做源实体匿名化的控制，但不能混进“原始具体对”后不说明。

### M2：通用摘要——记住一个教训

```text
比较两个人的年龄时，可以尝试检索两人的出生日期，再依据日期作比较。
```

简短、易生成，能覆盖不限于结构缺口的经验。风险是泛泛而谈，抽象范围扩大，省略关键前提。自然语言并不天然缺少条件；若它已经写清条件，就不能把它当作“无条件”对照。

### M3：动作模板——记住如何操作

```text
动作：把两人年龄比较转换成日期检索
输入：当前题的 person_a、person_b
输出检索词：{person_a} 出生日期 {person_b} 出生日期
保留：两个对象；原题的比较要求交给最终回答器
```

更可执行，换人名即可迁移。缺点是会执行不代表会选择，可能把任职年限误当年龄。模板只约束操作；当前实体是否识别正确仍需判断。语义改写也可写成“在当前语义已明确时，将表达 x 替换为语料术语 y”，不强制使用关系图。

### M4：状态—动作—预期变化——记住在什么局面采取什么动作

```text
源题可见状态：所需两个人物已确定，但当前证据未覆盖两人的出生日期
诊断：待补日期证据；诊断来自当时证据，不是用户问题自身有错误
动作：围绕两个人名与出生日期检索
预期变化：得到分别对应两人的可追溯日期证据
```

这组适合后续有限修复循环。它能解释“为什么再搜”，而不只记查询文字。风险是记录变长，源题状态不一定能迁移，judge 可能把未知说成缺失。

“预期变化”是待检查目标，不是保证一定搜到；没有新增结构证据的语义改写，可检查相关证据排名/覆盖是否变化，不能伪造一个关系缺口。

**PRE 限制：**在新题尚未检索时，不能把历史“未覆盖日期”当作新题已观察事实。当前状态应为未知，或者留到 POST 核验。这组只有来源具备真实状态记录时才能生成，不可从查询对补造前情。

### M5：条件—动作—核查——记住何时借鉴、何时不照搬

```text
支持条件：当前任务确为两人的自然年龄比较
不适用条件：实际比较任职时长、作品发布时间等不同属性
未知条件：人名对应对象尚不明确，不能先当已消歧
操作：M3 的日期检索动作
执行后核查：日期分别属于当前两个对象；最终比较仍遵循原题
```

直接面向适用性，但与 RRM/ReMe/QCR 明显重合，字段本身不新。我们可以研究条件怎样获得、哪些不可删除、哪些只是多余背景。

条件至少区分：源记录明确支持、模型归纳待验证、独立使用反馈支持。模型写出来的前提不能直接标“已证实”。首次只有成功来源时，不捏造经历过的反例；假设性禁用条件只能明确标为待验。

区分硬约束与软线索：实体/属性换错属于任务约束；某种词形过去效果较好是软线索。未知不等于不满足，也不等于满足。过严过滤可能漏掉有益经验，所以要测误拒率。

### M6：短卡＋按需读具体记录——记住简要规则，细节需要时再取

```text
默认读取：M3 或 M5 的短版本
外置来源：该卡对应的真实查询变化与必要上下文片段
不确定时：在访问预算内读取指定来源片段，再判断
```

不是“更多层的记忆”，而是同一条经验的两种读取方式。理论上可兼顾简洁与细节，但会增加读取、判断与延迟，未必便宜；ExpeL 已有具体与抽象并存，不能把双表示当新意。

单独比较“始终短卡”“始终完整视图”“预算内按需读取”。固定候选来源和总读取预算；若只有新方法可额外看完整原始反馈，收益不能全算给表示方式。

### 六种模式的成本与适用位置

这里是设计预期，不是实测 token 或效果排名。实际总费用按固定 tokenizer 与模型计量。

| 模式 | 默认读取量 | 主要优势候选 | 主要风险 | 优先场景 |
|---|---|---|---|---|
| M1 具体对 | 短至中，取决于查询 | 忠实、具体词汇对齐 | 旧实体带入、适用原因隐含 | PRE 起步对照 |
| M2 摘要 | 可短 | 简洁灵活 | 泛化过头、遗漏前提 | PRE/POST 通用对照 |
| M3 动作模板 | 通常可控 | 参数替换、执行明确 | 缺少何时用 | PRE 起步对照 |
| M4 状态动作 | 中至长 | 定向修复、可核增量 | 状态误判、检索后信息泄漏 | POST 扩展 |
| M5 条件核查 | 中，条件多会膨胀 | 可判断适用边界 | 过严、条件幻觉、验证开销 | 核心候选 |
| M6 按需双视图 | 常态短，最坏更贵 | 可取舍细节 | 额外读取成为隐藏优势 | 后续成本实验 |

## 5. 从哪些角度设计和删减字段

每个字段先回答“它影响哪个决定”，而不只是“看起来有解释性”。

1. **对象与角色**：哪些实体应替换，哪些关系方向不能变？旧答案、旧人名通常不应成为当前约束。
2. **操作内容**：只保存具体一句 query，还是保存可绑定当前对象的操作？动作会不会泛化过度？
3. **当前可观察性**：条件能从原题知道，还是必须先检索？未知值明确保留，不能替新题补证据。
4. **上下文的最小充分量**：只保留会改变使用决定的上下文。原文大段背景先放外置来源，不默认塞入提示词。
5. **历史反馈的权限和强度**：源题成功、其他题无增益、造成退步分开；相对谁比较也要明确。不能只给新卡更多成败监督。
6. **环境依赖**：索引/检索器/语言等作运行级指纹；卡只记录真正依赖的能力或语料条件。环境改变需复核，不是机械要求整个运行环境逐项完全一致。
7. **信息事实性**：来源明确、模型推断、待执行检查三者不混写。原始记录可追溯不等于每个归纳条件正确。
8. **总成本**：存储字节/向量、写卡 token、读取 token、选择器 token、额外检索与时延分账；按需读取尤其要算最坏情况。
9. **稳定性**：六种表示各自直接从同一原始来源生成；不让 M1→M2→M3 逐级重写形成不同漂移深度。

历史可靠性是“此前证据支持到什么程度”；当前适用性是“当前是否满足要求”；当前值得用还要考虑“FRESH 是否已足够、是否有额外成本”。满足前提但没增益，不应自动标成语义不适用。

## 6. 如何开始研究：先比较信息，后做复杂控制

### 第零步：文献与人工核查，不启动新收费实验

先读下节前 3 篇，从同一批真实源记录整理对应 M1/M2/M3/M5 草稿。若原记录没有状态，就不做 M4。可以人工检查例子是否忠实，但把这种检查记录为人工开发，不冒充自动建库泛化。

首轮先聚焦一个动作族，建议继续已有语义改写；扩写与拆分作为后续动作迁移。上面的年龄例子仅帮助理解，不因此更换实验分布。

### 第一组：表示能否帮助“更会选择”

固定同一候选来源 ID、同一动作、同一题的可见信息、同一选择器模型/提示词。只替换选择器看到的 M1/M2/M3/M5。选中后交给执行器的规范动作始终一样，不让执行器因组别收到不同正文。

先做候选可用/不可用判断，再扩展多候选选择。**这组表示选择实验明确规定：无卡或拒绝后回退 FRESH**，保留各组全部目标题的结果和成本，不只统计复用成功的题。报告“全题策略−始终 FRESH”，另列被选中同题的“REUSE−FRESH”。拒绝后仍付出的选择费用不能忽略。

这是新实验建议，不修改当前运行代码中的 BASE 回退。如果将来允许 BASE/FRESH 两种回退，需增加使用相同回退决策政策的无记忆对照；否则改善可能只是避开了有害 FRESH，不能全归因于经验内容。

这组回答“这种记法是否有助于判断值不值得用”，不是谁更会模仿示例改写。

### 第二组：表示能否帮助“更会执行”

固定选中的同一来源及当前题，再让不同表示进入同一个改写器。比较原约束保留、查询漂移、证据与答案结果。这组不重新选择来源，否则检索、选择和执行贡献混在一起。

### 第三组：更省信息而不损失效用

若 M5 有用，逐项删减条件、对象绑定、环境线索、核查项；再做“同样信息写成段落”的控制。只有这样才能区分信息内容有用与结构格式有用。

分别报告相同经验条数/相同 token 上限下的效果，以及固定总存储/读取预算下可容纳不同条数的效果。后者不再是同源池的纯表示实验。不给短卡填无用词，也不强行截断长卡关键约束。

### 第四组：接入低成本选择，再扩展 Agentic 循环

固定候选池，对照普通 QPP、历史查询/表现 QPP、相似度/场景索引、拟议条件选择。候选生成是否读历史另做对照，不能把历史生成的候选叫纯 FRESH。

之后从相同首轮证据出发比较 FRESH repair 与 REUSE repair；M4 可在这里使用。各组共享证据判断、累计规则、执行次数和停止规则。

循环停止原因区分“证据足够”和“预算耗尽/重复/边际信息不足”；后几种不证明答案正确。状态机体现控制流程，不自动构成新贡献。

### 什么结果值得继续，什么结果应停止堆叠

- 值得继续：相同预算下多保留有效修复、少引入退步；或相近效果下更少读取/执行。
- 需要反思：条件卡只因拒绝更多而显得安全；短卡只是删了关键限制；收益只存在于人为设计题；选错与执行错分不清。
- 有价值的否定结果：动作模板已经足够，复杂状态没有额外信息；此时保留简单表示，不必继续加字段。

## 7. 最少需要报告的维度

| 维度 | 测什么 | 避免什么误读 |
|---|---|---|
| 主效果 | REUSE−FRESH，答案 EM/F1；证据层单独看 | 把多轮修复功劳全归记忆 |
| 伤害与救回 | FRESH 对→REUSE 错；FRESH 错→REUSE 对 | 只看平均分抵消两种变化 |
| 选择质量 | 使用率、误用率、误拒有益候选 | 永远不用经验被判最佳 |
| 意图与约束 | 对象、属性、比较方向、时间等是否保留 | QPP 高却搜偏 |
| 记忆成本 | 总存储、建卡与更新、每题读取与选择 token | 只算最终回答费用 |
| 执行成本 | 检索、重排、Reader、总时延与失败调用 | Post-QPP 偷算为省了检索 |
| 迁移 | 表面改词、实体改变、任务属性改变、独立留出 | 所有变化都被机械拒绝 |

“误拒有益候选”需要额外离线配对才能知道；没有执行不能补标签。训练/校准反馈与冻结评价分开，当前目标题结果绝不提前给选择器。只观察选中卡的反馈存在选择偏差，未选卡不能自动算失败。

## 9. 核验范围与共同张力

本轮使用 academic-research-suite 的定向比较与 citation-management。沿已明确的问题继续，不重新做从零选题；不是系统综述。检索日期 2026-09-08，查询包含完整题名及 `procedural memory applicability experience representation`；优先 ACL/AAAI/PMLR/ICML/出版社与作者全文。无引用次数采集，无高引数杜撰。未下载和逐字重读全部正式 PDF。

三组定向比较，供用户精读后确认，并非全量两两文献矛盾检测：

- ReMe 与 QCR：都保留使用情境；前者持久程序经验，后者针对新题生成支持笔记。不是一方“有条件”、另一方“没条件”。
- GAM 与 S2G：前者跨题更新句子检索先验，后者单题维护证据状态。对象不同，不以谁“字段更多”论优劣。
- ExpeL/AWM 与具体轨迹：抽象帮助迁移的结果不证明无限压缩/持续重写安全；保持同源、同预算后再检验本任务。

共同点是从经验或当前反馈改善下一步行动；尚待本项目验证的是**哪些信息对实际复用决定不可替代**。来源清楚、字段齐全、条件看似合理，都不等于额外收益已证实。
