# 决策记录：路线 A「查询侧可信复用层」

决策日期：2026-08-19
状态：已确认
决策人：项目负责人

## 已确认的主方向

GrowRAG 第一篇工作选择：

> **在第一次正式检索前，判断一条历史上验证过的查询变换是否既可靠、又适合当前问题；只有两项都满足要求才复用，否则保持原查询。**

公开讨论时暂用简单名称：

- 中文：**查询侧可信复用层**
- 一句话：**过去成功的查询变换，这次该不该用？**
- 项目名继续使用 GrowRAG，暂不新造缩写。

## 第一版固定边界

1. 不修改基础检索索引；
2. 不保存历史答案或历史文档正文；
3. 保存具体 `q → q'`、细粒度变化和完整来源；
4. 在线动作只有 `DIRECT / REUSE`；
5. `FRESH` 仅作为离线强基线；
6. 先做经验风险控制，不在第一版承诺 conformal 理论保证；
7. 不训练大模型，不从强化学习或 contextual bandit 起步；
8. 先运行 full-information oracle，证明迁移空间存在后再训练或校准轻量 gate。

## 论文主问题

> 在文本 RAG 中，查询侧历史经验复用能否在保持有用覆盖率的同时，显式减少“原查询本来正确、复用后反而错误”的伤害？

## 主贡献候选

当前允许争取的贡献是：

1. 严格区分来源成功、历史可靠和当前适用；
2. 把 `DIRECT 正确 → REUSE 错误` 定义为一等风险；
3. 提供无泄漏的成对执行协议和 risk–coverage 评价；
4. 提供一个可拒绝、可审计、环境版本绑定的轻量 sidecar。

当前不声称：

- 首次记住成功改写；
- 首次复用检索经验；
- 首次检索前 query variant selection；
- 首次经验可选；
- EMA 或多级队列本身是创新；
- 已经获得形式化安全保证。

## 默认技术取舍

用户尚未逐项修改以下细节，因此按此前讨论的推荐默认值启动：

- 经验表示：具体 `q → q'` + 原子变化 + 变换类型；
- 选择策略：历史可靠度和当前适用性分别过门；
- 环境策略：corpus/retriever/index 版本不匹配时硬拒绝；
- 风险策略：小样本使用保守置信上界，不只看平均成功率；
- 应用接口：第一阶段接收预先生成的目标题 query variant，不把“如何迁移改写”与“该不该复用”混成一个黑箱；
- 数据顺序：先小型 oracle 风险矩阵，再 HotpotQA/2Wiki 主实验。

这些是可修改的工程默认值，不改变已确认的主方向。
