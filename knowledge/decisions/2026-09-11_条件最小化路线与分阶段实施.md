# 从表示对照到最少适用条件：当前研究路线

日期：2026-09-11。性质：用户已选主线＋可证伪研究计划；不是论文效果声明。

## 1. 本轮已经确定的选择

- 先研究跨题经验，HotpotQA 起步，文档层后置。
- 先做 E1：同来源、同候选、同选择器，只换选择器看到的经验表示；选中后执行同一个规范动作。
- 必须同时做 E3：经验的额外收益 = REUSE 的效果 − 无历史 FRESH 的效果。BASE 只说明整套改写流程相对原查询怎样。
- 第一轮后优先研究**最少需要哪些适用条件**：逐项删字段，检查误用与误拒。QPP 后置，不放弃。
- 本轮允许普通按量 API 小批量真实调用，**整个授权批次累计不超过人民币 5 元**，包括建库、表示构造、选择与所有对照。不得每个阶段重置为 5 元，也不自动沿用以前的余额。
- 先处理 64 道来源；256 只是事先冻结的潜在扩容顺序，本批不自动扩源。来源不足先诊断，不以放宽录入标准凑正结果。

## 2. 现在真正要回答的研究问题

> 在同一批历史修复、同一批候选动作和同一检索底座下，哪些能从当前问题核对的经验条件，值得保留下来，才能少选有害动作、少拒绝有益动作？

“值得”必须同时考虑答案、证据和成本。条件写得更长、模型自称更有把握、源问题成功，都不是这道新题值得复用的证明。

### 三个具体假设

| 假设 | 怎样检验 | 什么结果会否定它 |
|---|---|---|
| 操作关系比历史实体相似更能帮助选经验 | 同候选下比较原始 q/q′ 与含操作关系的表示；检查比较、关系连接、共同属性等混淆 | 相同信息下没有减少误选，或更短原始对同样好 |
| 记住“不能改掉的条件”可减少有害复用 | 对完整表示分别删时间范围、关系方向或比较条件，只改变一个信息族 | 答案无改善，或只是更多拒绝导致覆盖下降 |
| 区分来源观察与迁移猜测，可减少过度泛化 | 有无依据类别标记，其余文字相同；未知不伪装成已验证失败 | 更谨慎但漏掉同等或更多有益动作，净增量更差 |

这些是候选研究假设，不是已确认的创新。观察到信号后，还要在独立批次和强近邻对照下确认。

## 3. 两步实验，不一次堆满所有模块

### 第一步：四种记法，问“能不能帮助选”

| 编号 | 看见的经验 | 不允许偷偷增加的内容 |
|---|---|---|
| M1 | 来源原问题及实际执行的改写 | 历史答案、当前题 gold |
| M2 | 简短自然语言经验，可包含必要条件 | 不故意删去所有条件做弱对照 |
| M3 | 参数化操作、占位符、保留项 | 不把“会执行”当作“当前适用” |
| M5 | 条件—动作—核查，区分观察与假设 | 不虚构已观察反例，不把未知 gap 当已知 |

四组从同一来源独立形成，不连锁改写。当前代码可接收已准备好的四组文本；**M2/M3/M5 的真实模型构造、逐卡语义复核及目标批量入口尚须接通**，不能把测试夹具当真实生成。

### 第二步：逐项删条件，问“到底哪条值得记”

先做五个小对照，而不是把所有字段组合穷举：

1. 完整 M5。
2. M5 的同信息自然段：条件内容完全相同，只改变组织方式。
3. 去掉“操作关系”信息，例如比较双方数值还是查两者共同属性。
4. 去掉“必须保留的约束”，例如时间范围、实体身份、关系方向。缺哪类约束，后续再拆小项。
5. 去掉“范围未知／证据依据类别”，观察过度泛化和过度拒绝是否改变。

M2 仍保留为短文本参照。不适用于某张卡的字段不能硬填；报告每个消融真正改变了多少张卡和多少题，否则平均分很容易稀释现象。删字段时应删掉该信息在其它字段中的同义复述，不能只删 JSON 键；同时不改变规范动作正文。

源文本本身隐含的条件无法完全抹掉。因此“删去显式标记”只能检验显式表达的作用，不能宣称模型完全不知道该条件。条件交互可能存在：逐项删除不等于找到全局最小集合；只有发现明确交互时，再增加少量双字段实验。

### 误用和误拒要说清楚

- **结果层误用**：选了经验，结果比同题 FRESH 差。先按答案 F1 计算，另列证据增减和 EM 改坏。
- **结果层误拒**：选了 FRESH，但共同候选池里至少有一个动作实际更好。
- **语义条件判断**：人工检查操作是否与题意相容；与上述结果标签分开。语义适用不保证检索有益，偶然答对也不证明条件成立。
- **无法判断**：某候选执行失败、答案或 usage 缺失，不用零分假装已测，也不默默删除该题。

只在离线审计中把候选都执行一遍，获得事后比较表。线上不能先查看这些结果再冒称提前预测成功。候选都不比 FRESH 好时，不把责任推给表示；先检查经验来源和动作覆盖。

## 4. 数据与阶段安排

| 阶段 | 数据与动作 | 完成标准／停止规则 |
|---|---|---|
| 0：实验接线 | 合成离线样例、四视图、共享候选、规范执行、失败/费用审计 | 测试通过仅代表接线正确 |
| 1：来源可行性 | 官方 train 完整版本或有来源凭证的镜像；固定 64 道 memory_seed | 诊断是否至少 6 个非重复动作、2 类人工核查模式；不足停止排名 |
| 2：首次信号 | 32 道新的 calibration_dev：8 调试、24 冻结内部检查 | E1＋E3；不得按成绩换题或只展示赢家 |
| 3：最少条件 | 新调试材料上设计删除项；再用新的独立检查批 | 同信息格式对照＋单字段删除；尽量保留最短有效表示 |
| 4：确认与迁移 | 更大 Hotpot 官方 dev；再选 2WikiMultihopQA 或 MuSiQue | 各方法同底座、同可用历史与预算；按官方划分；不写入评测答案 |
| 5：低成本与闭环 | 只有前面存在可复现经验信号才加 QPP，再到有限 POST 修复 | 每次只加一个变量；多轮优势不得冒充记忆优势 |

官方 train 内沿现有固定角色规则 80% memory_seed、10% selector_train、10% calibration_dev；这不是把官方 test 拿来训练，也不是论文提供的标准比例。首轮保留 selector_train 不用，不训练任何模型参数。24 道检查仍是内部开发，不是最终论文测试。

首轮来源与目标都按 bridge/comparison 均衡，便于找错误，**不是官方自然题型分布**。后续正式报告恢复自然分布并分类型列成绩。当前题内句 BM25、标题＋句子 top-4 是 distractor 诊断，不是 fullwiki，也不能直接宣称超越论文榜单。

排除已暴露的旧 200 题及规范化重复。语义近重复、共享实体与共享支持文档仍需另行审计；不把按题划分称为跨文档泛化。第二数据集尚未敲定，不在看见它的分数后挑赢家。QASPER／DG-RAG 文档结构分支保留，但不进入这轮主实验。

## 5. QPP 与有限修复循环何时进入

**目前选择的是历史动作卡，不是已经生成的全部查询文本。** 后续若使用 QPP，先给各组相同的候选 q′，再比较只看 QPP、只看条件、二者结合。生成这些候选的费用照计；未选候选可以不执行完整 RAG。不能只预测“动作名称”就冒称复现查询表现预测。

QPP 论文包含历史查询信息类预测器；不能把“历史＋QPP”本身当空白。参见 [QPP Query Variant Selection](https://arxiv.org/html/2604.22661v1)。

若错误主要来自“首次查询无法观察到的证据缺口”，再加 POST：所有组从同一首次证据出发，用同一个 gap 判定器比较 FRESH、静态缺口规则、历史修复。先一轮，再有限多轮；证据足够、查询重复、证据无增量、预算/轮数耗尽是不同停止原因。停止不自动意味着能够可靠作答。

## 6. 和前人怎样比较，哪些不算创新

AWM 已有具体经验、抽象工作流及不同表示的研究，也讨论何时偏离历史流程；不能说我们首次研究表示或抽象。[AWM §3.2.1、§4](https://arxiv.org/html/2409.07429)

QCR 已在固定检索来源的设置中研究复用表示。我们 E1 特意把表示放在**执行前选择阶段**，执行器仍看同一动作，以隔离“更会选”和“更会执行”；这种实验定位有价值，但还不是独占的新算法。[QCR](https://arxiv.org/html/2608.12847v1)

ReFormeR、ReMe、RRM 是改写经验与适用条件的强近邻。详细逐篇阅读角色沿 [17 篇聚焦包](../../zotero/curated/2026-09-11_minimal_experiment/README.md)，不把 M1/M2/M3/M5 自建变体当成四篇论文完整复现。当前暂不再堆新增阅读包。

可能形成贡献的路线是：**识别最容易导致错误套用的条件，提出足够短、能被当前输入核对的记法，并以同候选规范执行的配对实验证明它保留收益、减少伤害。** 如果短摘要同样好，就接受短摘要；如果永远拒绝经验才最好，则经验选择的正向价值尚未成立。

## 7. 后面给用户的选择，暂不阻塞当前代码

第一优先级已经选定，不再重复询问。看到第一批错误后，只需要在下列两种条件策略中选一个做下一步，建议先软策略：

| 候选 | 好处 | 代价 |
|---|---|---|
| 软条件提示：未知标记留给选择器权衡 | 轻量，较少因条件不齐而误拒；适合先定位有用字段 | 判断受模型波动影响，必须报告实际误用 |
| 硬必要条件：少数可明确核对的冲突直接拒绝 | 清楚可审计，适合时间/关系方向等明确矛盾 | 条件定义过宽容易挡掉好动作，不能把“未验证”都写成禁止 |

两者均不改变来源真实性、身份隔离、版本检查等工程底线。先用错误案例决定哪一类语义条件值得硬化，不先造复杂规则引擎。若当前 pool 不足，优先选择“扩来源”还是“改变来源任务”需要另行讨论，不能用本批 5 元授权自动无限扩充。
