## 1. 先说结论与本轮纠正

我们的首选仍是 **HotpotQA → 2WikiMultiHopQA → MuSiQue**，但每一套数据的作用不同：先做自然问题的可信复用，再查结构化关系迁移，最后测困难多跳及局部上下文缺证据。理由来自下方逐篇原文，而不是“大家都这么用”。

本轮最重要的更正：

1. **40% 建经验 / 35% 独立迁移验证 / 25% 校准，是旧 assistant 提议的工程初值，不是任何一篇论文的公认规则。** 只能用于官方 train 内，比例是否合适要通过不看测试集的 pilot 检验。
2. “不微调 LLM”不等于“不需要数据”。经验库来自数据，门限/可信度也需要独立数据；第一版可以只积累与校准，不做神经网络训练。
3. **MuSiQue-Full 的 unanswerable 是相对于给定上下文而言。** 其不可回答实例通过移除必要支持信息构造；若开放检索把这段信息找回来，不能仍用这个标签判“应该拒答”。因此 Full 先只用于给定候选段落的充分性/拒答诊断，开放检索主实验用 MuSiQue-Ans。[MuSiQue 原文 §5 S8 / §6](https://aclanthology.org/2022.tacl-1.31.pdf)、[官方数据与格式](https://github.com/StonyBrookNLP/musique)
4. GAM-RAG 的部分主结果属于同一批问题上的重复记忆/再评测；**2026-09-06 补正：Table 2 / 附 D 另有 Different Query，在 2Wiki 各题型内将来源与目标拆开，检验不同语义和答案的新题。** 不能说它没有独立迁移实验，也不能用同题结果替代新题结果。RRM 则是有延迟 gold 的在线协议，不是我们静态 train→held-out 协议。[GAM-RAG §4 与附D](https://arxiv.org/html/2603.01783v1)、[RRM Experimental Setup](https://arxiv.org/html/2607.28156v1)
5. 旧文档要求将支持文档、实体、答案、模板全部联合成连通簇再切分，过于强硬：共享一个常见实体就可能把大量题连成巨簇，导致无法切分/分布失真。主实验先保持官方划分，严格做重复题/来源泄漏审计；文档/关系不重叠作为单独的迁移压力测试，不强制所有维度同时不重叠。
6. “官方公开 dev 作为研究 held-out”与“官方隐藏 test”必须分开表述。很多论文口中的 test 实际取公开 dev；不能据此宣称我们跑了官方排行榜测试。

## 4. 几篇最直接的“划分依据”，到底借鉴什么

| 论文 | 原文明示的安排 | 我们真正借鉴的原则 | 不应照搬的部分 |
|---|---|---|---|
| [ReFormeR §3.1](https://arxiv.org/html/2604.01417v1) | 从 MS MARCO train 派生 Diamond 抽 10,000 成功改写对；TREC DL19/20/Hard 评测 | 建模式的题与目标评测题分离；保存成功查询变换可行 | “MRR=1”是源题检索成功，不证明新题复用有益；10,000 不是最低门槛 |
| [ERM / RAG without Forgetting §5.1](https://arxiv.org/html/2602.05152v1) | 适配比例 0.3–0.8、每次加 0.1；各 split 重置 keys，在其余不重叠 query 上冻结评测 | 每次从空状态构造、冻结后测未见题；做数据量敏感性 | BRIGHT 适配/评估切法不是 Hotpot 官方 train 的固定比例；它改 key/索引侧 |
| [ReMe §4.1](https://aclanthology.org/2026.findings-acl.829.pdf) | BFCL V3：50 建经验 / 150 评估；AppWorld：90 train / 168 test-normal | 少量来源任务也能先做 pilot；经验构建与测试分开 | 环境执行正确性比自然语言 QA 更容易自动验证，比例不能直接迁移 |
| [Adaptive-RAG §4/附A](https://aclanthology.org/2024.naacl-long.389.pdf) | 实际运行各策略来构造 classifier 标签；classifier 题与 QA 评测题不重合 | 我们也用同题 BASE/REUSE/FRESH 的实际结果产生选择标签，而非手工猜简单/复杂 | 复杂度标签与历史经验的迁移收益标签不是同一个任务 |
| [QPP for Conversational Search §3](https://arxiv.org/html/2305.10923v1) | CAsT 五折；OR-QuAC 官方 train/valid/test，另测预训练迁移 | 数据少时交叉验证；问答/检索质量的预测器需要单独训练和验证 | 五折只能在开发材料内部做，不能反复把最终 held-out 当验证集 |

| [RRM Experimental Setup](https://arxiv.org/html/2607.28156v1) | 空库在线、batch 后揭示 gold；同视频全部预测后再更新并排除当前视频 | 如果以后做在线实验，反馈必须晚于预测，关联样本需要隔离 | 不能偷偷在静态 held-out 期间更新经验，更新后再称冻结测试 |
| [GAM-RAG §4/附D](https://arxiv.org/html/2603.01783v1) | 同题/同义题/不同题分别评价；Different Query按2Wiki题型将来源与目标各半拆分 | 借鉴分开报告复现、同义迁移与独立同型题迁移 | 已有新题实验；但不是同一篇文档连续多题协议，也不等于我们的FRESH配对条件 |
| [Controlling Counterfactual Harm 实验节](https://papers.nips.cc/paper_files/paper/2024/file/e9e3e5bdb017bbc887271c6f6de5353f-Paper-Conference.pdf) | 图像人机决策数据 10% calibration / 90% test，重复随机切分 | 将选择门限的校准数据与评价数据分离 | 这是人机辅助分类，理论假设不自动适用于生成式 RAG；10/90 不是我们的标准 |

**新增近邻，不计入旧 86 篇：** [When Continual Learning Moves to Memory: A Study of Experience Reuse in LLM Agents](https://arxiv.org/html/2604.27003v1) 在 §2.1 使用 ALFWorld/BabyAI 阶段式经验流；附 A.1.6/A.2 明确每阶段 200 个 memory-building/train 实例与 100 个 test 实例，2 次独立运行。它以 AgentGym + ReMe 为基础、用 BM25 取经验，实验允许成功和失败轨迹入库。§2.3 已用 correct→wrong 类诊断观察回归/负迁移。因此我们不能把“测原来对、复用后错”单独包装成首创；需要在查询变换上证明一种可部署选择机制确实改善收益—风险权衡。它是环境任务研究，不为 Hotpot 40/35/25 提供比例依据。

## 5. 哪些数据有何种 gold

Gold 通俗说是“评卷参考”，但未必全是逐条人工写的；有的是人工答案，有的是规则/知识库构造、执行测试或相关性标注。必须说明类型，不能把 LLM 自评分当人工 gold。

| 数据 | 原生参考标准 | 我们能评什么 | 不能直接推出什么 |
|---|---|---|---|
| HotpotQA | 答案、支持句（标题+句号位置）、问题类别；train/dev 公开 | Answer EM/F1、支持标题召回、支持句/联合指标；同题配对伤害 | 未标中的另一正确证据不能一概算错；正确答案可能来自模型记忆 |
| 2WikiMultiHopQA | 答案、支持句、关系 evidence、实体 ID/alias | 关系/桥接实体迁移与具体适用条件；答案与证据双评 | 不能把模板/实体相似当迁移成功；不同数据版本 alias 处理不同 |
| MuSiQue-Ans | 答案/别名、支持段落、2–4 跳分解 | 困难跨题迁移、哪一跳被补足 | 某些单跳 seed 来自 NQ/SQuAD 等，跨集合也可能有来源泄漏 |
| MuSiQue-Full | Ans + 给定上下文下不可回答实例 | 闭集上下文充分性与拒答 | 不能代表开放全库永远找不到答案 |
| NQ / NQ-Open | 完整版有长/短答案与页面；Open/DPR 版本字段更精简 | 简单题上的过度改写与性能退化 | NQ-Open 不自动有人工最小支持链；版本规模不能混写 |
| TriviaQA | 答案别名、收集/远程监督 evidence | 单跳与跨域答案评价 | evidence 不等于人工最小推理链 |
| BEIR / TREC DL / BRIGHT | qrels：查询—文档相关性（部分分级） | Recall/MRR/nDCG；改写检索收益 | qrels 不是生成答案 gold；未判文档不一定无关 |
| TREC-RAG | qrels 与答案 nuggets 等多层参考 | 检索、事实覆盖、QPP variant oracle | 56 个 topic 的 31 个 variant 不是 1,736 个独立问题 |
| ALFWorld/BabyAI/AppWorld/BFCL | 环境状态、可执行检查或任务成功标准 | Agent 行动/工具任务成功 | 成功信号不能自动定位为 query rewrite 的贡献 |
| HumanEval/MBPP/LiveCodeBench | 隐藏单元测试/执行结果 | 代码是否通过测试 | 模型自己生成的内部测试通过不等于最终正确 |

官方依据：[HotpotQA](https://hotpotqa.github.io/)、[2Wiki 数据格式](https://github.com/Alab-NII/2wikimultihop)、[MuSiQue 数据与反泄漏说明](https://github.com/StonyBrookNLP/musique)、[Natural Questions](https://github.com/google-research-datasets/natural-questions)、[TriviaQA](https://nlp.cs.washington.edu/triviaqa/)、[BEIR](https://github.com/beir-cellar/beir)、[TREC-RAG 2024](https://trec.nist.gov/data/rag2024.html)。

### Hotpot distractor / fullwiki 要明确区分

distractor 每题给 10 个候选段落，系统只需在局部候选里找证据；fullwiki 需要从指定 Wikipedia 语料中找证据。两者都值得实验，但难度和能支持的结论不同。[官方定义](https://hotpotqa.github.io/)

建议 distractor 只用于前期查指标、卡片结构与终止逻辑。论文主要检索迁移结果用 fullwiki，并明确语料快照、切块、索引和 BM25/dense 版本。不允许先看 gold 支持标题再给检索器提供候选；那是 gold-candidate 诊断，不是开放检索。

2Wiki / MuSiQue 的“开放检索”不能随口称 fullwiki。可以复用 [IRCoT](https://aclanthology.org/2023.acl-long.557/) 的协议，将所规定集合中提供的文本去重后建立共享检索库，或使用固定 Wikipedia；必须固定所用协议与文档清单。全库中存在测试题相关公开文档是正常 RAG，不等于标签泄漏。

### MuSiQue 的特殊防泄漏规则

官方仓库提供 `dev_test_singlehop_questions_v1.0.json` 等来源题排除说明；如果经验来源混用了它的单跳构造源，先排除这些来源题。语义改写、翻译、同一道组成单跳的另一形式也不能跨角色“伪装为新问题”。[官方说明](https://github.com/StonyBrookNLP/musique)

## 6. 我建议的最小可行协议

下面全是**我们的工程建议**，不是文献结论或用户已确认参数。

### 阶段 0：几十题确定东西算对了

使用合成样例与少量 Hotpot distractor 的 train 题，不看拟定的最终测试题：

- 验证 BASE、无记忆 FRESH、REUSE 能在相同底座运行；
- 验证答案与证据指标、计费、缓存、超时/空检索等异常；
- 必须能重现“BASE 对、REUSE 错”和“BASE 错、REUSE 对”两种样例；
- 暂不做强模型多后端、RL、复杂记忆三层全功能对比。

### 阶段 1：4,000 + 500 的 Hotpot pilot

从官方 train 先抽 4,000 个去重后的问题，而不是一开始把约 90K 全跑完。最终样本数在分组/去重后略有偏差可以接受，公开实际数量。

| 数据角色 | 建议数量 | 具体干什么 | 可否改变系统 |
|---|---:|---|---|
| Source / 建经验 | 1,600 | BASE 与无记忆 FRESH 成对跑；完成后用 gold 审计，从确有价值的成功轨迹生成候选卡 | 可建候选卡、改开发 prompt |
| Shadow / 独立迁移验证 | 1,400 | 在新题比较 BASE、REUSE、无记忆 FRESH；更新来源卡的迁移统计；将来训练小 gate 可用本段 | 可学习，但每次预测只能看此前统计；阶段结束冻结 |
| Calibration / 校准 | 1,000 | 在冻结卡库、固定特征/提示词上选择预先规定网格的复用门限、轮数等 | 仅按预登记规则选门限，不再改卡片内容/拟合新表征 |
| Pilot held-out | 官方 dev 抽 500 | 完全冻结后统一评估，一次查看整个预定实验表 | 不建卡、不晋升、不更新可信度、不调 prompt/阈值 |

这里的 1,600/1,400/1,000 正是 40/35/25，但只是便于开始的初值。建库产出不足可以在不打开 held-out 的前提下扩大 Source；不能看测试表现差再回头挑题/改比例。

500 题只能检验机制是否值得继续，不足以承诺极小伤害率。例如只复用 50 题且观测零伤害，也不能证明真实风险等于零。必须报告复用题数量、错误计数和区间，不只报百分比。

**冻结顺序**：先用 Source+Shadow 完成 prompt/卡生成/特征设计，随后冻结；再在 Calibration 选择预先规定的阈值；最后才打开 held-out。若读 Calibration 后大改模型或卡内容，它也变成开发数据，需另留新的校准数据。若要同时拟合概率校准器又选风险门限，需在 Calibration 内预先进一步拆分或设计交叉拟合，不能无条件复用相同标签自证可靠。

Source/Shadow 题的 gold 只能在轨迹完成后用于审计，不给部署形态的 query rewriter、applicability judge、QPP 模块读取。可以另设“给 gold 的 oracle”作为非部署上界，且必须单列。

### 阶段 2：扩大 Hotpot 与做 2Wiki 独立验证

只有 pilot 表明存在足够“可复用且有增益”的机会，才扩大来源题规模，画出经验量曲线，例如固定校准/评估条件下增加 400/800/1,600/... 来源题。这组取值同样是工程初值；一张卡的多条轨迹不能算多道独立问题。

2Wiki 建议明确区分两项实验：

1. **单数据集独立建库**：2Wiki train 内三角色，2Wiki dev held-out，沿用 Hotpot 已定的整体方案；允许预先声明的 2Wiki train 内校准。这检验同分布可重复性。
2. **严格跨数据集迁移**：只用 Hotpot 的卡和已冻结门限，直接测 2Wiki / MuSiQue-Ans；不读目标训练标签、不重新调 gate。这才叫 zero-shot transfer。若在目标 train 上适配，必须另列 adaptive/target-calibrated 结果。

至少预先保留两类测试切片：与来源实体/关系接近、与来源实体/关系较远。它们用于解释适用性，不可只挑优势切片当总成绩。

### 阶段 3：MuSiQue-Ans 与单跳过度改写测试

MuSiQue-Ans 作为更难的跨数据集检验：重点看长推理链上经验是否错误套用。再补一个 NQ-Open 或 TriviaQA 单跳集，观察“原本已能解决的问题”是否被额外改写伤害。单跳不是越多越好，选一套即可，不必第一篇同时铺十几个数据集。

MuSiQue-Full 另开**给定候选上下文**实验，只测充分性/拒答；若把它改成开放检索任务，要重新定义可回答标签，不能直接继承。

### 阶段 4：后续学习 gate、漂移和无 gold

- 小模型 gate：只用 Source/Shadow 产生的成对动作结果训练；保持 rewriter、retriever、generator 不变。先逻辑回归/树/小交叉编码器，不急于 RL。
- 无 gold 模拟：继续在有 gold 的保留集上评估，只是对系统隐藏它；让 QPP、reranker、支持性 judge 给代理反馈，执行后再揭 gold 检查代理是否漏掉伤害。RL 不能让不可靠 reward 自动变真。
- 在线流另设实验：每批预测完再允许延迟反馈更新，报告顺序、批大小、冷启动、初始库；与冻结库主表分开。
- EMA 只在允许更新的开发/在线流中使用；静态 held-out 中不更新。EMA 能让新近反馈权重变大，不是“经过衰减就有统计保证”。

## 7. 我们的核心评价不是“改写看起来像不像”

对相同原问题、相同 RAG 底座和相同预算，离线执行动作分支，得到答案/检索结果，再用 gold 形成配对标签：

| BASE 原路径 | REUSE 历史复用 | 含义 |
|---|---|---|
| 对 | 对 | 质量保持；是否省成本另算 |
| 错 | 对 | 获益 beneficial |
| 对 | 错 | 伤害 harmful |
| 错 | 错 | 都未解决，不能称有效经验 |

必须另外比较“REUSE 对 无记忆 FRESH”：否则 REUSE 胜 BASE 可能只是“多做一次改写/检索”，不说明历史经验有价值。对喜欢的方案B，固定相同 fresh-repair 框架、步骤预算与停止规则，只切换是否和怎样读取历史，最有助于隔离经验贡献。

建议主表同时列：

- Answer EM/F1（标准短答案提取，保留原答案别名规则）；
- Gold-document Recall@k，必要时支持句 F1 / Joint 指标；
- 获益率、伤害率和**复用覆盖率**；
- harm 的分母：全体问题、实际复用问题、BASE 正确问题分别标清，不混称同一指标；
- 检索次数、LLM tokens、延迟、费用；
- 多次运行时的方差与成对置信区间。

不用把所有指标压成一个黑盒总分。若需要 gate 标签，先预先定义“达标”规则；EM/F1 边缘题与支持链冲突题做盲审敏感性分析，不在看完某个方法结果后修改定义。

本轮新增的 correct→wrong 诊断近邻说明该指标不是首创。我们需要争取的贡献是“**在新 query 上，利用可迁移证据选择历史查询变换，稳定减少错误复用，同时保持有效覆盖与成本收益**”，是否成立由这些独立配对实验决定。

## 8. 防泄漏：什么必须禁止，什么可以做

必须禁止：

1. 同一道题及其改写、翻译、近重复、同源分解题跨 Source/Shadow/Calibration/held-out；
2. 测试题答案、gold 支持标题、gold 分解、测试轨迹进入 ExperienceCard 或模型 prompt；
3. 在静态测试时因答对/答错而升降卡片可信度；
4. 根据测试结果反复修改 prompt、动作预算、终止条件、检索器或门限；
5. 以“每题 30 variants”为由把同题变体分到不同角色；
6. 用题目自带 gold 候选池跑完，却宣称在全 Wikipedia 开放检索。

允许但必须记录：

- 公共检索库中出现测试问题需要的公开文档；RAG 本来就是要检索它们。
- 建索引时将官方协议允许的正文去重合并，但不把题—答案对应关系、gold 段落标识或题目本身写进索引字段。
- 同一 Wikipedia 文章跨不同问题出现，在标准官方 split 中不必全部删除；应量化这种重叠，并加严格迁移切片验证是否只是近邻记答案。

**不要盲目用巨大连通簇切分。** 将“共享任意一个实体/答案/文档”全部连边可能连成巨簇。更可行的安排：

- 主协议保留官方 split，先按原始 query ID/近重复/构造 seed lineage 分组；
- 对文档、实体、关系模板分别统计 overlap，不把所有关系取传递闭包后强制分组；
- 另设严格文档不重叠或实体不重叠测试子集，先定规则，再剔除边界题，报告保留数量与分布偏差；
- 文档级 DocumentSession 在 held-out 开始时清空，默认不让一个测试问题的推理/答案跨题影响另一个；公共文档的静态内容缓存可复用，但不要把测试产生的经验缓存冒充静态索引。

## 9. 动工前需要明确的少数决策

建议默认值如下，供主路线文档和用户讨论，不要求用户逐个手填几十个参数：

| 决策 | 建议默认 | 主要代价/替代方案 |
|---|---|---|
| 第一套主数据 | HotpotQA fullwiki；distractor 仅调试 | fullwiki 索引更重，但更能研究真正的检索修复 |
| 第一版训练 | 冻结 LLM；离线建经验+小规模校准 | 无训练便于因果归因；覆盖不足后再训小 gate |
| 主实验记忆更新 | 测试全程冻结 | 在线更贴部署，但顺序/延迟反馈更难公平比较，另设副实验 |
| 迁移标准 | 官方 split + 近重复/来源去泄漏 + 单独 strict-transfer 切片 | 全维度强制不重叠会损失大量题且改变分布 |
| gold 的用途 | 只离线评卷/造训练标签，部署门完全看不到 | 代理信号更现实，但仍须 gold 保留集审计其误判 |
| 查询变换收益比较 | BASE、无记忆 FRESH、REUSE 同题同预算 | 多跑分支增加离线成本，但才能回答“经验本身有没有价值” |

## 10. 可追溯性与本轮局限

每个实验产物需记录 dataset 名、版本/revision、许可证、原 split、实际 query-ID 清单及 checksum、去重/排除规则、语料/索引版本、prompt/gate/card 版本、随机种子、检索/生成预算。把这些写 manifest，不只在论文里写“遵循前人”。

本轮是 AI 辅助原文核验与工程建议，没有运行 benchmark，也没有人工复标。矩阵中的“部分待核”保留了具体缺口；尤其 MuGI 正文九项与表格八项的BEIR计数矛盾、Useful Memories 对 Mind2Web 的具体实验及若干代码划分，不能在正式方案中假装已核实。Think Then Rewrite 和 SegMem 的数据清单已在本轮末通过官方 PDF 补齐；Matches Made in Heaven 的三套规模通过作者官方资源补齐。Useful Memories v2 的 AppWorld 轨迹来源在附录 F.4 比正文概述更具体，以 F.4 为准；轨迹可先转为保留过程的摘要，不应泛称全部原封不动保存完整 CoT。会议/期刊层级与阅读顺序由同日文献审计文档统一处理；本文只为数据事实与协议负责。
