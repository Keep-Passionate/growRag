## 1. 结论：先保留官方划分，再把官方 train 拆成三种用途

**不把整套 HotpotQA 的 train/dev/test 混起来重新随机切。** 那样会破坏官方问题难度与评测身份，使我们与别人论文的比较失去基础。

当前决定：

1. 主数据是 HotpotQA，先做跨题查询经验，文档会话层不参与首版。
2. 第二数据是 2WikiMultiHopQA，用于验证关系链缺口与条件迁移。
3. MuSiQue-Ans 先作为冻结的跨数据集迁移评测，不先拿它调提示词；如果以后另做域内适配，使用独立实验名称。
4. QASPER 保留为文档层后续专项，不为了凑三层同时加入主实验。
5. 官方 train 内部按约 **80% / 10% / 10%** 分成经验来源池、选择器训练池、校准开发池。**这是 GrowRAG 的工程决策，不是某篇论文规定的标准比例。**
6. 当前小批量题仅从 train 内部的校准开发池取，不使用官方 dev 选模型、改提示词或筛选“好看的题”。

通俗地说：经验来源池是“做练习、记错题和成功操作”的材料；选择器训练池是“教系统何时拿哪张经验”的材料；校准开发池是“调规则和排错”的材料；官方 dev 是之后冻结方案再统一考试的公开卷。

## 2. 数据集结构、公开 gold 和优缺点

Gold 指评价所用的参考标准，不等于所有字段都是人工逐项写成，也不等于模型可以看到它。

| 数据集 | 官方规模与 gold | 一条数据的组织方式 | 我们能检验什么 | 主要限制与决定 |
|---|---|---|---|---|
| HotpotQA | 当前 v1.1 train 90,447；dev 7,405，均有答案与支持句。fullwiki test 7,405，不公开答案/支持事实 | 一道独立问题；`context=[标题,句子列表]`；支持事实是标题与从 0 开始的句号索引；bridge/comparison 两类 | 跨题修复经验；新增支持句与答案变化分别评价；答对变错风险 | 不是文档连续问答；旧基准有模型预训练污染可能。**首选起步** |
| 2WikiMultiHopQA | train 167,454；dev/test 各 12,576。train/dev 有答案、支持句、关系三元组；test 不公开这些标签 | 类似 Hotpot，额外 `evidences=[主体,关系,客体]`；comparison/inference/compositional/bridge-comparison | 关系链或桥接实体缺口、结构化经验条件；更直接检查“缺的哪条关系” | 模板化、维基与 Wikidata 对齐噪声；别名和分句版本需固定。**第二主数据** |
| MuSiQue-Ans | train 19,938；dev 2,417；test 2,459。train/dev 可用于答案/支持评价；官方隐藏标签格式用于盲测 | 2–4 跳；通常 20 个候选段落；`paragraphs`、答案/别名、支持段与问题分解 | 困难问题上跨数据集迁移，验证不是只适合 Hotpot 句式 | 不能把人工分解和中间答案交给运行中的改写器；与单跳来源数据存在污染风险。**先零适配评测** |
| QASPER v0.3 | train/dev/test 为 2,593 / 1,005 / 1,451 道问题；共 1,585 篇论文、5,049 题。官方包已含 test 与 evaluator | 一条顶层记录是一篇论文，含章节、段落和多道问题；答案可抽取、自由文本、yes/no、不可回答，且可有多参考 | 文档内导航、局部术语与别名、回答和段落证据评价 | 不保证每篇都有足够多重复知识；图表、长答案使首版适配复杂。**文档层专项后置** |

核验来源：Hotpot [官方格式](https://github.com/hotpotqa/hotpot#json-format)与[固定元数据版本](https://huggingface.co/datasets/hotpotqa/hotpot_qa/blob/cb440e4e72efe5808fe5df497ffa0b4e8da85c32/dataset_infos.json)；2Wiki [COLING 2020 论文表 1](https://aclanthology.org/2020.coling-main.580/)与[官方仓库更新/字段说明](https://github.com/Alab-NII/2wikimultihop)；MuSiQue [TACL 2022 论文表 2](https://aclanthology.org/2022.tacl-1.31/)与[官方标签转换器](https://github.com/StonyBrookNLP/musique/blob/main/raw_data_to_official_format.py)；QASPER [NAACL 2021 论文 §4.1](https://aclanthology.org/2021.naacl-main.365/)及[作者机构维护的数据加载定义](https://huggingface.co/datasets/allenai/qasper/blob/main/qasper.py)。

### 2.1 不混淆候选池与真正全库检索

- Hotpot distractor 每题给定 10 段候选；在其中用 BM25 选择，再让模型看少量结果，是**候选池内检索实验**。
- fullwiki 则要面对规定的维基语料。官方 fullwiki JSON 内附的十段是官方检索系统的返回值，不是完整语料，也不保证包含全部 gold 支持段。[官方明确说明](https://github.com/hotpotqa/hotpot#data-download-and-preprocessing)
- 合并少量开发题的候选段建立小索引，也只能叫“开发子语料检索”，不能叫 fullwiki。
- 首轮选择候选池，是为了检验运行和反馈；若论文最终主张开放检索改进，必须补真正固定语料的检索实验。
- 索引中有官方允许检索的文档是正常的；用测试答案/支持标注挑选或排序文档则是 gold 泄漏。预先规定的文本语料与答案标签必须区别处理。

### 2.2 哪些字段绝对不进入运行模型

| 数据 | 改写器/选择器/回答器不能接收的参考字段 |
|---|---|
| Hotpot | `answer`、`supporting_facts`；官方 `type/level` 只做离线分层分析，不给运行模型走捷径 |
| 2Wiki | `answer`、`supporting_facts`、`evidences`、`answer_id`、`evidences_id`、gold 段落对应 `entity_ids`；答案别名文件只供评测 |
| MuSiQue | `answer`、`answer_aliases`、`question_decomposition` 中的 gold 子问题/中间答案/支持索引、`is_supporting`、`answerable` |
| QASPER | 答案参考、`evidence` 与 `highlighted_evidence` 标注、gold 不可回答标签；提问者身份等与任务无关字段不进入提示词 |

问题本身当然必须进入选择器；这里禁止的是**目标题的 gold、同题历史执行答案，或者同题复制成的“经验”**。不能为了防泄漏误解成选择器连当前问题都不能看。

## 3. 官方 train 的 80 / 10 / 10 用途

| 内部分区 | 比例目标 | 可以做什么 | 不可以做什么 |
|---|---:|---|---|
| `memory_seed` | 约 80% | 运行来源题，离线用 gold 审核操作，构建候选经验；对建库成本单独计量 | 来源题运行过程预先看 gold；把正确答案直接塞进跨题检索指令 |
| `selector_train` | 约 10% | 固定来源经验库；对新题真实运行 BASE/FRESH/REUSE，产生“哪种动作更好”的监督标签；以后训练小选择器 | 将这些目标题的成功记录回灌来源库后，再评价它们自己的选择质量 |
| `calibration_dev` | 约 10% | 少量开发烟测、提示词调整、阈值/预算/轮数校准、错误分析 | 写入正式 serving 经验库；当成未见测试报告；依据其结果重新抽掉失败题 |

“serving 经验库”就是推理时实际拿来复用的那份库，不是所有日志。

比例理由：经验来源需要较大的多样性；选择器拟合和门限调节需要与来源独立的题。现阶段不训练 LLM，也不需要把 80% 的题全跑完。大池是**合法来源范围**，实际建库先用很小且固定的预算，后续按曲线扩充。

冻结要求：

1. 使用下文冻结的规范问题哈希算法分配角色，另记录稳定数据 ID 与数据集版本。哈希桶划分只保证近似比例，实际数量以 manifest 为准，不能伪造恰好 80/10/10。
2. 同一个问题的所有改写、配对分支、轮次、人工注释必须归到同一内部分区。
3. 重复 ID 或完全重复问题，先报错/归组；近重复问题另作审计，不能只检查 ID。
4. 保存选中 ID、原数据校验和、池名称、抽样种子和排除原因。不能只写“随机取几题”。
5. 小批量负结果也保留。没有足够通过审核的来源经验，就如实报告冷启动不足，不从校准/官方 dev 偷补成功题。
6. 当前实际 seed、抽样题数、成功建卡数应读取运行清单；本文不把尚未执行的规模写成已完成。

本轮冻结的角色算法是 `growrag-split-v1`，seed 为 `42`：问题先做 NFKC 规范化、casefold（大小写归一），再提取 Unicode 字母数字片段并用空格连接；计算字符串 `growrag-split-v1:42:` 加规范问题的 SHA-256，取前 16 个十六进制字符转整数，再对 10,000 取余。小于 8,000 分到 `memory_seed`；8,000 至 8,999 分到 `selector_train`；其余分到 `calibration_dev`。相同规范问题必在同一角色，不因下载顺序变化而跨角色移动；近义改写仍需另查近重复。

### 3.2 本轮真实开发子集的限制

本轮实现计划从官方组织 `hotpotqa/hotpot_qa` 的 train 起始 200 条记录中，按以上角色划分规则选取最多 **8 道来源题＋8 道校准目标题**。完整返回字段需校验，并记录数据版本、内容哈希、offset 与题目 ID。CMU 原下载地址不通时可使用该官方组织镜像，但不能静默换成别人清洗过且无版本的数据集。

这是**固定位置的便利开发样本**，不是在全部 90,447 题中做出的代表性随机抽样，也不是已经下载并物化了全量 train 分区。它只用于低成本接通与排错，不能由 8 道目标题推断总体增益。分区算法后续可直接应用完整 train，已下载题的角色保持不变。实际执行题数、成功经验数、失败数和费用以本轮运行清单为准，不由计划数代替。

### 3.1 积累经验不是训练大模型

阶段一：冻结模型和提示词版本，运行来源题，保存经核验的操作记录；**不更新任何模型参数**。

阶段二：来源库固定后，在 `selector_train` 生成配对标签，用小模型学习选择；这才是参数训练。其特征只能是做选择时可见的问题、证据、候选经验及其历史统计，不能用执行后才知道的答案分数当输入。

阶段三：在 `calibration_dev` 调门限，冻结配置后才使用官方 dev 公开评测。不能一边看官方 dev 分数一边反复调出最好配置，还称其为严格未见评测。

## 4. 各阶段的具体实验去向

| 阶段 | 数据与用途 | 冻结/训练状态 | 进入下一阶段的条件 |
|---|---|---|---|
| P0 工程烟测（当前） | Hotpot train 内校准池少量固定题；来源经验仅允许来自来源池 | 不训练；允许排错，但每次代码/提示词改动都留版本 | 真实请求、状态、检索、答案、gold 分离、成本和异常都能追溯 |
| P1 小规模可行性 | Hotpot 来源池小预算逐步建库，校准池固定更多题做 BASE/FRESH/REUSE | 不训练；分开看改写能否工作与经验是否增益 | 先排除工程错误；完整检查提升/退化/无差异，不以“必须正向”作为偷偷换样本理由 |
| P2 域内正式评测 | Hotpot 官方 dev；第二步 2Wiki 官方 dev | 各自只用其 train 建库/训练/校准；冻结库和选择器 | 固定同基座、同检索语料、同预算；报告全部预登记评测题或预登记子集 |
| P3 跨数据集迁移 | MuSiQue-Ans 官方 dev；可增加 Hotpot→2Wiki 对照 | 只用 Hotpot 经验/选择器；不使用目标 train/dev 调规则 | 与同一目标任务的 BASE/FRESH 比；报告跨数据集重叠审计 |
| P4 可选域内 MuSiQue | MuSiQue train 三分；官方 dev 评测 | 独立重建经验库并校准 | 标成域内适配，不与 P3 混算“零适配” |
| P5 文档记忆专项 | QASPER train 按 paper 分组开发；dev 校准；test 冻结评测 | 跨文档长期库只能源于 train；目标文档的局部记忆只含此前实际交互信息 | 必须先证实文档内有可复用知识，并对比无局部记忆、简单缓存等 |

Hotpot、2Wiki、MuSiQue 官方 dev 因公开 gold 可在本地评价，但**表格标题仍写 official dev，而不是假装 official test**。若后续参加官方隐藏测试，只在冻结方案后提交；服务器可用性与提交流程届时核查。QASPER 已有公开 test，仍需内部保持不可见评测边界。

另保留 MuSiQue-Full 作为后续停止/拒答专项。它为可回答问题构造缺失关键上下文的对应实例，数量是 Ans 的两倍；其“不可回答”是相对于给定上下文，不能解释成开放全库中永远找不到答案。[原论文构造步骤 S8](https://aclanthology.org/2022.tacl-1.31/)

## 5. 泄漏与“学会经验”要分清

### 5.1 Hotpot/2Wiki：共享百科文章不自动等于泄漏

开放域检索本来允许很多问题访问同一维基文章。不必把所有共享文档的题粗暴隔离，否则可能形成巨大连通组并改变任务。

但是必须分别统计：问题重复/近重复、来源与目标实体重叠、答案重叠、支持标题重叠。附加做“低实体重叠”或“未见支持标题”子组，可以检验模型学到的是操作还是旧事实。不得在运行中把历史答案当目标证据。

### 5.2 MuSiQue：官方已有专门的来源泄漏提醒

该数据由单跳问题组合而来。使用 NQ、SQuAD、T-REx、MLQA、Zero-shot RE 训练或建库时，要排除官方发布的 `dev_test_singlehop_questions_v1.0.json` 中 ID。否则即使多跳问题 ID 不同，也可能提前见过中间答案。Hotpot-only 也仍需做实体/文本交叠审计，不能宣称绝对无污染。[官方 usage caution](https://github.com/StonyBrookNLP/musique#data)

### 5.3 QASPER：必须按整篇论文分组

同一篇论文的题不得拆进训练和测试。目标文档内部可顺序积累实际发现的术语或位置，但不能读取未来题的答案。问题原始列表不是自然发生的时间流，需要预先固定问题顺序，并用多个顺序检查稳健性。局部累积条件和每题重置条件必须配对比较。

### 5.4 静态冻结和在线更新是两份协议

主实验首先冻结经验库，官方 dev 上不根据 gold 更新置信度、增删卡片或训练选择器。否则后面的题已经受测试反馈影响，不能继续叫冻结评测。

动态 reliability、EMA、晋升、合并和遗忘保留在下一步的在线协议：预测完成后才揭示反馈，并规定批次/分组隔离。RRM 的同视频整组预测后再更新是可借鉴原则，但它不是 Hotpot 官方静态 train/test 切法。[RRM 实验协议](https://arxiv.org/html/2607.28156v1)

## 6. 和其他方法公平比较：必须一起固定什么

- 同一套问题 ID 与检索候选/语料版本；同样的段落切分、去重和召回 top-k。
- 同一回答模型快照、上下文 token 上限和回答提示词。若某方法依赖专属训练模型，要另列“原生系统复现”，不能与统一基座实验混成一个结论。
- 同样的首次检索状态。BASE 使用已有证据；FRESH 不看历史自行改写；REUSE 在同一状态看历史再改写。单步比较先固定额外检索次数。
- 相似历史、随机历史、始终复用与选择性复用都来自同一来源池、同等经验预算。不要给我们的卡更多来源数据或更长提示词却不披露。
- 费用分开报来源建库、选择、改写、检索、回答；共享首次检索也必须在端到端成本中计算。无经验选中也是结果，不强行改写。
- API 异常、格式错误和拒答的分母与处理规则预先规定；没有响应不是正常的“答错内容”。不得静默丢掉坏样本。
- 小样本先报告逐题结果、胜/平/负和实际 token；正式比较再按题做配对置信区间。几个题的正向变化不能证明一般性效果。
- 以 Answer EM/F1 为主要任务指标；支持召回/支持 F1、FRESH→REUSE 的正确变错误数量、调用与 token 成本为关键补充。不同数据集证据单位不同，不能把句子与段落的 Recall 混称同一指标。

我们的自定义反馈负责诊断，不应替代数据集官方完整评价脚本。Hotpot joint 分数、2Wiki 关系/别名评价、QASPER 多参考评价均需按各自官方规则实现或调用再报告。

## 7. 文献依据与明确不是文献规定的内容

- **保留官方切分**：依据各数据集的公开协议；MuSiQue 特意控制组合源重叠，2Wiki 的 dev/test 被构造成更难的部分，合并随机重切会抹掉这种设计。
- **来源/目标分离、评测时冻结**：ERM 在不重叠的适配问题与剩余问题之间评价，并在每个划分重置记忆键；借鉴这个原则，不照搬其 BRIGHT 的 30%–80% 范围作为 Hotpot 的标准。[ERM §5.1](https://arxiv.org/html/2602.05152v1)
- **执行后生成选择标签**：Adaptive-RAG 从策略运行结果构造选择学习信号。我们的目标是“这条经验比 FRESH 是否值得”，不是照搬简单/复杂题标签。[Adaptive-RAG](https://aclanthology.org/2024.naacl-long.389/)
- **80/10/10、优先顺序和阶段预算**：是本项目为防泄漏、低成本起步所做的选择，不是最优性定理，也没有某篇参考论文替我们验证过。

## 8. 本轮落地与暂不做的事

本轮先落地 Hotpot 数据适配、可复现 train 内分区和小批量执行；正式 dev 跑分、2Wiki/MuSiQue/QASPER 适配、训练选择器都不是为了“齐全”而立即展开。

原始数据与真实调用日志不直接混入 Git 历史；代码、无密钥配置、分区算法、抽样 ID 清单、校验和、简洁汇总和协议文档应做版本控制。数据再分发遵循许可，不能因为本地能下载就把所有原文上传仓库。

**最终成功标准不是“能产生一个更高分”，而是：同一个明确协议下，经验选择在收益、误用和成本之间带来可以重复观察的改善。若没有改善，保留结果并先定位证据、改写、选择或回答哪一步失效，再决定是否继续扩大投入。**
