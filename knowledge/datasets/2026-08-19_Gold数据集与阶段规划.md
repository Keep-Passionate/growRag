更新日期：2026-08-19  
状态：当前数据路线；正式下载前还需固定具体版本与许可

## 先理解“有 gold”是什么意思

Gold 是数据集提供的人工参考标准，不等于“LLM 自己认为正确”。不同 gold 能回答不同问题。

| Gold 类型 | 通俗解释 | 能判断 | 不能单独判断 |
|---|---|---|---|
| Gold answer | 标准答案或答案别名 | 最终回答对不对 | 检索证据是否真正正确 |
| Supporting document/fact | 标准支持文档或句子 | 是否找全必要证据 | 其他未标注证据是否也正确 |
| Graded qrels | 人工给文档 0–3 等相关性 | 排序与召回质量 | 最终生成是否正确 |
| Gold nuggets | 长答案必须覆盖的原子事实 | 答案事实覆盖与完整性 | 通常规模较小 |
| Decomposition / evidence triples | 标准子问题、实体关系或推理链 | 查询分解和迁移类型 | 生成答案是否正确 |
| Environment success | Agent 是否完成任务 | 整体控制策略是否有效 | 错在检索、证据还是执行 |
| LLM judge / answer-string hit | 自动代理分数 | 无 gold 时的近似反馈 | 不能称 gold，可能系统性误判 |

GrowRAG 的核心标签不是数据集直接给出的单个字段，而是对同一道题运行两条路径后构造：

- `beneficial`：`DIRECT` 不达标，`REUSE` 达标；
- `harmful`：`DIRECT` 达标，`REUSE` 不达标；
- `neutral-good`：两者都达标；
- `hopeless`：两者都不达标。

Gold 只在执行后用于构造标签或评价。真正部署的选择器在行动前不能看到目标题 gold。

## 推荐数据集总表

| 数据集 | 主要规模 | 原生 gold | GrowRAG 用途 | 主要限制 |
|---|---:|---|---|---|
| TREC-RAG 2024 | QPP 论文使用 56 个主题、每题 30 个变体 + 原查询 | 人工 0–3 qrels、Vital/Okay nuggets、答案支持等级 | 多阶段 oracle 和指标管线的最佳小型起点 | 主题太少，不能训练可靠 gate |
| HotpotQA | train 90,447；dev 7,405；总量约 113K | 答案、支持标题、支持句、bridge/comparison 类型 | 第一主数据集；同时评价答案和证据 | distractor 只适合调试；正式结果用 fullwiki |
| 2WikiMultiHopQA | train 167,454；dev/test 各 12,576 | 答案、支持句、证据三元组、实体 ID、四种题型 | 第二主数据集；最适合测试“历史可靠但当前实体/关系不适用” | 模板化会让相似度虚高，需严格去泄漏 |
| MuSiQue | train 19,938；dev 2,417；约 25K | 答案、支持段落、2–4 跳分解、可/不可回答 | 困难、充分性和拒绝复用压力测试 | 需按官方列表排除 source-ID 泄漏 |
| BRIGHT | ERM 使用版本 1,322、11 领域 | gold 文档、相关性与推理线索；部分生成 GT | ERM 复现、跨领域推理检索 | 官方主要是 evaluation 数据，不训练 gate |
| BEIR: NFCorpus / SciDocs | 查询数约 323 / 1,000（版本需核对） | qrels；NFCorpus 有分级相关性 | 轻量 ERM 机制复现与跨检索器测试 | 只有检索 gold，没有 QA 支持链 |
| TREC DL 2019/2020/DL-HARD | 43 / 54 / 50 topics | 人工分级 qrels | ReFormeR 与 QueryGym 复现 | 只有检索 gold；pooling judgment 不完整 |
| Natural Questions | 约 307K train、7,830 dev | 页面、long/short answer、yes/no、无答案 | 大规模单跳对照；以后训练轻量 gate | 完整版大；NQ-Open 常缺证据 gold |
| TriviaQA | 约 95K QA、650K+ QA-evidence pairs | 答案别名、远程监督证据 | 大规模答案与 OOD 检验 | evidence 不是人工最小支持链 |
| TimeQA | test-hard 约 3,078 | 时间答案、段落、时间事实 | 历史经验的时间条件失配 | 静态阅读理解，不能等同真实在线漂移 |

## 推荐的分阶段路线

### 阶段 0：ERM 机制复现

依次使用：

1. NFCorpus；
2. SciDocs；
3. BRIGHT Psychology 或 Robotics；
4. 成功后扩到 ERM 使用的 11 个 BRIGHT 子集。

目标是回答“我们的复现和接口是否正确”，不是验证 GrowRAG 的核心创新。

固定输出 nDCG@1/@5/@10、MRR、Recall@k，以及每轮写入量、索引变化和负向 delta。

复现前要核对：

1. BRIGHT 当前页面与 ERM 使用版本的 query 数可能不同，必须保存 dataset revision；
2. ERM 表中的 SciDocs/NFCorpus corpus 大小与 BEIR 公共表可能不一致，需确认过滤规则；
3. ERM 正文、表注和图对 nDCG cutoff 的描述不完全一致，因此全部 cutoff 都输出。

### 阶段 1：把成对风险矩阵跑通

两个并行小实验：

1. TREC-RAG：优先利用公开的 31 个 query variants 和运行结果，校验 oracle、qrels、nugget 评价；
2. HotpotQA distractor 500–1,000 题：校验答案 EM/F1、支持标题召回、支持句 F1 和 harm/benefit 标签。

这一步用于查指标错误、估计 oracle 上界，不作为主论文最终证据。

### 阶段 2：论文核心实验

主数据集：

- HotpotQA fullwiki：经验来自 train，目标题来自 dev；
- 2WikiMultiHopQA：经验来自 train，目标题来自 dev。

至少报告两种协议：

1. **Standard**：官方 train → dev；
2. **Strict transfer**：历史与目标题之间去除或单独切片相同答案、实体、gold 标题、Wikidata ID、关系模板及高近似 query。

为什么两者组合：

- HotpotQA 更自然，支持句标注能同时测检索与答案；
- 2Wiki 的实体、关系和题型结构更清楚，最适合分析“问法相似但语义条件不同”的 harmful reuse。

核心指标是 answer EM/F1、gold document Recall@k、supporting sentence F1、benefit/harm/coverage、risk–coverage 和成本。

### 阶段 3：轻量 gate

只有前面证明存在迁移空间才做。不训练 retriever、rewriter 或 generator，只训练/校准小型 applicability/risk gate。

标签来自同题成对运行：beneficial、harmful、neutral、hopeless。

推理时 gate 只能看当前 query、历史经验与过去统计、环境版本，以及允许的 pre-retrieval QPP 特征。目标题 gold 在执行后才揭示。

### 阶段 4：困难、充分性与拒绝

依次使用 MuSiQue-Ans 和 MuSiQue-Full 的 unanswerable 问题，研究：

- 历史经验看起来相似但证据不足时，能否保持 DIRECT；
- 是否应转入检索后 FRESH_REPAIR；
- 何时应该拒答。

必须遵循 MuSiQue 官方单跳 source 泄漏排除列表。

### 阶段 5：外部有效性与漂移

- BRIGHT：跨领域推理检索；
- TREC DL + QueryGym：跨 BM25 / SPLADE / dense retriever；
- TimeQA-hard：时间条件失配；
- 人工构造 corpus/index version shift：验证硬失效与回滚。

这些是增强实验，不是 MVP。

### 阶段 6：无 gold 与 Agent 扩展

在 held-out 的 gold 数据上向控制器隐藏标签，只允许使用 reranker feedback、QPP、NLI/entailment、引用支持、答案置信度或用户反馈。执行完成后再揭示 gold，测 proxy 与真实 beneficial/harmful 标签的一致性。

强化学习不能凭空解决“奖励也不知道对不对”的问题。只有 proxy 跨域稳定，才考虑 contextual bandit 或完整 Agent 控制。

## 推荐的最小可发表组合

**最小版**

- TREC-RAG：oracle 和高质量多阶段 gold；
- HotpotQA：自然多跳与支持句；
- 2Wiki：结构化关系和当前适用性。

**增强版**

- MuSiQue：困难、分解与不可回答；
- BRIGHT/BEIR/TREC DL：ERM 复现与跨检索器；
- TimeQA：时间条件失配。

不建议项目一开始就使用完整 Natural Questions、RRM 多模态数据或重型 Agent 环境。

## 推荐论文的数据启示

| 论文 | 数据与反馈重点 | 我们借鉴什么 |
|---|---|---|
| ERM | BRIGHT + NFCorpus + SciDocs；qrels/生成 GT 或 judge | 机制复现，但不足以证明跨题安全复用 |
| QPP Variant Selection | TREC-RAG 人工 qrels + nuggets | oracle 与候选选择上限 |
| Query Rewriting in RAG | HotpotQA 等；answer gold 与 answer-string Hit | Hit 不能替代证据 gold |
| RaFe | NQ/TriviaQA/HotpotQA 等；reranker feedback | 无 gold proxy 基线，需验证是否识别 harm |
| ReflectiveRAG | WebQuestions、Hotpot distractor、私有 InternalQA | 检索后 FRESH 修复对照 |
| S2G-RAG | TriviaQA、HotpotQA、2Wiki | gold 只用于训练/审计、不泄漏给推理 gate |
| ReFormeR | TREC DL19/20/DL-HARD qrels | pattern 基线与检索级指标 |
| GAM-RAG | Hotpot、2Wiki、MuSiQue、TimeQA 等 | 同题型/不同语义切分与漂移 |

## 数据下载原则

- `data/raw` 保存原始版本，不手改；
- `data/processed` 记录转换脚本版本与 checksum；
- 每个实验记录 dataset revision、license、split、过滤规则；
- 测试集不参与经验建库、阈值、提示词或 pattern 选择；
- 大数据和索引不提交 Git。
