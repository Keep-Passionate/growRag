# 固定槽值查询消融：执行前协议

## Material Passport

- Origin Skill: academic-research-suite / experiment-agent
- Origin Mode: run + deterministic verification
- Verification Status: 执行前设计，尚未产生本实验结果。

## 科学问题

固定一次历史调用已经填出的槽值后，经验模板中的其他文本是否提供额外检索收益？

这是对研究问题“有用的是规则、条件，还是实体/其他槽值”的小型开发诊断，不是新独立测试，也不比较完整有记忆/无记忆系统。槽值可能已受卡片引导；没有声称无历史系统能免费得到它们。

## 样本和固定因素

- 纳入首修99题封存记录中**全部16个实际执行历史首修**的题，不按收益筛题。
- 只纳入本版可解释的一步无条件模板；若实际动作不满足本协议则整批拒绝，不悄悄删除难题。
- 保留原问题、共同初检、原槽值、精确文档版本、只读BM25索引、top6、累计去重/可见窗口。模型和prompt不变，因为此次根本不再调用模型。
- 原失败第100题标签不开；原100开发题不回写长期库、不训练路由。

## 四个视图

| 视图 | 查询内容 | 回答的问题 |
| --- | --- | --- |
| BASE | 原问题，只有共同初检 | 修复前有什么 |
| HISTORY_ACTUAL | 封存的首条真实历史query，必须由原模板/槽值按原执行器的format_map后strip精确重建 | 原动作实际做到什么 |
| SLOTS_ONLY | 按模板第一次出现顺序拼接其实际引用的槽值，不包含特殊`original_question` | 去掉原问与模板固定词后怎样 |
| QUERY_PLUS_SLOTS | 原问题＋同样的槽值 | 去掉模板固定词，保留原问目标后怎样 |

例：原动作`{person} nicknames aliases`且person=Gordie Howe，SLOTS_ONLY为`Gordie Howe`。槽值可能是实体、关系、属性或其他文本，**不把SLOTS_ONLY一概叫entity-only**。

不改拼出的词，不额外同义替换，不用gold挑槽值。槽名重复只拼一次；slot必须来自封存首个proposal并被首条模板引用，未使用字段不得混入。若仅有original_question、拼不出非空槽值，则拒绝此批合同，不伪造无动作。

执行前结构核查发现：16题中9题有可删除的固定动作词，4题是原问题＋槽，3题是整个query从槽直通（其中2条原规则动作先经过REWRITE）。结果按这三个结构组分别报告；不能把7个没有固定动作词的退化对照也当作“删除动作规则”的独立证据。

相同query应同序返回；在本BM25实现中，大小写归一化后的去重词集合相同也应同序返回。两个电影候选本来已在原问中，重复添加不改变词集合；两条query_text已含原问，再加原问也不改变词集合。这些作为确定性负对照如实保留。

## 执行与审计

1. 核验上轮99题重放封存及输入SHA，确认16题纳入名单和原动作。
2. 一次性构造并封存16题的全部query变体；之后才实际查询。基于旧开发轨迹的事后设计如实披露。
3. 每题实际执行原问和三种修复query，共计划64次CPU检索，哪怕query相同也照实重放。原问/真实历史两者返回有序ID及正文必须精确吻合原封存。
4. 先完成检索、封存新文档，之后只按这16个旧许可ID投影标注评分。新query阶段不接收gold。
5. 每种修复报告单独top6和C0并集两种证据覆盖，分别原文与可见句；记录新增段落数、query/有序ID是否相同。
6. 原始支持并集必须不降。零命中保留，不记模型失败。所有旧结果不改、新目录不覆盖，异常留失败记录。

## 如何解释结果

- HISTORY_ACTUAL优于两个控制：固定槽值下，原查询形式仍有机会；不是已经证明经验检索/选择有效。
- SLOTS_ONLY或QUERY_PLUS_SLOTS相同/更好：不能把全部收益归给模板固定词；仍可能是卡片帮助了实体选择或槽值绑定。
- 同一个query返回相同文档：是应有的确定性结果，不是多次独立成功，不给记忆额外加分。
- 指标仅覆盖标注证据；相同覆盖不等于证据内容完全相同。单独报告有序文档集合的一致性。
- 没有新的Reader、judge或答案，因此没有新EM/F1或最终可靠性结论。
- 16题经过旧系统执行选择，只描述这个子集，不估计全部HotpotQA上的模板价值。不得挑3正例报告其余略过。
