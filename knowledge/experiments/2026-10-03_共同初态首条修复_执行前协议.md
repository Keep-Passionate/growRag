# 共同初态、首条修复：执行前协议

Origin Skill: academic-research-suite / experiment-agent  
Origin Mode: run + deterministic validation  
Verification Status: 本文件先于本次重放结果建立；结果另行记录。

## 为什么先做这个

旧99题的完整流程显示FRESH答案较好，历史分支没有独有答案收益。但是这还不能说明历史查询都无效：分支可能没有执行、执行了不同轮数，或者获得证据却没有答对。

本次只问一个较小的问题：**从共同的初检证据出发，各自第一条实际修复查询，能补回多少标注证据？**

## 固定和改变什么

- 固定：已封存A0v2的99个共同完成开发题，原问题、共同初检结果、76,691段语料、原SQLite BM25索引、top-6、证据追加顺序、原确定性可见窗口。
- 比较：BASE初检；初检加FRESH原版首条实际修复；初检加历史分支首条实际修复。没有修复的分支保留初检，明确标记NO_ACTION，不伪造动作。
- 如果一个动作原来产生多个query，这次也只取第一条；因此是查询级诊断，不是完整宏动作复现。记录被省略的后续查询数。
- 不重新生成查询，不换prompt，不扩库，不改选择器，不调用Reader，不训练，不写持久经验。
- 查询来自过去封存的真实模型调用。这是事后开发诊断，不是独立盲测；没有宣称新模型推理已经发生。

## 数据边界与执行顺序

1. 核验旧反馈四文件封存、原冻结/终态锚点、99题ID和各原始报告SHA。
2. 只允许这99个已开放gold的ID；原失败第100题不得补读gold，整个旧100题继续禁止持久建库和路由训练。
3. 每题核验两分支初检query、排序doc ID和正文完全一致。首条修复必须是第一决策的实际查询，不能把第二轮新实体提前使用。
4. 在已有只读索引实际重放初检和两分支首条修复，逐一要求top-6排序ID及正文与原报告完全一致；索引不存在就拒绝，不重建。
5. 所有重放记录先封存。之后才按旧许可99个ID投影读取标注，计算证据指标。标注不传入查询或索引。
6. 每题结果、汇总、输入SHA和终态写入新的runs目录；任何失败不覆盖旧日志，不以自动重试掩盖差异。

## 指标：能回答什么，不能回答什么

| 指标 | 含义 | 边界 |
| --- | --- | --- |
| 首条修复的执行率 | 多少题实际发生一次追加检索 | 选中卡不等于执行 |
| 原文支持句覆盖率 | 标注支持句所在精确版本段落是否已在累计证据中 | 段落返回不等于模型理解了句子 |
| 可见支持句覆盖率 | 支持句是否完整落在确定性正文窗口内 | 窗口不是充分性判断器 |
| 新段落与重复比例 | 追加top-6中多少不在初检 | 更多段落不一定更有用 |
| HISTORY−FRESH的逐题覆盖差 | 正收益、负收益、平手分别有多少 | 不称新答案净收益 |
| 首条与原完整轨迹覆盖差 | 后续检索补了多少证据 | 不推算删轮后的答案成绩 |

累计原文覆盖在追加证据时不应下降；可见覆盖可能因为每段窗口分额缩小而下降，需要单独报告。只报告描述性结果，不做事后显著性筛选，不把人工诊断题当随机测试集。

**本次没有Reader调用，因此不产生新的答案EM/F1，也不能证明两轮系统已经超过三轮系统。** 本次新增API费用为0；真实CPU检索次数与耗时照实记录。

## 执行前的方向判断规则

- 如果历史首条查询在部分题上有独有证据收益，却没有原答案收益：先检查选择、动作目标和Reader利用，不立即训练大路由器。
- 如果历史基本不执行：优先查候选覆盖与选择遗漏，不把这些题全部归成有害复用。
- 如果修复只增加不相关段落：研究目标/角色适用条件，而不是仅奖励新增文档数量。
- 如果原文增加但可见支持下降：先查窗口挤占，不立即断言记忆语义错误。
- 本次发现的任何规律只作为下一批新题的假设；验证集和最终测试不按观察结果反复改分。

下一步仍是A路线：稳定两阶段条件观察器，满足原接口门后再做新自然题验证。此次重放不绕过接口门。
