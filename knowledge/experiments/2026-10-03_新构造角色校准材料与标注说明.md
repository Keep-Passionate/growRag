# 新构造角色校准材料与标注说明

> 这16条材料专门检查：观察器是否分得清“本次动作正在查哪个对象”，以及“问题最后需要哪种答案”。它不是HotpotQA，不是人工标注的自然题gold，也不是盲测。我们已经看过旧失败后才构造它，因此将来跑通只算开发校准，不能宣称泛化提升。

## 2. 四个判定保持原定义，没有换标准

- **T：类型是否有当前事实支持。** 例如当前槽要求电影，就查它是否为电影，不因为最终答案是导演便要求当前电影也是人。题干提到了“Kestrel-4”，只证明问题的目标名，不证明它事实上是行星。
- **R：这一轮查的关系、方向和条件是否对齐原目标。** 中间步骤可以合法，不必一跳给出最终答案。R不是“这条检索一定有收益”的标签；关系偏题也可能偶然找到有用文档。
- **P0：填入的值是否在当前Q/E可见范围出现。** 这是已有本地词边界匹配，不由模型覆盖。本套件16条的P0都为supported，因此本套件不评价P0的区分性能。
- **P1：填入值是否担任明确写出的当前对象角色。** “名字出现”“类型相同”都不等于角色正确；没有角色证据是unknown，显式否定或不兼容条件才是contradicted。

这里的 `target_role` 始终描述**当前动作对象**，不偷换成最终答案角色。例如：

| 原问题链 | 当前槽对象 | 最终答案 | 不允许的错误理解 |
| --- | --- | --- | --- |
| 饰演角色的电影→导演 | 电影 | 导演 | 因答案是导演而把电影槽按person检查 |
| 主相机→厂家→总部国家 | 相机 | 国家 | 要求相机同时是厂家或国家 |
| 出版物→2021年主编→出生城市 | 出版物 | 城市 | 要求出版物具有主编的人物类型或出生地 |

P1失败并不自动把R也改成失败。例如槽中电影不是目标电影，但“director”关系仍是原问题要查的关系；本套件将对象绑定错误记在P1，不重复制造一个R错误。

## 3. 16条名义判定总表

向量顺序固定为 **T / R / P0 / P1**，S=supported，U=unknown，C=contradicted。

主policy为原来的“仅有反证时拒绝”：

- 存在C：`reject`。
- 无C但存在U：`allow_uncertain`，不是已经证明可用。
- 全S：`allow`。

另一个原有严格policy会把U也拒绝，它只是离线重放对照，不改变主policy。

| 行号 | 向量 | 主policy | 最需要学会区分的事 |
| --- | --- | --- | --- |
| role-cal-01A | SSSS | allow | 动作对象是正确电影，而非最终导演 |
| role-cal-01B | SSSC | reject | 另一部也确为电影，但明确不是该演员饰演目标角色的电影 |
| role-cal-02A | SSSS | allow | 当前资料明确证明目标为行星 |
| role-cal-02B | USSS | allow_uncertain | 题干命名可支持身份，但不能补出未给定的行星分类 |
| role-cal-03A | SSSU | allow_uncertain | 在机构讲课不能证明创立机构；信息缺失不是否定 |
| role-cal-03B | SSSC | reject | 增加明确“没有创立”以后才有反证 |
| role-cal-04A | SSSS | allow | 带记录号的同名人物中，选中了译者 |
| role-cal-04B | SSSC | reject | 同名同为人也不能把封面设计者当译者；已有明确否定 |
| role-cal-05A | SSSS | allow | 查相机制造商是有当前证据桥接的中间步骤 |
| role-cal-05B | SCSS | reject | 转查二手价格偏离目标关系，不是相机绑定错误 |
| role-cal-06A | SSSS | allow | 导师→受指导者方向正确 |
| role-cal-06B | SSSC | reject | 有反向关系和原方向的明确否定，不能当无向关联 |
| role-cal-07A | SSSS | allow | 查出版物2021年主编是合法且保留年份的中间步骤 |
| role-cal-07B | SCSS | reject | 改成2023年查找违反原题时间约束，出版物身份仍对 |
| role-cal-08A | SSSS | allow | 类型及设计者角色有当前支持 |
| role-cal-08B | SSSU | allow_uncertain | 等优先级资料一支持一否定，不能只取其中一条 |

名义总量是7条allow、6条reject、3条allow_uncertain。**03A本来就不确定**，不能沿用“所有A必须全supported”的旧正例统计规则。

## 4. 每对标注依据与信息边界

### 第1对：电影对象不是导演答案

原问题问：Mira Sol饰演Captain Tern的电影由谁执导？

当前资料明确写出Signal Station和Harbor Signal都是电影；Mira Sol是在前者饰演该角色，且明确没有在后者饰演该角色。

- 01A填Signal Station，T由电影事实支持，P1由饰演关系支持。查director直接对齐目标，R为supported。
- 01B填Harbor Signal，T仍有电影事实，P0仍出现，R仍是director；但P1有明确角色否定，原reason为`target_role_negated`。
- 当前资料没有任何导演姓名。我们没有把隐藏导演答案放入输入，也不要求当前电影类型为person。

### 第2对：明确问题身份不等于事实类型

原问题问Kestrel-4的轨道周期，当前槽明确要求planet。

- 02A的资料直接说它是extrasolar planet，T reason为`expected_type_supported`。
- 02B仅说目录存在这个名字、未给分类，没有相反类型。T reason为`insufficient_type_evidence`，而不是类型冲突。
- 两条P1都由题干直接命名支持，reason为`question_target_supported`；P0也可来自Q。
- “orbital period”暗示天体，但不是planet类别的明确事实证明。本例故意要求把身份、语义关联与事实分类拆开，不能用常识猜测。

### 第3对：没有证明创立，不等于证明没有创立

原问题问Dr Alia Ren创立的研究机构位于哪个城市；当前候选是Meridian Lab。

- 03A只给出研究机构类型和Alia在此讲课。T为supported，P0出现，location city关系对齐；P1 reason为`missing_role_evidence`。
- 03B保留讲课记录，再明确增加“Dr Alia Ren did not found Meridian Lab”。P1才变为contradicted，reason为`target_role_negated`。
- 03A不是正角色样本，不应为了A/B平衡而强行标supported。这一对专门检查开放世界下的“缺证据”和“反证”区别。

### 第4对：同名、同类型，也可能是不同角色

原问题问Tide Ledger译者获得的奖项。两个当前记录都叫Leon Vale、都明确为person，但用L17和L44区分。

- 04A填`Leon Vale (record L17)`，资料明确该记录是译者。
- 04B填`Leon Vale (record L44)`，资料明确该记录做了封面设计，且明确没有翻译此书。P1 reason为`target_role_negated`。
- 不因为“做封面”本身推断“不可能翻译”；反证来自显式否定句。
- 槽值的记录号在原文中完整出现，P0不依赖模糊别名合并。两个记录都为person，T/P0无法代替P1角色判断。
- 这里测试带记录限定的同名消歧，不宣称已经解决自然语料任意同名实体识别。

### 第5对：相机→制造商是合法桥接

原问题要找到Crown Observatory主相机制造商的总部国家。当前资料确认主相机为digital camera Aster C2。

- 05A查`Aster C2 manufacturer`，不是最终国家，但它是目标链中必要的制造商桥接。R reason为`permitted_intermediate_subgoal`，引文必须同时来自Q、A1和当前E。
- 05B改查resale price，R reason为`relation_conflict`；相机类型和主相机角色没有变，T/P1仍supported。
- 当前资料未提供制造商或国家答案。合法桥接不是从历史记忆偷偷填出答案，也不要求已经知道制造商才能查制造商。
- R关系不对并不证明实际检索收益为零；自然题上仍应影子执行检查误拒造成的证据损失。

### 第6对：有方向的角色不能化成共现

原问题要找到被Dr Zola Kern指导者的就业办公室城市。当前槽是Nia Piers。

- 06A明确“Kern mentored Nia”，P1有方向支持。
- 06B明确“Nia mentored Kern”，并额外明确“Nia was not mentored by Kern”。P1 reason为`direction_conflict`。
- 不能只靠反向关系假设指导必定不可互相发生；本例显式否定原方向，避免引入隐藏排他性。
- employment office city仍是原问题的关系，R不因P1角色错而重复改为contradicted。

### 第7对：当前出版物角色与年份约束

原问题问Vesper News在2021年的主编出生城市。当前动作对象是出版物Vesper News，不是主编本人。

- T依据当前资料的news publication事实；P1由Q直接命名的出版物身份支持。
- 07A查editor-in-chief 2021，当前E证明出版物及该职位存在，R为`permitted_intermediate_subgoal`。
- 07B只把查询年份改成2023，R为`constraint_conflict`；仍不能把同一出版物的T/P1也改错。
- 当前资料未给任何年度主编或出生城市；我们检查的是第一跳查找约束，不是最终答案正确性。

### 第8对：支持与反证并存时保留不确定

原问题问Aurora Dome设计者的母语，当前槽Eren Dast。E1说它是human architect且设计了该建筑。

- 08A另一个资料只是建筑开工年份，不否定设计角色，P1为supported。
- 08B的E2明确说Eren没有设计该建筑，与保留的E1设计断言冲突。P1为unknown，reason为`conflicting_evidence`，必须引用两个不同当前段落。
- T的人物证据没有被否定，native language关系也没有变化。
- 不用先出现的E1获胜，不凭一支持一否定投票，也不擅自增加资料优先级。主policy为allow_uncertain，而不是确定放行或确定拒绝。

## 5. 为什么这不是“把旧32条换名字再跑”

我们没有替换旧套件，也不希望只测试几种词汇是否好理解。

本套件新增的控制重点是**动作对象—目标角色—最终答案三者的链式对齐**：

1. 一次动作可围绕film/camera/publication，即使最后答案分别是person/country/city。
2. 题干直接身份与T事实类别明确分离，不用查询语义暗示补全分类。
3. 同名记录在T/P0都正确时，仍可以P1错；需要记录限定和角色证据。
4. 方向与时间约束分别定位到P1和R，不把一个错误扩散为每个维度都失败。
5. 存在不确定的A例、存在不确定的B例，不人为制造“所有A都好、所有B都坏”的选择捷径。

不过这些仍是已知问题之后设计的短小开发材料。标签容易被作者与模型共同理解，不足以证明复杂真实段落、隐式关系或别名歧义上的可靠性。这个局限要随结果一起报告。

## 6. 本地核验究竟证明了什么

已经对16条逐一完成：

1. `prepare_payload` 验证原有八字段输入、槽覆盖、窗口长度、当前角色及required_checks。
2. 仅将独立保存的名义引文wire交给现有 `resolve_response`：核对引文唯一存在、Q/E/A来源权限、合法reason，以及中间步骤的当前E引用。
3. 把本地P0与名义T/R/P1组成ObservationReport，再运行两种已有 `decide`；得到expected的主/严格policy。
4. 验证16个完整输入哈希不同，8对结构完整，模型user消息仅为input。

核验结果是：**16条名义合同均可表达、引用结构合法、policy计算自洽。**

这不是“观察器答对16条”；核验中的T/R/P1来自作者标签，**没有调用语义模型**。程序也不能靠引文存在自动证明引文在语义上支持作者标签，仍需Root独立审阅。

## 7. 后续冻结与真正模型校准的顺序

1. Root审阅本说明、16个输入和标签理由；不满意时只能在任何真实运行前修订。
2. 提交新版材料与结构输出实现，冻结文件、prompt、模型、顺序、输入哈希和预算合同。
3. API只看input，运行结构输出定位/判断；原始HTTP、失败、token、费用、时间都保留。不得把annotation作为few-shot样例暗中送入此批次。
4. 完整预测封存后再读取expected，区分接口合法率与T/R/P1语义符合率；失败不能填成unknown挤入正确率。
5. 旧32条结构回归、新16条角色校准分开报告；不能混成一个“更多题准确率提高”的数字。
6. 校准稳定后，再安排新自然题的影子观察与检索收益检查。自然题效果才回答角色观察是否减少有害复用、同时保留有益间接查询。

若新版观察器依然常把当前对象当最终答案，先定位证据窗口、类型解释和角色说明的责任，不因短材料答错立即训练7B或改变检索底座。若标签引发合理歧义，应保留争议及旧结果，另开版本解决；不能调标签追逐模型输出。
