# 经验怎样记，才能帮助选到值得执行的改写？

日期：2026-09-11。状态：下一轮实施用的实验计划，不是实验结果。

## 0. 这轮确定什么，暂不做什么

沿用用户的方向编号：方向一是“选到值得执行的改写”，方向二是“记住哪些信息，才能判断当前是否适用”。表示研究服务于选择，不交换主辅。

用户明确认可先做“同来源、同候选、同选择器，只改变经验表示”的实验。建议下一轮先实施 **E1 选择端表示实验＋E3 相对 FRESH 的增益对照**，不同时扩建整个系统。本文的样本量、卡片上限等是建议默认值，并非用户已确认的最终论文协议。

本轮只读取本地代码、DG-RAG 记忆和论文，更新方案与 RDF；没有读取密钥、调用收费模型、生成新实验分数、训练、修改运行代码或推送 GitHub。

### 三种比较，避免继续混淆

| 编号 | 固定什么 | 改变什么 | 回答什么 | 顺序 |
|---|---|---|---|---|
| E1：选择端表示 | 来源、候选 ID、当前问题、选择器、每张卡的规范执行动作 | 选择器看到的经验表示 | 哪种记法帮助选对？ | 首轮 |
| E2：执行端表示 | 当前问题、选中的同一来源经验、执行模型与预算 | 执行器看到的经验表示 | 已经选对后，哪种记法更容易用好？ | 后置 |
| E3：经验增量归因 | 问题、起点、RAG 底座、执行预算 | 有历史经验 vs 无历史的 FRESH | 经验相对现场改写多带来多少收益？ | 首轮必须配套 |

所以：用户对第一类的理解正确；“固定表示再和 FRESH 比”也是必要实验，但它是 E3，不是原先 E2 的定义。我们不需要下一轮把三类全部做完。

这里的“同一个规范动作”是指：**同一候选 ID 在四个表示组中对应完全相同的动作**。不是让三个不同候选都执行一个动作，否则无法比较选择。

## 1. 第一轮只比较四种表示

沿用已有 M1–M6 编号，不再创造另一套编号。它们是“表示方案”，不是四个完整前人系统。

| 组 | 选择器看到什么 | 优点假设 | 可能的问题 | 借鉴对象 |
|---|---|---|---|---|
| M1 具体改写对 | 来源原问题 q 与实际执行的 q′ | 原始信息可追溯、不经过摘要漂移 | 容易只看实体相似；条件隐含 | ReFormeR 的查询改写来源、具体经验对照 |
| M2 简短自然语言经验 | 一段话说明过去怎样改、适合什么情况 | 简单、紧凑、便于 LLM 阅读 | 容易概括过宽；重要限制可能埋在文字里 | ExpeL 的 insight、ReMe 的经验提炼 |
| M3 参数化动作 | 操作步骤、实体/属性占位符、必须保留的部分 | 突出“要做什么”，弱化历史实体干扰 | 会执行不等于知道何时不要执行 | AWM 工作流、ReFormeR 改写模式 |
| M5 条件—动作—核查 | 适用线索、禁用/未知条件、动作、执行后检查项 | 使选择器更容易发现“不适用” | 更长；模型补出的条件可能错误；过严会误拒 | ReMe、RRM；QCR 是必须排重的强近邻 |

M2 可以在自然段中写条件，不能故意做成没有任何适用线索的弱对照。M5 的“禁用条件”可能只是待验证假设，**不能冒充已经观察到的失败反例**。

M4“当前状态—动作—预期变化”留给检索后实验；首轮纯检索前不能凭空知道当前缺失的证据。M6“短卡＋按需原始记录”留给读取成本实验。GAM 的主要记忆对象与自然语言卡不同，不把 M5 直接称为 GAM 复现；S2G 的 gap 是单题当前状态，不等于持久经验卡。

### 用已有真实来源解释四种写法

来源记录见 [09-06 实跑报告](2026-09-06_PRE真实建库与比较_结果.md)。真实来源改写为：

- q：Between two tennis players Kim Clijsters and Mary Pierce, who is older?
- q′：Kim Clijsters vs Mary Pierce age comparison

以下只是拟设计的表示示意，**尚未调用模型建出四张新卡**：

| 表示 | 示例正文 |
|---|---|
| M1 | 保存上面这对 q→q′，不存答案 |
| M2 | 比较两个对象的年龄时，可把提问压成两个实体名与比较属性，减少叙述词；保持比较对象及原问题的比较含义 |
| M3 | 抽取 A、B 和属性 P；生成以 A、B、P 为中心的检索表达；不替换实体，不提前给出比较答案 |
| M5 | 源观察：两个明确人物、年龄比较。候选动作：突出双方及年龄属性。未知：是否适合身高等其他属性。待验证禁用条件：关系交集、同一属性真假判断不应自动套年龄比较策略。核查：改写保留实体，取回证据是否覆盖双方 |

这个来源的免费检索诊断发现“仅保留两个人名”也取得同样的有序 top-4，说明成功不一定归功于 `vs` 或 `age comparison`。因此卡不能写成“加入 vs 必然有效”，也不能把一条年龄成功泛化成所有比较问题都可信。

“谁更老”和“两座城市是否都在中国”都可能属于官方 comparison，但需要的操作不同。这正是值得测的地方：**不是只识别大题型，而是在相近题型内辨别某个动作是否真的适用。**

## 2. 严格控制：四个选择器到底看到什么

```text
同一批来源记录（只允许来源原问题和真实改写）
                 │
       先冻结每个 ID 的规范动作
                 │
       独立生成 M1 / M2 / M3 / M5
                 │
新问题 → 共用候选召回 → 同样的 3 个候选 ID
                 │
       四组分别读取自己的表示
                 │
       同一选择器：选一个 ID 或 FRESH
                 │
       规范动作执行器 → 同一 RAG → 独立评价
```

1. 每种表示直接从同一份来源白名单记录生成，不走 M1→M2→M3→M5 的连续改写链。规范动作也先独立冻结，不根据 M5 或目标题结果重新设计。
2. 表示生成器使用同一模型版本和同等调用上限；可看到同一来源 q、真实 q′和预先冻结的规范动作，不看答案、gold、原始完整 CoT、目标题和目标题结果。M1 只投影具体 q/q′。建卡实际 token 和调用数单列，不能说四种建卡同价。
3. 四组共用候选召回。首轮建议仅根据来源原问题建立一个固定词面索引，取至多 3 张；不得分别用四组文本重建索引。若没有正匹配，记录为空并回 FRESH，不硬凑“适用”候选。
4. 每题候选顺序、ID 完全一致；公共外壳只给中性 ID、阶段等必要信息，不把完整条件、动作名称或置信度偷偷作为所有组的公共输入。
5. 选择器看到当前 q 和本组卡片视图；输出一个候选 ID 或 FRESH。不看当前题检索文档、官方 type/level、gold、未观察到的 gap 或其他组选择。
6. 执行器只收到当前 q 与该 ID 的规范动作，不收到选择理由、选择器看到的卡片正文或组名。同一 ID 的执行结果可跨组复用缓存。
7. 所有组 Reader 始终回答原问题 q0，而不是改写后可能改变含义的问题。
8. 建议每张卡正文上限 200 个被测模型 tokenizer 的 token，至多三张。记录实际长度，不填充短卡；超长表示不盲目截断关键条件。超限源记录如何处理，在目标题前统一冻结，所有组用同一来源子集。200 是开发默认值，不是最优长度结论。

### 这不是纯“排版格式”实验

同来源仍可能保留了不同信息。第一轮比较的是“选择哪些信息＋怎样表达”的整体方案。

若 M5 占优，下一步必须增加 **M5-同信息自然段**：保留完全相同的条件与动作，仅去掉字段形式。再分别删“未知范围”“必须保留项”等，才能判断收益来自信息内容还是结构格式。不能凭第一轮宣布 JSON 优于自然语言。

- 沿 [09-06 正式数据协议](../datasets/2026-09-06_正式数据协议与阶段划分.md) 的固定角色：规范化问题＋固定 SHA256 规则，80% memory_seed、10% selector_train、10% calibration_dev。不是重新划官方 test。
- selector_train 角色本轮保留不用；本轮不训练模型参数。建经验库不等于训练 LLM。
- 下轮需要扩展现有只含前 200 条的便利样本。本轮未下载扩展数据，未生成新名单，不宣称已完成随机抽样。

### 建议样本和冻结顺序

1. 在 memory_seed 角色中按固定种子、官方两类型分层抽取 **首批 64 道来源题**。先冻结完整扩容顺序；如不足，最多扩到 256 的计划须在收费前获批预算。
2. 沿现有来源录入条件：实际改了查询；FRESH 答案精确匹配；答案与支持句召回不退化，且至少一项相对 BASE 有增量。不为凑卡临时放宽标准。
3. 暂以“至少 6 张非重复候选、至少 2 种可观察的查询模式”作为工程可行性门槛。去重按规范动作及保留约束，模式按源问题的操作关系（如双方比较、关系定位）记录；同一动作换人名不算新增模式。分类与去重在查看目标结果前保存。此门槛不保证统计效力或迁移覆盖。
4. 如果达不到，停止表示排名，输出来源失败/同质化诊断；不能因测试结果差偷偷换库。
5. 从 calibration_dev 角色预先抽 **32 道新内部开发题：16 bridge＋16 comparison**。排除已暴露的 16 题与重复/近重复问题；旧题仅作回归检查。
6. 其中 8 题（每类 4 题）做流程调试。调试后冻结卡、prompt、候选规则和参数；剩余 24 题（每类 12 题）只做一次内部冻结检查。若据此改方法，下一次必须换新的检查批。
7. 来源与目标的实体/支持文档重合另作统计；随机按题分不等于跨文档泛化。不得依据 gold 迁移效果给目标补“正确卡”。

32 道类型均衡题用于诊断，不代表官方自然比例，不称论文正式测试集。后续扩大时按官方 dev 的自然分布独立评价；隐藏 test gold 不能本地拿来训练或筛卡。

### 检索设置

首轮沿现有句级 BM25：索引每题给定候选上下文的“标题＋句子”，取 top-4 句。BM25 是本地词面相关性检索，无额外 LLM 调用。

这是 **distractor 候选上下文内的句检索诊断**，不是 fullwiki 全库检索，也不能直接与不同底座的论文榜单总分比较。先定位是否有信号，再扩语料和检索器。

## 4. 不靠模型自称“选对”：离线把同题候选分别跑一遍

选择结果先落盘冻结，之后才读取答案和支持事实 gold。然后在离线实验中，对同一问题分别运行：

- BASE：原问题直接检索与回答。
- FRESH：不看历史，认真完成一次当前问题的语义改写，然后同一 RAG。
- REUSE(c1)、REUSE(c2)、REUSE(c3)：每个候选的规范动作各运行一次。

四种表示组的选择，随后映射到这张共同结果表。同题同动作不为四个组各自随机再生成一遍，从而尽量隔离执行波动。

这叫离线配对审计，不是部署时让系统先试所有方案再装作提前选对。**实际研究账单需要支付这些对照；上线策略的路径成本只是依据日志重建，不能称实测在线延迟。**

缓存身份至少绑定问题、可见状态、规范动作及版本、模型和 prompt 版本、检索索引/配置、预算及随机设置。同一经验 ID 出现在不同题上不能共用答案缓存。

### 教学示意：不是真实结果

假设某题 FRESH 的答案 F1=0，c1=0、c2=1、c3=0，则选 c2 比现场改写有额外收益。另一题若 FRESH=1，三张卡都≤1，拒绝经验可能正确；若 c1 和 c2 都为 1，不应硬指定唯一正确卡。

oracle 是这张**事后结果表中的最好值**：只表示当前候选池的可达上限，不是部署路由器。它不允许接触选择器输入。随机生成可能抬高最大值，后续独立重复才有更稳的上限估计。

### 必须分开两种判断

- 语义适用：这条操作的条件是否符合当前问题。
- 值得执行：实际执行后是否比同阶段 FRESH 更有用。

语义适用但与 FRESH 持平，不等于语义判断错；不适用却偶然答对，也不能直接变成长期可信经验。gold 答案、证据召回和人工诊断分别保留，不压成一个万能成功标签。

## 5. 指标与错误分析：不只给一张平均分表

主指标是全体问题的配对差：

`经验策略净增量 = mean(F1_所选路径 − F1_FRESH)`

无卡、拒绝经验统一执行 FRESH，因此这些题增量为零，同时仍计算选择成本。此为实验协议，不改变当前运行系统的 BASE 回退策略。若以后允许回 BASE，需要另加同回退策略的无记忆对照。

同时报告：

| 指标 | 为什么需要 |
|---|---|
| 答案 EM / F1 | EM 是规范化后完全匹配，F1 允许词级部分匹配；都非万能语义正确性 |
| FRESH 错→策略对的题数 | 经验实际救回多少题 |
| FRESH 对→策略错的题数 | 是否为了少量收益引入有害复用 |
| 相对 BASE 的同类统计 | 看整个流程表现，但不把 FRESH 收益记到经验头上 |
| 复用率、拒绝率、无候选率 | 防止“永不复用”的伪安全，以及区分召回和选择问题 |
| 候选池中存在正增益动作的题数 | 如果库中没有好动作，不能怪表示没帮助选对 |
| 有益候选被拒绝／有害候选被选中 | 检查安全条件是否过松或过严 |
| gold 支持句 Recall@4 及新增/丢失句 | 是否改变了证据覆盖；不等同于官方预测支持事实 F1 或答案蕴含 |
| 卡 token、建卡/选择/执行/回答开销 | 紧凑性与效果一起看；审计总成本和策略路径成本分列 |

F1 取值统一用 0–1 或统一转百分制，不能混写。API 失败独立计数，不静默删题；结果缺失时该候选增益及 oracle 标成未知。正式统计同时保留全题可用率，避免只报顺利完成题。

建议对所有选择不一致的题逐例展示：当前 q、三个 ID 及各组视图、选择、实际查询、检索证据、最终答案、gold 后评结果。再预先抽取一组选择一致题作对照，避免只展示赢家。

错误归因先分七类：来源本身不稳、摘要过度泛化、候选池覆盖不足、选择误用/误拒、实际改写漂移、检索失败、证据到答案的阅读失败。允许多标签，人工事后诊断不回灌当前冻结批。

统计单位是“题”，不是 32×4×3 个独立样本。首轮展示逐题配对差及不确定性，不依据几题领先宣布最佳、显著或可投稿。后续需新问题、更大样本、独立随机重复，置信区间按题重采样；方法挑选与确认使用不同批次。

## 6. 做完后如何决定方向，而不是预定 M5 获胜

| 观察 | 下一步 |
|---|---|
| 大多数题没有任何候选比 FRESH 好 | 先改来源/动作质量与候选覆盖；不是先训练选择器 |
| 池里有好动作，四种表示都经常选错 | 研究选择器、QPP 及可观察条件；先看具体误选原因 |
| M5 较好但又长又慢 | 等信息自然段＋删字段对照，找最小必要条件 |
| M1/短摘要同样好或更好 | 接受简单表示；不要为卡片复杂化找理由 |
| 只看题型的静态规则就同样好 | 加强近邻对照；记忆优势尚未成立 |
| 所有策略≈FRESH 或更差 | 不宣称正增益；分析差异能否在新批次复现，再决定换任务或止损 |

值得争取的结果不是“我们也有卡片”，而是：**哪些来源可观察条件能在相近问题之间减少错误套用，并且不把真正有益的经验都挡掉；这些信息值得付出多少存储和选择成本。** 目前是待检验问题，不是已经证明的新贡献。AWM、ReMe、QCR 都已有表示/经验相关对照，不能声称首次比较表示。

## 7. 下一轮最小编码边界

复用现有实验骨架，不从头重写 RAG，也不立刻移植全部前人框架。当前关键模块：

- `src/growrag/experiments/pre_pilot.py`：来源 BASE/FRESH、候选录入与当前弱匹配。
- `src/growrag/experiments/query_comparison.py`：同阶段 BASE/FRESH/REUSE 的单次查询对照。
- `src/growrag/experiments/lexical_retriever.py`：句级 BM25。
- `src/growrag/experience/query_views.py`：现有 CardMemoryView；不能为了消融放松生产视图合同。

建议只增加四个小职责，不新增六套卡架构：

```text
来源与规范动作（冻结）
  ├─ 表示投影：M1/M2/M3/M5，只供选择
  ├─ 共用候选池＋固定提示词选择器
  ├─ 规范动作离线执行缓存：BASE/FRESH/c1/c2/c3
  └─ 配对报告：选择、净收益、伤害、证据与成本
```

先用明确标为合成的离线用例测试：候选顺序一致、gold 不可见、选择理由不进入执行器、无卡回退、缓存身份、失败保留。合成/假模型只检验接线，不能算模型效果。之后才开真实 8 题调试；预算与具体模型快照在运行前核验并确认。

源建卡、四视图构造、四次选择、各候选改写和 RAG 都需要记账。首轮不训练 QPP 或 controller，不合并/衰减记忆，不增加 DocumentSession，不运行多轮 POST。QPP 后续要在同一候选池中检验是否补足表示选择，而非同时改变候选质量和排序器。

## 8. DG-RAG 和 HotpotQA 如何进入这个课题

详见 [DG-RAG 迁移启发与 HotpotQA 题型](../datasets/2026-09-11_DGRAG迁移启发与HotpotQA题型.md)。主实验不换成结构 QA；后续用结构问题检验“需要哪类证据/操作”与“底座是否提供该能力”的适用边界。

DG-RAG 通过实际文档解析/计数提供证据，不只是换 query。若增加 DG 工具，应对所有比较组提供相同工具；否则新增信息的收益不能算到记忆表示。
