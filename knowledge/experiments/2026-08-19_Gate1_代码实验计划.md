## Experiment Overview

- **Title**：历史查询变换复用的 full-information oracle 可行性
- **Objective**：测量历史查询变换在独立目标题上是否存在足够迁移空间，以及有害复用是否真实存在
- **Hypothesis H1**：至少一部分目标题存在历史 REUSE 明显优于 DIRECT 的候选
- **Hypothesis H2**：同时存在不可忽视的 `DIRECT good → REUSE bad`，因此 always-reuse 不安全
- **Type**：analysis

## Setup

- **Language/Framework**：Python 3.11，标准库 + GrowRAG
- **入口命令**：`python scripts/run_oracle_pilot.py --input <csv> --output <json>`

## Inputs

每行表示“某个目标题使用某条历史经验”的一次完整反事实执行：

| 字段 | 必需 | 含义 |
|---|---|---|
| `target_query_id` | 是 | 目标题编号 |
| `experience_id` | 是 | 历史经验编号 |
| `memory_snapshot_id` | 是 | 冻结的经验库快照编号 |
| `candidate_rank` | 是 | 该经验在固定 top-m 历史候选中的排名 |
| `direct_score` | 是 | 原查询结果 |
| `reuse_score` | 是 | 复用该经验后的结果 |
| `fresh_score` | 否 | 当前题现场生成新改写的结果 |
| `retrieval_query_count` | 是 | 各动作共同使用的查询数预算 |
| `requested_top_k` | 是 | 各动作共同使用的文档 top-k |
| `context_token_budget` | 是 | 各动作共同使用的上下文 token 预算 |

同一目标题的 `direct_score`、`fresh_score`、记忆快照和三项预算必须一致，否则输入无效。`candidate_rank` 是历史经验召回排名，与文档检索的 `requested_top_k` 是两个独立概念。

## Expected Outputs

| 输出 | 格式 | 成功标准 |
|---|---|---|
| 每题 oracle 上限 | JSON | 每个 target 有 DIRECT、候选集最佳 REUSE 和 policy 上限分数 |
| 聚合报告 | JSON | 包含 helpful coverage、pair harm、各 oracle 均值 |
| 示例结果 | JSON | 示例数据可重复运行、固定输出 |

## Primary Analysis

1. `helpful_coverage`：至少一条历史经验比 DIRECT 高出最小增益的目标题比例；
2. `pair_harm_rate`：所有 target–experience 对中，DIRECT 达标而 REUSE 不达标的比例；
3. `oracle_reuse_mean - direct_mean`；
4. `offline_policy_oracle_mean - direct_mean`；
5. full-memory 与固定 top-m candidate-set 的差距；
6. always-reuse / nearest-history / random-history 与 oracle 的差距。

## 预算公平

- 所有 query variant 使用相同 retriever；
- 固定查询数、每查询 top-k 和最终 context token；
- 若 REUSE 产生多个子查询，匹配总检索预算或单列成本；
- 生成模型、prompt 和随机种子保持一致；
- 不能把历史答案或历史 evidence pointer 注入当前上下文。

## 数据阶段

1. 合成示例：只验证分析器；
2. TREC-RAG 公开 variants：验证多阶段指标；
3. HotpotQA distractor 500–1,000：查错；
4. HotpotQA fullwiki + 2Wiki：正式迁移实验。

## 内部止损条件

以下是项目管理信号，不是学界通用阈值；正式阈值必须在看 test 前冻结：

- oracle helpful coverage 低于约 10%，且收益仅来自近重复题；
- oracle REUSE 不能优于 DIRECT；
- FRESH 明显更好且 REUSE 没有真实成本优势；
- 收益主要来自更多检索次数或更长 context；
- strict-transfer 切分后收益消失。

若触发止损，转成迁移边界/负结果论文，或切换到检索后修复路线。
