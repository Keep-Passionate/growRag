## 最需要知道的结论

**目前不能把“零复用”解释成门槛太严，更不能解释成经验必然无用。** 本次发现三个更具体的问题：

1. 当前召回器在全部8道开发题上，只把同一组3张卡送给选择器，另外3张从未出现；所有非零词重合居然都来自 `of` 或 `and`。这说明当前抽象短描述与原问题直接做词重合的召回很弱。
2. Sep23实际只有3次“带记忆的PRE路由”完成。模型都直接选BASE，没有一次先选REUSE再被程序硬约束挡回。因此，尚无日志证据证明硬门槛造成了本批零复用。
3. 六张卡全是PRE的单步同义/关键词改写，没有POST缺口动作。POST自动FRESH是阶段约束的正常结果，不是学习控制器判断历史全无用。

本次没有调用API、没有改选择器或卡片、没有触碰24道检查题的gold。八道题本来已在Sep20开发实验中公开使用，下面不是盲测结果。

## 1. 候选库到底有什么

为便于阅读，本笔记使用A—F简称，不改变真实ID。

| 简称 | 原始memory ID | 主要动作 |
|---|---|---|
| A | `pre-card-5a79b3fd554299148911fa3a@v1` | 电影时间比较：made→released、film→movie、first→earlier |
| B | `pre-card-5a88ad525542997e5c09a6a7@v1` | 多个实体的属性比较：保留实体和属性，压缩问句为关键词 |
| C | `pre-card-5a70f21b5542994082a3e416@v1` | 带军队/国家和日期的历史事件：压缩为实体、日期关键词 |
| D | `pre-card-5ae4cba75542990ba0bbb13b@v1` | 行政等级比较：改成same administrative level |
| E | `pre-card-5a885f3a554299206df2b245@v1` | 两实体共同时间参照：压缩关系和时间表达 |
| F | `pre-card-5ae28dd1554299495565dab5@v1` | 地理同国判断：删除部分地区限定，保留实体和关系 |

它们都是 `paraphrase / pre_retrieval`，生命周期仍是候选，不因已有一次来源成功而自动可信。B看起来比军队或电影模式更接近“两个航天员中谁有某属性”，只是**结构适配假设**，并非已经证明执行B有收益。

## 2. 八题确定性召回复算：语义没有进入排序

当前 `APIRoutingPolicy._recall` 对问题与卡片 `conditions.query_pattern` 做小写词集合Jaccard：交集词数÷并集词数；不去停用词；分数为0仍填满top3；同分按memory ID排序。

以下直接使用原八题的question文本和冻结库重算，不读取答案或评分。编号是原开发题编号，不是v2目录编号。显示四位小数。

| 原编号/问题摘要 | top3（分数） | 产生非零分的全部匹配词 |
|---|---|---|
| 000：1995冠军出生省份 | A(.0526)、C(.0000)、E(.0000) | A：`of` |
| 001：两部电影哪部更早 | A(.0625)、C(.0000)、E(.0000) | A：`of` |
| 002：Lincoln车型由谁销售 | C(.0556)、A(.0000)、E(.0000) | C：`and` |
| 003：两位航天员谁是法国空军准将 | C(.0000)、A(.0000)、E(.0000) | 无，六张卡全0分 |
| 004：Interstate 20经过Rockdale哪座城 | C(.0000)、A(.0000)、E(.0000) | 无，六张卡全0分 |
| 005：两名人物共同职业 | C(.0625)、A(.0000)、E(.0000) | C：`and` |
| 006：某书推荐者、癌症去世的作者 | A(.0417)、C(.0370)、E(.0000) | A：`of`；C：`and` |
| 007：两位导演是否都来自巴西 | C(.0500)、A(.0000)、E(.0000) | C：`and` |

**B、D、F从未进入top3；原003/004的排序完全由ID决定。** A在电影题排第一只是结果恰巧合理，不能据此说召回器理解了电影比较。反过来，也不能断言把B或F召回就一定提高分数；这需要动作执行对照。

只去停用词不是完整修复：当前非零分会全部归零，仍然面临短抽象描述与自然问题的词汇鸿沟。应把“候选覆盖”与“候选效用选择”分开测试。

## 3. 真实路由发生了什么，而不是什么

读原Sep23 v1及v2的 `ADAPTIVE_MEMORY2.route_records`：

| 原题 | 实际PRE带记忆路由 | 模型给的主要理由 | 程序硬门槛拒绝REUSE？ |
|---|---|---|---|
| 000 | BASE | 问题明确；候选分别要求电影比较、军队日期、共同时间关联，都不匹配 | 否，模型没有选REUSE |
| 001 | BASE | 两电影名及比较意图已明确，没看到需改写的优势 | 否，模型没有选REUSE |
| 002 | BASE | 车型及销售关系已明确，三个候选类型都不合适 | 否，模型没有选REUSE |
| 003 | 未执行到此模块 | BASE后的judge先失败 | 不是一次拒绝或选择样本 |

三次PRE响应的 `condition_checks=[]`，没有 `fallback_reason`。原000与001的POST记录均为本地规则 `no_eligible_post_memory → FRESH`。

这里可以怀疑“句子已经明确→BASE”的收益启发式过于简单，但不能从一个电影题就证明它误拒了**独有的历史收益**：Sep20该电影卡输出 `Which movie was released earlier: Portrait of Gina or Crazy Love?`，FRESH输出几乎相同；两者答案F1都为1，gold支持召回都为.5；RRR关键词改写同样答对、支持召回为1。它说明经验并没有展示FRESH做不到的机会。

## 4. 卡里的适用条件：有些可观察，有些需要先知道答案

以下是字段质量审查，不是篡改旧卡。新版本需另存、保留原来源，并重新评价。

| 卡/条件例子 | PRE能判断吗 | 问题与下一步 |
|---|---|---|
| A：问两个具体作品哪个发生更早；不比较质量或受欢迎度 | 通常可从问题意图判断 | 合理的结构条件。但made→released仍可能改变制作/发行的时间粒度，不能一律视为同义 |
| B：两实体、目标为明确事实属性 | 通常可见 | 可以成为选择特征；不直接保证检索改善 |
| B：禁用“实体不能由目标属性区分” | 经常不可见 | 可能要先知道两实体的属性值，即先知道答案；不宜让PRE必须证明它不存在 |
| B：禁用“需要复杂推理而非直接查询” | 部分可见、部分不可见 | 查询结构能暴露某些间接关系，但文档分布和所需证据通常要检索后才知道 |
| C：必须有军队/国家和明确时间 | 通常可见 | 条件对源题过窄，而动作只是通用关键词压缩；应检验领域限制是否真预测收益，不能直接删除后假设泛化 |
| D：两个地点/组织、行政级别比较 | 多数可见 | “不适用于事实查询，只适用于分类”边界含糊，因为分类也可属事实问答；应明确定义目标属性 |
| E：禁止“需要不同中间步骤的多跳推理” | 明显的桥接结构可见，但并不总可判定 | 与Hotpot桥接题的拓扑不合；放宽门槛不等于该关键词动作能解决多跳 |
| F：禁用“两个地点在不同国家” | 一般不可见，几乎就是本题待验证事实 | 会把同国判断中的否定答案排除。应记录为“不应提前假定共同国家”的不变量，而非需要事前证真的事实条件 |
| F：删除地区限定 | 是否属于问题约束可检查，是否多余常需背景 | 删除Shandong等地域限定可能改变问题，不应仅凭源题成功授权跨题删除 |

当前代码把 `_checks` 的query_pattern、preconditions以及“contraindication absent”全当成必须supported且critical的项。**这在设计上可能把不可观察条件变成永久拒绝；但本批日志尚未出现硬门槛触发，不能把设计风险写成已证实的实验原因。**

建议下一版区分三类字段，先只做标注、不改变路由：

- 硬约束：不泄漏历史答案、不改变关系方向/否定/时间要求、不使用PRE不存在的证据；满足不了就禁用。
- 可观察的适配特征：比较/桥接、显式实体数、待查属性、是否已有时间限定；用于预测收益，未知可显式保留。
- 只能事后获知的结果事实：两实体的真实国籍、是否有不同属性值、是否实际补齐证据；不许伪装成PRE已知输入。

## 5. 为什么可以把来源问题召回作为简单对照，但不是ReFormeR

Sep20的 `run_pre_opportunity.shortlist` 用原问题和**来源问题**做词重合，原003曾把B送入top3；带条件投影选择了B（该题c3）。Sep23改为短query_pattern后，B完全丢失。这个对照提示“具体问题例子”可能有助于候选覆盖，尚不能证明哪种召回总体更优。

来源问题也可能只匹配实体词，仍需与以下控制比较：

1. 全六卡枚举：库很小时直接消除top3召回瓶颈，专门测试机会是否存在。
2. 来源问题召回：便宜的检索对照，保留同题排除；不附历史答案。
3. 抽象描述召回：当前版本作为基线，显式报告0分占比与平局率。

**这三者都不是ReFormeR完整复现。** ReFormeR式POST参照需要首检索上下文选择模式，随后按规则/示例生成；我们的这个PRE候选召回诊断不能改名充当该方法。

## 6. 最有信息量的下一次机会实验：先不训练路由器

前提：当前judge输出/语义稳定性关卡尚未通过，应先修复并在独立合成题上验证；不因本笔记而绕过关卡或自动重跑旧API。

### 第一步：零API的覆盖及字段审计

固定旧六卡和原八题，输出完整8×6的召回/适用字段表。逐条标出：结构匹配、已观察冲突、PRE未知、需要POST证据。不能读取gold决定适用性。旧卡不改，审查结论作为单独注释。

这是为了判断“想选的动作根本不在候选集”还是“在候选集里却选不好”。人工结构适配不是效用标签；人工认为相似也可能没有增益。

### 第二步：固定动作来源的PRE机会矩阵

新协议冻结后，在全部原八道开发题上消除top3瓶颈：六张卡分别生成一个规范查询，另外用不看历史的FRESH生成等数量候选；BASE单独保留。明确不满足硬语义约束的动作标为禁用/负面对照，不能进入“可部署oracle”。这只是离线诊断，不是让在线系统强制复用。

执行器、BM25、Reader、输出上限全部相同。生成候选与RAG次数分别记账；同题、完全相同Reader/judge输入共享实际响应。保留重复率，不能把六个相同查询计为六种机会。FRESH的候选生成协议必须事先固定，不能看过历史结果后专挑弱prompt。

首先看三件事：

- 历史是否产生FRESH没有覆盖的**有效证据增量**？不只看是否碰巧答对。
- 历史最优候选相对等数量FRESH最优候选是否有剩余收益？这是离线机会界限，不是可上线选择器的成绩。
- 哪些差异只是语序/标点，哪些改变了实体覆盖、约束保存或证据集合？若多数动作与FRESH重合，就先改经验来源与动作，而不是优化路由拒绝率。

旧Sep20已经有一个警告：三候选的历史最优答案F1，没有一道超过当时的一候选FRESH（8题开发诊断，不代表普遍无效）。因此追加机会实验的目标不是“证明历史有效”，而是定位当前卡是否缺乏新的可执行信息。

### 第三步：只有确有机会，再测最少适用条件

固定第二步的候选及结果表，执行器看到相同规范动作，选择器分别看：

1. 规则＋来源query→rewrite示例；
2. 同样内容＋原始全条件；
3. 同样内容＋仅PRE可观察条件，事后条件标为不可观察而不冒充事实；
4. 等token的无关说明控制，排除“提示更长”解释。

记录漏选有益、误选有害、保持FRESH/BASE的比例，以及费用。若不存在可获益候选，不能用“选择器更会拒绝”冒充学会了选择有益经验；应停止扩大选择器训练。

本轮只定义这个最小计划，未启动额外实验，未创建新长期卡或放宽门槛。
