## 2. 编码原则：接通实验，而不是先扩展整套 Agent

保留已有不可变 episode、来源指针、追加事件与日志思想；不为了兼容旧 facade 强行改变研究对象。新的配对执行器与旧 demo 并存，旧字段使用显式适配，不将 direct_score 悄悄改成 fresh_score。

本文件中的类、路径、命令都是拟议内容，不表示已创建。当前没有可宣称可运行的真实 QA 入口；实施前先确认数据、模型与预算，再给实际命令。

## 3. 最小数据流

```text
开发数据角色清单              冻结来源经验库
      ↓                            ↓
原问题 → BASE 检索 → 决策状态快照 → 固定候选 ID
                         ↓             ↓
                    分支执行器 ← 经验读取视图
                         ↓
              FRESH 与各 REUSE 分支结果
                         ↓
             独立 gold 评价器 → 配对报告
```

这是离线配对实验：为了比较，允许执行所有指定分支。部署选择器只能先选一支再执行，不能读取上述所有结果后冒充在线路由。

### 输入/评价分离

- `RuntimeQuestion`：题目 ID、原问题、允许公开的文档信息；不含 gold 和目标结果。
- `GoldRecord`：答案、支持事实与评价规则；只能由独立 evaluator 读取。
- `SplitManifest`：source、shadow、calibration、heldout，附题目组/来源与去近重复规则。
- `DecisionState`：q0、已执行查询、当前证据 ID/文本哈希、已支持项、gap、剩余预算、RunContext ID、状态构建版本。
- 已支持项逐项记录 pre-repair evidence ID；经验前提注明来源当时已满足或事后提出待验证。状态生成不得读取 gold supporting facts，新获得证据不得回填旧状态。
- `BranchSpec`：action、source_experience_id、view_type、候选池版本、生成配置和独立随机流标识。
- `BranchResult`：实际 query、当前检索证据 ID、答案、错误/退出原因、实际花费；先冻结，之后再附外部评价。
- `BranchComparison`：两个结果 ID、共同前缀 ID、比较基线类型、得分差、伤害与实测成本。BASE 和 FRESH 分别作 reference，禁止混用分母。

决策状态中没有源题答案、目标 gold、候选实际得分或“哪支最优”。语料里自然包含答案不是泄漏；通过隐藏标签、测试答案文件或事后结果形成 prompt 才是需要阻断的通道。

## 4. 按四个可独立验收的增量实施

### P0：共同协议与三种读取视图

拟新增：

- `src/growrag/experiments/protocol.py`：数据角色、不可变决策快照、分支、预算与比较合同。
- `src/growrag/experience/views.py`：同一个来源 ID 渲染具体查询对、抽象卡、实例＋前提；另支持实体原样/角色化对照。
- `tests/test_branch_protocol.py`、`tests/test_memory_views.py`：用小型合成样例检查合同。

设计要求：

1. 来源记录只存一份；视图产物携带 source ID、renderer/prompt version、实际 token 数。
2. 具体 view 不含答案字段与评价文本；角色绑定只来自当前 q0/证据，不从源题复制姓名。
3. 抽象 view 的输入来源范围与其他 view 相同，不偷偷多读若干经历或目标 gold。
4. 现有卡片候选态与已验证态分开。影子实验可以评估来源正确但尚未多题验证的 candidate，不把它包装成已可信上线。
5. 先不启用 portfolio/EMA/自动合并，避免候选池边跑边变。

验收：同一来源可以生成三种可追溯视图；格式异常能解释地失败；旧存档不被覆盖；错误/未知 source 不被新建成默认可用经验。

### P1：真实单步配对执行器

拟新增：

- `src/growrag/adapters/`：Retriever、StateJudge、QueryRewriter、Reader 的小接口；具体实现放单独适配器。
- `src/growrag/experiments/paired_runner.py`：先执行一次 BASE 检索，固定状态，再分叉 FRESH/REUSE。
- `src/growrag/experiments/costs.py`：每次调用事件与预算核账。

两支都使用同一 q0、已有证据、gap、reader、rewriter、检索器与后续查询数量上限。区别只能是历史视图及被研究的选择策略。FRESH 不是“很弱的一行改写 prompt”，而是同样能使用结构化状态的无历史版本。

一个源步骤可能产生多个候选实验分支，但每个分支的额外 query 数均单独计算；decomposition 若发出两条 query 就计两次，而不是当一个 action 免费扩预算。首轮最好先只发一条下一跳 query。

初始实现可以使用 BM25 便于排错，不能把现有 Jaccard 改名冒充 BM25；选定真实 retriever 后固定索引版本。BM25 模型也不是唯一合理底座。先核验语料大小、机器资源与已有基线，再决定本地 BM25/向量实现；不在本轮下载全库或部署模型。

不要直接将简易 `rank-bm25` 全量载入视作 fullwiki 可行方案。小规模调试与大规模索引分别验证，必要时用成熟持久化索引适配器并核对版本/许可。

### 成本合同

- 分开记录最大预算和实际消耗；相同预算不是在所有方法上伪造相同实际次数。
- 实际记录：经验召回、选择器、改写、检索、reader、judge、重试、失败和回滚；区分输入/输出 token、调用次数、延迟。
- 同时报告记忆提炼/建库的一次性费用与每题在线费用；不用摊销数字掩盖建库成本，也不在没有使用量假设时宣称回本。
- BASE 可复用同一首检缓存，离线物理只执行一次；部署口径的每题成本仍要包含这次首检。共享前缀不能让某一方法看起来免费。
- 同预算多次 FRESH 作为额外强对照；离线 oracle 的全部候选费用单独报告。
- 同改写/检索机会和同总成本上限分别报告。总成本对照允许 FRESH 用节省的记忆/选择费用进行预先规定的额外生成或自检；没有实现这一对照时不写“同总计算预算更优”。
- 打平时使用实测成本，不沿用旧代码的动作名称成本顺序。

验收：同一状态分叉；所有结果只回答 q0；分支证据互不污染；失败也留完整计费记录；可以重放结果而无需再次调用模型。

### P2：配对报告与表示实验

拟扩展或新增：

- `evaluation/paired.py`：保留旧接口，通过新 BranchComparison 增加明确的 FRESH reference。
- `evaluation/oracle.py`：新报告支持 prefix/view/实际成本/重复试验；旧 CSV 格式不能伪装成执行审计。
- `experiments/reports.py`：按表示、问题类别与选中子集汇总。

建议产物（尚未生成）：

| 文件 | 内容 |
|---|---|
| `manifest.json` | 数据划分、全部版本、固定候选策略、预算、角色与随机设置 |
| `decision_states.jsonl` | gold-free 决策状态与前缀哈希 |
| `memory_views.jsonl` | 同源视图及内容哈希/长度 |
| `branch_results.jsonl` | 实际执行、证据、答案与成本 |
| `evaluation/labels.jsonl` | 只供评价/开发训练使用的 gold 与分支分数，不在在线加载目录 |
| `paired_report.md` | 质量、FRESH/BASE 破坏与修复、覆盖率、成本及局限 |

采用 JSONL 是一行一条记录，便于追加、断点与检查，不需要首轮上图数据库。

验收：报告清楚区分同来源自然长度对照、固定 token 上限对照与角色化消融；不能把候选行数当独立样本数；FRESH 分母为零时输出不可估计。

表示配对的实际 `source_step_id` 必须相同，不只是候选池一样。候选通过预定采样形成训练配对，不将一次 oracle 最大值直接当稳定标签；最佳经验标签需额外复核或小样本稳定性审计，包含平局/不确定。

### P3：选择器与组合实验

拟新增 `selection/repair_selector.py`，接口概念：

```text
choose(当前状态, 冻结候选视图, 允许的历史特征)
  → FRESH
  或 REUSE(经验 ID)
```

先实现随机、最近邻、条件匹配、冻结 prompt 四种策略；历史特征有足够独立 shadow 反馈才加入。q-only/q+gap/q+证据+gap 的可见信息必须由配置与输入构建器强制区分，不只在 prompt 写“不要看”。

把选择器与 QueryRewriter 分开。选择前没有生成的候选 query，就没有该 query 的 QPP；若以后比较“先生成两种 query 再选择”，它是另一个付费候选生成协议，应单列，不能混入轻量先选后写的主结果。

同日细化：在配对结果上先加入“FRESH/REUSE 候选均已生成→检索前 QPP 选一条”的简单对照，再比较经验条件及联合特征；记录两支生成费用，不先声称它是最佳线上协议。若要比较省掉新检索的能力，只能使用生成新 query 后、执行新检索前已经可得的特征。原 query 首检结果可以描述当前状态，但不是新 query 的检索后 QPP。QPP 值不是已校准的最终答案正确率。

小模型训练后置，不先装 RL/bandit 框架。影子开发数据可以生成监督标签，但训练特征中的历史统计必须用时间前缀/交叉拟合，排除样本自身及其近重复组的结果。heldout 从不生成训练标签、选阈值或改 prompt。

验收：线上只执行选中分支；关闭经验退回同版本 FRESH；与固定表示的便宜基线比较；再做小型 2×2/完整交叉实验。

## 5. 必须比现有测试更进一步的检查

1. **gold 隔离**：合成 canary 标签混入结果文件后不能出现在选择/改写/reader prompt；检查候选构建、渲染、缓存键与工具日志路径。不宣称只靠字段名测试就形式证明绝不泄漏。
2. **同一决策状态**：配对前缀 ID、证据哈希、gap、模型/索引/prompt/预算版本不匹配即拒绝；缺失字段不能默认当一致。
3. **随机性与分支隔离**：每支有独立可重放的随机流；换执行顺序不应改变缓存输入或让后一支看到前一支证据。共同实验种子和有意重复试验分别标识，不能把随机性最大值叫真实增益。
4. **预算真实执行**：超预算阻断；重试/回滚计费；失败标注，不能删除失败行美化均值。
5. **语义隔离**：题目 ID 不同但近重复、同源实体/答案泄漏仍可发生。实际 split manifest 校验；同一 episode 的多 turn 不算多次独立验证。
6. **来源一致**：三个视图指向相同源步骤；抽象 view 无额外来源；比较选择器时候选 ID 集合一致。
7. **读取视图边界**：源题人名不被默认绑定为新题实体；缺少必要证据时不猜；不因缺少非必要元数据而全拒绝。
8. **停止与 q0 不变**：首个实验最多一个后续查询；重复 query 和明显不可执行动作退出；错误路径不偷偷触发多轮补救。
9. **统计与成本**：分母零为不可估计；实际 token 而非硬编码动作优先级；拒答纳入覆盖率和主评价。
10. **测试期冻结**：输入 heldout 不能晋升、更新置信度、改候选池或渲染 prompt；训练期与在线期导入模块边界分开。

## 6. 最小规模、预算和停止开发的条件

按既有 HotpotQA 来源/影子/校准清单先抽少量开发样本测成本和排错，不挪用冻结的最终评价样本。正式样本数与是否部署本地模型，等实际每题费用和机器资源核对后决定。现在没有效应量或方差，不做假的 power calculation，也不承诺某个样本数一定够发表。

在 mock 测试通过前不调用真实模型。真实运行必须另行确认模型端点、数据范围和最大费用；超时与预算设置显式保存。运行异常不自行无限重试。

如果候选集 oracle 没空间：先检查候选覆盖、重复抽样和表示，不立即加 controller。若有空间但选择器找不到：优先改善可见状态信号，不能拿 oracle 成绩当部署结果。若效果仅来自实体泄漏、更多 token 或额外 FRESH 次数：不支持中心假设。

## 7. 用户审阅代码时只抓这六件事

- 它改的是下一条检索 query，还是偷偷改了最终回答目标？
- 三种经验内容来自同一份历史吗？哪些信息被删掉或新生成？
- 选择发生时，它看到了哪些信息？有没有未来结果/gold？
- FRESH 和 REUSE 出发证据相同吗？有没有某支免费多搜？
- 我能从一次错误追到源经验、渲染版本、实际 query 和检索文档吗？
- 所谓提升是否同时报告改坏的题、拒答和实际花费？

用户无需先审完所有 Python 语法。先审这些信息流和公平性，再逐模块看接口与测试。
