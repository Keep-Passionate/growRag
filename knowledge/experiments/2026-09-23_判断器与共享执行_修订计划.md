# 判断器稳定性与共享执行：明确修订后的开发实验

Origin Skill: experiment-agent

Version: stability-v1

## 本轮要解决什么

先解决两个已观察到的实验问题，再继续原开发题：

1. 判断器曾漏掉说明字段、输出非法 JSON，并可能把二选一过度拆成必须排除另一项。保留核心字段验证，启用 JSON 输出模式及已经写好的最小必要条件提示词。
2. 完全相同的 Reader 请求曾得到不同答案。配对分支应共享同一题内、完全相同输入的回答与证据判断，不能把采样波动算成经验增益。

这是执行协议修订，不是旧失败实验的自动重试。旧两批的失败、费用、报告与锁均保留；不能将修订后的结果与旧结果拼成同一个同协议均值。

## 固定流程

人工构造的证据判断小题 → 全部通过预先列出的基本判断检查 → 原 8 道开发题中闭环尚未开始的最后 4 题 → 逐题分析。

- 合成题只验证输出协议和少量基本语义，不是 HotpotQA 成绩，也不能证明 judge 普遍可靠。包含二选一、同时满足、比较缺值、冲突、缺信息不能答 No、文档注入等边界。
- 旧题是否执行过，按两个旧 run 的预先冻结顺序、逐题日志和完整费用账本交叉核查。已经开始但失败的题也排除，不按分数挑题。
- 这 4 题此前在 09-20 的 PRE 诊断中已经暴露，因此仍是开发题，绝不是新的盲测集。原 24 道检查题不使用。
- 六臂不变：BASE1、FRESH1、S2G_GAP2、REFLECTIVE2、ADAPTIVE_NO_MEMORY2、ADAPTIVE_MEMORY2；每条路径最多两轮，原 6 张 PRE 候选卡冻结。
- JSON / 最小必要条件提示、共享执行均在计划中声明。S2G 与 Reflective 仍是同底座方法适配，不冒充原论文完整复现。

## 共享的边界与费用

共享缓存只存在于本次实验的同一道问题中。原问题、提示词、模型设置、证据文本与顺序、当前回答、上一轮状态中真正传给判断器的信息都必须一致；语义相近不算同一输入。

仅复用经过解析验证的成功结果。错误不缓存、不重试；不跨题、不从旧失败 run 取响应，也不把不同模型版本混用。回放明确标为本地共享结果，新增 API / token 为零，并保留来源审计与原调用用量。判断器回放也恢复该分支的结构化缺口。

同时报告两本账：

- 实际采集账：真正发出了多少请求、多少 token、费用多少；共享不会重复收费。
- 单方法影子账：假如独立运行该方法，需要承担共享前缀和共享组件的原成本。不能因为某方法后运行、命中了另一个方法的缓存，就宣布它更便宜。

当前共享重点是 Reader 与 judge；改写器和路由器仍按各自真实输入调用。共享只控制本次配对的随机差异，不等于部署时模型确定，也不取代将来的预注册重复实验。

## 预算与停止

- 延续累计人民币 50 元授权；本轮子上限 1 元、最多 150 次 API、最长 30 分钟。
- 固定 `qwen3.7-flash-2026-07-15`，温度 0，关闭 thinking，JSON object 输出，1536 输出 token 上限；调用前冻结代码提交和提示词。
- 历史账必须包含 09-20 及 09-23 两个原始费用根账本，不能只承接最近的一条链。历史一笔未知费用继续保留预留。
- 首次协议 / API 错误立即停止；合成题语义检查不通过则不进入 Hotpot 闭环。不得自动换目录、调 prompt 后再跑同一批直到通过。

## 这轮能证明和不能证明什么

能检查修订后的执行链能否在小样本上完成、共享是否正确、有限 FRESH 如何补证据，以及当前路由是否真的调用历史。

不能证明记忆优于强 FRESH、不能证明条件字段有独立创新、不能训练出可靠 QPP。若仍没有 REUSE，不调低条件直到调用；下一步回到等候选数的机会对照：强 FRESH、静态规则、历史动作，先问有没有值得选择的机会，再问怎样选。
