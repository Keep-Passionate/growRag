## 1. 先学会一张实验设计卡

每次运行前回答六个问题：

1. 假设：哪一个机制可能有用？
2. 只改变什么：例如让选择器多看一组适用条件。
3. 什么固定：同题、同候选动作、同模型、同执行器、同轮数、同证据预算。
4. 看什么结果：F1、改对/改坏、选卡率、费用，而不只是均分。
5. 什么结果会反驳假设：条件多了只让系统拒绝一切、没有额外正确题。
6. 如果反驳，接下来改什么：查字段是否不可观察/太严格/冗余，而不是增大模型掩盖问题。

混杂变量指“同时改变，导致不知道是谁带来差异的东西”。例如M5两轮、M1一轮，不是只比较记法；给REUSE更多候选而FRESH只有一个弱prompt，也不能归因历史。

可模仿：
- [QCR §4–6](https://arxiv.org/html/2608.12847v1)：固定来源和被选轨迹再比较表示。我们把被操纵部分移到选择器输入，执行保持一样。
- [S2G §4.5.4 Table4](https://aclanthology.org/2026.acl-long.1185.pdf)：固定组件与预算比较压缩；§4.5.5再单独变轮数。不要一次变两个机制。
- [ReFormeR](https://arxiv.org/html/2604.01417v1)：先有明确模式与基线，再说明每个比较控制什么；其原论文是检索评测，我们的Hotpot答案评价是适配版。

## 3. E0具体工程任务（先纯离线）

### A. POST共享状态与有界累计Reader

优先复用outer_loop、PairedRunner现有组件，不另造整套agent框架。共同前缀记录原q、实际首query、首轮答案和证据、结构化状态、成本和指纹。

验收夹具：

- 首轮发现人物名、次轮找到属性；最终Reader同时看到保留的两轮真实证据且仍回答原q。
- 同ID同内容去重；同ID不同内容报冲突，不无声覆盖。
- 分支FRESH新增的证据不进入REUSE，反之亦然；禁止使用可变共享列表。
- 裁剪可复现；最终引用只来自Reader实际见过的证据，不是“曾经检索到但已裁掉”的证据。
- 已充分不二搜；query重复、预算不足、API错误停止；所有路径最多两次检索。
- 缺证据暴露能力与确实检索为空分开：None与空集合不是一回事。
- judge格式无效不伪装充分；请求消耗照记，不自动无限重试。
- 语义改写/扩写不要求编造一个缺实体；当前阶段只做已支持的单query动作，不增加分解成多query。

### B. 显式比较事件，保留旧schema

旧账本DIRECT-only；新实验事件最少包括：
question_id、reference_strategy、treatment_strategy、stage、max_retrieval_calls、shared_prefix_hash、model/prompt/reader_budget_ids、reference/treatment_run_refs、metrics、feedback_origin、costs。

它是配对审计，不是给生产卡自动晋升。REFERENCE=FRESH不允许写入旧direct_score。改名也不能假装兼容。

验收：更换gold不改变运行时选择或query；两个分支不同前缀/预算被报告不匹配；旧episode/卡样例仍可读取；PRE卡进入POST拒绝；源题改ID但同文本仍排除；没有结果的分支保持unknown/failed而不是记0分。

旧FrozenQueryEpisode不只要求BASE-first，还要求每次修复绑定非空、真实存在的prior gap。只有满足原状态机合同的POST轨迹才可导出v0；无明确gap的语义修复暂存新实验记录，不为兼容而伪造gap。通用PRE-first导出以后另做小版本，不在本阶段重写全部archive。

### C. 安全续跑与逐题过程报告

新入口必须先支持dry-run（不读key、不发请求）；实跑绑定已提交代码、数据hash、prompt hash、exact模型与预算配置。

原账本：runs/2026-09-14_fresh_baseline_32_v1/final_budget.json、cumulative_budget.json。
截至上一批累计保守预留0.3199766元，已知估算0.0411068元另有1次未知费用；不是完整账单。全阶段仍沿原5元总额，不能每个目录重开5元。

验收：
- 保留失败未知预留；已完成请求不重放；未知是否完成的请求不能假设可免费重试。
- 请求ID/配置键/输入指纹决定复用，不只按题号判断缓存。
- 不兼容旧prompt/model不得读取旧结果冒充新结果。
- 原成功日志只读，新执行事件追加到新运行目录并写清parent账本。
- mock测试覆盖请求前崩溃、返回后落盘前崩溃和已落盘后重启。
- 每个组件费用只计一次；同一个CallEvent的父聚合与子事件不能双计。
- 不允许凭估算费小就忽略保守上界；失败或模型漂移立即停止自动收费。

交接时明确哪些命令已存在，哪些runner仍待实现。不写一条不存在的“完整POST运行命令”诱导模型直接执行。

## 4. E1：prompt实验与POST FRESH，不混成一次变量

E1a沿09-16计划：
BASE / RRR_MINIMAL / RRR_KEYWORDS。每题1+2+2=最多5次API，32题最多160次。实际API数和真实费用照日志，不以次数乘固定单价冒充账单。旧已曝光11题仍属于开发。

主要只改变详细保留原意提醒。原q拼接RRR_QUERY_ANCHOR另做组合方式消融，不混称prompt效果。

E1b最小POST FRESH：
原q和首轮证据 → requirements/support/gaps → 生成一条针对问题的query → 第二次检索 → 累计证据回答。
使用同一开发池先少量调试，不读新独立目标。选定一版就冻结。充分性不应主要问“你有多自信”，而是要求按需求关联证据并标未知；人工抽查至少覆盖判充分、判不充分和冲突三类，有多少实际样本如实报告。

停止条件：充分；没有可合法生成的新query/重复query；预算；错误；已达2轮。第二轮检索后无新增支持时不再第三搜。只有当轮后才知道“没有新增证据”，不能把事后信号冒称免费事前预测。

本阶段不会证明经验有用，只证明无历史对照与状态接口值得信赖。充分性判断有误差，gold supporting facts只事后诊断，不能直接做线上oracle。

## 5. E2：共同第一轮上的经验增量

### 来源

从既有来源角色中另冻新POST source清单，先16题。执行相同首轮BASE和POST FRESH；成功来源只能成为POST候选。保留原问题、真实动作与证据增量；无查询变化只有答案波动不计改写成功。

首版POST候选录入建议沿旧PRE的严格数值条件：query确实改变，修复后EM=1，EM/F1/支持召回均不低于共同BASE，且至少一项严格改善；另需能查回原始执行记录，条件来自原q/观察证据而不是gold答案依赖。这是拟沿用的准入政策，不把POST记录伪装成PreSourceProvenance。若以后想允许支持退步或仍答错的候选，必须另立政策与实验，不能暗中放宽。来源成功不等于跨题可信。若重复/无效候选多，报告，不硬凑10种模式。

### 目标

新目标32题：8调试、24一次冻结检查；新manifest，按题型分层，排除来源、旧保留8/24、历史曝光与规范化重复；共享实体/文档另外审计，不能仅换ID冒称独立。

对每题：
共同BASE前缀 → 同一状态 → FRESH2 / 最多3条候选各自REUSE2。
第一轮答案就是BASE1参考，不再重跑一次。FRESH没有历史字段，REUSE仅多程序性经验。两者同模型、累计上下文预算、第二轮query数。

开发诊断可明确强制执行合法第二轮估计机会，包括judge决定早停的题；这些是离线反事实分支，不冒充实际早停策略。候选必须由事前规则召回，不看目标gold。正式上线模拟由冻结judge决定是否二搜。

用普通简单关键词改写不能冒称最强FRESH。先比较证据状态感知的FRESH，再谈历史增量。若强FRESH已足够，记忆不必总是提升，这是允许出现的结论。

## 6. E3：怎样只测“选择能力”

新POST试验三种选择视图：
- V0：规则＋来源例子，不提供额外条件段。
- V1：同样内容＋可观察适用/不适用条件。
- V1-text：与V1完全相同信息，写成自然段；测试信息与格式的区别。

它们不是将既有M1–M5重编号，而是新POST小实验的精简对照。若V1有信号，再逐项删除关系方向、时间约束、必须保留实体、条件依据/未知标记。一次只删一类，保留其它部分；所有试过的版本都记录。

各视图：
- 相同候选ID、排序、来源池、选择器模型和prompt；
- 选择器只选ID或不用历史，不把自己的解释交给改写器；
- 执行器始终拿同一个冻结规范动作。可为每题×动作缓存一次实际query/执行结果，避免为每种视图重复跑RAG；
- 选择必须在看不到这些结果和gold的隔离流程中完成；
- 缓存不免除生成规范动作的采集费用，部署估算只计该策略实际需要的路径；
- 若加入可靠性统计，各组保持完全相同；不能V1偷偷增加更强模型或额外独立数据。

短视图实验有两个不同问题：自然长度对应真实部署成本；同输入token预算对应等资源比较。首版报告真实token与截断，不能用无意义padding骗成同预算。

必要简单对照：永不复用→强FRESH、来源相似度、历史平均收益。后者只能用来源/训练期的独立迁移反馈，不能用待测题结果；数据不够就标未估计，不用来源成功伪造历史均值。

## 7. 结果如何读：正反两种结果都给出下一步

- V1比V0救回更多、损害更少或成本更低：值得研究哪些条件贡献最大；还不能说新领域范式。
- V1损害更少但几乎不复用：可能只是拒绝过度。报告误拒本来有益的候选；必须真的执行过才能标误拒。
- V1与V1-text近似：信息可能有价值，JSON字段格式不是主要贡献。
- 规范动作oracle也不优于FRESH：来源/动作没提供新机会，训练更强选择器难救。
- oracle有空间但选择器没收益：值得学习条件预测/校准，不先扩记忆量。
- 两轮多了证据却答案更差：查Reader干扰、意图漂移、引用/充分性，而不是直接称经验有害。

oracle仅指事后“这批已运行候选里最好能怎样”的上限，不是在线可免费使用的选择器。

## 8. 主指标、统计与扩大条件

主指标：全题策略F1−强FRESH F1；EM作为严格正确性辅助。
同时报告：
- FRESH错→策略对、FRESH对→策略错，BASE对应转移另列；
- 全题数、完整配对数、实际复用数；条件损害率分母说明；
- 不用历史率与拒答率分开；
- 证据支持召回和新增支持，允许存在替代正确证据；
- token、实际金额、失败未知金额、时间、实际检索/模型调用；
- 卡长度、选择开销、离线建库成本；
- 固定成本权重的统一效用，见另文；裸分不被替代。

API失败不是答错也不是无成本。报告缺失、保留不完整尝试；主要横向比较共同完成题，另做失败处理敏感性，不静默删失败题。

以问题为配对单位，后期用配对bootstrap区间等检查不确定性。多个动作/视图不算新增独立题。存在强文档关联时增加按组的压力分析。小样本不能靠p值或零损害宣称安全。

扩大须满足：
1. 接线、来源与预算审计通过；
2. 多道不同题上的机制有可解释记录，而非只展示一个漂亮案例；
3. 冻结检查方向与开发发现相容，并报告不确定性；若不相容，先查原因；
4. 根据观察到的配对差分方差、希望检出的最小收益和可用预算规划新增样本；
5. 新检查集不参与改prompt。扩大/停止都写原因，不不断加题直到显著。

最终基线：同模型强FRESH、ReFormeR式规则/示例、来源相似度/历史均值；RRM式OQR+经验作为后续近邻对照。原论文模型、检索集合、预算不相同时，叫适配对照，不能直接把论文表抄到我们的表。
