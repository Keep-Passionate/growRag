# 实验阶段与止损门

更新日期：2026-08-19  
原则：先证明现象，再做选择器；先测上界，再投入训练

## Gate 0：复现与协议校验

目标：

- 跑通原查询、多个 query variants、统一检索预算和指标；
- 复现 QPP-4-RAG / ReFormeR 中至少一个公开设置；
- 验证同一题的 `DIRECT` 与不同改写可被成对比较。

数据：TREC-RAG 56 topics 或小型公开 qrels 子集。  
用途：冒烟测试与复现，不用于训练可信门。

通过条件：

- query、文档、qrels、生成结果和成本日志可追踪；
- 改写不能靠增加查询数或上下文 token 偷预算；
- 随机种子和环境指纹可复现。

## Gate 1：Oracle 可行性

对每个目标题运行：

- `DIRECT`；
- top-m 历史经验各自的 `REUSE(e)`；
- `FRESH`；
- 必要时 ReFormeR / QPP 强基线。

计算：

- 有至少一条历史经验能改善当前题的比例；
- `DIRECT good → REUSE bad` 的伤害比例；
- full-memory oracle 与 candidate-set oracle；
- `FRESH` 相对 `DIRECT` 的可修复率；
- 经验召回瓶颈与路由瓶颈。

内部止损信号：

- oracle 只对近重复题有帮助；
- 可获益覆盖非常低（例如不足约 10%，阈值需在看测试前正式确定）；
- best reuse 仍明显不如 fresh，且没有实际成本优势；
- 改写收益主要来自额外检索/上下文预算。

若触发止损，不训练 gate；转为边界/负结果论文，或转检索后修复路线。

## Gate 2：最简单可部署门

先比较：

- always DIRECT；
- always REUSE；
- random history；
- nearest-neighbor history；
- historical reliability only；
- current applicability only；
- reliability + applicability 固定阈值；
- pre-retrieval QPP。

不使用大模型训练。若需要参数，只在 dev/calibration 集冻结阈值或逻辑回归。

通过条件：

- 相对 always-reuse 显著降低 harm；
- 相对 DIRECT 保留有意义的 benefit；
- 与 FRESH 相比有可验证的 token/延迟/调用成本优势；
- 在不同比例阈值下 risk–coverage 关系稳定。

## Gate 3：经验风险控制

目标：

- 对被接受复用的伤害概率做经验校准；
- 报告 coverage、selective risk、worst-group harm；
- 分别测 trust 和 fit 的校准误差；
- 做 entity conflict、template shift、retriever/corpus version shift。

第一版只承诺经验结果与置信区间。只有在数据假设满足时，才研究 conformal risk control。

## Gate 4：无 gold 条件

先在有 gold 的测试框架里“对控制器隐藏 gold”，仅提供：

- QPP；
- query/experience 兼容特征；
- 检索稳定性和证据 proxy；
- 多 verifier 一致性。

实验结束后才用隐藏 gold 评价真实 benefit/harm。只有 proxy 在多域稳定相关，才进入小规模真实反馈实验。

强化学习不在这一 Gate 自动启用；没有外部奖励时，RL 不能解决正确性问题。

## Gate 5：扩展路线

根据前四个 Gate 决定：

- 实现可回滚、条件化 ERM overlay；
- 加入检索后 `FRESH_REPAIR` 回退；
- 引入 EMA 适应漂移；
- 使用小监督路由器或 contextual bandit；
- 比较 query pair、pattern、压缩轨迹笔记三种经验表示。

## 必报指标

### 答案层

- Exact Match；
- token-level F1；
- 任务成功率或人工盲评。

### 证据/检索层

- Supporting Fact / Paragraph Recall@k；
- Recall@k；
- nDCG@k；
- MRR；
- 必要时 MAP。

### 安全复用层

- benefit rate；
- harm rate；
- reuse coverage；
- selective risk；
- risk–coverage curve；
- worst-group harm；
- oracle gap。

### 成本层

- 检索查询数；
- 每查询 top-k；
- 最终 context token；
- LLM 输入/输出 token；
- 调用次数；
- 延迟和估算成本。

## 公平比较与防泄漏

- support 建库、dev/calibration 调阈值、test 冻结；
- 近重复、同实体和同模板需要显式标记或隔离；
- test 不得用于初始建库、提示词选择和阈值调整；
- 所有动作使用相同候选集、检索器、生成器、上下文预算；
- 若多查询改写增加检索次数，必须匹配总检索预算或单列成本；
- full-memory oracle 和 candidate-set oracle 分开；
- oracle 只能用于诊断上界，不能作为可部署结果；
- 以问题为统计单位做 paired bootstrap / McNemar，并报告 95% CI。
