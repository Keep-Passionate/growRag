# A路线：先排查经验没用，还是有用但没选到

本轮由用户选择A：保留44张既有卡片及其动作正文，先修候选召回，不重建经验库，不开展路由训练。

## 这轮回答什么

历史没有超过现场修复，可能是库里没有适用动作，也可能动作没有进入选择器。先区分这两者，才有理由训练路由或扩大记忆库。本轮不预设记忆一定有价值。

旧25题只做无答案的排序诊断，不当作新测试。其历史与BASE的Reader输入全部相同，答案多对一题不能归因为经验。新实验因此同时保留原始答案成绩与“相同Reader输入使用同一答案”的分析成绩。

## 每步用途

1. 无gold检查44张卡的实际动作和候选排名：确认旧排序有没有被JSON字段名、通用描述和卡片长度干扰。
2. 五个合成场景真实调用模板填参：验证FILL-v2确实可执行，不冒充真实题选择器，也不计入准确率。
3. 锁定50道新HotpotQA train开发题：来自索引已覆盖的7,692题背景池，排除旧source/cal/eval及所有已声明题、同文本题。只读id/question，不按答案、难度或题型筛选。
4. 分5、20、25题执行五路，先完整封存所有预测和API轨迹，后读取答案评分；不根据前5题准确率决定扩大。
5. 对照证据收益、修复/损害、动作实际执行和费用，决定该研究候选检索/适用条件，还是库本身需要改进。

## 固定与改变

| 路径 | 候选来源 | 候选数 | 执行 |
| --- | --- | ---: | --- |
| BASE | 无 | 0 | 原问题检索一次 |
| FRESH | 无历史卡 | 0 | 当前证据上的v3即时规划，最多三次检索 |
| history_legacy3 | 原JSON-Jaccard词汇排序 | 3 | 原选择器及原卡 |
| history_body3 | 动作正文BM25词汇排序 | 3 | 同一选择器及原卡 |
| history_body8 | 同一动作正文BM25 | 8 | 同一选择器及原卡 |

共50×5=250条真实路径。全部共享同一76,691段语料、已有SQLite BM25索引、Reader、qwen3.7-flash-2026-07-15、温度0、2048输出上限。历史库冻结：10条参考规则+34条来源动作模板；published不是trusted，所有适用条件目前为空。

本轮FRESH是当前代码的v3即时动作规划器，不是原作者S2G完整复现；参考规则也不是ReFormeR完整训练选择器。

legacy→body改变了候选检索文本和词汇计分；不能把收益单独归给BM25公式，也不能叫语义检索或QPP。body3→body8测候选覆盖的增量，并记录增加的提示token成本。选择端展示仍是原卡“规则＋示例”，本轮不是经验表示消融。

## 评分预登记：防止生成波动冒充经验收益

每条路径实际独立调用Reader，原始响应、usage和花费一律保存。

主分析按每题固定顺序BASE→FRESH→legacy3→body3→body8分组：实际Reader messages的SHA完全相同时，只在评分分析中采用组内第一条真实Reader输出。不得修改任何预测，不声称线上做了缓存，不从成本中扣除已发生调用。另报原始EM/F1，展示波动。

同时记录：相对BASE/FRESH修复数和损害数、标注证据覆盖变化、Reader输入真正改变的题量、参考规则/学习模板的候选及选择及执行次数、检索轮次、全部API请求及输入输出token与估算费用。

还单列：①body3对legacy3、body8对body3的配对差，分别看召回正文与候选数量；②BASE/FRESH都错而历史答对的题，并核查实际学习模板检索及新增标注证据。历史只比FRESH好而不比BASE好，可能只是避免了FRESH伤害，不能叫经验创造了额外修复机会。答对且多了证据依然只是开发观察，不是因果证明。

可计算三个已执行历史策略结果的事后最好值作为诊断上界，但这不是遍历44动作的完整oracle，也不是可部署成绩。gold只用于封存后的评分，不进入选择、生成或记忆更新。

## 边界与停止

这50题来自官方train中索引已覆盖的背景子池，是新开发题而非正式测试；不能代表整个HotpotQA，也不能把文档在索引中出现称为监督泄漏。题目与答案不进入训练和持久记忆；官方测试集不动。

首5题只有在合成检查成功且方法源码/卡库不变时启动；后20/25题要求之前完整封存同一版本。任何传输/合同失败均停止、保留记录和费用，不自动修补重跑失败题，不事后替换“坏题”。若需要修方法，另开版本和新题，旧结果保留为工程失败。

本系列额外保守预留上限5元，沿用全部旧项目费用和未知用量预留，项目累计守卫200元。本轮核对北京<=32k输入官方价格：输入0.2/输出0.8元每百万token（估算而非账单）：[阿里云官方模型信息](https://help.aliyun.com/zh/model-studio/qwen3-7-flash)。本地CPU及现有API足够，不需要租GPU。

50题仅是描述性开发小试，不作显著性或论文最终优势声明。若没有学习模板增益，只能说这些候选策略未发现增益，不能证明整个44动作库没有任何机会。

## 后续研究分叉

- 有证据增益且超过FRESH：再固定候选动作，逐项删适用条件，研究“何时值得用”。
- 模板进入候选但被误选/误拒：分析具体状态和缺失条件，先修选择合同，不急着训练路由。
- 依旧没有额外证据：先做有限的单动作执行探针，或另建更有能力的库；动态新增算子后置。
- 模板合同失败：这是工程兼容问题，先修接口，在新题新版本检验，不算经验有效性的负例。

## 已完成的无标签准备

- 经验库实际是34个单步lookup模板，全部无requires_bindings；并不是已验证的多跳经验宏。跨题是否适用仍未知。
- 旧25题无gold排序审计：原top-3的75个位置中15个为学习模板；动作正文Jaccard为18个，动作正文BM25为68个。这只说明候选组成改变，不代表匹配正确或分数提升。
- 新50题从6,432个可用、未声明背景题中确定性抽取，旧source/cal/eval重合均为0；ID顺序hash为`1ccecfc8c08004a1e2ec580e1d9516dab1de71aec83504eb6a24720febe165b4`。
- 新bundle manifest外部hash为`e8aa9cb2fe6323a2823d9085acecb6b4b70418cf2a82075413f02e0621e3dbef`，运行端不能自行接受被替换的manifest及其旁边新hash。
- top-8候选选择请求不含证据时最大7,238字节，加上保守证据窗口预估24,238字节，低于30,000字节上限。实际运行仍逐请求检查，不截断卡片。

## 执行入口

默认均不发API，`--allow-network`才是真实调用。三个真实批次必须顺序执行，禁止失败后重复运行同一声明。

```powershell
.venv\Scripts\python.exe -m growrag.experiments.history_fill_probe --allow-network
.venv\Scripts\python.exe -m growrag.experiments.history_candidate_study --start 0 --count 5 --allow-network
.venv\Scripts\python.exe -m growrag.experiments.history_candidate_study --start 5 --count 20 --allow-network
.venv\Scripts\python.exe -m growrag.experiments.history_candidate_study --start 25 --count 25 --allow-network
.venv\Scripts\python.exe -m growrag.experiments.score_history_candidates --score
```

最后一个命令在250条正常预测、源码、原始HTTP、逐调用预算和查询合同离线回放全部验证后，才读取本批50题gold。合同回放只重放已保存的响应和检索记录，不重新调用模型，不算第二次实验。
