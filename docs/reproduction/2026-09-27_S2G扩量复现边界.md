更新：2026-09-27。用途：固定本轮实验的称谓、配置差异和成功标准。

## 一句话结论

## 哪些一致，哪些不同

| 维度 | 论文/作者实现 | 本轮 Qwen 迁移 |
| --- | --- | --- |
| 控制流程 | 判断充分性和 gap，检索，抽取证据，再判断 | 执行固定作者函数与提示词，不重写其方法语义 |
| 模型 | Llama-3-8B 回答/抽取，LoRA Llama-3.2-3B Judge | 三角色使用固定版本 Qwen API；不是作者训练后的 Judge |
| Judge 数据 | 2,804 个轮次状态，90/10 划分 | 本轮不训练、不写入长期记忆；状态数不等于问题数 |
| 问题集 | 论文写官方 dev；作者评分脚本取结果前 1,000 个唯一 ID，未见精确 ID 清单 | 已有 8 题是 train 调试；新增 train 子集仍属于开发验收，不能改称官方 dev 复现 |
| 语料/检索 | 作者使用 BEIR Hotpot 共享语料和 Pyserini/Lucene BM25 | 从每题候选池升级为共享小语料；仍不同于作者全库，SQLite BM25 也不冒充 Lucene 相同排序 |
| 检索预算 | 最多 4 次，每次 top-6 文档 | 对齐，并记录实际轮数、耗时和费用 |
| gap 数 | 论文默认 1；Hotpot 代码默认最多 3 | 显式 `paper_k1`，不能称完全原样 CLI 默认 |
| 去重/切句 | 论文说标题去重；代码为 doc-ID 去重；可使用 pysbd | 跟随代码 doc-ID 去重及作者切句回退分支，披露差异 |
| API 格式/容量 | 原本地生成和原解析行为 | strict schema、旁路格式校验；Judge/Extractor/Answer 上限为 768/128/256，单独记录作者请求上限 |

原始模型权重、准确评价 ID、完整语料、检索实现及生成设置没有全部对齐前，不承诺复现原论文分数。

## 实验顺序与判定

1. 先完成共享语料上的新开发题；冻结题目清单、语料、源码、模型版本和参数，不按结果重抽样。
2. 先比较同底座的 `BASE1` 与 `S2G4`。它同时改变轮次、查询和证据抽取，因此是系统对照，不是单因素消融。
3. 逐题保留 query、检索文档、保留证据、Judge 决策、停止原因和真实调用记录；只有两臂执行结束后才载入 gold 评分。
4. API、格式或评分协议错误不记成答错 0 分；首错停止，保留已消费费用和未完成状态，禁止自动重放。
5. 待工程验收通过，再确定独立官方 dev 子集评价。官方 dev/test 不用于调 prompt、训练选择器或积累经验卡。

**本轮成功标准不是“达到或超过论文数值”。** 成功首先是可重跑协议正确、逐步记录可核查、两臂公平、无 gold 泄漏、费用承接完整。效果方面诚实报告修复、损害、EM/F1、证据覆盖、实际成本与不确定性；负结果也保留。

## 哪些可继续，哪些才需要选择

- 可直接继续：已授权 Qwen 迁移扩量、纯离线测试、共享检索及预算内的冻结批次；目前无需为 API 推理租 GPU。
- 真正需要新决策：超过项目累计人民币 50 元、租用新服务器、重新生成监督数据并训练 Judge，或改变研究目标。
- 原权重暂缺只限制“严格原模型复现”，不是停止目前工作的理由。

## 后续研究边界

S2G 已比较 gap 表示/数量、抽取句数、检索宽度和 Judge 骨干。只修改这些参数不能自动算新贡献。我们的后续诊断应区分“没有检索到”“检索到了但没保留”“保留后仍误判”，再验证历史适用条件是否带来超出现场修复的净增益；尚未完成这些实验时，不宣称创新已获证明。
