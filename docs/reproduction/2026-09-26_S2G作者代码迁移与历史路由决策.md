## 2. S2G 究竟训练什么

它训练一个小“检查员”，输入：

`原问题 q + 到目前为止累计的原文证据 C`

输出：

`sufficient：是否够回答；gap_items：如果不够，缺哪个对象/属性/关系/证据片段。`

主方法把 **Llama-3.2-3B-Instruct** 用 LoRA 微调成这个检查员。LoRA 可以理解为训练一小组附加参数，而不是重新训练全部模型。它不是历史经验库；换一道题时，本题累计证据重新开始。

训练过程：用训练问题产生逐轮检索状态 → 强教师标注充分性与缺口 → 清洗 → 训练 Judge。论文附录报告 2,804 个状态快照、2,523 训练/281 验证，3 个 epoch。一个问题可产生多个快照，不等于 2,804 道独立题，也不是完整 HotpotQA 训练集都必须跑完。原文与详细配置见[§3.2、附录B](https://arxiv.org/html/2604.23783v1)。本轮沿用9月24日正式PDF训练审计，并复核当前代码；未实测训练费用。

[训练脚本](https://github.com/nianaaa/S2G-RAG/blob/5d842a67a0a99a7b545bbad0dc402ceaae0e5eff/training/train_s2g_judge_lora.py)按快照随机90/10划分；我们如果重训，必须按问题ID分组，同题的所有轮次放同侧。作者最终训练题ID尚不可获得，不能断言其训练/验证实际泄漏的数量。

三个部件应分清：

| 部件 | 职责 | 主实验的训练要求 |
|---|---|---|
| Judge | 判断够不够、输出缺口 | 3B LoRA |
| Extractor | 从检索文档挑原句 | 不为本方法重新训练 |
| Answer reasoner | 最后基于证据回答 | 不为本方法重新训练 |

特别注意：作者的下一轮查询构造不是再调用一次大模型自由改写。当前代码主要把原问题与缺口的 `target + slot` 拼接；二者不完整时才回退使用 `description`，没有有效缺口就保留原问题。因此未来历史模块可以只改变“缺口如何转成搜索表达”，先不动充分性判断器。这是候选插入点，不是已证明的创新。

### 为什么仅填 Qwen API 还跑不了原脚本

[load_reasoner_and_gate](https://github.com/nianaaa/S2G-RAG/blob/5d842a67a0a99a7b545bbad0dc402ceaae0e5eff/inference/inference_bm25.py#L860)无论是否使用 `--gpt`，都会要求 Judge 底模及 `SUFF_LORA_PATH`。GPT 开关只切换 Extractor/Answer，不切换 Judge。

还发现配置不一致：加载检查读取 CHATANYWHERE_API_KEY，实际调用读取 OPENAI_API_KEY；请求域名与模型名写死为 OpenAI/GPT-4o-mini。**不能把 Qwen 密钥复制进去期待自动兼容**。应改传输适配和配置校验，记录真实返回的模型版本，并禁用SDK隐式重试。

因此有三条清楚分开的路线：

1. **取得作者权重**：最接近原版，优先可行但目前缺文件。
2. **作者代码＋固定API Judge（建议先小测）**：保留原循环/原prompt/原query builder/原句提取流程，只换模型调用后端。命名为“作者代码 API 迁移版”，不能报作者原成绩。论文已有教师控制器变体，但全链Qwen不等于作者那个变体。
3. **自行重训3B Judge**：按作者流程、用允许的train题重新标注，属于重训练复现；先测再估GPU时，暂不为此租卡。

## 3. 数据隔离：作者叫 dev 的，也要当我们的保留评测集

作者[Hotpot预处理](https://github.com/nianaaa/S2G-RAG/blob/5d842a67a0a99a7b545bbad0dc402ceaae0e5eff/data/prepare_hotpotqa.py)将官方 train 前10,000题导为 train.csv，将 validation 导为 dev.csv。TriviaQA同样读取官方train/validation；2Wiki读取官方train.json/dev.json。

**文件叫 dev，不代表可以拿来调我们的记忆。**论文用于最终比较的数据，对我们就是保留评测数据。

| 数据集 | 功能开发、建卡、路由学习 | 保留评测，禁止写经验/调参 |
|---|---|---|
| HotpotQA | 只从官方train再按问题ID分组划分 | 全部官方validation及官方test |
| 2WikiMultiHopQA | 官方train中的互斥子集 | 官方dev/test |
| TriviaQA rc.wikipedia | 官方train中的互斥子集 | 官方validation/test |

执行规则：

- 第一次接口测试用8道train开发题；不能从论文测试题挑简单题。
- 训练侧再分 memory-build / router-fit / tuning-dev，三者问题ID不相交；同题的轮次、改写、卡片后代继承同一来源。
- 首次小测不建任何卡。S2G稳定后，再声明100–300道train建库与独立路由/开发题清单；具体数量由实测成本决定，不先跑全量。
- 每次调用前只给模型原问题和合法文档；gold答案、支持标注留给评分/允许的训练反馈，不能拼进推理提示。
- 正式评测时冻结权重、prompt、记忆、阈值、语料与预算；评测日志不能后来晋升为经验。
- 核对ID交集与规范化问题重复；另记录跨数据集重复、公开模式来源与基础模型预训练污染的未知部分。按ID隔离不能保证语义近重复全部消除。
- 开发时已查看的旧8题仍是开发；旧24检查题继续保护，不重新投影其gold。
- 已写 `check_memory_source` 的train白名单/保留ID拒绝检查并做合成测试。**它还不是所有旧写卡入口的全局防火墙**；新的作者代码建卡入口接通之前必须接入此检查，本轮无写卡。

注意：作者BM25用 BEIR Hotpot 全维基段落语料，不是每题10段小候选池。其资源加载中出现 `split="test"` 是 BEIR 加载器接口，随后只使用 corpus；不意味着可以用test问题/相关性标签训练记忆。知识库文档和带答案的评测问题要分开管理。

另一个评价陷阱：[原评价脚本](https://github.com/nianaaa/S2G-RAG/blob/5d842a67a0a99a7b545bbad0dc402ceaae0e5eff/evaluate_S2G-RAG.py#L29)截取预测中前1,000个唯一ID，推理默认 end_index=5000。最终比较必须明确实际题ID和分母，不能把不同截断的成绩混称全量结果。

## 4. “历史＋FRESH路由”有人做了吗

**宽泛方向做过；甚至“从相同状态比较调用/不调用经验的收益”也已有直接先例。**不能保证没有重复，更不能只给旧模块换名字。

| 工作 | 已覆盖我们哪部分 | 仍可与我们的具体问题区分之处 |
|---|---|---|
| [Adaptive-RAG，NAACL2024](https://aclanthology.org/2024.naacl-long.389/) | 根据问题选择不同检索复杂度 | 不是特定历史查询动作相对同预算S2G的增量选择 |
| [RRM](https://arxiv.org/html/2607.28156v1)，本轮仅确认预印本 | 本题query refinement与跨题检索经验互补；适用条件、失败模式、query-only复用、生命周期 | 视频/多模态设置；不能因此推断文字Hotpot的同样机制就自动新颖 |
| [Zhao等ExpWeaver](https://arxiv.org/html/2605.07164v1)，本轮仅确认预印本 | 保持原记忆构建不变，动态决定何时调用；包括Hotpot实验及移除/随机调用消融 | “记忆可选”“强模型少用”“只改路由”均不可独占；不要与Feng等latent-RAG同名论文混淆 |
| [ProactAgent / Ask Only When Needed](https://arxiv.org/html/2604.20572v1)，本轮仅确认预印本 | §3.3从同一prefix生成有/无经验检索分支，用效果与步数差作奖励，再训练策略 | 这是增量奖励非常近的先例；主要是交互环境与策略RL。我们的候选方向是不调骨干的查询动作选择，但还需实验证明它的价值 |
| [MemRL](https://arxiv.org/html/2601.03192v2)，发表状态本轮不升格 | 冻结LLM，按相似性召回＋经验效用重排，反馈更新Q值 | 效用更新本身不是我们的新意；其环境记忆不能自动变成Hotpot查询修复卡 |
| [AutoGuide，NeurIPS2024](https://proceedings.neurips.cc/paper_files/paper/2024/hash/d8efbb5dd415974eb095c3f06bff1f48-Abstract-Conference.html) | 从历史提炼条件化指导、根据当前上下文选择 | “经验卡写适用条件”早有顶会先例 |

这些工作之间主要是条件与任务差异，不是互相矛盾；没有做全面两两排重。此次检索针对仓库、arXiv、ACL/NeurIPS正式记录及作者项目页，不宣称系统综述。

建议暂把待验证问题收窄为：

> 冻结强FRESH与记忆来源后，只改变查询动作选择：当前可见的哪些条件，能预测一条历史动作相对现场动作的额外证据/答案收益？能否以少量额外开销减少有害复用？

“差值”是评价与学习信号，不是已成立的创新。需要过三关：有互补机会 → 能在执行前选中 → 优势不是更多候选、提示更长或多搜几轮造成。

## 5. 历史模块参考什么：代码、现成经验和权重不是一回事

### 首个可用的静态历史参照：ReFormeR模式库

[ReFormeR，ECIR2026短文](https://doi.org/10.1007/978-3-032-21300-6_30)有公开[10种模式的JSON](https://github.com/aminbigdeli/ReFormeR/blob/main/reformer/patterns/extracted_patterns.json)，含名称、描述、规则、示例。这是提炼后的文本资产，不是要部署的“记忆神经网络权重”。不需要先训练7B才能读取。

但不能无条件照搬：本轮发现其发布示例把原问题国家由 Ecuador 换为 Mexico，另有查询目标变化。这个观察说明成品文件需要核查，不足以推翻论文整体结果。保留原文件版本作为原样对照；如修正/过滤，另起 ours-audited 版本，不能悄悄改baseline。来源数据与我们的评测重合仍需审计。仓库未见LICENSE，不直接公开转存代码/整库。

它适合快速检验“静态改写规则有没有互补性”，**不能用它代替“GrowRAG从真实历史中学到了东西”的证据**。

### 动态记忆主参照：ReasoningBank；检索效用参考MemRL

- **[ReasoningBank，ICLR2026](https://research.google/blog/reasoningbank-enabling-agents-to-learn-from-experience/)**：顶会、[官方代码](https://github.com/google-research/reasoning-bank)、Apache-2.0；可参考提炼与调用流程。当前官方任务入口是WebArena/SWE-Bench，不是现成Hotpot修复经验库。移植后应叫ReasoningBank-style QA适配，不能冒称原论文QA复现。
- **[MemRL官方代码](https://github.com/MemTensor/MemRL)**：MIT，适合后续效用更新/重排对照。其现有环境为HLE、编程、具身、系统/数据库任务，不能假设下载后已有适合我们模型和语料的查询经验。
- **RRM**：最接近“经验只指导检索，历史答案不进入最终生成”的方法参照；本轮未核验到可直接运行的官方发布物，因此不选它作最快代码底座。
- **ERM**：修改索引key而不是我们当前的查询侧模块；适合门控思想参考，不适合作本轮低耦合插入点。

建议顺序：**S2G作者流程跑通 → 现成静态模式作低成本探针 → 用独立train问题生成小型真实历史库 → 再研究路由。**历史库不必微调一个LLM，但一定需要来源适配与独立性审计。用户要求先完成S2G，因此本轮不下载/运行完整记忆系统。

## 6. 最小插入位置，避免一次换掉半个系统

第一版保持同一个retriever、语料、Extractor、Judge、Answer不变：

```text
原问题＋本题证据
      ↓
作者 S2G Judge
      ├─充分/预算耗尽 → 原 Answer
      └─不充分 → 当前 gap
                    ↓
              可关闭的查询适配器
                    ├─FRESH：作者默认 gap → query
                    └─REUSE：历史规则＋当前实体/条件 → query
                              ↓
                       同一检索器/原句提取
                              └── 回到 Judge
```

这是查询动作层的适配，不是另做一个完整历史问答系统。历史只提供程序性规则，不拿旧答案当本题事实。

这版路由位于**Judge之后、下一次检索之前**。后续轮有证据，所以不是严格“首检之前零检索信息”的PRE方案。完全q-only的便宜前置路由单独作为下一阶段对照，不能混用两种信息权限。

第一版不要同时更改停机条件、证据压缩、Judge训练和历史结构，否则无法归因。

| 实验臂 | 含义 |
|---|---|
| F | 作者FRESH策略；不查历史 |
| H | 有匹配历史时固定走历史动作；无匹配回FRESH并单记回退率 |
| H+F routing | 根据当前条件二选一；选中后只执行一个动作 |
| Always-inject | 无条件注入历史的负面对照 |
| Offline oracle | 两种动作都实际测完后事后择优，仅作机会诊断上界，不部署 |

训练/诊断阶段可以付费执行两个分支得到配对差；线上不靠跑完所有分支再选来冒充低成本。F/H共享同一最大检索次数，同时完整计入历史查找、候选生成、路由判断开销。

## 7. 分阶段做，不一开始就训练路由器

1. **现在：代码/资源审计。**已完成固定快照、24文件语法和6项纯函数检查。不是完整推理成功。
2. **下一次：作者代码最小后端迁移。**待用户选择权重路线；不修改算法。先1–2个合成接口用例，再8道官方train开发题，冻结T=4、top_docs=6。仓库Hotpot默认gap最多3、论文附录K=1，两种配置独立命名，不能静默混用；建议论文profile作后续比较，另记录仓库默认检查。
3. **真实小测验收。**日志必须有每轮Judge输出、query、文档标题、被保留原句、停止原因、最终答案和API实际模型/token。先评格式/运行稳定，再评答案EM/F1与分层证据覆盖。极小样本不是有效性证明。
4. **独立开发配对。**FRESH稳定后，保留一批未参与改prompt的train开发题，加入小规模静态/历史动作；先问有没有超越强FRESH的机会，不先训练复杂router。
5. **有机会才学习。**冻结经验池，比较相似度、历史平均收益、当前条件预测；按问题/来源分组验证。没有互补时停止加复杂记忆，定位检索/提取瓶颈或收窄问题。
6. **最后正式评测。**全部配置冻结，官方validation只评一次预注册主比较；参数不因测试结果反复回调。报告救回、损害、复用率、EM/F1、证据覆盖、调用/延迟/费用。

预算：维持用户已授权项目累计50元；首个真实小测建议子上限5元、最多100请求，无自动重试。8题的作者T=4控制流通常上界为每题5次Judge＋4次Extractor＋1次Answer，再加BASE对照1次，共最多88次模型调用；上线前按真正执行分支重新验证。上下文过长时先估价并停，不悄悄裁剪基线。租GPU另行决定。
