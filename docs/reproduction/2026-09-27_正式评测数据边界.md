# 正式评测数据边界（2026-09-27）

## 最重要的结论

**当前500题来自官方 train，只能称训练集内开发诊断，不能称论文测试复现。** 下一步需要先选定检索与模型路线，再冻结官方 dev 的留出评价子集。把官方 dev 问题放进我们自建的小语料池，并不会自动变成原论文复现。

本次只读调查没有下载数据正文，没有读取官方 dev 答案，没有修改已冻结的32题或500题数据，也没有新增运行代码。

## 本地与来源核查

- 项目目录及默认 Hugging Face datasets 缓存中，没有发现官方 dev/fullwiki 数据文件。已有的是 train 原始镜像、历史开发池和两份自定义共享语料。
- [Hotpot 官方主页](https://hotpotqa.github.io/)提供 distractor dev（标注44MB）、fullwiki dev（45MB）和 fullwiki test。官方公开 test 不带答案与支持事实；公开 dev 可以本地评分，论文表格仍应写 **official dev**。[官方数据说明](https://github.com/hotpotqa/hotpot#data-download-and-preprocessing)
- 官方 JSON 地址为 `http://curtis.ml.cmu.edu/datasets/hotpot/hotpot_dev_distractor_v1.json`。本机本次 HTTP/HTTPS HEAD 均超时：这是当前网络核查结果，不等于资源永久失效。
- 可用镜像：[HF validation 分片清单](https://huggingface.co/api/datasets/hotpotqa/hotpot_qa/parquet/distractor/validation)本机返回200，仅读取98字节元数据；其中 `validation/0.parquet` 的 HEAD 返回200，长度 **27,452,575字节**，没有下载文件正文。若后续使用，需保存 URL、分片 SHA、转换程序及格式信息，不能宣称与 CMU JSON 字节一致。
- S2G 作者快照的 `data/prepare_hotpotqa.py` 确实加载 `hotpotqa/hotpot_qa` 的 `distractor/validation`；但其 `bm25_search/fullwiki_resources.py` 检索底座使用 **BEIR HotpotQA 全语料**，而不是每题10段或我们的72,713段。BEIR 官方表列出约 **5.23M文档、7,405个评价查询**。BEIR 的 split 命名不等于 Hotpot 官方隐藏 test。[BEIR 官方数据表](https://github.com/beir-cellar/beir#-available-datasets)

## 两条需要用户选择的路线

| 路线 | 需要对齐什么 | 可以怎样表述 | 主要代价与边界 |
|---|---|---|---|
| 正式复现优先 | 作者 BEIR/Pyserini 检索配置、模型与训练 Judge、数据/提示词/迭代预算和评测流程 | 核实各组件对齐以后，才能称相应程度的 S2G 复现；差异逐项披露 | 全语料索引、模型/检查点与训练资源需要单独准备；当前尚未完成 |
| Qwen 迁移诊断优先 | 同一共享语料、Qwen版本、同预算的 BASE/FRESH/S2G适配对照 | Qwen条件下的受控迁移诊断，用来定位改进机会 | 可以较快开展，但不能直接把分数与原论文表格比较；正式结论仍需独立留出评价 |

当前500题和72,713段的配对实验属于第二条路线。它可以帮助排查检索覆盖、改写退步、判断器错误和成本，不证明原论文结果已被重现。

## 官方 dev 500题的最小冻结方案（仅建议，未执行）

1. 在 train 开发实验完成后冻结模型版本、提示词、检索参数、经验库与停止条件，再登记独立 seed 和源文件 SHA。
2. 只根据 dev 的 ID/type 按真实类型比例分配500个名额，使用固定哈希排序；另用独立哈希混排执行顺序。**不照搬 train500 的404/96比例，不按答案、难度、覆盖率或模型结果挑题。**
3. 只导出运行问题、检索文档；gold、题型、文档归属与来源边仅离线可见。坏标注保留原ID并明确指标可评分性，不偷偷补抽。
4. 检查与实际建库/训练/调参题的 ID 和可获得的规范化问题哈希重叠；未做的近重复检查必须披露。禁止 dev 标签进入经验更新或选择器训练。
5. 官方 dev500 若被用于调整方法，就不再是严格未见的最终评价集；需要披露并保留另一个未参与决策的评价集合。

### 检索语料不能随意沿用

- **不建议直接沿用 train 的72,713段作为正式 dev 检索库。** 目前没有测量其对 dev 支持文档的覆盖；若缺文档，分数会混入语料不完备因素。不能按 dev gold 缺什么就补什么，也不能只选择已有证据的 dev 题。
- 低成本的过渡方案是：使用全部 dev 题的全部 context 构成固定共享语料，只用 context、不依据 supporting_facts 筛文档；再评价预冻结的500题。其段落槽位数量约为7,405×10，去重后的实际规模尚未测量。这是**自定义 closed shared-corpus 留出评价**，既不是官方每题10段 distractor，也不是 fullwiki，不能默默作为正式复现默认方案。
- 如需原论文检索规模对齐，优先核实作者所用 BEIR 语料/索引。Hotpot 官方还发布了全维基首段资源，压缩体积约1.55GB；它与 BEIR 的格式、文档ID、句子位置关系仍要核验，不能假设可直接替换。[官方 Wikipedia 资源说明](https://hotpotqa.github.io/wiki-readme.html)

## 若选择继续，最少要补的代码

1. **独立 official-dev 制备器**：保存下载/镜像来源和 SHA、冻结500题、流式语料构建及 exact-support 定位，不修改现有 train 冻结文件。
2. **明确的官方 dev 协议入口**：当前 `shared_s2g_corpus.py` 与 `run_shared_s2g.py` 都严格限定 `train/development`。需增加经过审查的独立 schema/role 分支，而不是删掉检查或把 dev 冒充 train。
3. **检索底座对应的覆盖与评分适配**：私有 gold 后加载；区分答案指标、支持句定位缺失、语料覆盖不足。对齐[官方评价脚本](https://github.com/hotpotqa/hotpot/blob/master/hotpot_evaluate_v1.py)时报告答案/支持/联合指标，不能把我们自定义支持召回直接叫官方 Joint F1。
4. **保持冻结和数据权限可审计**：运行时仅可读 runtime/corpus；模式选择器、Judge和经验模块都不能看到gold或每题原候选归属；保存模型/提示词/预算/索引指纹。

**本轮到此为止：没有制备官方 dev 子集，也没有默认替用户选择上面任一路线。**
