## 0. 先读这一页：下一步究竟做什么

不要一上来训练路由器，也不要继续扩充历史库。先解决两个更基础的问题：

1. 对已经选出的历史动作，我们能不能用当前证据给出可审查的适用性判断？

推荐实施顺序：

**核对旧结果 → 新两阶段观察器 → 本地合同测试 → 一次完整的32行开发诊断 → 通过后准备40新自然题 → 固定动作影子执行 → 封存评分 → 决定后续。**

## 1. 科学问题：我们要证明的不是“记忆有用”这么宽泛

### 1.1 总问题

> 在固定检索底座和固定历史动作库下，哪些可观测的适用条件，能帮助系统少执行不合适的历史修复，同时保留确实带来额外收益的修复？

“额外收益”至少分两种对照，不能混在一起：

- 历史相对BASE：历史修复比什么都不改写多修好多少？
- 历史相对FRESH：历史修复比不用历史、仅在本题现场生成修复多修好多少？

历史比BASE好，不自动说明历史知识不可替代。它可能只是多了一轮检索，而FRESH也能做到。

### 1.2 当前A1只回答一个局部问题

本轮固定已经选出并填好的动作，不改变卡的召回、选择或生成能力。只检查“执行这个动作之前，条件观察有无价值”。

因此，它能发现：

- 动作参数虽然在文档里出现，却不是本题所需的那个角色。
- 查询关系或时间约束与当前问题不一致。
- 本来有价值的动作被过严检查挡掉。
- 观察条件在真实卡上大量未知，根本没有区分力。

但它不能直接证明：

- 当前历史SELECT已选到了库里最好的卡。
- 没选到卡的问题不存在可用经验。
- 四十四张卡之外没有更好的动作。
- 初检后有效的检查可以直接前移到第一次检索之前。
- 两阶段观察器本身就是足够新颖的论文贡献。

### 1.3 暂定贡献陈述，必须带条件

现在只可写：我们正在研究“固定历史修复动作的适用性证据，以及保留收益与控制误用的权衡”。

如果自然实验支持，再收窄成可验证的主张，例如：

> 相比仅凭问题相似度选择经验，在相同历史候选与执行预算下，加入对当前实体角色和修复子目标的证据检查，可以降低一部分有害执行，同时保留一定比例的真实修复收益。

上句目前是待检验假设，不是结果。不要提前写成“解决了有害记忆复用”。

## 3. 两阶段观察器：最小增量，不再搭一个大系统

### 3.1 先把通俗逻辑说清楚

问题：“Glass Harbor的作者出生于哪一年？”

当前证据：“Glass Harbor由小说家Nora Venn创作。”

历史动作：“查询Nora Venn birth year。”

我们需要两件不同的事：

1. **定位：** 哪段现有证据把“Nora Venn”连到“这本小说的作者”？
2. **判断：** 在有这条连接的情况下，查她的出生年是不是合理的下一步？

第一步没有找到依据，不等于Nora不是作者；第二步认为查询合理，也不等于检索一定能找到答案。分别保存才能分清失败位置。

### 3.2 阶段一：只给候选证据位置

新增一个纯模块，暂定：

`src/growrag/experiments/a1_two_stage_observer.py`

输入复用同一份 `PreparedCheck`：原问、当前可见窗口、固定已填动作、固定槽位条件。引用目录复用catalog-v3。只允许当前Q/E作为定位候选，不用动作A文本给它自己提供事实依据。

建议输出形状：

```json
{
  "locations": [
    {"kind": "T", "slot": "gap.entity", "candidate_ref_ids": ["r3"]},
    {"kind": "R", "slot": "action.lookup", "candidate_ref_ids": ["r3"]},
    {"kind": "P1", "slot": "gap.entity", "candidate_ref_ids": ["r3"]}
  ]
}
```

这只是说明结构的合成例，不是模型真实输出。实际应对每个 `prepared.semantic_checks` 恰好一项；本地固定的P0和未声明T不交给模型重复判断。

第一版不要输出“found/false/conflict”之类额外标签，避免定位器顺便又做一次完整判断。允许空列表，意思是“本次定位器没有指出候选材料”，不是“世界上没有证据”。

定位器不得输出答案、新实体、新查询、置信度分数、长推理链或修改后的经验卡。不要先做通用知识图谱或自动本体。

定位列表应同时容许支持与反对材料，不要只提示模型寻找支持动作的证据。每个维度记录候选引用数及覆盖文本量；如果它总是把所有材料全选出来，不能声称实现了有效压缩。

### 3.3 阶段二：在同一完整窗口上作判断

阶段二继续看原来的完整可见窗口，同时获得阶段一的候选引用提示。**不把上下文裁成阶段一选中的几段。**

这样暂时只增加任务分解和定位提示，而不再引入“定位器漏掉材料就永远看不到”的证据瓶颈。

阶段二输出继续沿用catalog-v3的 `checks/kind/slot/status/reason/ref_ids`。例如：

```json
{
  "checks": [
    {
      "kind": "R",
      "slot": "action.lookup",
      "status": "supported",
      "reason": "permitted_intermediate_subgoal",
      "ref_ids": ["r1", "r3", "r4"]
    }
  ]
}
```

不要把该单项示意直接当完整响应模板；真实响应必须覆盖本次全部待判断项。

阶段二可以显式引用阶段一漏掉、但原本就在当前窗口中的材料，记录 `judge_added_ref_ids`。这些必须是阶段二模型实际选出的，不得由代码把阶段一引用自动补进判定。

旧R合同所要求的Q/A以及中间目标的E引用，第一版保持不变。去掉Q/A重复输出、改为程序上下文锚，是一个合理备选，但本次先不同时改变两套合同。若两步仍失败，作为下次有边界的方案再选，不偷偷补齐以通过旧校验。

### 3.4 阶段二的提示原则

- 原问不变，动作不变，证据窗口不变。
- 阶段一只是模型生成的候选提示，可能遗漏或选错，不是gold、不是可靠性证书。
- 允许合法中间子目标和比较问题的一侧，不要求一次查询完成整个问题。
- 缺角色信息是unknown，明确否定或互斥角色才可能是contradicted。
- 动作与问题表面关系不同，不自动证明检索无收益。
- 不使用库内历史答案、当前题gold、成功率或动作执行后结果。
- 只存可核验引用和简短枚举理由，不保存模型长思维过程。

### 3.5 为什么不在这一步顺便试十种prompt

这轮目标是建立可靠的最小观察路径，不是搜一个在32个例子上最漂亮的提示。

只冻结一个定位提示和一个判断提示，运行一次。合法但错误的判断记为错误；失败保留。若以后研究prompt，必须另立共同样本、调用预算与提示比较方案，不能把在旧开发例上挑中的最好提示当未见效果。

## 4. 必须区分“业务未知”与“观察器没有交代清楚”

建议新增记录的两条轴，不能混成一个状态：

| 轴 | 值 | 含义 |
|---|---|---|
| 观察执行状态 | `valid` | 成功解析，来源与依赖合同完整 |
| 观察执行状态 | `unverified` | 模型给了结论，但必要依据没有交代完整 |
| 观察执行状态 | `model_output_error` | JSON、字段、编号、重复检查项等不合法 |
| 观察执行状态 | `integrity_error` | 输入/动作/源码/库/账本等身份或完整性异常 |
| 业务条件状态 | supported / contradicted / unknown | 只存在于通过观察合同的报告中 |

这可作为新运行器的分类记录，不必重写旧异常类。不要仅靠随意匹配异常字符串作所有分类；为新接口建立稳定错误码或受测试的映射，原异常与原响应照存。

例如：

- 文档只说Nora讨论过这本书：合法业务unknown。
- 模型说她就是作者，却漏掉必要证据：观察unverified；不能顺手改成合法unknown。
- 非法编号r999：model_output_error。
- 运行中把卡库换了：integrity_error，立即停止。

`unverified`题如果将来产品要回退BASE，应叫“观察失败回退”，不得统计成门控识别了坏经验。当前自然研究主表对此保持缺失/失败口径，必要时另列预先规定的系统回退口径。

## 5. 已有四种条件如何保留，以及它们的局限

### 5.1 T：类型

只判断动作正文明确要求的语义类型，不能把字符串参数类型当person/work/organization。

现有34个事实槽的 `required_type` 未明确，T在这些自然实例上将是unknown。保留覆盖记录，不为了做出一条消融曲线从变量名臆造类型。

### 5.2 R：查询关系/子目标

检查实际编译查询是不是在追原问题的目标关系、合理中间目标或比较一侧，并保留方向、年份等约束。

它是风险观察，不是检索收益定理。某个“影片上映年份”查询也可能返回包含导演的页面。最终是否应该拒绝，必须让影子执行来检验误拒。

### 5.3 P0：当前来源的词面存在性

继续本地计算，不消耗模型调用，不让模型覆盖。普通gap参数也必须检查，不能只看 `GroundedBinding`。

这是本实验设定的接地政策，不是从原卡证明出来的普遍必要条件。别名、同义表达、日期换算等可能误拒。词面存在也不代表角色正确。

### 5.4 P1：是否是当前所需的那个角色

区分作者和封面设计者、导演和演员、1990年负责人和2010年负责人。名字出现、甚至类型相同，都不能代替角色关系。

P1应聚焦当前对象身份与角色；查询关系和约束主要由R负责，避免一条标准同时承担所有任务而无法解释。

### 5.5 sidecar在自然题之前的一次性整理

不要修改原 `a1_slot_contracts_v1.json`，新建版本，例如 `a1_slot_contracts_v2.json`，并保留变更清单：

1. 两张通用模板的 `property` 是任意text，不能保证没有实体/年份；建议改为unknown而非默认relation_text且无需来源。完整查询仍交R观察。
2. 人口年份角色允许有当前证据依据的合法中间目标，但仍需与地域对象一致。
3. 记录P0来自本实验接地政策，不声称原作者已证明必要。
4. 规则卡自由query仍明确未拆槽，不伪装完成实体检查。
5. 逐卡绑定ID/version/动作正文hash；只读正文，不用历史答案或本批题目结果来编条件。
6. 写清是执行代理审阅，未经人工确认就不得标human_reviewed=true。

冻结发生在准备新自然题之前。T覆盖不足和strict-all退化要提前写进协议，不在结果出来后才解释。

## 8. 新合成诊断协议：改变采集方式，不降低成功定义

### 8.1 保留什么

- 原32行输入、预期、顺序不变，仍是30个唯一输入。
- 不把row/pair/variant/expected或旧结果传给模型。
- 新fixture版本的元信息注明：已暴露开发回归，不是新盲测。
- 一行最多一次定位＋一次判断，零自动重试。
- 模型和生成参数固定，冻结两个prompt和完整消息构造代码。
- 旧quote-v2、catalog-v3及其成绩保持不动。

### 8.2 新采集规则

本方案建议的新版本不再让“一个局部模型响应不合格”自动导致后续30个独立诊断样本全部没有记录。该变更必须先登记：

| 情况 | 本行 | 整批 |
|---|---|---|
| 定位JSON或引用不合法 | 保留failed；不请求阶段二 | 记录费用后，继续下一预定行 |
| 判断缺必要引用、未知枚举等 | 保留failed/unverified | 不修补，继续下一预定行 |
| 合法输出但语义标签与预期不同 | 记录有效观察，之后算错 | 按原顺序继续 |
| token用量未知、网络超时且账单不明 | 保留失败与预留 | 立即停止 |
| 身份、泄漏、文件/账本完整性异常 | 保留异常 | 立即停止 |
| 达到预先规定预算、请求数、总超时 | 剩余行not_attempted | 立即停止，不提额 |

每行失败只影响自己的观察结果；系统错误才影响继续执行的安全性。若要另加连续失败熔断阈值，必须在首次调用前固定并写入计划，不能边看输出边决定。默认本32行在费用和系统完整性正常时收集全部行终态。

这里的费用未知停止规则针对本新系列新增未知，及未经有效保守预留覆盖的未知。项目既有20次未知费用仍以经核验的旧保守账本继承，不改为0、不释放预留；若旧预留覆盖或总授权不能核验，付费前停止并询问，而不是重写历史让它看似全已知。

实施边界（首次调用前明确）：本版继承已有传输层，局部继续适用于HTTP200、模型/用量验证通过、finish_reason=stop的非空文本输出。截断length、空响应、refusal/tool_calls等被既有客户端拒绝的异常completion仍停止全批，费用保留；不在本版新增“解锁被阻断客户端”的补救路径。详见新预登记，不将这些异常称作已处理成功的普通解析错误。

这不叫“自动重试”，因为不再次请求同一失败行；也不叫“放宽验收”，因为失败仍使32/32有效观察这一准入要求不满足。

### 8.3 自然题准入门槛暂不降低

必须同时满足：

1. 32条都有完整、可核验的最终观察；只完成HTTP不算。
2. 主三态决策至少29/32与预期一致。
3. A组至少保留15/16。
4. 13个明确冲突B至少拒绝12个。
5. 三个unknown B全部保持不确定放行。
6. 两阶段原始HTTP、费用、输入绑定和离线回放全部通过。

这些是工程准入门槛，不是统计功效或自然准确率保证。可以出现“32条采集结束，但只有29条可核验，因此不准入”。不能只展示29条里面的漂亮比例。

### 8.4 如果又没过怎么办

这次应已经能看到更完整的错误分布：漏定位、定位对但判断未引用、合法引用但语义判错、纯格式错误分别统计。

保存报告，停止付费，让用户选：简化接口、换观察模型、采用单次轻量、或转向机会覆盖诊断。不要再自作主张做v5/v6/v7同题调prompt直到过线。

新增两步所带来的结果变化只能叫这个新工程方案在已暴露开发套件上的表现，不能归因于“结构化证据优于一步”，因为还多了一次调用和中间提示。将来若要声称该机制优越，需在共同未见题上加入相同预算的一步/两次直接判断对照。

## 9. 合成过门后，才准备40道自然题

### 9.1 必须补一个真正可执行的前置门禁

`prepare_a1_data.prepare()`的docstring说明要先过合成门，但其函数和CLI没有自己验证新gate封存。因此新自然入口必须先验证：

- 新synthetic freeze、terminal、feedback外部SHA。
- `gate.passed=true`且本新系列无新增未知用量，旧未知费用按第8.2及16节继承保守预留。
- 关联模型、prompt、版本确实是本次计划的两阶段观察器。

门禁通过后，才允许调用数据准备器。**默认只读preflight也会投影新题文本，不要在门没过时先运行它。**

### 9.2 数据用途

- 来自HotpotQA官方train中的未使用候选部分；这不是官方test。
- 只投影ID和问题文本，先不读取答案或supporting facts。
- 排除所有source/cal/eval、已声明运行ID、旧A0全部200题及可得的规范化重复题文。
- 旧题文本缺失的项必须披露；不能仅凭ID不重叠声称彻底消除所有语义泄漏。
- 固定40题顺序，5/15/20只做技术分批，不是看到成绩后的筛选。
- 不按是否像已有正例、卡命中分数高低、问题难度或事后答案挑题。
- 所有40题都被保护，即使某题失败或没跑，也不能后来拿去建库。

数据输出沿现有模块为：`data/hotpotqa/a1_applicability_shadow_20261003_v1`。如果执行前该目录已存在，先调查归属与封存，不能覆盖或改种子重新抽。

## 10. 自然40题的核心流程：先冻结选择，再观察真实后果

以下是每题的逻辑依赖，不是逐题交错执行的调度表。实际默认采用第13节的两遍盲化：先完成全部40题的步骤1—5、冻结有限替代题及动作；再按原顺序执行步骤6—8。5/15/20仅为每一遍内部的技术分批，不能首批出分后再决定其余题的动作。不是先把三路都跑完再假装提前选中了最好的一路：

1. 原问题只初检一次，保存原始证据及可见窗口。
2. 原HISTORY召回body8、SELECT、FILL一次；保存所有候选和选卡身份。
3. 用旧编译器编译完整动作，确认能在剩余一次检索内执行。
4. 固定问题、证据、卡、参数、query、来源映射与hash。
5. 两阶段观察，封存原请求、原响应、条件报告与派生gate。
6. BASE Reader读取初检证据，得到不执行该动作的结果。
7. 对所有合法已选历史动作做shadow：不论gate放行还是拒绝，都真实执行该固定动作，再用同一Reader回答。
8. original FRESH在同一初检快照上作一次现场修复，最多额外检索一次，再交同一Reader。
9. 所有40题运行及预定补充诊断终态封存，再允许评分进程读取本批gold。

因此每题保存的是三类实际结果：BASE、固定历史动作结果、同预算FRESH结果。条件政策只在BASE和固定历史结果之间回放，不偷偷选FRESH作为拒绝后的备用。

如果要研究“拒绝历史后改用FRESH”，那是下一阶段新的路由干预，不能混进当前只测适用条件的实验。

### 10.1 不能忽略的状态差别

- `no_selected_action`：SELECT没有选卡，观察器无动作可判断。
- `empty_plan`：动作编译没有产生请求。
- `repeated_query`：实际query与已检索query重复。
- `action_contract_failure`：动作本身不符合硬约束。
- `observer_unverified` / `observer_output_error`：观察器没有给出可用观察。
- `verifier_rejected`：有有效观察，策略明确拒绝动作。
- `shadow_executed`：固定合法动作已真实执行。
- `reader_failure`：最终Reader没有有效输出。

不要把前五种都写成“成功拒绝坏经验”。不要为了让每题都可评分，把运行失败自动替换成BASE成功。

### 10.2 观察失败后的诊断与主表

若只是某题观察输出失败、系统和费用完整，该题的合法固定动作仍可按新预登记继续shadow，以识别观察器失败是否遮住了有用动作；不能把它变成有效门控结果。

主表同时列固定40题的可用性以及各方法有效数。需要统一分母的配对表只对共同可评分题计算，并明确列出排除数量和原因，不能把缺失默认为错，也不能悄悄缩小题量。

A2门要求40题完整终态且观察覆盖足够。如果本批不满足，就报告有限诊断，不继续补跑缺失题。

### 10.3 自然题局部失败处理表

| 情况 | 后续处理 |
|---|---|
| HISTORY SELECT/FILL或动作合同失败 | 历史臂失败；不执行非法动作；BASE及FRESH各自按计划继续 |
| 观察器局部输出失败，固定动作合法 | 历史shadow仍执行；条件政策结果缺失，不算unknown或BASE成功 |
| FRESH规划失败 | FRESH臂失败，其他合法臂不受影响 |
| Reader输出失败、账本完整 | 同完整请求共享失败记录，不重试；其他不同请求可继续 |
| 新增账单不明、身份/文件/数据隔离异常 | 停止全批；不把系统错误当普通模型失败继续 |

40题都有终态记录不等于40题都有有效方法结果。未尝试、失败、成功分别计数；各配对分母另列。

## 11. 如何真正保持“同一个动作”和“同一个底座”

### 11.1 动作身份

`ActionProposal`没有selected_card_id。必须从同次 `history_execution`事件取卡ID/version，与冻结库/正文/spec核对，不能由query猜卡。

执行前保存完整 `ActionProposal`、旧编译器的requests、goal、gap/bindings。模型观察的对象就是这份已填实例，执行器不消费观察器随口生成的文字。

超出一次剩余检索的多请求plan整体拒绝，不截第一条让卡“看上去可执行”。

### 11.2 初检物理复用与逻辑预算

旧 `run_operator_episode`进入时会自己初检。若上层已经初检，后续shadow/FRESH包装器第一步只能回放相同冻结Evidence tuple，并记录 `initial_snapshot_reused=true`；不能暗地再请求一次BM25。

每个方法的逻辑预算仍为：BASE1，HISTORY最多2，FRESH最多2。整个配对研究的物理检索总数会因为测多路而更多，两者分开记。

### 11.3 证据窗口

先用完整Evidence ID构造 `visible_evidence()`窗口，再替换成E1/E2短编号，不利用更短ID偷偷多塞正文。

旧窗口含 `title_truncated/text_truncated`，而A1紧凑payload只接受 `text_start/text_end/original_text_chars`。完整窗口保留本地，模型输入投影允许字段，别直接把整dict塞进去触发合同失败。

初检后两阶段看完全相同的窗口。后续检索新增文档只进入执行结果，不能倒流回执行前观察。

## 12. Reader缓存、统一回答与自然单元测试

### 12.1 为什么需要缓存

同样的Reader输入即便temperature=0也不应被假定永远字节一致。若BASE和历史其实给了完全相同上下文，却得到不同答案，不能把这种波动全归因于经验。

本轮采用预先登记的真实缓存，比跑完后挑一个较好答案更清楚。

### 12.2 缓存键与命中规则

缓存键至少绑定：

- 实际完整messages及顺序。
- 模型快照、endpoint/后端身份、生成参数、Reader prompt版本。
- 原问题、可见证据顺序/窗口、短ID到完整Evidence ID映射。

单纯query相同、文档集合相同或答案相同都不够。短编号相同但完整ID不同也不能直接共享。

首版去重仅限同题，固定BASE→shadow→FRESH顺序。对完全相同的Reader请求只建立一个物理请求及其终态：成功时共享该成功响应；失败时共享该失败记录，其他臂标记 `shared_reader_failure`，不得因成功缓存未命中再次请求。错误不进入成功结果缓存，但必须进入请求去重账本，防止“直到首次成功”的隐性重试。不同完整请求仍各执行一次。命中保存 `cache_source_trace` 或 `shared_failure_source_trace` 及请求hash，不伪造新HTTP或token用量。

### 12.3 自然接线测试清单

- HISTORY SELECT/FILL只调用一次；观察以后不重新填参。
- 观察发生在shadow/Reader结果之前。
- 拒绝动作仍能shadow；非法动作不能执行。
- 门未通过时连prepare/preflight都不能触及新自然题。
- 各臂初检快照、检索预算、Reader版本一致。
- `candidate_answer`、`supported`与实际served `answer`分开保存。
- Reader的supported仍是模型声明，不是人工标签。
- 原始HTTP、日志、cache hit/来源与账本一致。
- 无卡不是观察拒绝，未知不是错误，运行缺失不是0分。
- 全部终态前不得读取gold；任何时候不得写长期经验库。
- 不因某臂Reader输入相同就把另一臂规划和观察的费用也清掉。

## 13. 有限替代动作诊断：回答“选错了，还是绑错了”

继承原草案的上限，不把它并入主系统成绩：最多8题、12个替代动作。

在读取gold、shadow结果和Reader答案之前，基于已经封存的观察状态按固定种子选：

- 最多4个有效gate拒绝的题。
- 最多4个SELECT未选卡的题。

如果每题运行完就立即看见shadow结果，执行代理再挑替代例就已不盲。因此自然研究固定分两遍：第一遍先收集全部40题原动作/观察并冻结全局替代题名单与全部替代动作；第二遍才执行BASE、shadow、FRESH和替代结果。全部第一遍及替代动作未封存前，禁止Reader和任何额外检索；初检允许。两个阶段之间也不读gold。

本版本固定采用两遍执行，不同时留下逐题流水的任选开关。若以后确需流水，应另行登记确定性的替代抽样与动作封存规则，不能由已经看过结果的代理后补。

对拒绝题：同卡一个有当前依据的替代绑定，以及body8中一个预定的未选替代卡；每题最多2个。没有可支持绑定则记 `no_supported_rebinding`。

对未选题：固定body8中预先规定顺序的候选，至多一次填参；硬合同失败就记录，不反复尝试直到有一个可执行。

所有替代动作都保持旧证据窗口、预算和执行器。人工或执行代理辅助标注要明确来源，不能伪装为自动系统能力。不得看旧答案补实体。

主系统与替代诊断分表；替代动作不能替换原SELECT选择、不能凑成“已选动作覆盖数”，也不能把其最佳结果写成主系统EM。

## 14. 评分：把“修复”和“损害”同时摆出来

### 14.1 答案指标

EM全称Exact Match：按数据集既定规范化规则判断答案是否完全匹配，单题0或1。

F1这里指答案token的F1：综合预测与参考答案token的精确率、召回率；不是分类宏F1，也不是证据充分性评分。继续复用本项目已审的HotpotQA兼容评分，不自创不同标点或yes/no规则。

### 14.2 两种差值

对可配对问题i，分别记录：

```text
历史修复增量 ΔHB(i) = EM(HISTORY_i) - EM(BASE_i)
历史相对现场修复的额外收益 ΔHF(i) = EM(HISTORY_i) - EM(FRESH_i)
```

同样分别算F1及标注支持证据覆盖的差值。不要在第一版把EM、F1、成本、轮数乘几个未经校准的权重揉成一个主分数。

ΔHF是有用的归因对照，但不是数学上完全分离了记忆知识的因果效应；两种方法生成的query、提示长度、调用数可能不同。报告已控制和未控制的因素。

### 14.3 gate的核心四格

对合法已选且BASE/shadow均有有效结果的动作：

- 有用：BASE错、shadow对。
- 有害：BASE对、shadow错。
- 两者都对：没增加EM，可能多花成本或改变证据。
- 两者都错：没修好，仍可查看F1/证据变化，但不叫EM修复。

接着交叉gate放行/拒绝，得到“保住有用”“误拒有用”“拦住有害”“放过有害”。

关键比率：

```text
有用保留率 = 放行的有用动作数 / 全部已观测有用动作数
误拒率 = 拒绝的有用动作数 / 全部已观测有用动作数
有害拦截率 = 拒绝的有害动作数 / 全部已观测有害动作数
观察覆盖率 = 有有效观察的合法已选动作数 / 全部合法已选动作数
复用率 = 策略实际会执行历史动作的题数 / 固定计划题数
```

分母为0写“不可估计”，不要写0%或100%。对于模型输出失败的题，业务gate不可用，单列覆盖缺口。

### 14.4 证据层和答案层独立报告

记录新到达文档、标注supporting facts召回、Reader可见窗口的标注支持覆盖、最终答案及引用。

区分：原始检索命中、累计证据、截断后可见证据、Reader实际引用。不要因为标注句未命中就断言答案绝无其他支持，也不要把“多了几篇文档”当信息必然增多。

### 14.5 政策回放

保留无条件放行、各单维、全部条件、strict-unknown-reject。用同一次有效观察派生，不为每个政策重复调模型。

拒绝时取真实BASE结果，放行时取真实固定shadow结果。无卡题直接沿用原系统无动作路径。strict-all当前很可能退化为BASE，它必须公开出现，但不能靠零有害复用宣称赢了。

这叫“固定动作的政策回放”，不是训练好选择器后的真实在线运行结果，更不是看完三个答案后择优。

## 15. 成本必须有三张账

### 15.1 实际研究账

所有真实HTTP：历史SELECT/FILL、定位、判断、BASE/HISTORY/FRESH Reader、FRESH规划、替代候选、失败调用。缓存命中增量0，但对应被复用的原调用仍在研究账中。

1. 40题终态、成本和数据隔离审计完整。
2. 至少12个合法已选动作有非退化观察，不是全部unknown放行。
3. 原已选或预定替代动作在至少3个独立问题上呈现相对BASE的真实有用动作。

## 25. 十一个统计/研究解释陷阱检查

本计划不是已经完成的统计验证。执行后至少逐项核对：

1. Simpson：不同版本、预算、方法与分母不能混合报一个胜率。
2. Ecological：整体均分不代表每题或某类问题都更好。
3. Berkson：只分析选到卡或成功解析者，会改变样本组成；同时报全40覆盖。
4. Collider：不能按被模型放行、Reader声称支持等后续变量挑评价题。
5. Base-rate：合成正负配比不是自然使用率；人工困难例不代表总体频率。
6. Regression-to-mean：修一个失败例再跑对，不等于整体改善。
7. Survivorship：失败、未尝试、观察不完整与费用都要报告。
8. Multiple comparisons：主对照提前指定；其余条件组合探索性，不能只保留赢家。
9. Forking paths：冻结prompt、样本和停止规则，保留每个失败版本。
10. Correlation/causation：ΔHF有归因价值，但不同query/调用成本仍可能混杂；当前不作强因果承诺。
11. Reverse causation：不能先看动作是否成功再写“当时它适用”，观察必须先封存。

40题主要做描述性、问题级配对分析。不许把2次观察调用、多个候选或九个展示视图当独立样本。后续若计算区间或检验，先规定以问题或合适来源组为单位的配对统计、处理缺失的规则，不因p值不好换检验。
