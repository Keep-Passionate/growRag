## 4. 不要只搬C盘工作副本

新副本 `.git` 实际是文本指针：

```text
gitdir: D:/project/GrowRAG/.git/worktrees/GrowRAG
```

它的Git历史依赖原D盘主仓库。只复制此文件夹到新机器，再删除旧D盘仓库，会留下失效指针。

推荐在新电脑全新克隆明确分支，再单独复制本地数据，而非依靠搬运linked worktree恢复Git。以下是操作建议，交接时没有在新机器执行：

```powershell
git clone --branch codex/a1-structured-contract https://github.com/Keep-Passionate/growRag.git D:\project\GrowRAG
git -C D:\project\GrowRAG status --short
git -C D:\project\GrowRAG log -5 --oneline
```

若目标目录已经存在，先检查里面是什么；不要覆盖或删除现有项目。保留旧代码核查时，可另建 `codex/a1-two-stage-observer` 的checkout/worktree。

1. 确认两个代码分支已推送；确认本机工作区改动已保存。不要以默认main代替指定分支。

4. 复制 `D:\notes\GrowRAG`；按需要搬论文PDF、Zotero数据库和storage附件。
5. 不直接依赖旧 `.venv`。当前editable安装绑在D盘旧src，Python基础路径也绑定原电脑。新机器重建环境。
6. 项目要求Python `>=3.11,<3.13`。`pyproject.toml` 声明依赖与extras，但没有完整锁定文件；需要环境完全一致时先记录旧依赖版本。

```powershell

```

8. 运行前检查 `growrag.__file__` 指向新机器实际选定代码根；若有两个checkout，不能由旧editable偷偷导入旧代码。
9. 原 `qwenAPI.md` 是私密本地配置，未提交。所有者确需继续API时私下配置或转移，不能发GitHub/公共交接包。
10. 新机器先只运行离线测试、读取结果，确认旧账继承与API端点/固定模型身份，再制定新实验。

旧freeze包含代码身份、文件SHA及绝对路径。换机器、换用户名或换checkout可能使旧运行器的严格路径核验失败。不要修改旧freeze、伪造旧路径、重新封签旧成绩来“过门”；保留原记录作档案，新实验用新路径、新freeze。严格结构新探针尚未freeze，迁移后可按真实新根首次冻结。
