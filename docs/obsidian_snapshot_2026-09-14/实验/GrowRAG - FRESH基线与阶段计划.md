# FRESH基线与阶段计划

## 最需要掌握的 3 点

1. 先建立强无历史对照，再谈经验额外收益。更长prompt或更复杂方法不保证更强。
2. 本批32题比较BASE、旧简单FRESH、关键词式FRESH、伪文档扩写式FRESH；不测历史收益。
3. 同模型、同文档池、同top4；每种方法独立调用。费用与延迟逐阶段记录，不能把全分支审计费当上线费。

## 本轮具体做什么

| 方法 | 怎样做 | 依据和差异 |
|---|---|---|
| BASE | 原query直接检索 | 必需对照 |
| SIMPLE_PARAPHRASE | 保留原冻结措辞改写prompt | 不覆盖旧结果 |
| RRR_KEYWORDS | 实体、所求关系、关键约束组成搜索query | [[GrowRAG - Query Rewriting]]的提示词式适配，不含SFT/RL训练 |
| QUERY2DOC | 原q加短假想段落，补文档词汇 | [[GrowRAG - Query2doc]]零样本适配，不是原四样本/词频加权复现 |

当前句BM25对query词去重，所以重复原q五次不会实现原文权重；必须记录这个差异。假想内容永远不作Reader证据。[[GrowRAG - HyDE]]的稠密编码尚未接入。

## 为什么先选这两种，而不是马上移植全部方法

| 方法路线 | 适合的位置 | 当前取舍 |
|---|---|---|
| Rewrite-Retrieve-Read | 查询侧单步改写；后续可学小改写器 | 先接低耦合的关键词提示适配，完整反馈训练后置 |
| Query2doc | 查询侧单步补文档式词汇 | 适合测试词汇不匹配；必须防止伪事实进入答案证据 |
| RaFe | 离线借排序反馈优化改写 | 有真实配对数据后再学，不能把一段prompt冒充训练版 |
| HyDE | 假想文档进入稠密编码器 | 需要改变本轮检索配置，另做稠密底座组，避免同时改模型与检索器 |
| ReflectiveRAG / S2G-RAG | 看到本题证据后再修复 | 适合作为有限多轮教师/POST强对照，不符合本轮纯PRE单次目标；不能只搬一个gap提示就叫完整复现 |
| ReFormeR | 显式规则和示例指导改写 | 主要历史模式基线；原有POST上下文与q-only适配分开报告 |

没有哪一种因论文发表就保证在我们的句BM25、Qwen和数据上更强。先冻结方法独立测量，再确定强FRESH；结果入口：[[GrowRAG - FRESH基线结果2026-09-14]]。

## 数据和成本

新32题来自官方train内部selector_train角色，桥接/比较各16，按固定哈希排序，不按答案抽题。它们是训练/开发诊断，不能称正式测试。原64源不改，原8调试/24检查题不曝光。

模型仍固定qwen3.7-flash-2026-07-15，同一个Reader，非思考、temperature0。7次API/题的上限，整批最多224次；共享之前5元总上限，新运行另限1元，继承旧预留。不重试、不自动换模型、不自动继续扩大。

## 想看哪些结果

- 每个方法EM、F1、支持召回。
- 把BASE答错的题救回多少；把BASE答对的题改坏多少。
- 词汇不匹配、遗漏连接、意图漂移、伪事实引导、评分别名问题各有哪些例子。
- 改写、Reader、索引和检索的token/耗时；选择/QPP本批未运行，不能写实测节省。

程序逐题保存真实query、证据、回答与调用审计。没有运行的历史召回与QPP阶段明确写未运行，不补造中间过程。

## 后续阶段

1. 本轮：确定更强FRESH候选与失败模式。
2. 同候选动作下比较M1/M2/M3/M5，继而同信息自然段、逐项删条件。
3. 获得更多独立动作配对数据以后训练[[GrowRAG - 选择器学习方案]]，不拿32题宣布可靠门控。
4. q-only动作选择，对比POST上下文选择及生成后Pre-QPP；量化多看文档的效果收益和成本。
5. 必要时研究有限多轮教师、单次部署学生；保留强多轮对照，不能隐去单步的信息损失。
