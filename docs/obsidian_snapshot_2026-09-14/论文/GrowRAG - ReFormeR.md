# ReFormeR

## 我们最需要掌握的 3 点

- 怎样把成功的“原查询 → 新查询”归纳成可复用模式。
- 怎样先看原问题和首次检索结果，再选择模式来改写。
- “模式属于哪类”的训练标签，不等于“这类模式比不改写更好”。

## 原文与发表状态

[ReFormeR: Learning and Applying Explicit Query Reformulation Patterns](https://doi.org/10.1007/978-3-032-21300-6_30)，ECIR 2026，已审稿的正式会议论文；不是期刊。[作者原文](https://arxiv.org/html/2604.01417v1)｜[作者代码](https://github.com/aminbigdeli/ReFormeR)。

## 用容易理解的话说

先收集确实改善检索的查询对，从中总结十种模式，例如消歧、补充检索词和增加区分条件。模式包含名称、说明、一般化操作和示例。新题先检索，选择器结合问题与检索上下文选择模式，生成器再执行改写。

论文描述了监督学习选择器：从历史查询对分配模式标签，再学习预测这些标签。注意区分论文训练描述与作者公开仓库中的提示式实现；移植时必须锁定代码版本、说明差异，不能把提示调用称为已经复现训练。

## 精读定位

先读方法中的模式归纳、模式分配函数 `g(q, q′)` 与选择器损失；再读实验模型设置、模式表和代码中的模式选择提示。不要混淆用于提取模式的大模型与执行改写的较小模型。

## 对 GrowRAG 有什么用，不能据此说什么

适合作为主要历史模式基线。我们可以借它的显式规则与示例，但“抽象模式＋选择复用”已经存在，不是新贡献。我们的待验证问题是：不读取首次文档检索结果时，哪些可观察条件能帮助选择真正带来额外收益的动作？这是信息更少、成本也可能更低的约束，不保证效果更好。
