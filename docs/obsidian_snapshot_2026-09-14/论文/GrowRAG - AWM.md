# AWM｜Agent Workflow Memory

## 我们最需要掌握的 3 点

- 将具体操作轨迹变成变量化的工作流程。
- 比较不同记忆表示时，究竟控制了哪些其他变量。
- 历史流程不合当前情况时，允许偏离，而不是强制照做。

## 原文与发表状态

[Agent Workflow Memory](https://proceedings.mlr.press/v267/wang25bx.html)，ICML 2025，已审稿的机器学习顶会论文。[作者原文](https://arxiv.org/html/2409.07429)。

## 用容易理解的话说

把做过任务的操作过程提炼成可重复使用的“做事步骤”。具体对象可被替换成变量，新的任务据此少走弯路。这里的 workflow 是可参考的流程，并不自动等于严格、穷尽所有状态的有限状态机。

## 精读定位

重点读 §4 的记忆表示实验、§3.2.1 对偏离既有流程的讨论，再回看 §2 的工作流抽象。逐项标出状态描述、操作、变量和示例分别提供什么信息。

## 对 GrowRAG 有什么用，不能据此说什么

我们借它思考 M3 动作模板，也借鉴“多放信息未必更好”的实验方式。GrowRAG 首轮固定同一批历史卡和规范动作，只改变选择器看到的文字；不是完整复现网页代理。

工作流抽象、跨题经验和表示消融都已有先例。真正要测的是：哪些字段减少误用，哪些只是增加输入长度。不能预先宣布结构化卡一定胜过原始查询对。
