# Query Rewriting｜Rewrite-Retrieve-Read

## 我们最需要掌握的 3 点

- 原问题不变，检索查询可以改变：查询侧是独立可优化环节。
- 让小改写器适配固定检索器与回答器，而非改造整个 RAG。
- 简单提示改写和经过反馈训练的改写器，是两个不同对照。

## 原文与发表状态

[Query Rewriting in Retrieval-Augmented Large Language Models](https://aclanthology.org/2023.emnlp-main.322/)，Ma 等，EMNLP 2023 主会，已审稿的 NLP 顶会论文。DOI：10.18653/v1/2023.emnlp-main.322。

## 用容易理解的话说

先把用户问题转换成更适合搜索的查询，再检索与回答。论文既讨论用大模型提示生成查询，也训练较小改写器，用下游回答反馈进行强化学习。小模型学习的是如何搜索，不是直接把标准答案写进每次查询。

## 精读定位

先读 Rewrite-Retrieve-Read 框架与提示式改写，再读小改写器训练、读者反馈和实验对照。沿一题追踪“原问题”“搜索 query”“最终回答”是否分开。

## 对 GrowRAG 有什么用，不能据此说什么

这是查询侧可插拔设计的基础必读。我们可先移植明确的改写任务和示例，形成更强 FRESH；以后用独立适配集训练小改写器。

只借提示思路、没有训练其模型时，应称受启发的提示基线。FRESH 的关键是不读取跨题动态历史，并非必须弱提示。固定示例可以作为强 FRESH 的一部分，但要公开其来源和所有组的信息预算。
