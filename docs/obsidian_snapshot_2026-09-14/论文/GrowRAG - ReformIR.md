# ReformIR

## 我们最需要掌握的 3 点

- 改写越多不一定越好，可能逐渐偏离原意。
- 排序反馈应锚定原问题，而不只奖励改写后的主题。
- 找回候选与昂贵重排的开销要分开计量。

## 原文与发表状态

[When More Reformulations Hurt: Avoiding Drift using Ranker Feedback](https://doi.org/10.1145/3805712.3809721)，SIGIR 2026，已审稿的信息检索顶会论文。[作者原文](https://arxiv.org/html/2605.00560v1)。注意：ReformIR 不是 ReFormeR。

## 用容易理解的话说

生成更多查询有机会补足词汇不匹配，也会引入不相关含义。该工作借助排序反馈约束漂移，并考虑检索候选合并和重排预算。看到“成本降低”时，需要指出到底减少了哪个环节。

## 精读定位

读方法中的原查询锚定反馈、候选处理与预算分配；再看增加改写数量后的效果变化和成本实验。在流程图上标记“这里已经运行过检索”。

## 对 GrowRAG 有什么用，不能据此说什么

我们可用原问题与改写动作的约束一致性作诊断：是否换了比较属性、关系方向或时间范围？但这些信号应另做消融，不能同时换卡片表示和检索器后把提升全部归给记忆。

它依赖检索/排序反馈，不是完全无文档检索的前置选择。它也不直接回答：同一组历史候选中，选择器最少需要知道哪些适用条件。
