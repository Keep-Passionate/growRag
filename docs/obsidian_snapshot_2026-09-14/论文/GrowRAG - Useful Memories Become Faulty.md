# Useful Memories Become Faulty

## 我们最需要掌握的 3 点

- 一次抽象丢信息，与反复覆盖造成漂移，是两种问题。
- 只保留原始情节经验，应作为有竞争力的诊断对照。
- 保留旧来源不等于避免漂移：新摘要若读旧摘要，仍可能继承错误。

## 原文与发表状态

[Useful Memories Become Faulty When Continuously Updated by LLMs](https://arxiv.org/html/2605.12978v2)，2026 年预印本，本笔记针对 v2；正式会议/期刊状态未确认，不能写成未投稿。

## 用容易理解的话说

即使原始轨迹正确，反复让大模型整合抽象记忆，也可能让以前会做的任务退步。v2 把首次压缩损失、旧抽象对后续抽象的影响、原位覆盖分开实验；禁止覆盖能减轻损害，但不消除所有损失。删除与改写也不是同一种操作。

## 精读定位

§4.2 episodic-only 对照、§6.4 “更新中什么造成损害”、附录 L.2 的更新方式控制。重点看是否允许读取旧记忆、是否原位改写、是否只删除。

## 对 GrowRAG 有什么用，不能据此说什么

保留原始 q→q′ 和执行来源；新卡正文做新版本，反馈可追加，但不能无限摘要套摘要。我们应分开比较：具体记录与一次抽象；一次抽象与持续改写。

用户偏好的“两三层后重建/弃用”可作为工程候选上限，不是论文证明的普适阈值。新版本只有来源指针也不够：若实际生成读了旧摘要，不能称完全从原始轨迹重建。
