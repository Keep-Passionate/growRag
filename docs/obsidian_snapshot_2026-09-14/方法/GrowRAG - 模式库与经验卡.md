# 模式库与经验卡

## 最需要掌握的 3 点

1. **采用名称、描述、规则、示例的显式模式库很合理，但这四字段不是我们的新意。**
2. **模式是操作类别，来源经验是一次具体观察。** 多条来源可支持同一模式，不能把十个大类别当十条已可信经验。
3. **规则之外优先补可观察适用条件、保留约束与独立净收益记录。** 所有新增字段都要通过删字段实验证明值得存。

## ReFormeR与我们当前形式

| 方面 | ReFormeR公开模式库 | 当前GrowRAG |
|---|---|---|
| 基本单元 | 10类归纳模式 | 单个成功来源提取的候选卡，本批6张 |
| 可读正文 | 名称、描述、一般规则、代表例子 | 问题模式、前提/禁用条件、rewrite_rule/preserve |
| 召回/选择 | 首次文档上下文辅助选模式 | 目前来源原题词面重合短名单，之后固定prompt选卡实验 |
| 更新状态 | 原论文固定模式库评价 | 有版本与统计字段，但尚未实际动态维护闭环 |

作者库十类为：意图澄清、主体澄清、概念转换、上下文扩展、上下文限制、泛化、地点明确化、目的明确化、语义澄清、时间调整。类别可能交叠，不必在Hotpot上强凑十类。

## 推荐小结构：统一外壳，正文是操作规则

```yaml
pattern_id: P_time_comparison
name: 两对象时间比较
description: 用明确的时间属性组织查询
rule: 分别查找两对象的同一种时间属性；不擅自替换属性
example_refs: [source_029]
applicability:
  observed: [问题明确要求比较时间先后]
  must_preserve: [两个对象, 所比较的时间属性, 先后方向]
  unknown: [索引是否有对应时间信息]
provenance: [原始q与实际query的审计指针]
validation: {independent_trials: 0, status: candidate}
```

这是**教学结构示意**，不是当前已执行的JSON，也不是断言source029支持全部概括。代表例子可通过指针按需读取；不是永远把历史实体和答案送入当前提示词。

暂不保存长CoT、重复全部文档、模型编造的跨题“成功率”。名称便于检索审阅，描述帮助理解，规则指导执行，示例核查概括是否忠实，条件用于选择，反馈用于验证是否比强FRESH值得。

## 公开库需要审查而不是照单全收

本轮核对作者库提交 `72e52450a922bc0051b5b39c3a6307186a555137`，发现个别地点/属性示例改变了目标：例如把厄瓜多尔的Quito改成墨西哥。它能说明示例有风险，不能据此推断整篇方法总体无效。[作者模式文件](https://github.com/aminbigdeli/ReFormeR/blob/72e52450a922bc0051b5b39c3a6307186a555137/reformer/patterns/extracted_patterns.json)

仓库当次核对未发现许可证文件，不把整份源码/模式库直接复制分发。近期采用自行实现并注明灵感的适配版；正式分发作者资产前核实许可。

## 不增加重复抽象层

模式只是执行视图/索引，不强迫旧卡持续改写。保存原始来源，条件改变生成新候选并重验；统计反馈可以追加，正文不原地覆盖。是否合并同类卡，先比较“分开保存”和“一次性抽象”再决定。
