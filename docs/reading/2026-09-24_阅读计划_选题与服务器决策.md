## 先看结论

**保留我们的方向，但把“添加记忆”收窄成“历史修复何时比强现场修复更值得执行”。**

主实验可以使用 S2G 式结构化状态作为诊断接口，DualRAG 非FT方法作为另一种强 FRESH 思路。先把新鲜修复做扎实，后加跨题程序经验。当前不要同时做RL、复杂压缩、三层记忆与全模型微调。

## 一、先前工作有哪些共同问题，哪些不能一概而论

| 问题 | 文献依据与边界 | 我们能做的具体检验 |
|---|---|---|
| 本题内检索越来越多，未必得到新证据 | S2G分析轮次收益饱和；DualRAG承认多轮延迟 | 同样最大轮次下，记录有效新证据、重复query、token与延迟 |
| 看见相关文档，不等于留下了足够证据 | S2G承认证据压缩会漏跨句信息；其Figure 2的truth实际使用支持文档标题覆盖 | 分开评估文档到达、支持句保留、judge判断、答案四层 |
| 知道当前缺口，不等于知道哪个动作最能填它 | S2G将target/slot机械拼接；DualRAG通过实体定向查询 | 固定当前缺口，比较机械拼接、自由改写、静态动作和历史动作 |
| 历史成功率不等于本题值得复用 | MemRL学习效用；RRM已有适用条件；Skill-Pro已有条件化程序 | 比较相似度、平均成功率、平均净收益、当前条件净收益预测 |
| 更抽象不保证更可迁移 | Useful Memories、QCR以及项目既有审计；不要说所有记忆系统都持续覆盖旧记忆 | 分开一次抽象和反复修改，保留同源原始记录；目前后置 |

共同的研究难点不是“前人没有memory”，而是**决策时能看到什么、最后收益归给谁、什么情况下拒用才值得**。本轮是定向检索，不是证明全领域没有相似工作的系统综述。

## 二、三个可选研究切口

### 首选：带适用边界的修复经验，能否选赢强 FRESH？

暂定问题：在固定检索器、语料、回答器和成本约束下，保存哪些可观察条件，才能从历史修复中选出比现场改写更有价值的动作？

不是发明gap或经验卡。我们要证明：**条件信息改变选择质量，而不只是让prompt更长、增加候选数量或记住答案实体。**

最小实验分三步：

1. **先找机会**：对每题运行同预算FRESH和固定历史候选。离线看历史中是否存在更好结果；最佳候选是事后oracle，只是可达到的实验上界，不部署、不让它接触线上选择。
2. **再看是否选得到**：执行动作全部固定，只改变选择器所见表示。
3. **最后解释为什么**：删字段、打乱条件、等长无关文字、新实体划分，检查是否真是适用条件起作用。

推荐表示对照：

| 名称（本轮新实验名，不改旧M1–M5定义） | 给选择器看的内容 |
|---|---|
| R0例子 | 来源问题＋来源改写；去掉答案，不提供测试事实 |
| R1规则 | 动作名称＋规范变换规则 |
| R2条件 | R1＋当前可观察的适用条件 |
| R3边界 | R2＋由真实无增益/退步执行形成的不适用条件 |
| R2-shuffle | R2相同长度，但条件随机配错；负对照 |
| R1-length | R1＋等长无关说明；排除只是提示更长 |

每种表示选中 `action_id` 以后，由同一个冻结执行器执行**同一个动作**。不要把更丰富卡片同时喂给生成器，否则选择与执行两种变化混在一起。

PRE只看原问题可见信息；POST才看当前证据和缺口。后者可以作为信息更丰富的参照，但检索开销要计入，不叫“检索前预测”。如果只有POST有效，就承認PRE有信息上限，不强迫模型猜不存在的信息。

创新风险：高，RRM / Skill-Pro / MemHarness非常近。潜在贡献是明确的信息边界、最小有效条件与受控的迁移结果，而不是字段本身。难度：中。工程可行性：高，现有配对底座可用。

### 备选：保住复杂约束的缺口—动作表示

从S2G作者的局限出发，选择**一种**关系约束先做：时间、双实体绑定、属性比较，不一次全上。

例如“收购前的CEO”不能被改写成“现任CEO”；“A和B谁更早成立”不能只查A。比较平面target/slot与带变量绑定/依赖的动作表示。先用现场动作验证结构必要性，再研究历史复用是否带来进一步收益。

关键对照：等长自然语言约束、固定模板、结构化规则；保持检索数量一致。若只是多写一句提醒就同样有效，不应夸大为新结构。

创新风险：中高，S2G自己已指出此方向，也有问题分解和程序化查询前例。难度：中。可行性：中高；HotpotQA可检验桥接和比较，但不足以覆盖大量时间约束。时间型扩展需单独核实数据集标注，不能临时造几题当正式结果。

### 小而清楚的补充：先修证据表示，再决定要不要再搜

S2G压缩漏掉的上下文，可能还在已检索段落里。先补原句的邻接上下文，再决定是否外部检索。它可以作为FRESH的诊断增强，也可形成一种修复动作。

对照：原句指针、固定邻句窗口、按需窗口；同token预算。测支持句覆盖、错误停止、额外检索次数、EM/F1。历史记忆在此不是必要前提，因而它更像一个独立小课题，不强行塞进主线。

创新风险：中高，语境压缩/重建已有大量工作，需专门排重。工程难度：低到中。可行性：高，Hotpot句级支持事实很适合诊断。

## 三、我们如何避免“永远不用经验”这个伪成功

报告至少六项：

- 修复：BASE/FRESH原本错误而历史动作答对多少。
- 损害：原本答对而历史动作答错多少。
- 复用覆盖率：实际使用历史的比例。
- 固定复用率时的净收益/损害，避免少用一切假装安全。
- 选择遗憾：事后最佳候选与实际选择的差距；事后上界不得变成线上方法。
- 成本：每个组件输入/输出token、模型请求数、检索数、时间；离线建库和在线服务分别计算。

同时保留 `memory−BASE` 和 `memory−strong FRESH`。差值不是我们发明的，也不是严格数学因果证明；它在固定底座的配对实验中提供更清楚的归因。证据召回、答案正确、引用支持也分别报告，不能一项替代所有项。

## 四、分阶段执行，不一开始全量

| 阶段 | 数据与工作 | 通过条件 | 失败后怎么做 |
|---|---|---|---|
| 0 功能诊断（现在） | 8道已暴露train/debug，BASE与DualRAG有界适配；保存全轨迹 | 调用可追溯，gold不进模型，协议/成本正确 | 记录失败，修工程；不把失败题悄悄换掉 |
| 1 强FRESH诊断 | 冻结协议后，新开发子集50–100题；S2G teacher-style与DualRAG适配 | 找出检索/压缩/判断/答案各层失败比例 | 若基线弱先核模型/语料/实现，不能利用弱基线制造记忆收益 |
| 2 独立来源建库 | Hotpot官方train另取约100–300来源题，实际执行后提取候选动作 | 存的是可执行程序，来源和反馈可核查 | 没有可迁移机会就改来源/任务，不堆字段 |
| 3 表示与选择 | 来源题、选择训练题、探针题分离，先100–300问题级配对 | 有机会且条件选择优于对照；用配对置信区间报告 | PRE无效可转POST，候选无机会就停止该支线 |
| 4 扩展验证 | Hotpot官方dev冻结评价；2Wiki测试迁移；TriviaQA检查简单题退步 | 成本—性能稳定，不靠一批调参题 | 缩小主张，保留负结果 |

这里的数量是计划，不是足够发表的统计保证。正式规模根据试验的效应大小/方差决定。官方隐藏test没有可直接使用的gold，不能拿其训练。开发集若多次用于选prompt，需明确称开发集而非独立盲测。训练judge时应按原始question ID分组切分多轮快照，避免同题多轮分别进入train和validation。

## 六、S2G重跑：究竟训练什么、花多少钱

### 作者实际设置

S2G主方法不是训练一个巨大的新生成器，而是把轨迹标签蒸馏给 **Llama-3.2-3B judge**：2,804清洗后快照，2,523训练/281验证，3epochs，最长2048，LoRA rank16、alpha32、microbatch2、gradient accumulation8。回答与抽取使用Llama-3-8B。默认T=4、每轮6文档，附录默认K=1 gap。论文写整条流程可在2×48GB vGPU或等效硬件复制，未报告完整训练小时数。

注意：2,804是状态快照数，不是2,804道独立问题；不能据此声称训练了整个HotpotQA。作者随机快照划分和我们推荐的问题级分组划分应分别注明。

### 预算怎么算

三轮训练样本呈现共 `2523×3=7569` 次。若平均计算长度1024，共约775万token；若达到2048则约1550万。实际时间用100步短测估计，不凭显卡名字保证。

假定长度1024、含20%额外开销，仅作敏感性算术：

| 假设吞吐（不是实测） | 训练墙钟时间 | 按4090 $0.74/小时演算 |
|---:|---:|---:|
| 200 token/s | 约12.9小时 | 约$9.6 |
| 500 token/s | 约5.2小时 | 约$3.8 |
| 1000 token/s | 约2.6小时 | 约$1.9 |

平均长度2048则上述量近似翻倍。**不能把这个表叫完整baseline复现总价**：还缺环境/模型下载、索引、轨迹生成、teacher标注、验证/正式评价、失败重试和存储。teacher标签本身按约几千次请求计算，详细假设见训练审计。严格照论文调用GPT-4o-mini和使用Qwen替代是不同协议。

当前[Runpod公开按时价格](https://www.runpod.io/pricing)（2026-09-24核验）：4090 24GB $0.74/h，A100 80GB $1.59/h；套餐主存/CPU不同，存储另计，实际结算页为准。这是价格例子，不代表推荐购买或保证有货。费用不换算假定实时汇率。

最合理的采购顺序：**先API诊断 → 有价值后租1小时短测 → 根据实测扩展**。现有50元是项目API累计授权，不自动扩展为服务器租赁授权。本轮不租卡。

### 服务器配置建议（工程估算，尚未进行显存实测）

| 任务 | GPU | 主存/CPU/磁盘建议 | 备注 |
|---|---|---|---|
| 当前小候选池+Qwen API | 不需新增GPU | 当前16GB主存可做小批；注意关闭其他重负载 | 不下载全wiki、不本地训练 |
| 单独训练S2G 3B LoRA | 可先试4090/3090 24GB；48GB更宽裕 | 主存64GB，8–16核，100GB以上SSD余量 | 24GB是否照原batch容纳须短测；必要时microbatch1+累积16，记录差异 |
| 本地完整S2G推理、3B+8B+检索 | 推荐1×48GB；更忠实从论文2×48GB配置出发 | 主存64–128GB，16核以上；SSD先预留200–500GB，下载前按具体语料/索引核算 | 不保证24GB同时装下所有组件；串行加载可节约显存但变慢 |
| DualRAG非FT，7B本地 | 1×24GB适合先试BF16小batch | 主存64GB，索引较大时128GB | 推理而非训练；上下文与KV缓存另占显存 |
| 72B本地 | BF16至少约144GB仅权重；常见2×80GB仍需核KV预算，4-bit常需48GB级或多卡 | 主存128GB以上，SSD容量按权重和索引另计 | 当前没必要；单4090不适合72B BF16 |

## 七、本轮代码与实验边界

新增DualRAG独立适配器，不复制未明确授权的作者仓库代码。作者论文、论文内提示和仓库代码许可证分别处理。

开发配对：同一批8道已暴露Hotpot train/debug，BASE1和`DUALRAG_NONFT_BOUNDED_ADAPTATION`；固定Qwen快照，两轮上限、最多80模型请求、最多30分钟、子预算3元且累计不越50元。首错停止，不自动重试，不使用24道保留检查题，不拿gold决定动作。结果另写报告，不在此预填分数。

这次目的：确认流程能运行、获得可审查的对错案例和模块成本；不是证明DualRAG优于BASE、不是证明我们的记忆有效，更不是与原文榜单比较。BASE与DualRAG完整流程的Reader上下文形式不同，也有不同检索预算，本批只能作方法级功能诊断。下一阶段的归因实验必须固定Reader和预算。

## 当前建议你选择

推荐维持主线：**先把S2G式强FRESH打牢，以“可观察适用条件的选择价值”作为核心实验；复杂约束表示作为可能改进，证据窗口恢复作为独立诊断工具。**

暂时无需决定RL算法或购买72B服务器。真正需要下一轮决定的是：我们首先追求“检索前便宜选中经验”，还是接受首检索后，以更可靠的状态匹配获得增益。可以先把两者作为信息受限/信息充分的对照再选，不用现在赌一个。
