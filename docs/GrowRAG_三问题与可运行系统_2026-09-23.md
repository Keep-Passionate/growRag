# GrowRAG：三条研究问题与第一版可运行系统

日期：2026-09-23。本文是实现说明；实验结果另写，不能把设计当作已证实结论。

## 先说我们的题目

暂用工作题目：**面向查询改写的历史动作选择：什么时候值得复用？**

目标不是证明“有记忆的 RAG 总是更强”，而是在固定模型、检索底座和预算下，回答：

1. **有没有机会？** 历史动作是否产生本次强 FRESH 对照没产生的有效查询？这里的“做不到”不是理论不可能，只是明确预算内没做到。
2. **选不选得中？** 不先看检索结果，仅凭新问题和历史记录，能否选中这些机会？何时必须看首轮证据？
3. **为什么有效？** 是适用条件有用，还是提示更长、候选更多、检索更多、记住了答案实体？

Useful Memories Become Faulty 提供“不默认旧经验一直可靠”的动机；Zhao 等 ExpWeaver 提供“调用经验应当可选”的参照。二者不是同一问题。QCR 已有 with-memory − no-memory 的效用定义，因此**差值本身不是创新**。我们把同预算强 FRESH、固定规范动作、首次检索前信息约束和反例分析结合为可检验设计，而不是宣布这些模块首创。

## 当前实现的流程

```text
原问题 q
  → 查询侧路由（暂用冻结提示词的模型判断，尚非训练好的 QPP）
      BASE：原问题直接检索
      FRESH：不看历史，按原意生成另一种查询
      REUSE：选一张符合当前条件的历史动作卡，再生成查询
  → 同一个 RAG 接口：检索 → Reader 回答原问题
  → 必要信息检查：当前答案是否得到当前证据支撑？
      足够 → 放行，但仍是可错的判断信号
      不足 → 记录具体缺口 → 再生成一条查询 → 第二次 RAG
  → 停止：足够 / 重复查询 / 没有新证据或有效增量 / 总计两轮 / 错误
```

不是把三个方法全部跑完再挑答案：**在线策略先选路，再执行。** 实验中都跑，是为了事后配对比较，全部实验费用单列，不能伪装成线上费用。

当前历史库只有 PRE 卡（适合首次检索前）。第二轮不能把它们改标签冒充 POST 卡；不足时先走 FRESH。将来建立经过独立来源验证的 POST 卡，才比较同一首轮证据后的 FRESH2 与 REUSE2。

## 路由究竟怎么判断

| 环节 | 当前实现 | 为什么这样做 / 还没解决什么 |
|---|---|---|
| 硬过滤 | 排除来源同题 ID/问题指纹；阶段必须匹配；需要当前证据的卡不能 PRE 使用 | 防数据泄漏与在尚未检索时偷用未来信息，不是预测有效性 |
| 候选召回 | 原问题与卡的 query_pattern 做词重合排序，最多取 3 张 | 透明、便宜的最低可用版本；不是语义最优，更不是 QPP |
| 三选一 | 冻结模型提示词，比较 BASE / FRESH / 候选 REUSE | 查询已明确时可以 BASE；确有词义或表达调整依据时 FRESH；有可观察适用优势时才 REUSE |
| 适用检查 | 逐条返回 supported / conflicted / unknown，并给短依据 | 当前保守版把必要条件视为关键约束；未知或冲突回退。后续用消融检验是否误拒太多 |
| POST 无卡 | 直接按缺口 FRESH，不再付一次必然选 FRESH 的路由费 | 省掉没有真实选择空间的调用 |

这些状态不是模型真实置信度。没有凭空赋一个 0.9，就说有 90% 成功率。历史可靠性也不能由“相似度高”代替。

## FRESH 为什么不再只是“请改写一下”

首次检索前允许语义改写：保留实体、关系方向、时间、比较与否定约束，调整检索表达，不要求问题一定有结构性缺失。

首次检索后使用同一个必要信息判断器：

```text
requirements:
  - description: 需要确定人物 A 的国籍
    status: supported
    evidence_ids: [当前真实句子 ID]
  - description: 需要确定人物 B 的国籍
    status: missing
    evidence_ids: []
gap: 还缺 B 的国籍，不能仅凭 A 判定两人是否同国籍
next_intent: 检索 B 的国籍
sufficient: false
useful_gain: null / true / false
```

证据不是模型编写的说明，而是检索返回的原句，包含 ID、标题、句号编号和原文。判断器可以错；代码只能验证 ID 确实存在、字段一致，不能证明文本蕴含关系。

本轮比较两种 POST 修复：

- **S2G_GAP2（先跑通的具体基线）**：借鉴 S2G-RAG 缺口生成查询的机制，原 q 加最多 3 个尚未被支持的必要项描述。本地拼接，不额外调用改写模型。原作者代码优先用 target/slot；本版本用 description，judge 也由训练模型替换为冻结提示词。因此叫同底座适配，不叫忠实复现。
- **REFLECTIVE2（自由生成对照）**：同一首轮证据、同一判断器，再让模型根据缺口生成一条查询。当前观察全文和已支持部分分别标明，部分线索可用，但不能把它当完整证明。借 ReflectiveRAG 的反思修复、S2G 的结构化缺口思想；不是 Verma 原论文多候选/向量去冗余的完整系统。

两者共享 BASE 首轮，累计证据规则和两轮上限一致。比较能回答：额外一次自由生成是否值得，还是朴素缺口拼接已经足够？

后续强基线是 **ReFormeR-style POST**：先检索，结合初检文档选模式，再按规则与示例改写。它更适合历史选择比较；当前还没有完成该论文选择器训练、原数据索引与完整复现，不将我们的 PRE 词重合选择冒称 ReFormeR。

## 两种记录：本题过程与长期卡片

### 1. 本题暂存：实际 LoopState + RoundRecord + 组件审计记录

| 保存项 | 用途 |
|---|---|
| 原问题 ID 与文本 | 始终回答原问题，避免改写替换任务目标 |
| 每轮动作、选中卡 ID、实际 query | 查出究竟执行了什么，也能阻止重复查询 |
| 本轮新检索证据 | 查检索动作是否带来新内容 |
| 实际 Reader 上下文 | 查回答真正看过哪些证据，不能拿未传入内容冒充支持 |
| 必要项、状态、来源 ID、gap、增益信号 | 定位缺口、驱动下一轮；不保存完整私有 CoT |
| 答案、引用、放行决定、停止原因 | 分开“答案正确”与“有支持才放行” |
| 原始组件请求/响应、版本、费用和耗时 | 能重新检查失败发生在哪一模块 |

结束后局部状态不参与下一题。JSON 审计仍保留；**保存审计不等于跨题记忆**。已有 FrozenQueryEpisode 档案模型不强行覆盖，本次外循环用的真实结构就是上述对象与 JSON。

### 2. 跨题调用：统一卡外壳 + 规范动作正文

完整 ExperienceCard 已有激活条件、动作、来源、验证与生命周期。在线只投影成不带 gold/历史答案的 CardMemoryView：

```text
memory_id / source_query_ids / source_question_hashes
form: paraphrase 或 expand
intent: 动作想改善哪种检索表达
conditions:
  stage: PRE 或 POST
  query_pattern: 什么问题模式可能适用
  gap_pattern: POST 才允许根据已观察缺口填写
  preconditions: 需要满足的条件
  contraindications: 不应使用的情形
body:
  rewrite_rule: 怎样改变表达
  preserve: 哪些约束不能改变
success_criterion: 希望改善什么（目标描述，不是已成功认证）
```

为什么分开：选择器看“什么时候用”，执行器只拿“怎么做”；历史成功答案不传给 Reader。来源和旧执行过程在审计中可追溯，不用把整段历史轨迹塞进每次调用。

本轮存储决策：复用已有 64 道 HotpotQA 来源题产生的 6 张 PRE 候选卡；冻结快照后用于诊断，**不称可信，不训练参数，不自动晋升**。只有来源题上改善，不足以确认跨题有效；9月20日已有转移诊断也不覆盖原始来源记录。

下一阶段建新 POST 候选时，先保存成功本题修复的原始动作与条件，再在其他题上比较 REUSE−FRESH。正文保持不可变；支持/无增益/损害作为追加事件，必要时限缩范围或暂停。EMA 是以后可比较的统计平滑方法，不是本轮已启用功能。

## 这一批实验想回答什么

这是**系统集成与基线诊断**，不是三条科学问题的最终证明。原 8 道已看过的开发题继续用，24 道检查题不参与评分/调参，避免把调试题伪装盲测。

| 方法 | 作用 |
|---|---|
| BASE1 | 原 q 一轮，确定底座表现 |
| FRESH1 | 无历史的一次语义改写，检查首轮改写是否有害 |
| S2G_GAP2 | BASE + 结构化缺口拼接，低成本两轮基线 |
| REFLECTIVE2 | BASE + 缺口自由生成，检查额外生成是否值得 |
| ADAPTIVE_NO_MEMORY2 | 同路由器但无历史，最多两轮 |
| ADAPTIVE_MEMORY2 | 同路由器可选候选卡，最多两轮 |

先跑日志，再看每题各模块：候选是否对、条件判断是否对、实际 query 有没有变、是否检索到关键证据、Reader 是否利用、judge 是否误放/误拒。统计原始 EM/F1、放行后 EM/F1、gold 支持召回、修复/损害、复用次数、两轮次数、费用与延迟。

ADAPTIVE_MEMORY2−ADAPTIVE_NO_MEMORY2 是**整个策略差**；两者可能选择不同首轮查询，不自动是单一历史动作净收益。后续必须另做共享首轮、固定候选动作与相同预算的严格配对。

## 接下来的阶段与判停

1. **现在：系统闭环与无记忆强基线跑通。** 发现组件错误先修，不扩大题数掩盖失败。
2. **历史机会：独立来源建 POST 候选，冻结后同前缀对比。** 历史 k 个候选需和等数量 FRESH / 静态动作比较。若无额外机会，先改善动作来源，不训练更复杂选择器。
3. **选择与表示：执行动作固定，改变选择器看到的记法。** 规则示例、规则+条件、具体轨迹、一次抽象；随后逐项删除条件，等长无关文字作长度对照。
4. **小模型与泛化：** 有足够独立配对标签才训练检索前选择器；分实体/问题来源验证，固定未参与更新的探针题，最后才扩大官方评价。

当前不需要租 GPU，不训练 7B，不加文档层，不先上强化学习；首先要把一个能解释错误的实验做好。
