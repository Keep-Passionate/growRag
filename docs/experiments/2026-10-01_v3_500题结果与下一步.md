# GrowRAG：500题真实实验结果与下一步

最重要的结论：**现场动态修复有效，但目前没有证明历史动作库优于同能力的现场修复。** 不应据此继续盲目扩库；下一步先研究哪些适用条件帮助选对动作，并检查历史候选是否干扰了现场创建。

本轮已跑通独立来源500题 → 四个经验库 → 独立评价500题 → 封存评分、统计和审计。483题七路完整，17题技术失败。下表全部使用同一批483题，不拿各路不同分母直接排名。

## 3. 当前代码到底执行了什么

```text
离线：独立train来源 → BASE/FRESH/STATIC轨迹 → 封存后评分 → 四库 → 冻结
在线：原问题首次BM25 → 当前证据 → STOP / SELECT旧动作 / CREATE现场动作
                                      ↓
                         有限查询计划 → 再检索 → 必要时再决策
                                      ↓
                         同一个Reader回答原问题 → 审计轨迹
```

- BASE只检索一次；其他分支最多三次实际检索（含首次），最多两次规划决策，每次取六段。一张动作生成两条query会消耗两次检索。
- FRESH与记忆分支有相同的动态动作表达能力，模型及检索预算相同，不把弱改写提示当成强对照。
- 当前历史候选初筛是词汇Jaccard匹配，最多展示三个动作规格；模型再选择旧动作、现场创建或停止。**不是训练好的QPP，也尚不是纯检索前选择。**
- 算子是受限声明式查询计划，程序不执行模型任意生成的Python。
- Reader收到当前证据并回答原问题，不收到历史gold答案或事后评分。规格合法、引用合法不等于语义安全已经得到证明。
- 本题新创建动作只保存在本题轨迹，评价期间不晋升长期库；这里没有在线训练或EMA置信度更新。

代码审阅入口见[正式架构与文件阅读顺序](../architecture/2026-09-30_v3正式实验入口与运行指南.md)。

## 4. 经验库规模与已发现的表示限制

| 来源题数 | 保留记录 | 只留候选 | 本轮可调用规格 |
| --- | ---: | ---: | ---: |
| 50 | 6 | 1 | 5 |
| 100 | 10 | 5 | 5 |
| 250 | 27 | 10 | 17 |
| 500 | 60 | 26 | 34 |

这些是来源前缀规模，不是固定卡片数容量实验。50与100库向模型发布的五个规格完全相同，所以二者效果不同不能解释为新增了更好的经验内容。

独立源码及冻结库检查发现：

- 500库的60条记录均为单步；`when=[]`、`requires_bindings=[]`，没有`{constraints}`模板位置。34个发布规格的任务意图均为`lookup`。
- 已发布规格大多只有一个来源问题支持；源题答对且存在某一观察指标增量，不等于跨题迁移已验证。
- 来源筛选按整条FRESH轨迹相对STATIC的增量，加答案及风险门；不能把整题增益因果分配给每个动作。即使一个维度有增益，也可能其他维度退步。
- 内部`validated`仅指来源/结构检查后的实验发布状态；全部`trusted=false`，不能误读为已经可靠。
- 当前表达可称为“浅层查询模板复用”；程序支持多步/条件，不代表本轮模型学出的规格真的用了这些能力。

因此，当前最值得推进的不是增加记忆层数，而是检查：**动作成功时的必要条件是否在压缩成卡片时丢了。** 例如需要先知道桥接实体的动作，不能仅凭问题词汇相似就提前执行。

实际执行过历史动作的题数：M50=4、M100=2、M250=6、M500=10；其已知episode分母分别486/485/485/484。按计划500题计覆盖率分别0.8%/0.4%/1.2%/2.0%。有的episode虽检索完成，Reader仍失败；这些分母不同于483共同评分题。

不能把MEMORY500的20次整分支修复全称为“历史复用成功”：该分支多数题仍是现场创建或停止。必须看每题实际执行来源。

### 4.1 实际复用与相同输入的诊断

以下只在原封存记录上分析，没有新调用API；它们是探索性诊断，不替代预声明统计：

- 共同483题中M500实际reuse=10题：相对FRESH为1修复、1损害；其余473题为19修复、22损害。未执行reuse不等于没有历史提示干扰，也不等于FRESH输入。
- 唯一“执行reuse且修复”的题`5a7bea3d5542996dd594b847`先由CREATE补入6条新证据，后续REUSE新证据为0。因此不能把这次答对归因于历史动作。
- 唯一“执行reuse且损害”的题`5adea95055429939a52fe931`在复用后生成了重复query而停止；FRESH则继续采用不同查询。需检验重复后的策略切换及证据绑定，而非只放宽置信度。
- FRESH与M500的完整Reader请求有317题相同，其中7题EM不同（5修复、2损害）。43个整臂EM差异中其余36题请求不同；“不同”不自动代表证据有实质增益。
- M50与M100发布规格相同，其483题首次planner完整请求也全部相同，但373题原始输出文本不同、最终EM有26题不同。文本不同不都意味着决策语义不同；这些结果不能当成建库来源规模的内容效应。
- 个别EM损害涉及答案措辞而非显然事实错误，必须一起看F1与人工案例。API温度为0也不能据此假定后端严格确定。

当前没有足够证据证明“历史动作已带来了现场动作做不到的收益”。P1机会检查仍是必经步骤，而不是直接拿20次整臂修复训练一个选择器。

## 6. 下一阶段：先验证机会，再研究最少适用条件

保持原三问题，不把拼装模块本身当成创新：

1. **机会**：相同当前状态与预算下，某个历史动作真的能做出FRESH没有取得的证据增量吗？
2. **选择**：执行前可观察的条件能帮助选中该动作并拒绝不合适的动作吗？
3. **归因**：有用的是条件本身，还是更多文本、更多候选、额外检索或源题实体？

建议按你已选定的“最少适用条件”主线推进：

| 阶段 | 最小实验 | 固定什么 | 想证明什么 / 不应声称什么 |
| --- | --- | --- | --- |
| P0：当前批诊断 | 核查真实reuse题、拒绝题、同Reader输入的输出差异 | 已封存预测与政策，不新调API | 定位故障；不能凭整臂差值判断某卡的因果贡献 |
| P1：机会检查 | 在独立开发状态上，少量配对执行候选旧动作和现场动作 | 同状态、Reader、预算与动作执行器 | 存在可迁移的额外机会；oracle只作事后上界，不能线上看gold |
| P2：表示对照 | M0动作正文；M1+任务关系；M2+执行前必须已知什么；M3+不适用条件；随后逐项删字段 | 同经验来源、候选ID/数量、选择器与规范动作正文 | 哪些条件提升选对/减少误拒；不是比谁提示更长 |
| P3：低成本选择 | 先做无需大模型训练的小选择器，保留FRESH/BASE回退 | 来源/开发监督与独立评价分开 | 是否在实际成本下值得选历史；不只优化成功题分数 |
| P4：新冻结评价 | 冻结方法，在从未参与修改的新题上报告修复/损害/覆盖/成本 | 新清单、索引范围、模型及分析协议 | 新方法迁移；当前500题已用于诊断，不能再冒充未见终测 |

条件字段优先候选：目标关系/比较意图；已确定的实体与别名；动作所需桥接实体是否有当前证据；哪些词/限制必须保留；什么情况不该使用。每个字段都须从来源题执行前状态产生，不能用事后答案补写后当成执行前可得。

同一经验正文和候选数固定，新增字段的等长无关文本对照、去实体/实体分组验证、实际检索次数及tokens对照需要安排。选择准确率和收益要分开：挑中的动作质量好，仍可能不值得额外成本。

为减少Reader波动混入修复效果，新协议可预先规定：同一题、同一完整请求体及模型配置共享一次Reader结果缓存；不同请求仍正常调用，来源与评价缓存隔离。或者预注册重复采样次数。必须在实验前确定，不能看完答案后挑一次最好结果；本轮原始成绩不删除、不重算成有利子集。

允许线上不知道条件：把unknown明确呈现，而非假装满足。Unknown时应倾向现场创建或保持原查询，具体力度由开发集验证；不是“一条未知就永远禁用”。

当前100校准题属于开发，不当最终测试。新验证题需排除所有旧题ID/规范化问题哈希，并核验固定语料的覆盖；必要时另建语料并公开口径，不能静默借用当前500题gold增强索引。

已有34个发布动作并不足以证明“只学一个路由器就有稳定收益”。若P1始终找不到净机会，应先改经验提炼对象/来源条件，而不是直接强化学习选择器。

## 7. 统计解释的11项检查

| 风险 | 本轮处理或保留限制 |
| --- | --- |
| 分组方向反转 | 总体结果已报；实体/任务分组尚未验证，不推断各子类同向 |
| 群体到个体误推 | 总均值不宣称每张卡有效；真实逐题轨迹另查 |
| 筛选偏差 | 17技术失败公开；共同有效题分析不能自动推广到缺失题 |
| 碰撞变量偏差 | 不只按“实际reuse且成功”筛选后宣称整体收益；该子集仅诊断 |
| 基率忽视 | 同时报修复、损害和覆盖；不只报成功复用次数 |
| 均值回归 | 来源成功不当跨题保证；不因测试负差追改同题 |
| 幸存者偏差 | 保留全部失败与候选；未启动臂不是零分 |
| 多重搜索 | 保留预声明十个EM比较，使用Holm；其他探索分析标为探索 |
| 分析分叉 | freeze固定bootstrap种子/次数/政策；没有换指标找赢家 |
| 相关与因果混淆 | 整体分支对比不等于卡片独立因果贡献；长度/调用/随机性尚待控制 |
| 反向因果 | 评价反馈不回写当前库；来源后验筛选不冒充执行前判断 |

置信区间是在给定这次API输出和冻结库下的问题重采样，不包含模型生成波动、建库抽样不确定性；问题独立性及实体聚类未得到完整验证。
