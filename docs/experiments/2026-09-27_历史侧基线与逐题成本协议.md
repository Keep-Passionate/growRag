- Origin Skill: academic-research-suite / experiment-agent

- Date: 2026-09-27

## 1. 500题的身份

500题是HotpotQA官方train来源的一个冻结开发子集，不是全集，更不是官方测试集。源训练集有90,447条，本批约占0.55%；404 bridge、96 comparison。方法没有在这500题上训练参数或建立卡片。500题对应72,713文档的自制共享池，也不是作者的全维基检索库。

本批全部500题已尝试，492完整配对，491可评分，8技术失败、1预登记坏标注。官方dev/test未使用。500和旧32题不用于后续建库或训练选择器；已经参与机制探索，不能再把它们冒充独立最终测试。

来源：本地`data/hotpotqa/shared500_sep27_v1/manifest.json`的source_record_count、runtime问题、语料和分割哈希；[HotpotQA官方说明](https://hotpotqa.github.io/)区分train、dev、test及distractor/fullwiki。

## 2. 下一步可以先历史，但不要先堆完整系统

推荐的小步路线：

```text
冻结现有S2G–Qwen和成本账本
        ↓
审阅并迁移一个历史方法；保留独立执行臂
        ↓
相同问题/底座/预算，测历史是否有独有机会或省搜索
        ↓ 有可重复互补性才继续
固定候选执行器，学习选择原问/现场修复/历史动作
        ↓
按失败类型只改一个模块，做消融和独立冻结评价
```

基线必须先保留不改版，改进另立版本；不是两个系统一起大改后再猜哪个有用。Lucene/全库的正式对齐仍需要，但可以与历史侧代码审阅分开排期，不必先训练原S2G Judge才允许检查历史假设。当前同底座开发对照可以检验局部机制，不能替代正式环境验证。

### 历史侧三个名字分别承担什么角色

| 方法 | 适合的角色 | 不能混淆的边界 |
| --- | --- | --- |
| **ExpeL，AAAI2024** | 若只选一个真正的跨题历史经验方法，推荐先做可复现性审阅与Qwen迁移 | 官方有Hotpot经验收集、洞见提炼和评价，且Apache-2.0；原Agent环境/工具/步数不同于S2G，整系统差值不是纯记忆贡献 |
| **ReFormeR，ECIR2026** | 简洁的静态模式库对照，紧贴query rewrite | 有规则和示例，不等于在线情节记忆；原实验是TREC检索，不是Hotpot问答；公开提示式调用不能称已复现论文监督训练选择器 |
| **RRM** | 适用条件、query-only复用和维护机制的直接近邻 | 原任务为长视频多模态；不把抽取某模块的Hotpot适配叫完整原论文复现 |

本轮检查ExpeL官方代码commit `e41ec9a24823e7b560c561ab191441b56d9bcefc`，有Hotpot Search/Lookup/Finish工具环境与经验学习入口。不更新LLM参数也能学习经验；但换Qwen、冻结本地语料/检索工具后要明确记录迁移差异。原方法允许的经验内容与我们的query-only限制如果不同，必须分别命名和评价，不能悄悄删功能后称原版。

ReFormeR官方代码commit `72e52450a922bc0051b5b39c3a6307186a555137`：本轮未核到LICENSE、单独训练selector的成品权重/训练入口。公开核心读取原问题与前三篇初检文档进行模式选择，再生成改写。正式训练叙述与公开实现有差异，先做行为审计；不公开复制其完整源码/库，不把一个提示式替代叫原监督模型复现。

来源：[ExpeL正式论文](https://ojs.aaai.org/index.php/AAAI/article/view/29936)、[官方代码](https://github.com/LeapLabTHU/ExpeL)、[固定Hotpot配置](https://github.com/LeapLabTHU/ExpeL/blob/e41ec9a24823e7b560c561ab191441b56d9bcefc/configs/benchmark/hotpotqa.yaml)；[ReFormeR论文](https://arxiv.org/html/2604.01417v1)、[固定核心代码](https://github.com/aminbigdeli/ReFormeR/blob/72e52450a922bc0051b5b39c3a6307186a555137/reformer/core/reformer.py)。以上是建议，尚未声称任何历史方法已迁移成功。

## 3. Lucene与训练后的Judge分别是什么

**Lucene是检索软件，不是大语言模型。** 它建倒排索引、处理查询词，再按BM25等方法返回排序文档。BM25是打分方法，Lucene是实现搜索的工具库，Pyserini是作者使用的Python接口。相同“BM25”名字不保证相同结果，分词、词干、参数、语料和同分排序都会影响文档排名。

当前用轻量SQLite倒排实现BM25；作者用Pyserini/Lucene。两者都做检索，但尚未对齐。Lucene主要需要CPU、内存和磁盘，不意味着必须租4090。[Apache官方介绍](https://lucene.apache.org/core/)

**Judge是证据检查员，不是事后阅卷用的gold评分器。** 它看到原问题和当前证据，输出“是否够答”和“具体还缺什么”。S2G用教师标注的2,804个轮次状态，通过LoRA微调较小的Llama-3.2-3B来做这件事；不是2,804道新问题，也不是在测试时查标准答案。LoRA可以理解为只训练较少的适配参数，让通用模型更适合这项专门任务。当前我们用固定Qwen API和提示承担这一角色，没有加载作者训练后的Judge。[S2G论文与训练附录](https://arxiv.org/html/2604.23783v1)

## 4. 成本可以成为主评价轴，但记录费用不等于创新

[Adaptive-RAG（NAACL2024）](https://aclanthology.org/2024.naacl-long.389/)已经研究不同复杂度查询的检索策略选择；[AutoSearch（Findings ACL2026）](https://aclanthology.org/2026.findings-acl.1399/)直接研究最小充分搜索深度和过度搜索。因此“最多4轮改成2轮”或“用分类器省检索”不单独作为新贡献。

更具体的候选科学问题：**历史修复动作能否减少本题探索，用更少搜索得到关键证据；哪些当前可观察条件能预测这笔经验调用值得花钱？** 这是待验证命题，不保证无人做过，不预先宣称成立。

三种结果都值得如实报告：同等成本更准、接近同等质量更便宜，或记忆开销抵消全部节省。不是永远不调用记忆就算成功；必须同时报修复、损害、实际调用覆盖率和成本。

### 建议比较组

| 组 | 要回答的问题 |
| --- | --- |
| BASE1 | 不改写的一次检索能做到多少，花多少钱？ |
| S2G1 / S2G2 / S2G4 | 无历史时，只改变最大检索轮数的质量—成本变化 |
| HISTORY-2适配臂 | 同一两轮预算，历史指导是否比现场生成更有用？ |
| HYBRID-2适配臂 | 路由选择现场/历史是否优于总用其中一个，且选择本身是否划算？ |
| 静态模式＋相同执行预算 | 提升是否其实来自固定的改写规则，而不是积累历史？ |

数字是最大检索轮数，不是每题强制执行次数。S2G1仍含Judge/抽取/可能首次改写，**不等于BASE1**。原论文/作者实现基线独立保留；统一S2G执行器后的历史模块实验必须标“适配”，不将两种实验混为完整复现。

先跑无历史轮次曲线与历史独立臂；互补性确实存在才拟合路由。学习路由时用独立训练/验证题，gold只生成离线监督标签，不进入在线选择。在线不执行完所有RAG分支后再声称提前省了钱。离线机会矩阵全执行的研究成本与部署时只选一条的成本分开。

### 两轮分数必须真实生成

不能删除四轮日志末尾的成本、却继续使用第四轮答案来冒充“两轮同样准确”。S2G2必须用第二轮时可见的证据实际生成最终答案。前缀若缓存复用，要有完全相同输入/配置的执行证据；API温度0也不保证严格确定，随机漂移和缓存政策需预先固定。上轮的免费检索重放没有重新生成答案，不能当成S2G2的EM/F1。

允许先探索，再在独立冻结评价上确认；不要用当前500题挑最优阈值后称未见测试。不能只报告平均轮数；目前492完整S2G题实际平均1.858轮而非4轮，固定上限4→2不会自动节省一半调用。

## 5. 逐题账本的强制要求

本轮核实：旧500执行器已经在每题`*_execution.json`和账本中保存真实API调用。本轮新增只读导出，方便用户查看；不是倒推或估算token数量。后续新增方法必须遵守同样合同，没记录的费用标未知，不能填0。

最少字段：

| 层级 | 字段 | 为什么要记 |
| --- | --- | --- |
| 运行 | run ID、源码/prompt/模型/索引/数据split哈希、价格版本 | 防止换环境或价格后仍当同一实验 |
| 每题每方法 | question ID、offset、arm、状态、实际轮数、停止原因、总耗时 | 区分成功/技术失败/未执行，关联效果和预算 |
| 每次模型调用 | trace ID、role/round、真实输入输出tokens、返回模型、API标识、耗时、失败状态 | 分清费用究竟花在路由、改写、Judge、抽取还是回答 |
| 每题金额 | 已知费用小计、未知调用数、可得时完整总额、保守预留 | 未知不算零，预留不是实付 |
| 记忆方法新增 | 召回耗时、卡ID与版本、选择/重排/改写费用、建库run关联 | 经验检索与选择不是免费，建库不隐藏 |
| 质量 | EM/F1、证据覆盖、修复/损害、失败率 | 单看省钱会鼓励不答或永远不修复 |

tokens除输入/输出基础用量外，供应商若返回cache/thinking细项要保留；没有则null，不能编造。当前固定模型thinking关闭；未来换模型必须换配置并重新核验计费规则。本地BM25不消耗LLM token，但消耗CPU/磁盘时间；不把“无API token”叫零成本。

成本分三本账：

1. **在线服务账**：所有召回/路由/改写/Judge/抽取/Reader调用及本地检索时间，按部署的一条真实路径计算。
2. **离线建库/训练账**：收集来源轨迹、评分、提炼经验、embedding、训练选择器；失败尝试也计入。已有公开模式库的原作者构建费若未知，明确未知，而非零。
3. **研究采集账**：为了离线对照执行多个候选的全部真实费用；共享一次调用只实付一次，但各独立部署路径仍报告其应需成本，避免实验缓存伪造在线优势。

总费用概念为“建库费＋维护费＋所有在线题费用”。报告服务规模N时，可另报每题平均分摊：`(建库费 + 维护费)/N + 在线均费`；N必须明确。还应报告用到多少题后才省回建库成本。若历史每题并不更便宜，就没有正的回本点。Qwen API单价随时间变化，原始tokens与单价版本都要保存。

比较时同时给全尝试总成本和同一有效配对子集的均值/中位数/p95；失敗和未执行不可以通过换分母藏起来。不以“每个答对题多少钱”单指标取代质量—成本曲线。只有在事前确定可接受的质量下降范围、并在独立题上验证后，才说“不明显损失质量”。
