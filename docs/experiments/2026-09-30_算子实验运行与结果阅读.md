## 一条主线，两个隔离阶段

```text
官方train来源500题 → BASE / FRESH / STATIC轨迹
                         ↓ 全部题有终态后，才读取来源答案
                    评分与来源审计
                         ↓ 先分别取来源前缀，再提炼
                  50 / 100 / 250 / 500四库
                         ↓ 固定方法、库、语料、runner和题序
                      冻结证书
                         ↓ 只读库，不更新任何经验
官方dev评价500题 → BASE / FRESH / STATIC / 四种MEMORY
                         ↓ 全部题有终态后，才读取评价答案
                    同题差值 + 修复/损害 + 成本
```

这是查询侧有界循环：先检索原问题，再由当前状态选择停止、现场提出动作或执行历史动作；最多3次检索、2次决策，最后统一Reader回答原问题。它尚不是训练好的QPP路由器，也没有证明记忆有效。

## 运行入口：先预检，再显式执行

以下是入口说明，不是一键从头重跑脚本。旧题已经有claim（防重跑登记），不得清空登记后重跑。尤其不要重新执行来源0–25来覆盖失败。

在PowerShell项目根目录：

```powershell
$env:PYTHONPATH = (Join-Path (Get-Location) 'src')
$env:PYTHONUTF8 = '1'
.\.venv\Scripts\python.exe -X utf8 -m growrag.experiments.run_operator_study --help
.\.venv\Scripts\python.exe -X utf8 -m growrag.experiments.score_operator_evaluation --help
```

| 阶段入口（`python -m growrag.experiments.`后接模块） | 默认行为 | 真正执行需额外显式参数 |
| --- | --- | --- |
| `run_operator_study` | 校验数据、配置与权限，不发API请求 | `--allow-network`；evaluation还需`--evaluation-freeze`及其SHA |
| `score_operator_sources` | 查来源500题的封存完整性，不解gold | `--score-new` |
| `build_operator_banks` | 根据已评分来源试构四库，不写新库 | `--build-new` |
| `operator_evaluation_freeze` | 完整核对发证条件，不写证书 | `--issue-new`；复核已有证书用`--validate` |
| `score_operator_evaluation` | 查评价500题及七组状态，不解gold | `--score-new` |

输出目录必须是新目录。SHA是文件指纹，作用是发现误改；不是第三方认证。签发后修改runner、提示、库或索引，必须停下，不可沿用旧证书。

先查看help。完整预检通过后，才在审核过的同一命令末尾添加`--score-new`。不要把占位SHA替换成随便生成的值。

## 三种终态，不能混为一谈

| 状态 | 含义 | 怎样算分 |
| --- | --- | --- |
| `completed` | 程序拿到了完整episode和Reader输出 | 标注有效时算EM/F1；空回答保留为实际输出，不偷偷删掉 |
| `failed` | 真实尝试但技术失败 | 质量未知，已产生的调用和费用照记 |
| `failure_induced_unstarted` | 同题较早方法失败，后续方法未启动 | 无预测，不补0；不冒称已完成 |

全题有终态不等于3500条预测全部成功。当前按整题保留失败，不补跑失败题的后续方法；固定方法顺序会使后面的MEMORY组可能有更多未启动项。这是需要披露的完整率限制，不可以只展示成功子集。以后如要改为逐方法续跑，应在下一份协议预登记，不能看到答案后补齐有利分支。

## 汇总结果先看哪里

评分器输出`audit.json`（来源和完整率）、`evaluation_reports.json`（规范化逐题状态）、`feedback.json`（四项指标、标注有效性及失败原因）、`summary.json`（描述汇总）和`inference.json`（同一共同题集上的区间与精确检验）。原运行目录和预测保持原样。

阅读`summary.json`建议：

1. 各臂`planned_questions`、`attempted_questions`和`status_counts`：先知道谁实际完成多少。
2. `all_arms_common_scorable`：同一批七组都有分的题上比较，不混各方法自己的分母。
3. `paired.memory50_minus_fresh`等：只在这一对共同可评分题上看净差值、`repairs`（修复）和`harms`（损害）。各指标的题号/分母保存在`denominators`，可核查并非选择性删题。
4. `execution`：区分确实用历史发出了检索、只是选中但没执行、没有历史回退FRESH、失败所以行为未知。
5. `all_attempted_cost`和`all_branches_evaluation_cost`：包含技术失败请求。某请求用量未知时，总数为null，同时给已知小计，不能把它算免费。

例如同一对题中修复10题、损害6题，EM净改善为`(10−6)/共同题数`，而不是10题全部都算额外收益。这个数字仍不能证明适用条件是原因，还需控制候选数、提示长度、实际检索次数及实体信息。

来源/校准开销不混进评价期每臂的在线成本。全七组都跑的研究采集成本不等于未来路由器只执行一路的部署成本。

## 新增统计怎样理解

**Bootstrap（重采样）**：把同一道题的七个方法结果绑成一行，从共同完成的题中有放回抽样，重复10000次，看平均差值变动多大。它不再调用模型。这里给95%区间，不能读成“有95%概率证明记忆有效”。同一指标的十个比较共用题索引，种子和算法在评价前固定。[配对重采样的官方定义](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.bootstrap.html)

**McNemar精确检验**：专门针对同题对/错配对，考察“修复”和“损害”是否存在不对称的证据。它不是把两个方法当两组独立题。**Holm校正**则处理同时检验十个比较时更容易碰巧得到小p值的问题；不只挑最好的记忆规模来报。[McNemar](https://www.statsmodels.org/stable/generated/statsmodels.stats.contingency_tables.mcnemar.html)、[Holm](https://www.statsmodels.org/stable/generated/statsmodels.stats.multitest.multipletests.html)

一个纯数学例子：只有5题且全被修复，差值都是1，简单percentile区间会退化成`[1,1]`，但双侧精确p是0.0625。因此代码保留“退化”警告，不能拿这个窄区间自动宣布可靠优势。这不是我们的HotpotQA成绩。

`inference.json`只使用七组都能评分的共同题集，可能比某一对的描述统计题数更少，必须搭配其中自己的均值和分母阅读。失败分支的缺失不一定随机，问题又可能共用实体/文档；当前独立性尚未验证，统计量不消除这些偏差。它也不覆盖模型随机输出及换一批来源题重新建库的波动。尚无真实实验效果，不能把统计代码通过测试当论文结论。
