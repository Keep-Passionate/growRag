# 先跑ReFormeR，再研究ExpeL式经验积累

## Material Passport

- 日期：2026-09-27；用户本轮选择：先ReFormeR，后续向ExpeL发展。
- Skill：academic-research-suite / experiment-agent；代码实施与有上限真实调用均属于用户已授权工作。
- 本文是调用前冻结的开发协议；结果另存，不根据跑出的分数改写协议。
- 当前目标：建立可审查的静态模式对照，而不是马上宣称动态记忆或路由创新。

## 1. 这条路线为什么合理

ReFormeR适合先学习“把改写方法存成名称、描述、规则、示例，再选择并执行”。ExpeL适合后续学习“从不同任务的成败中提炼经验”。这是一条工程学习路线，不表示两篇论文简单组合就是创新。我们的待验证问题依旧是：

1. 历史动作是否提供强FRESH未覆盖的机会，或以更低成本取得相当效果？
2. 不看本题答案，只用执行时允许的信息，能不能选中这些机会？
3. 有用的是适用条件，还是更多提示、候选、检索、示例中的实体答案？

```text
现在：原问 → BM25初检3篇 → 十模式选一 → 规则+示例改写
                                              ↓
                           原问+改写 → BM25取6篇 → 原问回答

保留：原问 → BASE单轮回答
      原问 → S2G缺口/充分性循环 → 回答（至多4轮）

后续：独立来源题 → 轨迹审计 → ExpeL式经验提炼 → 冻结经验库
                                                    ↓
                   同预算比较静态模式、动态经验、强FRESH
                                                    ↓ 有机会再学习选择器
                         BASE / FRESH / 历史动作的执行前选择
```

现在没有训练路由器，也没有把本批结果自动存为历史经验。

## 2. 本轮实现边界

作者固定提交：`72e52450a922bc0051b5b39c3a6307186a555137`。[公开仓库](https://github.com/aminbigdeli/ReFormeR/tree/72e52450a922bc0051b5b39c3a6307186a555137)与[论文](https://arxiv.org/html/2604.01417v1)分别核验，不能把它们的细节混为一谈。

| 事项 | 原始资料与本轮处理 |

| 模式 | 读取作者发布的十模式，不重新训练、不修正作者示例；固定SHA |
| 选择 | 实际执行作者`select_best_pattern`；原问+初检前三篇正文+模式库；不是已训练小selector |
| 改写 | 实际执行作者`apply_pattern`；原问+选中规则+示例；公开代码此步不再接收文档 |

| 生成设置 | select/rewrite上限512、temperature=0、top_p=1、thinking=false。论文512/1.0，public core默认500/0.1；差异明确保留 |
| 检索 | 现有共享SQLite BM25，非作者Lucene全库；初检3篇只给selector，二检6篇给Reader，不额外合并初检证据 |
| Reader | 与既有BASE/S2G相同作者Answer提示和容量协议；回答原问题，不回答改写后的新问题 |

| 选中内容 | 记录完整返回及其是否与库中模式完全一致，不暗中把生成规则替换为我们自己的“更好”规则 |
| 许可 | README有MIT徽章，但本轮未见完整LICENSE，GitHub API license=null。作者文件仅ignored external本地引用；公开仓库不复制提示/示例库/源码 |

此版本应称“ReFormeR公开方法的Qwen–Hotpot迁移＋论文hybrid查询”，不是原论文TREC数值复现，也不是ExpeL复现。

## 3. 固定100题开发协议

- 使用既有`data/hotpotqa/shared500_sep27_v1`的offset 0–99，不按答案或收益挑题。
- manifest SHA：`2fb117c03b64be3ab12398a297c82ce3315600c14e33f5dcd56c5c6c5c59e064`。
- 100题来源是官方train，已是开发题；不是官方dev/test，也不是100个独立最终测试样本。这500题和旧32题都禁止回流建库/训练选择器。
- 静态模式来自作者发布的MS MARCO来源库，不含本批Hotpot监督；仍不能声称与Qwen预训练不存在污染。
- 先5题格式/执行验收，再至多25题一批；后续是否继续由协议完整性决定，不由准确率决定。首错封口，不覆盖、不自动重试。
- 每题正常最多3次API：选择、改写、回答；2次BM25。初检不是免费，也不能称严格检索前QPP。
- 调用前保存源码、作者文件、manifest、配置、批次题号、预算快照；输出落盘后才读gold评分。
- 本系列预留子限3元，各批从共同子限扣除；项目仍累计50元。单批硬超时30分钟、单请求60秒内。未知费用保留预留，不补0。
- 先沿用已冻结的BASE1/S2G4输出节省开发费；这是缓存对照，非新同期随机试验。所有分数用相同完整题交集；技术失败、未运行与标注异常分别报告。

### 应报告什么

EM/F1、相对BASE/S2G的修复数和损害数、支持原文召回、所选模式分布、模式JSON回退/被模型改写情况、前后query长度、检索时间、逐角色token/费用/耗时。

“BASE或S2G或ReFormeR里选对答案”的oracle只是事后机会估计，不是已经能部署的选择器。不同方法的检索轮数/抽取/提示均不同，此比较不是单因素记忆消融；要证明确实是历史的作用，下一阶段必须加同预算、同候选和同提示长度控制。

## 4. Lucene和本地7B各解决什么

- **Lucene是索引与搜索软件**，BM25是其中一种打分方式，Pyserini提供Python接口。运行它主要用CPU、内存、磁盘；7B不是它的替代品。[Lucene官方说明](https://lucene.apache.org/core/)
- **Judge是判断角色**：判断证据是否足够、还缺什么。可以用本地量化7B来担任，但量化只是压缩模型，不会自动教会它这些判断。
- S2G用专门微调的轻量Judge，其附录也比较了3B与4B骨干。换一个未训练7B即使更大，也不能视作等价复现；须检验“错误地认为足够”的比例、缺口是否可执行和端到端质量。[S2G论文](https://arxiv.org/html/2604.23783v1)
- Qwen官方7B基准在其A100/Transformers环境、batch1、输出2048tokens条件下：AWQ短输入约5.39GB，6144输入约6.39GB，14336输入约7.92GB；BF16对应约14.38/15.38/16.91GB。这些不是本机保证值，系统显存、后端和KV缓存都会影响。[Qwen官方基准](https://qwen.readthedocs.io/en/v2.5/benchmark/speed_benchmark.html)
- 因此8GB卡可以考虑短上下文4bit试验，但长上下文较紧；24GB卡更适合稳定7B推理/精度对照。显存和普通内存不能简单相加。本轮CPU+API够用，不租4090、不下载大权重。

## 5. 向ExpeL发展时，先做什么

[ExpeL（AAAI2024）](https://ojs.aaai.org/index.php/AAAI/article/view/29936)是经验提炼的重要参照；[官方代码](https://github.com/LeapLabTHU/ExpeL)的原Hotpot工具Agent流程与我们底座不同，移植经验机制后要明确标为adaptation。

先从互不重合的来源题收集可追溯轨迹，提炼**不携带目标题答案**的操作建议；冻结后到新题检验。不要第一步就循环改写老卡或学习路由。保留三组：作者静态模式、未经抽象的具体经验、一次性提炼的规则＋示例。经验额外价值分别与同预算强FRESH和静态模式比较。

每条候选记录至少有：来源ID/版本、观察状态、动作规则、不可改变的限制、可观察适用条件、原始执行指针、支持与退步记录。字段是待消融的假设，不是全部默认必要。若模式复用大量伤害原本正确的题，优先检验“何时不该套用”和实体/约束保真；若无独有机会，不急着训练复杂路由。

## 6. 审查代码的入口

1. `src/growrag/experiments/reformer_api.py`：两次检索、选模式、改写、同Reader，及作者SHA加载边界。
2. `src/growrag/experiments/run_reformer_pilot.py`：题目范围、源码冻结、真实API、逐题日志、错误停止与事后评分。
3. `scripts/audits/analyze_reformer_pilot.py`：固定题交集、修复/损害、逐角色费用和可审查案例。
4. 对应tests：都是离线合成检查，不能当真实实验成绩；作者快照不存在时集成检查会明确skip。
