## 目标与固定设计

验证模型能否在当前问题、当前可见证据和已编译动作之间，给出可审计的 T（对象类型）、R（子目标关系）、P0（本地来源匹配）、P1（实体角色）观察。这里只测试接口与人为标注一致性，不能证明历史经验提高回答准确率。

## 接口如何变简单

1. 本地按问题 Q → 可见证据 E 的标题/正文 → 编译查询 A 的顺序生成编号目录，忽略空白字段。
2. 模型请求有原 8 键 input、紧凑 `ref_catalog` 和明确列出的 `model_checks`。目录只给编号与来源位置，不重复长正文；不包含行号、配对关系、预期标签、历史测试结果。
3. 模型给每项返回 `kind/slot/status/reason/ref_ids`。只许选择确实存在的编号，不许重复或自行发明。
4. 本地按所选编号展开为实际来源和完整可见字段，再用旧观察规则校验。不会自动补 Q、E 或 A；不会改 status/reason。P0 仍本地计算，未知仍未知。
5. 实际 raw-v3、完整本地目录、实际请求、展开后的 v2 响应、最终报告分别记录并 hash 绑定。失败同样保留原响应，不能只留下成功解析。

每个编号对应整个可见字段，引用粒度比 v2 的短句粗。同一字段内两个冲突句不能变成两个不同编号，重复编号不算两个证据。不会因此放宽旧 `conflicting_evidence` 的要求；如出现这种失败，按原样报告。目录是溯源工具，不自动证明整段文字支持该结论。

语义定义不变，模型提示更明确地列出待判项和引用要求属于此次接口设计变化，不能声称“只有 token 编码变化、语义表现一定相同”。
