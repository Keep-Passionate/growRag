## 1. 目标与实现边界

本阶段问：在**同一个已填、硬合同合法的第一条历史动作**上，T/R/P0/P1 能否拦住有害动作而保留有用动作？检查对象是动作实例，不是抽象卡片的永久好坏。

## 3. 条件元数据 sidecar：一次性、无题目结果

`CardSlotContract` 放在新文件，原 `HistoryCard/OperatorSpec` 不变。库 fingerprint、卡 ID/version、原正文 hash、sidecar hash 一起冻结。

```text
CardSlotContract = {
  schema_version, card_id, card_version, card_action_sha256,
  slots: [SlotContract],
  authoring: {mode, source_fields, authoring_version, reviewer, reviewed_at}
}
```

首版 `authoring.mode=manual_action_text_review`。只读该卡的 `name/description/transformation_rule/operator_spec/conditions`，不读本批问题、gold、历史成功率、当前预测或 shadow 结果；不用示例中的实体、答案代替普适条件。也可另立“一次性模型抽取＋人工审核”版本，但必须在抽题／观察前封存原输出和改动记录并计费，不能逐题临时抽取条件。

每个 `SlotContract` 按 kind 使用严格键集合：

- `entity`／`literal_constraint`：`{slot,kind,required_type,requires_current_source,target_role}`；`required_type`、`target_role` 为非空字符串或 null，未知不能写成支持；`requires_current_source` 为 bool 或 null，null 表示尚未确立要求。
- `relation_text`／`control`：`{slot,kind,requires_current_source:false}`；它们参与实际动作 R，不要求普通检索词逐字见于证据。若发现其值实际携带事实实体，应在**sidecar 冻结前**重分类或改为 unknown，不运行中补分类。
- `free_query`／`unknown`：`{slot,kind,requires_current_source:null}`；首版不拆实体，明确未覆盖。

`slot` 是实际路径，例如 `gap.entity`、`gap.year`、`binding.director`。每个已声明 gap/binding 恰好有一个条目；不能只登记名字含 entity 的字段。`literal_constraint` 用于 year 等语义约束值，保留其原 Python/JSON 整数类型；规范十进制字面量仅用于 P0 检索，不改写实际参数。

类型要求只能是正文确实支持的必要要求。例如 “birth year” 不自动成为 person-only；“city” 变量名也不足以将一切其他地理对象硬判错。`required_type=null` 产生 T unknown。`target_role` 是待核关系／目标角色描述，不是“此值已扮演该角色”的结论；通用卡可写“原问当前子目标所需对象”，再由当前问和证据判其 P1。

## 4. 两层输入：完整执行快照与紧凑观察输入

### 4.1 本地 FixedActionSnapshot（执行权威，不直接发给模型）

保存 question、初检完整 Evidence tuple、旧 `visible_evidence()` 结果、搜索历史、剩余预算、候选排序、SELECT/FILL 或 rewrite 原始响应、选中卡 ID/version、库／sidecar／源码／语料／索引 hashes、完整 `ActionProposal`、旧编译器的全部 requests，以及 aliases→完整 ID 映射。

执行器只能消费这份已冻结 proposal 和 query，不能消费观察器返回内容。先做旧硬合同校验；不合法记 `action_contract_failure`，不请求语义观察、不“补成合法”。无选卡是 `no_selected_action`；零编译请求是 `empty_plan`；与原问重复查询是 `repeated_query`，都不冒充 verifier 拒绝。

自然题第一步传 `decision_number=1, remaining_retrievals=1`，只调用一次历史 planner。编译出的请求必须全部能在 1 次额外检索内执行；多请求超预算照旧拒绝，不能截取第一条以改变卡能力。当前 34 个模板恰好都是单 step，但仍用旧编译器检查，不依赖该偶然事实。

### 4.2 与合成 fixture 共用的紧凑输入

`schema_version=growrag-a1-check-input-v1`。顶层严格为以下八个键，不放入 pair_id、variant、预期标签、自然题答案或历史正确率：

```json
{
  "schema_version": "growrag-a1-check-input-v1",
  "original_question": "In what year was the author of Glass Harbor born?",
  "visible_evidence": [
    {
      "source_id": "E1",
      "title": "Synthetic current evidence",
      "text": "Nora Venn is the sole author of Glass Harbor.",
      "window": {"text_start": 0, "text_end": 45, "original_text_chars": 45}
    }
  ],
  "previous_queries": [],
  "remaining_retrievals": 1,
  "proposal": {
    "spec_id": "synthetic_typed_relation_lookup",
    "spec_version": "1",
    "template": "{entity} {relation}",
    "gap": {"entity": "Nora Venn", "relation": "birth year"},
    "bindings": [],
    "compiled_queries": [{"step_id": "lookup", "source_id": "A1", "query": "Nora Venn birth year"}]
  },
  "slot_contracts": [
    {"slot": "gap.entity", "kind": "entity", "required_type": "person", "requires_current_source": true, "target_role": "author of Glass Harbor"},
    {"slot": "gap.relation", "kind": "relation_text", "requires_current_source": false}
  ],
  "required_checks": [
    {"kind": "T", "slot": "gap.entity"},
    {"kind": "R", "slot": "action.lookup"},
    {"kind": "P0", "slot": "gap.entity"},
    {"kind": "P1", "slot": "gap.entity"}
  ]

```

此示例仅示意结构，T 的 person 支持不能由 “author” 一词或问题前提自动升级；观察器仍按固定说明和可见证据判断。例内 text 长度、窗口边界须由构造器计算并测试，不让模型填写。

对自然题，`proposal.template` 是单个可执行 step 的原模板；rule 用旧临时 spec 的 `{query_text}`。完整 spec、GoalContract、card_id 和语料身份仍保存在本地快照，通过输入 hash 绑定，不需要模型抄写。bindings 保留 `name/value/evidence_ids` 结构，在该观察投影内把 ID 精确映射为 E 标签；原 proposal 的完整 ID 不变。

可见正文先用**原完整 ID**执行原窗口算法，再替换 E 标签；不因 alias 更短而增加正文。title 也是原算法的可见 title。紧凑 window 的三个字段是旧完整窗口的投影，其他截断标记仍在审计快照。不能读取被截掉的尾部来填 T/P0/P1。

canonical JSON 固定为 UTF-8、`ensure_ascii=False, sort_keys=True, separators=(",",":"), allow_nan=False`。`input_sha256` 对完整紧凑 input（不含 hash 自身）计算。请求 envelope 为 `{input_sha256,payload:<input>}`；同时在审计中保存 `snapshot_sha256`。运行前检查二者的派生关系，不能靠模型回显 hash 证明输入未变。

## 5. 输出、引用、unknown 与 conflict

### 5.1 模型输出只做 T/R/P1；P0 由本地计算

公开纯函数建议如下：

```python
prepare_check(observation, proposal, *, selected_card, slot_contract, compiled_plan) -> PreparedCheck
observe_p0(prepared) -> tuple[Check, ...]
observer_request(prepared) -> list[dict]
resolve_check(raw_response, prepared) -> ObservationReport
decide_check(report, *, policy) -> GateDecision
```

`PreparedCheck` 同时携带紧凑 payload 和本地 audit snapshot，不可变／深拷贝。`required_checks` 是最终合并报告的精确 `(kind,slot)` 集合：每个事实实体／字面量约束槽有 T/P0/P1，每个编译 step 有 R；多个实体分别判断，R 的 `action.<step_id>` 对照完整联合查询。无实体的空列表不是通过。

free_query/unknown 槽也保留 T/P0/P1 三项，但首版本地固定为 unknown，reason=`uncovered_free_query`／`unclassified_slot`。relation_text/control 的 T/P0/P1 不在 required_checks；以显式 `dimension_not_applicable` coverage 行记录，而不是填 supported。

语义 API 所需键集合确定性等于 required_checks 减去 P0 和上述固定 unknown 项。一次响应检查所有剩余 T/R/P1，不为每种政策、每一维再次调用。P0 本地结果只在合并时加入，不接受模型覆盖。

模型输出严格为：

```json
{
  "input_sha256": "64位小写SHA256",
  "checks": [
    {
      "kind": "P1",
      "slot": "gap.entity",
      "status": "supported",
      "reason": "target_role_supported",
      "refs": [{"source_id": "E1", "field": "text", "start": 0, "end": 45}]
    }
  ]
}
```

上例只展示一项形状；实际输出须与该请求的语义键集合完全相等，每项恰好一次。缺项、多项、重复键、未知枚举、非规范引用、额外字段、字符串化数值、错误 hash 均为 `observer_contract_failure`，不降成 unknown，不重试，不据此产生业务拒绝。原始文本与实际费用保留。观察器合同失败按草案停止该阶段，不能套用 A0 的“可继续下一臂”政策。

最终 `ObservationReport` 合并本地 P0／固定 unknown／模型 T/R/P1，并给每项添加 `producer=local|model`、引用解析后的原文与 coverage；原始模型内容另存。只存结构化理由，不索取思维链、隐藏推理或长篇自我解释。

### 5.2 引用只有精确字符跨度

- `Q.text`：原问，独立命名空间；不是真实文档 EvidenceID。
- `E1.title/E1.text` 等：此次冻结可见标题／正文。
- `A1.query` 等：实际编译的 query，仅允许 R 引用；不是当前事实来源，不能用于 P0/P1。
- start/end 必须为真正整数，按原字符串 Unicode code point 的左闭右开区间；`0 <= start < end <= len(field)`。不按 UTF-8 bytes 或 UTF-16 单元计数。
- source_id 必须逐字等于本次 allowlist；拒绝 `e1/E01/[E1]`、重复跨度、过期映射、未知字段。解析器不修引用、不猜 offset，不用 fuzzy match。
- T/P1 的支持或明确矛盾至少有一条 Q/E 引用；R 的关系相容／不相容须引用 Q 与 A；桥接 R 另引用必要的当前 E。引用合法只证明字符串存在，不证明语义。
- `unknown/missing_type_requirement` 等没有证据要求可 refs=[]；`unknown/conflicting_evidence` 至少引用两段相互不相容的当前材料。把同一事实复制两遍不算冲突证据。
- P0 absence 的“没有出现”不能伪造正向跨度：由本地全允许窗口搜索得到 `refs=[]`，记录被搜索 source 集合、算法版本和 input hash。

### 5.3 固定语义规则与理由枚举

| kind | supported | contradicted | unknown |
|---|---|---|---|
| T | `expected_type_supported` | `expected_type_conflict` | `missing_type_requirement`、`insufficient_type_evidence`、`conflicting_evidence` |
| R | `direct_goal_relation`、`permitted_intermediate_subgoal`、`comparison_side_subgoal` | `relation_conflict`、`direction_conflict`、`constraint_conflict` | `ambiguous_subgoal`、`conflicting_evidence` |
| P0（local） | `current_value_occurs` | `current_value_absent` | `source_requirement_unknown`、`uncovered_free_query`、`unclassified_slot` |
| P1 | `target_role_supported`、`question_target_supported` | `target_role_negated`、`exclusive_role_conflict`、`direction_conflict`、`constraint_conflict` | `missing_role_evidence`、`ambiguous_role`、`conflicting_evidence` |

固定 free_query/unknown 的 T/P1 也允许对应覆盖理由。所有 reason 仅能出现在上述对应 status/kind；不接收自由文本理由。`required_type=null` 强制 T unknown；`requires_current_source=null` 强制 P0 unknown；不把检查缺失编码为失败或通过。

P0 使用当前逻辑的一致规范：casefold、空白折叠、Unicode `(?<!\w)…(?!\w)` 词边界；Ann 不匹配 Joanne。不加别名、翻译、词干或模糊拼写。自然题同义实体未逐字出现可导致 P0 contradicted，必须在局限中报告，不把词面不存在等同语义虚构。跨度要通过规范化字符→原字符串映射回原文，不能拿规范化 offset 索引原字符串。

P1 不采用封闭世界假设：“没说 Nora 写过”是 unknown；“Nora 不是作者”或“另一人是唯一作者”才支持 contradicted。提及姓名或它是 person 均不证明作者角色。相同优先级资料同时支持和否认时记 `unknown/conflicting_evidence`，不多数投票、不偏信第一条，也不新设来源优先级。

原问可证明该名字是问题要求的目标／比较侧，但不能证明未知身份、出生日期等事实。R 允许查询尚未知桥接关系，例如问作者出生年时先查作品作者；无需一条 query 解完整问题或同时查比较双方。

**R 不相容不是“检索必然无用”的证明。** 例如查询 death year 可能检索到同时写有 birth year 的传记。P1 错角色的查询也可能偶然找回所需页面。因此语义 conflict 只是可检验的拒绝信号；其答案后果必须看全部合法动作的真实 shadow，不能用观察器自己的标签给自己的效用打分。

### 5.4 政策纯函数

对选定维度集合：任一 required check contradicted → `reject`；否则任一 unknown → `allow_uncertain`；全部 required check supported → `allow`。未知覆盖不是零检查。返回同时带 `decisive_checks`，仅列精确 `(kind,slot)`，不改写 proposal。

固定派生政策：原样放行、T、R、P0、P1、全条件、strict_unknown_reject；另报告全拒/BASE。strict 策略将 unknown 视为拒绝仅作敏感性分析。不同政策共享一次 ObservationReport，不能各自重新生成语义判断。拒绝不重新选卡、不重新填参、不转 FRESH，答案路由到相同初检 BASE Reader。

## 6. verifier-before-shadow 与 fixed-first-action 时序

```text
同一初检 top6 / 预算余1
  → 旧 body8 + 一次 SELECT + 最多一次 FILL/规则改写
  → 旧硬编译（完整 batch；不截 step）
  → FixedActionSnapshot + PreparedCheck 封存
  → 本地 P0 + 一次 T/R/P1 观察 → ObservationReport 封存
  → BASE Reader + 每个合法固定动作各一次 shadow 检索及 Reader
  → 全40题终态、全部预定诊断与费用封存
  → 才读标签，回放所有固定政策
```

语义检查完成并封存之前，不能生成该动作的候选检索结果或 Reader 答案。若提前运行过，标记 `shadow_preceded_observer`，排除该观察的盲态声明，不能仅改时间戳来补救。BASE Reader 也安排在观察封存之后，避免在同进程里让生成选择的人先看到答案。

调用前、执行前、封存时都复核快照、库、sidecar、索引、窗口与 proposal hashes；同 evidence_id 改文本、增加证据、预算增大、重新编译 query 不同均停止。观察输出只控制离线 `BASE` 或 `shadow` 的路由，不回写源卡。

所有硬合同合法已选动作都做 shadow，包括 verifier 拒绝和 unknown 的动作；拒绝不得省略其后果。无选卡、硬合同失败、观察失败、检索失败、Reader 失败、预算停止是不同终态。失败／缺失不自动当作 BASE、零分或负样本。没有 shadow 的动作不能计入已测误拒率。

政策回放键为 `(question_id, initial_snapshot_sha256, fixed_action_sha256, observation_sha256)`，不只按 query 文本复用。Reader 共享必须是完整消息、prompt/model/config、可见窗口与 alias 映射一致；只“答案相同”或“证据 ID 集合相同”不够。按预注册缓存实际少发的请求与事后控制 Reader 随机性的替换严格区分。

## 7. BASE、强 FRESH、历史验收：预算与成本不要混称

自然题保留同一初检 BASE、强 FRESH 和固定历史动作。强 FRESH 使用 A0 冻结的 focused 提示，仅允许一次决策、一次额外检索；所有非 BASE 臂 top6、总检索上限2、Reader一致。FRESH 不读历史卡／sidecar，不因历史 rejected 而临时加一次调用。

| 项目 | BASE | 强 FRESH | 历史固定动作＋观察 |
|---|---:|---:|---:|
| 初检 | 同一个1次 | 共享 | 共享 |
| 额外检索上限 | 0 | 1 | 1（研究 shadow 对全部合法动作执行） |
| 规划请求上限 | 0 | 1 | SELECT 1＋FILL/rewrite 1 |
| 四维观察请求上限 | 0 | 0 | T/R/P1 合并1；P0本地 |
| 最终 Reader | 1 | 最多1个新输入 | 最多1个动作后新输入；拒绝政策路由 BASE |

这保证的是**相同检索预算上限和证据／Reader条件**，不是已消费人民币或模型调用数相等。BASE 无需人为烧掉预算；历史观察多出的费用不能隐藏成免费安全层。

费用接口至少分开：`research_actual_usage`（所有生成、观察、BASE、shadow、替代诊断和失败调用）与 `policy_projected_usage`（按固定缓存及政策路由估计）。研究实际数来自真实 HTTP；政策估算必须带 `counterfactual=true`，不能从总账退款。

若以后声称“等模型成本下超过强 FRESH”，须另行预登记 FRESH 的等总 API/token/CNY 上限策略和调用分配，冻结后真实执行；不能仅让 FRESH 的单次上限与历史相同便称严格等成本。当前 A1 先报告每题真实费用、预算上限、答案收益与成本曲线，不从成本不同的比较推出记忆独有收益。

## 8. 与 32 条 fixture 的交接及验收

与数据准备方约定：fixture 外层严格 `{row_id,pair_id,variant,input,expected}`，input 使用第4节紧凑 schema；观察器仅接收 input 的哈希 envelope。pair_id/variant/expected 不进入请求或模型可见 filename。`expected` 记录精确检查键的预期状态和派生 gate，不是模型输出。

当前 fixture 为32行／16对，canonical input 去重后为30份：`07A=08A`、`01A=16A`。重复的共同基线保留各自配对身份，仍按草案逐行只观察一次、按32行应用原门槛；不得宣称32份独立输入、以去重改变门槛或把两次结果当独立证据。这32行共用一个合成 typed-relation 模板，不等于已实测34个真实模板与10个规则。44卡登记完整性、free-query固定unknown与各维实际覆盖须另由机械测试及自然动作报告。

草案第10/12/13组的角色交换必须在 A/B **共同保留明确唯一性**（sole author/director/1990 producer），或使用明确否定，才让 B 的 P1 contradicted 有根据。仅有“另一个人写作／导演／制作”并不排除共同作者／共同导演／共同制作人，不能从 role omission 硬判矛盾。该澄清只使合成事实符合既定 unknown 规则，不根据新自然题结果改标签。

first-pass 合成结果原样封存；局部 JSON 合同失败不能人工修成正确标签。32 条语义例与机械单元测试分开：测试合计、模型实际作答数、拒绝数、unknown、接口失败和真实费用分别报告。继续门槛沿用草案，不把 fixture 测试全过称为模型语义全过。

最低机械测试清单：

1. 44 卡完整身份覆盖、34 个 gap-only 模板可投影、10 个规则不漏报；multi-slot 不被合并。
2. 一次固定编译／不重复规划；硬合同失败在语义请求之前；计划预算不足不截断。
3. alias/window 与完整 ID 旧窗口一致；尾部不可见，Ann/Joanne、不规范编号、重复／过期引用都可检出。
4. 严格键／enum／hash／span／required_checks 集合；P0 不可被模型覆盖；unknown 不转 bool true。
5. 明确否定／唯一关系才矛盾；无角色证据 unknown；冲突 unknown 保留两组引用。
6. R 允许合法中间子目标、比较单侧；semantic mismatch 的 shadow 仍实际执行。
7. 所有可执行动作含拒绝项都先封存观察再 shadow；不按观察“好坏”挑动作测后果。
8. 无选卡不算 verifier 拒绝，失败不伪造 BASE 成功；全拒政策答案恒等 BASE。
9. 被拒有用动作进入误拒统计；无有用动作时收益保留率不可估计，不写100%。
10. 完整研究成本包含观察器、失败和 shadow Reader；未知费用保留预留，不能归零。
