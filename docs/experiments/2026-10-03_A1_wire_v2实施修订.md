## 1. 目的、版本与不变项

减少与研究目标无关的长SHA回显和字符offset抄写负担。未来观察器wire版本固定为 `growrag-a1-observer-quote-v2`：SHA由本地绑定，模型引用由唯一原文quote确定性解析。T对象类型、R子目标关系、P0当前可见词面来源、P1角色／方向／约束的定义、理由枚举和unknown政策全部继承上游。

不修改已经执行或失败的任何旧响应，不用新解析器重判A0。新fixture是 `a1_conditions_v2`，外层元数据schema升级为 `growrag-a1-conditions-fixture-v2`；行的五键合同及模型可见八键input仍为 `growrag-a1-check-input-v1`。fixture版本、input schema与observer wire版本分别登记，不混为同一件事。

**唯一quote的可接受引用范围比offset更窄，不是无损等价。** 旧offset可直接选中重复短语的某一次出现；新wire无法仅凭该重复短语决定位置，模型必须自己引用更长且唯一的原文，否则记机械合同失败。不得把这种覆盖差异解释为语义能力提高或把失败转成业务拒绝。

## 3. 请求与响应：模型不回显SHA或offset

本地PreparedCheck仍保存不可变完整快照、紧凑input及其SHA。发送给模型的任务数据仅为input，不再使用含 `input_sha256` 的回显envelope；row_id、pair_id、variant、expected、哈希表和本地修订记录均不进入提示或模型可见文件名。

一次响应的顶层严格只有 `checks`；每项仍严格为 `kind/slot/status/reason/refs`。每个ref严格只有 `source_id/field/quote`。例如以下只展示一项的形状，实际集合仍须与本次所需语义检查集合完全相等：

```json
{
  "checks": [
    {
      "kind": "T",
      "slot": "gap.entity",
      "status": "supported",
      "reason": "expected_type_supported",
      "refs": [
        {"source_id": "E1", "field": "text", "quote": "Nora Venn is a person."}
      ]
    }
  ]
}
```

模型输出SHA、start/end、未知字段、重复JSON键、错误类型、未知枚举、多报／漏报／重复检查仍是 `observer_contract_failure`。语义检查集合仍为required_checks减去本地P0和固定unknown项；模型不能输出或覆盖本地P0。未知状态合法，不将缺项或格式失败降级为unknown。

本地审计绑定至少保存：input_sha256、snapshot_sha256、wire/prompt/schema/model配置身份、本地唯一调用身份、实际发送请求、原始响应及二者对应关系。供应商返回请求ID时一并保存；没有时不得伪造。解析始终使用该次调用的冻结PreparedCheck，而不是响应携带的身份或“最近一次请求”。

发送前、响应解析时和封存时复核input与快照派生关系；请求串线、过期alias、窗口改变或proposal改变均失败。模型回显SHA本来也不能证明没有串线，移到本地后更不能省略这些检查。原始wire和确定性解析结果分开保存，不重试、修补或回写原始响应。

## 4. exact unique quote规则

1. quote必须是真正字符串、非空且不是纯空白。可以保留实际存在的前后空白，但不得先trim再匹配。优先引用简短原文；没有隐含的自动截短、补长或未登记长度阈值。
2. 只在ref指定的、此次允许的**单个字段**中逐字查找。不得跨字段拼接、访问完整文档尾部、补查其他文档、借旧响应或示例寻找摘录。
3. JSON解码后的quote按Unicode字符逐字匹配。不得大小写折叠、空白折叠、Unicode规范化、实体展开、别名／翻译、fuzzy match或拼写修正；这与P0已有的本地规范化搜索是两个不同算法。
4. 必须恰好出现一次。零匹配或多匹配均失败；统计包含重叠出现，例如 `aaa` 中 `aa` 出现两次。不能默认取第一个，也不能偷偷选择“最符合语义”的位置。
5. source_id必须逐字来自当前allowlist；拒绝 `e1/E01/[E1]`、未知／过期ID。Q仅允许text；Ei仅允许此次可见title/text；Ai仅允许实际编译query。字段名也严格匹配。
6. T/P1仅能引用Q/E，不能把A.query当当前事实来源。R可用Q/E/A；supported或contradicted的关系判定仍须引用Q与A，合法桥接另须引用必要的当前E。沿用原status/reason对应及unknown引用要求。
7. 同一个check.refs内重复的已解析 `(source_id,field,start,end)` 失败，不自动去重；同一 `(kind,slot)` 检查重复失败。不同检查合法复用同一证据不属于重复项。
8. 解析器在唯一匹配后确定性导出左闭右开的start/end，单位为Unicode code point，不是UTF-8字节或UTF-16单元；核验原字段切片恰好等于quote。保存quote、派生跨度与原文，不改模型原始文本。
9. `unknown/conflicting_evidence` 仍需要至少两段语义互不相容的当前材料；复制相同事实、两个不同quote或两个合法跨度本身不证明冲突。引用合同成立也不证明内容支持模型的语义判断。

上述任何机械失败均保留原始输出、费用和独立失败终态，按A1原停止规则处理，不套用A0v2局部失败后继续其他臂的政策。本文不改变失败成本或停止门。

## 5. P0的false分支：不适用，不是假支持或unknown

补全 `entity/literal_constraint` 槽的 `requires_current_source` 三分支；类型必须是严格bool或null：

| 值 | P0处理 | gate与统计 |
|---|---|---|
| true | 保留原本地词面搜索；出现supported/current_value_occurs，缺失contradicted/current_value_absent | 纳入required_checks、gate和相应P0检查分母 |
| null | 保留unknown/source_requirement_unknown；free_query/unknown的既定覆盖理由和优先级不变 | 仍按既有unknown政策处理 |
| false | 不创建P0语义check；本地coverage记not_applicable/source_not_required | 不进入required_checks或gate，不进入“已判断P0事实来源”的分母；单列不适用数量 |

false的本地coverage记录至少为：

```json
{"kind":"P0","slot":"gap.year","producer":"local","applicability":"not_applicable","reason":"source_not_required"}
```

该记录不带supported／contradicted／unknown的status，不伪装模型观察。T和P1仍照常保留，false不证明对象类型或目标角色正确；原required_type=null等规则不变。relation_text/control仍沿用原“不适用”覆盖，不新增事实检查。

因此不需要给P0的supported/contradicted/unknown枚举硬塞一个“无需来源”理由，也不会让strict_unknown_reject无端拒绝明确不适用的项。不得将“不适用”混入已核查来源的成功数。当前32行entity槽均为true，本补全不改任何fixture required_checks或expected；false/null回归必须另作机械测试，不算新增语义例。
