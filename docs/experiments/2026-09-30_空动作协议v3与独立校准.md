# 空动作协议 v3：先解决输出歧义，再扩大实验

## 先读这几句

这是**执行协议修复**，不是新研究贡献，也不是问答效果提升的证据。v2 校准在第4个启动问题的 FRESH 第二次决策失败：模型说停止，却仍填入动作参数。全部失败日志保留。

v3 把停止明确写成 `actions: []`；只有需要执行时，才写一个带参数的动作。它不增加检索次数、不改变模型、不删除来源验证，也不把坏输出自动修好。

## 1. 最小架构与改动位置

```text
原问题 + 当前检索证据 + 剩余预算
                  │
             同一规划模型
                  │
        action-list-v3 输出协议
          ┌───────┴────────┐
       actions=[]       actions=[动作]
          │                 │
       停止检索       类型/候选ID/来源/预算验证
          │                 │
          │             原有算子执行器
          │                 │
          │              BM25检索
          │                 └──累计当前证据，有限返回规划器
          └───────固定 Reader 生成答案
```

- BASE：原查询检索一次，再回答；不调用规划器。
- FRESH：没有历史候选，现场生成动态查询动作。
- STATIC：只选择预定义种子动作，不创建新动作。
- MEMORY：协议支持选择历史动作或现场创建；**本次校准不开放真实记忆库**。

新文件 `operator_model_v3.py` 负责格式协议及显式转换；`operator_schemas_v3.py` 负责输出字段形状；`operator_profiles.py` 隔离运行版本。原 `operator_loop.py` 和 `macro_operators.py` 继续决定能否执行、执行几次和如何停止。Reader 复用 v2，不另换提示词。

## 2. 不允许的“修复”

- 不取多动作列表的第一项来掩盖其余动作，列表长度大于1直接失败。
- 不删字段、不改类型、不补全截断 JSON、不自动重试到成功。
- 不把校准题或评测题生成的动作放进长期库。
- 不因为失败换题；已启动和已声明占用的旧题保持原记录。
- 不把格式成功、模型自评充分、或一次答对当作可迁移经验的证明。

`actions=[]` 转换为原执行器的 STOP，是公开定义的协议映射，不是从错误响应中猜答案。

## 3. 预先固定的校准安排

- 保留原 manifest：来源500 / 校准100 / 评测500，题ID不交叉。
- v1 已使用或占用校准索引0:8，v2 占用8:16；v3 使用**16:24**，8道题，BASE/FRESH/STATIC三路配对。
- 若这8题完整通过，且代码、提示词、方法指纹不变，则下一批固定**24:40**，16道题观察稳定性；不能在看答案后选容易题。
- 任一批出现执行异常即停止并保存；失败不是自动释放旧题或重跑的授权。
- 不读 gold，所以只报告完整率、动作类型、实际检索数、延迟、tokens与费用；不报告EM/F1。
- 固定模型 `qwen3.7-flash-2026-07-15`，无thinking，temperature=0，top_p=1；输出上限2048 token；最多3次检索（含第一次），最多2次规划，top-6。
- 首批保守费用上限0.5元；后续16题1元。均纳入项目累计200元，不清除旧未知费用。

即使24题零格式失败，也不能保证500题稳定；还要查看真实 CREATE、SELECT、STOP 是否都被执行覆盖，不能只用大量 STOP 宣称动态动作可用。

## 4. 与正式实验的关系

校准入口暂时不开放来源采集、银行建库和评测。正式迁移需统一来源评分、四种规模库、冻结证书、评测和报告中的版本识别，不能把v1/v2来源轨迹当作v3产生，也不能只改运行文件夹名称绕过防重检查。

待迁移完成后，正式路线仍是：独立来源题产生轨迹 → 按50/100/250/500来源规模建库 → 冻结库与方法 → 同一500道评测题比较各路表现与成本。这里的“训练历史”首先指形成经验库，不是微调模型权重。

## 5. 尚未解决的研究问题

1. 普通文本 gap 可以承载中间实体，但并不强制它走附引用的 bindings。v3仅消除停止参数歧义，**未**解决所有实体来源验证。
2. 目前候选初筛是廉价词汇相似度，不是学会了预测收益的QPP。
3. 当前来源库候选录入是题级结果筛选，不是每个具体算子的因果增益判定；不能直接声称动态算子优于现场修复。
4. PDF提出的固定候选表示实验、独立状态验证和生成计划后统一选择，仍需分阶段接通，不应和本轮兼容校准混为一个结果。

这些限制保留在记录中，避免基础设施运行成功被包装为论文贡献。

第一批中，FRESH的一次真实CREATE把原问题后面追加`house`。这个词原问题已包含，当前BM25按去重后的查询词工作，因此此次查询的词集合与检索结果顺序都没有变化；程序按`no_new_evidence`停止。这不是证据增益，更不是可直接晋升的经验。

### 8.1 离线重放得到的具体问题

4次计划拒绝的第一个触发条件均为 `operator does not support the goal intent`：两次STATIC选择只支持`bridge`的BRIDGE_HOP却声明`lookup`；两次FRESH的新规格只支持`group_by`，也声明`lookup`。这里无需API或gold就能复现。它首先说明同一输出内部的契约不一致，不能把拒绝本身归因于证据验证太严，也不能假设放行后一定答对。

17条实际追加查询中，5条的真实BM25去重token集合与原问题相同（FRESH3、STATIC2）；5条全部返回与初检同序的证据ID，新增证据0。当前字符串去重没有拦住它们，因为文本多了词，但新增词原文已有。检索器感知的等价查询过滤值得作为成本诊断/工程改进，**不自动作为论文创新**，也不推广为稠密检索下完全等价。

后续要分开处理：输出内部一致性属于实现质量；什么条件下历史动作带来强FRESH之外的机会，才属于核心研究问题。任何提示/执行规则修订都须新签名、独立校准后冻结，不能在本24题上改到成功再覆盖现有结果。
