# 历史基底接通：25题开发实验

## 本轮要回答什么

先验证新的历史基底能否完整执行：找候选 → 选卡 → 按原卡改写或填模板 → 检索 → 回答 → 留下可核查的日志。随后观察哪些步骤失败、历史是否出现额外机会。25题只能做开发诊断，不能证明方法普遍优于FRESH。

历史库已经冻结：10个ReFormeR作者规则、34个来源训练题的可调用模板，另26个候选仅作审计。本轮不更新这套库，不训练模型权重。

## v1结果与v2接口校准（评分前登记）

v1前5题四路完成，后20题在第15题的模板填参被严格校验拒绝：模型给未声明的binding填了值，并把`original_question`误当文档证据ID。共19题四路完整、1题部分完成、5题未启动但保留原声明。162次真实请求，已知估费0.0693758元。原始响应和费用保留；未读这25题gold，未做重跑或补字段。

v2只澄清填参接口：请求列出模板允许的binding名称和当前可见证据ID；没有所需binding则必须返回空列表。选择器、规则改写、模板正文、库、底座和其他参数不变。版本标识为`growrag-history-base-fill-v2`。

v2使用另一组预先按顺序取出的官方train校准题：先[65:70)5题，成功后[70:90)20题，共25题。仍继承整个新系列3元预留上限与项目旧账，不重置经费。v1全体[40:65)保持声明，不重新执行。

新旧版本题目不同，不能由分数差宣称“提示词改进有效”。v2首先验证技术接通；效果只在同批25题的四路配对内比较。全部100份预测和调用账本通过核验后，才解封v2的gold。v1完整性门禁不放宽。

冻结前联合专项294项及接口/预算回归144项通过，共438项；新增FILL-v2专项38项包含真实预算/审计组件与合成transport的集成验证，未冒充真实API。Lint和格式检查通过。独立审阅确认新增拒绝没有扩大动作表达能力，旧关键方法文件保持不变。

## 每一步的用途

| 步骤 | 做什么 | 解决什么问题 | 进入下一步的条件 |
|---|---|---|---|
| 1. 冻结协议 | 固定库、模型、题序、底座、预算、提示版本和源码 | 防止方法变化与数据变化混在一起 | SHA和角色检查通过 |
| 2. 离线测试 | 合成输出检查选卡、填模板、规则改写、绑定、预算、重复查询 | 付费以前发现接口或执行错误 | 有意义的合同测试通过 |
| 3. 5题接通 | 官方train校准题[40:45)，真实四路调用 | 确认模型真正支持新接口 | 5题所有臂完成；异常日志保留 |
| 4. 20题扩展 | 同一冻结方法跑校准题[45:65)，不重跑前5题 | 看故障是否重复、候选实际被怎么选 | 全部预声明题和臂有终态 |
| 5. 封存后评分 | 此时才读取这25题gold，计算答案和证据指标 | 防止测试答案进入选卡、改写或经验库 | 预测文件与调用账本核对通过 |
| 6. 逐题诊断 | 查看修复、损害、未选卡、无新证据、模板误用、同Reader输入波动 | 决定下一阶段具体改哪个模块 | 给出失败类型与原始轨迹链接 |

cal[0:40)已有旧声明，哪怕部分未输出也不重用。新25题按已有官方train清单顺序取，不依据难度、gold或预期结果挑题。旧dev500继续仅作为已分析诊断资料。

## 四路对照

| 名称 | 流程 | 作用 |
|---|---|---|
| BASE | 原问题检索一次，Reader回答原问题 | 不修复的起点 |
| FRESH | 当前自写v3动作规划器，最多两次现场修复，无长期卡 | 同底座现场修复对照；不是原版S2G |
| STATIC_RULES | 只从10个作者规则选卡，执行规范规则改写 | 检查静态模式是否已能解释收益 |
| HISTORY | 从10规则+34训练来源模板选卡，选不到就停止修复 | 检查新历史基底；本轮不混入CREATE或FRESH回退 |

所有修复臂最多3次检索（含初检）、最多2次决策、每次top-6，使用同一BM25索引、证据累积和Reader。BASE一次检索。每一条子query单独计数。

两种选卡臂均固定最多3个候选，用原问题与卡片规范正文的词汇重叠排序，不使用gold、成功分数或作者示例中的实体。该初筛不是训练后的QPP。选择端使用规则+示例；执行端始终取回原卡，不能改模板或规则。候选字段、相似度、顺序都记入日志。

目前44张卡的适用条件均为空，因此本轮不做“有条件/无条件”有效性结论。STATIC_RULES与HISTORY的候选内容不同；小样本差值只是诊断，不能将更多模板、提示长度或额外API调用的作用自动归因于经验。

## 模型接口与停止条件

采用原项目固定Qwen快照，关闭thinking，temperature=0，top_p=1，输出上限2048。新接口明确采用服务端JSON-object语法约束＋本地严格字段/身份/证据校验。所有四路使用同一接口设置。它不是服务端strict JSON Schema，也不会在strict失败后偷偷降级。

停止原因包括：选择器不选卡、现场规划器停止、重复query、没有新证据、预算或决策轮数到达上限。非法模型输出保存为技术失败，不自动补字段、猜引用或改成另一种动作。未知条件不视为满足。

模板执行另作一次参数填充请求，只能填写已选模板的gap/当前证据绑定；正文仍是原OperatorSpec。语义规则另作一次改写请求，默认保留原问题并拼接新query。Reader始终只看到原问题和本题检索证据。

规则执行器目前只读取原问题和规则/示例，选择器与模板参数准备器才读取当前证据。故第二轮规则可能重复，暂不把规则路线称为完整证据驱动修复。这是本轮要记录的诊断现象，后续单独改版本比较。

## 记录什么、怎么比较

- 每题：候选及排序分、选中ID/版本、选择原因、规则或模板正文、参数、实际query、每轮证据与新增证据、停止原因、最终答案。
- 每请求：prompt版本、完整请求和响应、供应商请求ID、真实token、耗时、已知估费及未知计费状态；密钥不进入日志。
- 每方法：EM、F1、标注证据覆盖、实际检索次数、真实模型请求数和费用。
- 配对：HISTORY−FRESH、HISTORY−BASE、HISTORY−STATIC_RULES；同时报告修复数、损害数和实际历史模板使用率。
- 相同Reader输入单列：如果当前证据和原问完全相同，答案变化可能来自API波动，不能直接归因于检索修复。

EM是Exact Match（规范化后完全匹配），F1是答案词级精确率与召回率的调和平均。新增文档数不等于新增有用证据；封存后才用标注支持句检查后者。

## 经费、复现与下一阶段

本轮v2已完成25题100臂与离线评分。实际EM为BASE48%、FRESH64%、STATIC48%、HISTORY52%；HISTORY没有来源模板执行，三个作者规则检索没有新增文档，Reader输入均与BASE一致。多答对的一题不归因经验；FRESH增益也有同输入波动。详见[实际诊断与下一批设计](../../knowledge/experiments/2026-10-01_历史基底真实接通与诊断.md)。

本轮新系列预留上限3元，继承项目所有旧账和未知预留；项目累计上限按当前已授权200元执行，不能把历史50元字段当成新额度。费用仍是声明单价估算，不是供应商结算账单。本轮不需要GPU服务器。

两个批次必须使用同一方法签名；源码/提示/库变化需新版本，旧结果保留。本轮只有开发校准入口，不开放正式评价或持久记忆更新。

如果发现额外机会，下一阶段从独立来源轨迹提炼最少适用条件，固定动作正文和候选池做逐字段删减。若候选几乎不被使用，先检查召回和动作能力；若频繁误用，先查适用边界。动态动作、改善S2G、训练路由按既定顺序后续推进。
