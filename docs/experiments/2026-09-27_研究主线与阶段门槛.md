# 研究主线与阶段门槛：先有机会，再学会选择

日期：2026-09-27。性质：待执行研究计划，不是实验结果；不增加预算授权。本页依据[当前记忆](D:/project/GrowRAG/knowledge/CURRENT_PROJECT_MEMORY.md)、[09-27真实结果](D:/project/GrowRAG/knowledge/experiments/2026-09-27_S2G_Qwen迁移真实结果与决策.md)、[近邻与切口核验](D:/project/GrowRAG/knowledge/literature/2026-09-26_S2G改进切口核验.md)。

## 主线保持不变

> **在固定检索底座和执行预算下，历史修复动作能否提供强 FRESH 候选没有覆盖的机会？如果能，经验的哪些适用条件能帮助系统在执行前选中它，并减少有害复用？**

“没有覆盖”只指固定模型、候选数和预算下的实测，不是 FRESH 理论上做不到。创新候选是**适用条件的独立作用与最小充分表示**，不是 S2G + ReFormeR 的模块组合，也不是“经验效果减去 FRESH 效果”这一算式。前者与[ExpWeaver](https://arxiv.org/html/2605.07164v1)近邻，配对收益与[ProactAgent](https://arxiv.org/html/2604.20572v1)近邻；仍需在有结果后复核差异。

```text
稳定强 FRESH → 检查查询改进机会 → 独立训练题建立小经验池
           → 同数量候选的历史 / FRESH 机会矩阵
           → 固定候选与动作，只改变选择器看见的适用条件
           → 冻结后官方评测
```

JSON/截断修复是工程前提，不是论文贡献。证据抽取诊断用于避免把其他错误误归因给查询；**不因此自动转成证据压缩项目**。“缺口保真改写”是可能改善 FRESH 的候选机制，须由轨迹支持，不能取代上述中心问题。

## 下一步最小实验：32 题、一个共享文档索引

1. **先过工程门。** 单列 Qwen 输出容量配置并冻结，验证可解析、指针合法、停止有界；旧 8 题只是工程集。至少用合成/受控情形执行到第二轮，不能把已有五题均一轮结束当多轮验证。首错停止、保留日志，不静默改上限重试。
2. **数据先定后跑。** 仅官方 train。固定 seed 和来源文件哈希，排除旧已暴露题、旧建库来源与受保护 ID。建议选 1,024 道 train 记录作为共享语料来源，索引其全部 context 文档，按标题与正文去重；不看答案选文档、不只保留 gold 支持文档。只读必要的 ID/type/context 字段；gold 另隔离，运行结束才评。
3. **从该来源框中预选 32 道新诊断题：16 bridge、16 comparison。** 分层只是便于看两类故障，不代表 HotpotQA 自然分布，不据此报告全体准确率。32 题及其后代轨迹不得进入后续经验库或路由训练；它们从此是已暴露诊断题，不是最终盲测。
4. **所有题与所有方法检索同一个冻结索引。** 这能避免每题仅十文档造成的过易环境，但仍是共享小语料，不是作者全维基复现。记录语料数、重复数和哈希。包含诊断题来源文档是语料覆盖设计，不是把其问题/答案放进索引；正式评价以后仍需更完整语料。
5. **首批只运行 BASE 和作者流程的 S2G–Qwen。** 固定 top-6、最多 4 轮、模型/提示/格式/容量；报告预算不同，不把二者当单因素消融。不建卡、不训练选择器、不接 ReFormeR。运行前生成请求与费用上限，计入累计 50 元账本，所有旧 run 的费用继承。

每题记录：原始查询、逐轮 gap、取回文档/原句、保留句、停止原因、答案、token/检索次数/耗时。评分分四层：**文档到达→支持句保留→充分性判断→答案正确**。标题覆盖和支持句匹配都是代理信号；精确文本对齐失败需单列，不能当语义不支持。协议失败计工程失败，不算 EM=0。

## 阶段门槛：什么证据允许我们继续

| 阶段 | 要回答的问题 | 继续条件 | 若不满足 |
|---|---|---|---|
| G0 工程验收 | 作者循环真的能执行吗？ | 冻结协议完成预定检查；真实请求、停止与费用可核对 | 只修接口，不报告方法优劣 |
| G1 32题诊断 | 共享语料下有什么错误？ | 出现可检查的检索/缺口失败及非饱和状态；分清抽取和回答错误 | 若仍几乎全一轮成功，扩大语料而非调低Judge阈值；若纯抽取问题，先记录而非转题 |
| G2 同状态机会 | 相同 gap 下改变 query 有用吗？ | 在冻结状态上，一次相同 top-k 检索预算出现可重复的证据或答案改善 | 若只增加轮次才有效，不能归因改写；若机会极少，不训练路由器 |
| G3 历史机会 | 历史是否超出强 FRESH 与静态规则？ | 独立 source 题建库；同数量候选与同执行器下存在历史独有成功/成本优势，不由实体答案重复解释 | 若静态模式已同样好，就暂不做长期记忆；若多采样FRESH已覆盖，缩小或否决历史假设 |
| G4 条件作用 | 条件帮助选择，还是只增加文本？ | 固定候选/选择器/规范动作；删字段、等长控制和实体分组仍显示有用条件 | 条件无效就删，不靠增加卡片复杂度维持故事 |
| G5 冻结评价 | 是否独立泛化？ | 官方保留 dev/test；记忆与prompt冻结；报告损害/收益/覆盖/成本 | 不用评测题继续建卡后重报同一分数 |

32 题是诊断规模，不是显著性保证；以上门槛不设“必须提分几点”的事后筛选。进入 G2 时，每题最多取**第一次检索后仍不足**的一个状态，避免长轨迹题被重复计权。比较作者拼接、同 gap 普通改写和一个由诊断提出的改写候选，后续抽取/回答相同。受控恢复被丢原句可以作为故障定位旁路，但不混入 query 方法成绩。

G3 的关键量：相同候选数下，`最好历史候选 − 最好FRESH候选`；这是离线机会估计，上线看不到 gold，不能直接用这位“事后最好者”当路由器。只有机会成立，才做 G4。相同最终查询/Reader 输入可共享真实执行，但实际账与单方法部署账分开；不能把缓存延迟当算法加速。

## 到时真正需要用户选择的分岔

- **研究权限：**首轮查询前只用问题与可见经验条件，还是后续轮允许看 S2G gap/已有证据？建议先以后者做状态级机制验证，再增加严格 q-only 对照；二者不能混称“完全检索前”。主目标仍是每次昂贵检索执行前选择 query。
- **若历史机会很小：**接受改做更强的无历史查询修复，还是保留历史目标并换更有跨任务规律的数据？必须依据 G3 决定，不先承诺记忆一定有用。
- **若主要瓶颈是抽取：**建议只修到稳定公平的基线并继续查询主线；要转向证据压缩研究，应另行明确改变题目，不能在排障中悄悄转向。

现在无需用户决定学习率、卡片全部字段或租哪张 GPU。API＋CPU共享小索引先做；需要完整索引的内存/磁盘或本地模型时，先测量资源再申请 SSH。上述规划未执行、没有新增付费调用或经验卡。
