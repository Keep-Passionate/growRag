# GrowRAG 战略回顾与选题报告

日期：2026-09-20。本文供选题决策，不是已完成实验的论文。

## 先读这一页

**大方向值得保留，贡献表述必须收窄。** 查询侧外置层适合我们起步；本题有限修复和跨题经验也有合理用途。但“改写＋记忆＋路由＋循环”已经是拥挤的组合，不能靠把这些模块接起来证明创新。

推荐暂定题目：**历史查询修复何时值得提前复用？——面向 RAG 的低成本经验选择。**

通俗说：以前做题总结出一个好办法，并不代表新题用它也好。我们要研究，系统在尚未搜索新文档时，能凭哪些线索判断值得借用；哪些情况必须先查一轮再决定。

本轮最重要的新发现是 ProcMEM 和 MemHarness：前者已有可观察激活条件、动作和停止条件；后者已经比较来源状态、当前状态，并做不适用状态探针。因此，“记适用条件”“避免误用”“删字段做消融”都不能单独作为新意。[ProcMEM §3–4](https://arxiv.org/html/2602.01869v1)<!--ref:proc_mem--><!--anchor:section:3.2-->, [MemHarness §3、4.5](https://arxiv.org/html/2607.28272v1)<!--ref:mem_harness--><!--anchor:section:4.5-->

下一步先检验三件事，而非继续加模块：

1. 历史动作有没有提供现场改写做不到的机会？
2. 有机会时，检索前的信息能否帮助选中它？
3. 有效的是适用条件本身，还是更长提示、更多候选、额外检索或实体记忆？

这三个问题中，任何一个回答为否，都应缩减或调整路线。50 元是本项目 API 累计上限，不是要花满的指标。

**回顾后的实际诊断：** 8道开发题、104次真实API已完成。历史候选即使事后选最好，答案F1也未超FRESH；加条件避开1次有害复用。另有1条历史动作补到关键反例证据，却未被选择，属于探索性线索。当前应先研究动作同质性、证据/答案反馈和弱底座问题，不宜直接扩大选择器训练。[完整实验与逐题分析](../knowledge/experiments/2026-09-20_PRE八题真实结果与选题修正.md)

## 1. 本次回顾如何避免继续沿错路线

采用“已有机制→条件性证据→具体待验证缺口”的顺序。优先寻找能否定我们首创主张的工作，不把文献未涉及某数据集当成充分创新。检索范围与主张登记见 [检索审计](../knowledge/literature/2026-09-20_选题回顾检索与主张边界.md)。

本次是定向研究回顾，不是穷尽所有论文的系统综述。“尚缺证据”仅限本文核查的近邻范围；不能保证没有同时进行或未公开的工作。正式主会、Findings、Industry、期刊和预印本分开标记，不能用文章在 arXiv 上就判定它没经过审稿。

研究范围固定为：**文本问题→选择是否/怎样改写→固定 RAG 底座**。长期记忆保存程序性修复，不是保存历史答案作为新的事实库。文档切块、索引和 Reader 首先固定；多模态、图 RAG、单文档长期会话、完整强化学习暂不进入主问题。

## 2. 哪些问题已经被研究得很充分？

这里的“充分”是指基本机制和直接先例已经成立，并不表示所有场景都解决了。

| 想法 | 已有代表工作 | 我们应如何定位 |
|---|---|---|
| 在 RAG 前改查询，不改检索器/回答器 | [Query Rewriting，EMNLP 2023](https://aclanthology.org/2023.emnlp-main.322/)<!--ref:query_rewriting--><!--anchor:section:Abstract--> | 合理代码底座；不能再说首次提出可插拔前置改写 |

结论：**问题重要，不等于我们的解法新；别人做过一个机制，也不等于这个机制的适用边界已经讲清楚。** 选题应落在后一处。

## 3. 哪些还在争议？

### 3.1 查得更相关，是否就答得更好？

不一定。eRAG 用下游回答效用重新评价文档；QPP 变体研究也指出排名目标与生成目标不完全一致。[eRAG，SIGIR 2024](https://arxiv.org/html/2404.13781v1)<!--ref:erag--><!--anchor:section:Abstract-->, [QPP Query Variant Selection §4–5](https://arxiv.org/html/2604.22661v1)<!--ref:qpp_variant--><!--anchor:section:5-->

对我们而言，要分别看“找回了什么证据”和“原问题是否答对”。例如补到第一跳人物名但未补第二跳属性，是有信息进展，却不是回答成功；答案偶然答对、证据没有改善，也不能自动证明改写值得存。

### 3.2 抽象记忆更好，还是具体轨迹更好？

这取决于任务与更新方式。Useful Memories 研究持续更新造成失真；When Continual Learning Moves to Memory 在任务切换下发现抽象洞见有时更利于迁移，粒度和调用频率也有条件性。[Useful Memories v2 §5–6](https://arxiv.org/html/2605.12978v2)<!--ref:useful_memories--><!--anchor:section:6.2-->, [Continual Memory §3–4](https://arxiv.org/html/2604.27003v1)<!--ref:continual_memory--><!--anchor:section:3.3-->

它们并未形成“所有压缩一定好/坏”的矛盾结论。至少须拆开：第一次抽象、反复修改旧卡、调用时为本题重构。本轮继续保留原始审计与一次抽象，不急于做自动合并和多次重写。

### 3.3 纯检索前选择够用吗？

便宜的 PRE 预测有竞争力，但 ReFormeR 使用首轮文档选模式，ReformIR 使用排序反馈减少漂移。它们的信息权限不同，不能直接用不同论文的表格宣布哪种始终更好。[ReFormeR §2](https://arxiv.org/html/2604.01417v1)<!--ref:reformer--><!--anchor:section:2-->, [ReformIR §3](https://arxiv.org/html/2605.00560v1)<!--ref:reformir--><!--anchor:section:3-->

教学例子：问题明确问“甲是否早于乙出生”，比较目标和时间方向在检索前可见；“甲和乙实际属于同一国家”“第一轮已找到导演但没找到出生地”通常需要外部证据。不能把后两种条件当成已经观察到的 PRE 输入。

### 3.4 强现场改写之后，历史还剩多少价值？

这是我们尚未回答的核心可行性问题。Think Then Rewrite 已利用推理、对比奖励和训练提升领域改写；强 FRESH 不应被固定成一句“请换个说法”。但仅搬它的提示，不等于复现其训练方案。[TTR，AAAI 2026，§4](https://ojs.aaai.org/index.php/AAAI/article/view/38527)<!--ref:think_then_rewrite--><!--anchor:section:Abstract-->

我们需要允许三种结果：历史提高正确率；历史不提高正确率但降低成本；历史两者都没有。第三种出现时，不应继续靠增加记忆模块掩盖它。

### 3.5 可插拔，是否就与底座无关？

不是。词汇改写对 BM25 和稠密检索器可能作用不同，查询侧也无法保证修好文档编码偏差。相关分析没有替我们证明下游 QA 的普遍收益。[Masking or Mitigating?，Findings ACL 2026，§6、8](https://aclanthology.org/2026.findings-acl.414/)<!--ref:masking_mitigating--><!--anchor:section:Abstract-->

因此首先声称“在固定底座下有效”，再做换底座实验；不要上来写“适用于任何 RAG”。如果索引根本没有某条事实，改写本身无法创造它。

## 4. 哪些被反复提出，却仍缺一块关键证据？

不能诚实地说“没人做适用性”。我们的机会是以下问题的交叉处，在本次近邻核查中尚缺完整受控回答。

### 缺口 A：经验的成功条件，到了前置层是否还看得见？

离线过程看到很多内容：文档、缺口、候选结果、反馈；上线 PRE 只有新问题、固定配置和历史记忆。**离线知道经验为什么成功，不等于上线有足够信息判断何时重用。**

可研究：把适用条件按可观察来源分组，比较仅依赖原问题与允许首检索观察时的选择质量，并明确哪些经验应当延后使用。不是给不可见事实打个“置信度高”就当它可见。

### 缺口 B：记法帮助的是选对，还是执行器更会改写？

QCR 已隔离选中历史后的重用表示。MemHarness 也已经做来源状态与不适用探针，不能称所有前人未做条件消融。[QCR §4–6](https://arxiv.org/html/2608.12847v1)<!--ref:qcr--><!--anchor:section:6-->, [MemHarness §4.5](https://arxiv.org/html/2607.28272v1)<!--ref:mem_harness--><!--anchor:section:4.5-->

我们的更小实验固定同一动作与执行结果，只改变选择器看到的信息：多一个条件后，是否选中真正有增益的动作？最后须运行真实 RAG，不能只让 judge 说“这条更适合”。MemHarness 的最小状态探针只看重构输出，不能替代这里的终局执行检查；但其主实验和来源状态消融已经测了任务成功率，我们并非首次把条件接入端到端执行。

### 缺口 C：历史究竟比静态模式库多提供什么？

若所有卡最后都变成“保留实体”“比较两个对象”“检索人物属性”，可能几条固定规则就够了。此时复杂经验库没有得到证明。应固定候选数、执行器和预算，直接比较静态规则与真实历史归纳规则；再比较相同规则有无历史适用边界。

这三项的关系是：**A 为主科学问题，B 为归因方法，C 为推翻“必须有长期记忆”的必要对照。** 不再开三个独立项目。

## 5. 收窄后的科学问题与贡献

### 主问题

在检索器、索引与回答器固定时，能否只用原问题和少量可观察条件，选择出相对同预算现场改写真正有额外价值的历史动作？哪些动作仅凭查询难以可靠选用，首轮证据能否改善判断？这里研究实际方法的信息依赖，不宣称证明任何模型都不可能提前判断。

### 三个可证伪假设

- H1，机会存在：独立题上，真实历史动作相对等数量无历史/静态模式候选仍有增益空间。
- H2，条件有价值：固定候选、规范动作和选择器，加入可观察条件可改善增益—损害—复用率的权衡，而非只拒绝全部经验。
- H3，存在前移边界：不同类型动作对首检索信息的依赖不同；允许延后选择，能在固定质量约束下减少成本，或在固定成本下改善质量。

H1 不成立，优先核查来源/对照或转向无记忆改写。H1 成立、H2 不成立，不能把卡结构写成贡献。H2 成立、H3 未成立，可以只做轻量 PRE 选择，不必为了 agent 标签保留复杂循环。允许“样本不足，尚不能判断”，不能把未显著等同于没有效应；也不能不断换经验池直到获得阳性。

### 最终可能成立的贡献，不是现在就已经拥有

1. 一套经验前移可行性的实证规律：区分“查询可判”“需证据可判”，揭示典型误用与误拒原因。
2. 一个简单、可复现的选择方法：使用少量条件预测相对 FRESH 的增益/损害，未知时保留默认路径或延后检查。
3. 一个控制变量清楚的评测协议：同来源、同候选、同规范动作，分离选择信息和执行效果，并报告完整成本。

第 3 项主要提高研究可信度，通常不足以单独支持一篇方法论文。前两项需要跨题、跨模式或跨底座的结果，不能只有 JSON 字段设计。

**不主张：** 首个记忆 RAG、首个安全复用、首个增量奖励、首个双记忆、首次查询改写状态机、保证不会退步。

## 6. 保留的最小系统

```text
离线：训练题 → BASE / 现场改写 / 有限修复
                   ↓ 真实结果与来源审计
            候选规则＋适用条件＋来源指针
                   ↓ 独立题配对验证
               冻结经验库/选择器

在线：新问题 → 查询侧选择层 → 原有 RAG 第1轮
              BASE / FRESH / REUSE       │
                                 足够则回答
                                 不足且有预算
                                       ↓
                         依据本题证据再选修复
                                       ↓
                               原有 RAG 第2轮
                                       ↓
                              回答或说明不足
```

BASE 是原问题直接检索。FRESH 是没有跨题记忆的现场改写。REUSE 是历史程序参与改写。它们是动作来源，不是三层记忆。

QueryEpisode 保存本题的动作、证据、判断、成本；ExperienceCard 保存可迁移规则。Reader 始终回答原问题，只把本题检索到的真实资料当证据。DocumentSession 后置；EMA、自动合并、在线写回、强化学习均非首轮必需。

低耦合不等于没有接口要求。仅有黑箱答案、没有可追溯证据的 RAG 后端，只能接 PRE；要做充分性和证据增量控制，后端须返回检索证据。循环是外部调用包装，不修改内部索引/Reader，但仍要明确证据与费用接口。

### 适用条件的最小设计

| 信息 | 存在哪里 | 理由 |
|---|---|---|
| 动作规则、必须保持的意图 | 跨题卡 | 定义真正要执行什么 |
| 条件内容＋需要哪类观察 | 跨题卡 | 例如查询表达、运行配置、当前证据；不要每次凭空猜来源 |
| 本题满足/冲突/未知及依据 | 本题状态 | 同一规则在不同题可能不同，不写成卡的永久真值 |
| 真实 q→q′、来源证据和反馈 | 审计记录，卡存指针 | 便于回查；历史答案不进入当前 Reader |
| 独立迁移结果 | 配对验证账本 | 来源成功率不能冒充迁移可靠性 |

这些字段是拟验证设计，不说字段本身新。首版未知不是失败：硬性意图冲突拒绝；可选条件未知交给选择器；若关键动作必须知道本题实体绑定，则不能靠臆测在 PRE 执行。力度要通过误用与误拒共同评价。

### 学习方式

先冻结 prompt，收集同题各动作的真实结果。数据足够后学一个轻量预测器，预测 `动作F1−FRESH F1` 和退步概率。先用简单线性/小型模型作为下限，不直接微调 7B；只有简单模型无法解释而数据量支持时才扩大。

学习目标可用统一质量—成本效用，成本权重只在训练/开发定好并冻结；裸 F1、损害率仍独立报告。不要学习一个可任意放大第二轮分数的权重，然后据此宣布胜出。

## 7. 怎么区分三类查询问题？

| 问题类型 | 示例性质 | 前置层能尝试什么 | 不能凭空做什么 |
|---|---|---|---|
| 词汇不匹配 | 用户说法与文档术语不同 | 同义/术语规范化、保留关键实体的扩写 | 保证一个近义词在该语料里完全等价 |
| 意图漂移 | 改写丢掉“之前”“哪一位”“两者”等约束 | 保留关系方向、比较范围、时间条件；拒绝明显改题 | 用语义相似度证明答案等价 |
| 描述不足 | 缺少需要先找到的桥接人物/机构 | PRE先保留角色；必要时POST用有出处的实体补齐 | 把历史题的人物或模型猜出的答案当本题已知事实 |

这是分析标签，不要求新增一个复杂分类器。第一轮先由人工审查和可复现规则标注错误，确认这些类型在真实数据中有足够样本，再考虑自动预测。

## 8. 分阶段实验：每一步都能决定是否继续

### E0：本轮机会诊断，先把真实 REUSE 跑起来

- 使用现有 6 张 PRE 候选卡，不自动晋升，不重新写卡；来源与目标隔离。
- 只开原 8 道调试题，24 道检查题冻结不动。
- 固定事前 top3 候选，比较 BASE、规范 FRESH、RRR 关键词适配、每条 REUSE。
- 选择器先看规则/例子或额外条件并落盘，再执行结果；规范执行器不随视图改变。
- 记录每题原文、候选及召回分、选中项、实际改写、证据、答案、EM/F1/支持和成本。

注意E0的额外条件是旧卡原样条件，可能含答案依赖或当前不可观察的错误推断；这是旧池审计，不代表新“仅可观察条件”方案已实现。不得将旧条件表现差直接解读为适用条件普遍无用。生成后未改变原query的回退单列，不冒领为实际执行的历史改写。

这个实验只检查旧来源池是否值得继续。**3条历史候选的事后最佳胜过1条FRESH，不足以证明历史比增加采样更好。** 规范 FRESH 与 REUSE 共用动作生成合同；RRR 是额外较强对照，不是完整训练版 RRR，更不是最终最强 FRESH。

### E1：确认历史价值，不把候选数量当贡献

在新的训练角色题上，预先冻结同数量候选池：3条无历史改写、3条静态模式、3条历史动作。候选数相同，生成调用/token预算单列；Reader、top-k、上下文和检索次数相同。

先开发32题，再按失败类型和配对方差决定一次独立64题检查；这些数是诊断计划，不是统计功效保证。可采用 q-only 推理后改写作为 FRESH 候选，标清独立适配；如要正式比 TTR，另核其代码、数据和训练协议。

看历史池是否增加独有正确题、真正证据覆盖、或同质量下的成本优势。事后最优只用于估算机会，不能当实际部署策略。即使机会为正，也不能推出能学会选择。

### E2：固定动作，检验经验表示对选择的作用

建议后续视图，和旧 M1/M2/M3/M5 命名分开：

| 新视图 | 选择器可见内容 | 要排除的解释 |
|---|---|---|
| V0 | 规则＋代表性 q→q′ | 规则示例已经够用 |
| V1 | V0＋当前阶段可观察适用条件 | 条件是否提供额外信息 |
| V1-text | 与V1同信息，普通自然段 | JSON结构优势，还是信息优势 |
| V1-minus | 只删一类条件 | 哪类条件不能删 |
| V-state，后续影子诊断 | 相同卡＋共同首检索观察 | 多看真实状态的价值 |

每题每条规范动作只执行一次，所有选择视图共享结果；不得把选择器生成的解释再传给执行器。控制来源、候选次序、模型、规范动作、token上限。既报自然长度成本，也检查截断/信息预算，不靠空白填充“公平”。

单次执行只给出该次实现的结果，不等于可靠的期望效用。扩大到E1/E2时，预先指定一部分重复运行或可用的固定种子组；所有表示共享同一组重复结果，检查收益是否来自偶然生成。低温度也不保证API完全确定。

尤其注意：q-only 选择器不能看到根据本题首轮文档生成的具体查询，不能从候选文本偷看桥接实体。V-state 若与 PRE 共享 POST 执行，只是信息诊断；真正免首检索的部署仍须单独用 q-only 生成并测完整成本。

### E3：有限修复与提前复用的边界

接通共享 BASE 首轮状态，比较同第二轮预算的 FRESH2 与 REUSE2。参考 S2G 的缺口表示和 ReflectiveRAG 的停止逻辑，但不要把自己的一次提示适配叫原论文完整复现。[S2G-RAG](https://aclanthology.org/2026.acl-long.1185/)<!--ref:s2g_rag--><!--anchor:section:Abstract-->, [ReflectiveRAG，EACL Industry 2026](https://aclanthology.org/2026.eacl-industry.27/)<!--ref:reflective_verma--><!--anchor:section:Abstract-->

随后再比较真正部署策略：始终 PRE、始终首检索后选、查询侧不确定时延后。统一最多两轮，分别报告实际早停率与质量。强制执行合法第二轮可用于离线机会诊断，不能混成线上早停策略。

### E4：学小选择器，再做独立迁移

只在历史有机会且条件有信号后扩大配对采样。按实体/文档关联分组验证，避免模型只背住题目词。训练、阈值选择、测试三者隔离，测试卡库冻结。

比较最低限度：永不复用、最相似来源、静态模式库、ReFormeR式规则示例、QPP类选择、RRM式本题修复＋经验。使用同一模型/底座的适配结果，不直接搬论文分数混排。还应比较“无记忆但用相同离线数据学更好的改写器”，防止把所有数据学习收益归给显式记忆。

## 10. 评价与否定路线的条件

主结果同时报告：相对 FRESH 的F1差、改对题数、改坏题数、实际复用率、漏掉有益动作的情况、证据变化、实际成本与耗时。EM 是答案完全匹配，F1 衡量答案词重合；支持句指标单列，不把它当完整事实正确性证明。

E1付费扩大前登记主质量指标、最小值得继续的效应、成本口径与最大损害容忍。阈值应结合E0的方差和实际部署需求决定，不在看完检查集后倒推。最终可判支持、不支持或样本不足。

### 避免三个假成功

1. **永不复用的安全**：损害少，但错失所有收益。用“始终FRESH”作基线，并比较相近复用率下的损害；小样本不宣称风险受保证。
2. **多算出来的好分数**：历史3候选、FRESH1候选或历史2轮、FRESH1轮。先做同预算对照，再单列实际策略质量—成本权衡。
3. **事后解释的适用性**：先看gold和候选得分，再写“因为适用所以选中”。选择输入、时间顺序和日志必须隔离。

以问题为统计单位；同题3动作不算3个独立样本。较大实验用配对区间和关联组压力测试。API失败是缺失结果与可能费用，不自动赋0分，也不能删了不报。多次试prompt的记录全部保留，检查集不能用到调赢。

### 明确转向条件

- 等数量强FRESH/静态模式已覆盖历史所有增益：暂停复杂记忆维护。
- 历史池有机会，但原问题信号无法稳定预测：主线改为首检索后选择，不强求免首次检索。
- 条件只让系统全部拒绝：不能宣称成功，检查硬约束和未知处理。
- 新实体/新检索器下收益消失：限定主张为特定域，或先研究迁移失效原因。
- 证据更好但答案更差：单列 Reader 干扰，不能继续只优化召回。

这些是执行后解释规则，不是“做到某分数才挑出来发表”。

## 11. 可行性、成本和代码推进

已有 Python 环境、Hotpot 数据、BM25、API 客户端、规范改写与表示对照组件，可支持第一轮。现在不需要租 GPU；训练大模型不是验证主问题的前提。

用户已批准总累计50元。先给机会诊断单独设置最多3元、最多150次真实请求、30分钟期限，错误停止。旧失败账本保留，不自动重试；新实验不是续跑旧失败Query2doc请求。模型继续固定 `qwen3.7-flash-2026-07-15`，不静默换更强模型来制造增益。

费用须把过去不同根实验一起承接，不能只承接09-11→09-14这条链。已知token估算、未知失败费用、保守预留与供应商账单分开。旧文档中的0.3199766元是该链预留，不是全项目历史总支出。

本轮运行前重对五个真实历史run：503次请求，已知usage估算0.0769154元，保守预留0.5898764元，另有1次请求费用未知并保留预留。旧09-06 POST试验曾运行8道目标，REUSE与FRESH的EM均为0.75；不能说项目从未运行经验，但旧版本的小样本零净增益也不能替新六卡证明有效。

从现在起，代码顺序调整为：**PRE机会诊断先于完整POST扩建**。这是本轮战略回顾后的推进顺序，不是删除已定两轮外层架构。先跑最容易推翻路线的实验，确认值得再接累计证据与结构化judge。

真实运行已完成，代码版本、逐题结果与预算见[独立实验记录](../knowledge/experiments/2026-09-20_PRE八题真实结果与选题修正.md)。本轮104次费用估算0.012841元；历史＋本轮已知估算0.0897564元，历史1次费用未知，累计保守预留0.7132028元，不是供应商结算账单。

## 13. 最后的方向选择

推荐主线 A：**检索前经验适用性与低成本选择**。最符合你想做的 query rewrite 小分支，成本低；风险是信号太弱或静态模式已足够。

备选 B：**证据出现后再用历史修复**。若 A 的信息不够，这是自然退路；更接近 agent，但与 RRM/S2G/MemHarness 竞争更直接，不能仅靠循环架构立项。

备选 C：**不依赖长期记忆的强改写选择**。若历史没有独立价值，转向此方向可复用大部分实验底座；但 QPP/ReformIR/TTR 已很强，仍须更明确的场景或机制。

本轮先按 A 的最小诊断推进，B保留，不需要你立即在三个大系统之间再次选择。我们要选择的是有证据支持的问题，而不是维护已经画好的架构。

诊断后进一步收紧执行优先级：先比较明确的静态/无历史动作，确认经验是否有不可替代的贡献；当前条件视图质量持平FRESH、影子路径成本却高74.51%，尚不能证明“低成本”已实现。第007题的证据收益值得追踪，但不能事后用它替代未胜出的答案主结果。第005题两个实体已在原问题，可先试PRE分解；第000/006题则可检验首轮桥接线索的作用。所有建议需新协议，而非修改已经冻结的八题结果。
