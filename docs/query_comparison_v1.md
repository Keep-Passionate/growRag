# 前置查询三分支比较：先判断经验有没有额外价值

更新：2026-09-06。对应 0.3.0 研究执行器，不是已验证有效的算法。

## 这次实现了什么

将已实现的“统一经验卡＋独立 RAG 外循环”接入同题对照实验。原问题不变，首次检索前从空证据开始：

| 分支 | 查询怎样产生 | 历史经验 | 最多执行 |
|---|---|---|---|
| BASE | 直接使用原问题 | 不提供 | 1 次完整 RAG |
| FRESH | 根据当前问题独立改写 | 不提供 | 1 次改写＋1 次完整 RAG |
| REUSE | 借助一张预选经验卡改写当前问题 | 只读、白名单视图 | 1 次改写＋1 次完整 RAG |

重点看 REUSE 相对 FRESH：如果两者打平，说明不能仅凭 REUSE 胜过 BASE 就说“历史经验有用”。这只是合理的研究检验，不宣称三分支比较本身是我们的创新。

## 代码怎么连接

```text
RuntimeQuestion 原问题（不含答案标注）＋预选 CardMemoryView
                         │
           QueryComparisonSpec 冻结本题实验
                         │
           run_query_comparison 检查全部配置
                         │
            ┌────────────┼────────────┐
          BASE         FRESH         REUSE
            │       共享版本改写器   共享版本改写器＋卡片
            │            │             │
            └── 各自 run_outer_loop ──┘
                         │
         RagRequest(原问题, 当前搜索查询)
                         │
           各自独立的原有 RAG → 原始记录
                         │
           comparison_report（此时才读 gold）
                         │
          run.json / report.json / report.md
```

- `src/growrag/experiments/query_comparison.py`：实验规格、三分支预检查、执行与结果容器。
- `src/growrag/query_actions.py`：共享改写 prompt；只有 REUSE 获得历史视图。
- `src/growrag/outer_loop.py`：复用已有完整 RAG 接口；本协议限制每支只运行一轮。
- `src/growrag/experiments/comparison_report.py`：运行后评价、风险分项和保存。
- `scripts/demo_query_comparison.py`：无网络、零 API 的独立流程演示。
- `tests/test_query_comparison.py`：隔离、公平性、失败、费用、数据保存等合同测试。

## 为什么要这样控制比较

1. **先固定改写目的和形式，再选匹配的卡。** 不从卡片偷拿一个高质量指令只给 REUSE，也不因为看了目标答案而选择卡片。当前目的为实验外部给定，自动决定目的/找卡仍未实现。
2. **FRESH 与 REUSE 使用同一个系统 prompt 和版本。** `paired_prompt=True` 启用 `growrag-paired-query-v1`；允许两者都保持原查询。旧模式的 prompt 保留，不悄悄改动旧试跑。
3. **每支独立实例、同样声明的模型/底座配置。** 全部检查完成后才开始调用；按题号与种子确定执行顺序。这个种子只控制分支顺序，不保证远程模型确定性。
4. **同机会不等于同花费。** 一次完整 RAG 包含检索和回答；REUSE 的卡片会增加输入长度。报告记录实际 tokens、请求、耗时，不把“各一次”说成等钱。
5. **历史来源和目标隔离。** 检查卡片全部来源问题 ID 与规范化题文指纹；同题换 ID 也不能作为跨题迁移。尚不能检测所有语义重复或第三方预训练污染。
6. **实际动作与计划动作分开。** 计划 REUSE 但产生原查询，实际动作记录为 BASE，保留改写费用；相同查询产生不同答案不能直接归功于改写。

配置指纹是适配器的声明和审计索引，不是证明第三方组件真实、无共享状态或模型没有漂移的安全沙箱。工厂构造应无付费副作用；真正运行还需固定语料、检索配置、模型快照、生成参数、卡版本和 API 审计。仅实例不同也不保证底层缓存完全隔离。

## 结果怎么看

`report.md` 用于逐题阅读，`report.json` 用于之后汇总，`run.json` 保存完整规格和事件。输出目录必须是新的，拒绝覆盖旧实验。

- **答案层**：EM（标准化后精确一致）、F1（答案词重合）；正确变错误与正确变弃答分开。
- **证据层**：命中人工支持句的比例、引用的支持句情况；评价只看该分支 Reader 实际读到的证据，不冒用外层累计证据。
- **未知状态**：底座不暴露证据时记未知，不写成召回为零；引用 ID 存在不证明答案被语义支持，`answer_supported` 仍未知。
- **失败状态**：保留失败分支，不仅汇总成功样本。普通组件调用异常脱敏记录，不自动重试或回填；组件内无法观测的费用标未知。
- **成本状态**：RAG 聚合事件和内部检索/回答细节不能重复相加。三支总费用是实验费用，不是部署时一次选择的费用；不含建索引/建库。

这里的分层指标不是完整 Hotpot 官方评测器。原标注未覆盖的有效替代证据可能被支持召回漏计；这些指标不构成数学正确性证明。报告也不会自动晋升经验、训练 gate 或更新可靠度。

保存前先验证 gold 与序列化，使用排他创建；磁盘写入失败仍可能留下不完整的新目录，不得当作完成的实验。真正批量实验需要再补运行清单与可恢复落盘。

本地完整测试 497 项通过（较 0.2.0 新增 73 项），代码规范和格式检查通过。CI 增加独立的零 API 三分支演示入口；远端结果另见版本验证记录，不以本地通过代替远端通过。

## 本轮没有扩大哪些内容

- 只接通**首次检索前**的三分支；POST_RETRIEVAL 卡片明确拒绝，不假称已支持共享首检后的修复对照。
- 只支持语义改写和扩写；拆分多查询、自动路由、充分性 judge、多轮配对均后置。
- 卡片是明确预选的候选，不冒充已自动筛出的 trusted memory。
- 真实模式默认关闭，显式允许后仍需调用层费用上限；不允许自动切换模型或失败后用 mock 替代。

## 下一小步与最终目标

下一步在现有 Hotpot 官方 train 内固定少量来源题与独立开发题，构造可追溯的新版卡视图，核查固定目的/适用条件，再用同一个真实模型小批量比较。不要同时加新数据集、训练控制器和多轮逻辑。凡需要修改运行预算或模型设置，先明确记录。

优先检查：REUSE 有没有超过 FRESH、在哪些题上有害、证据是否真的增加；负结果也保留。之后才比较不同笔记写法和便宜选择器。目标是找到“值得用经验”的可重复信号，而不是把可运行的代码包装成已证明的创新。
