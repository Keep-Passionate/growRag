# 表示选择实验：代码与当前边界

日期：2026-09-11。最小目标：同一个动作，只因“经验怎样写”而改变被选中的机会。不是重写 RAG，不是已经有效的自动可信控制器。

## 一眼看懂逻辑

```text
来源题 BASE / FRESH 配对 → 既有录入标准 → 来源候选卡（不是 trusted）
                                           │
                               冻结规范动作与四种选择视图
                                           │
新问题 → 同一次候选召回，至多 3 卡 ───────────┤
                       M1 / M2 / M3 / M5 各选 ID 或 FRESH
                                           │
                                  先保存全部选择
                                           │
                      BASE / FRESH / 各候选动作各执行一次
                                           │
                               一张共用、只读的结果表
                                           │
                  事后加入 gold：增益、误用、误拒、证据、费用
```

## 代码只新增小职责

| 文件 | 负责什么 | 特意不做什么 |
|---|---|---|
| `experiments/representation_manifest.py` | 来源、目标、调试/检查身份，冻结抽样、去重与排除 | 不按答案分数挑题 |
| `experiments/run_representation_manifest.py` | 完整 train 文件核验；保存名单和带来源哈希的离线子集 | 不调用模型，不将 gold 投入路由 |
| `experiments/source_pool_pilot.py` | 逐题来源 BASE/FRESH、沿现有标准提卡、共享预算及落盘 | 不自动扩源、重试或晋升为可信记忆 |
| `experiments/run_source_pool.py` | 默认预检；显式真实入口核对固定模型、干净代码与预算 | 不打印密钥，不启动目标实验 |
| `experiments/representation_views.py` | 同一来源四视图、共用词面候选、选择输入白名单 | 不凭代码结构保证语义正确，不生成假 API 结果 |
| `experiments/representation_runner.py` | 所有选择先冻结、动作只执行一次、按规范动作独立执行 | 不向执行器传表示正文、选择理由或历史答案 |
| `experiments/representation_report.py` | 事后配对效果与失败/费用核算 | 不让 oracle/gold 反向影响选择 |

路径均相对 `src/growrag/`。基础 RAG、句 BM25、Reader 和既有源录入标准继续复用；不是照搬上游仓库，也没有声称已复现完整 RRM/AWM/QCR。

## 四种表示为什么不会干扰执行

每张候选卡有两个用途独立的对象：

- 选择视图：M1 具体 q/q′、M2 简短经验、M3 参数化动作、M5 条件—动作—核查。这里只帮助选 ID。
- 规范动作：该 ID 对应的固定动作正文。无论哪个表示组选中，执行器拿到的是同一份正文。

FRESH 的执行输入没有历史。REUSE 只加入规范动作正文，不加入条件、来源答案或选择器说明。四组共用同题候选结果，避免四次随机执行把差异混入表示比较。

目前不加载跨运行缓存、不自动续跑。缓存键用于结果身份核验，绑定问题、动作及版本、模型/prompt、索引配置与随机设置；表示文字变化会改变实验指纹，但不改变同一个规范动作的执行身份。

## 已实现与尚未接通

已实现：不可变视图合同、固定候选、真实 API 选择/规范执行适配器、离线共享结果运行器、后评报告、64 来源建库入口和完整数据清单入口。

尚未接通：M2/M3/M5 的真实自动生成及语义审阅、真实目标批量入口、实际 tokenizer 长度约束、条件逐字段消融、训练/QPP、DocumentSession、自动多轮可信控制。

当前表示文本上限是 **1200 字符工程限制，不是 200 token**。正式目标比较前需固定实际被测模型 tokenizer 或明确采用字符预算协议；不能将字符数冒充 token 数，也不能静默截断单组以取得长度优势。

候选使用来源原问题词面 Jaccard（词集合交集与并集的比），仅用于固定短名单，不是“适用性已经可信”。已选卡的真正增量要靠独立 FRESH 对照验证。

## 如何审阅

1. 当前 q、三张候选 ID 是否对四组完全相同？
2. 每次选择是否在候选结果生成前保存？
3. 规范动作是否不夹带答案、gold 或表示组的信息？
4. 同一 ID 的执行结果是否共用，而不是四组各跑一次？
5. 报告是不是 REUSE−FRESH；失败是否留着，未知是否被错误当零？
6. 审计总费用是否包括没被选中的对照；“线上路径费用”是否明确只是日志重建？
7. 源成功是否仅产生 candidate，而没有自动宣称跨题 trusted？

推荐下一步按 [分阶段路线](../knowledge/decisions/2026-09-11_条件最小化路线与分阶段实施.md) 执行。离线测试通过只代表接线正确；真实来源阶段也不等于已经测到表示选择的效果。
