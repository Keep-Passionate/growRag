# 模型分工与轻量选择器：把名字说清楚

## 最需要掌握的三点

1. 7B表示约70亿参数，不表示“选择器”这一职责。一个LLM可以兼任改写、选择或回答，但每次调用都计成本。
2. 我们先说的“小模型”是CPU能训练的线性模型/小预测头，不是必须部署一个7B。
3. 当前真实实验只使用同一个固定Qwen API模型；下面本地7B、学习选择器和两轮judge分工是规划，尚未部署或训练。

## 推荐的模型分工

| 角色 | 当前 | 下一阶段建议 |
|---|---|---|
| 改写器 | 固定Qwen API，不同冻结prompt | 先保持模型不变比方法；以后单独测试本地7B |
| Reader回答器 | 同一个Qwen API，只读真实检索证据 | 基线与我们保持相同，避免模型能力混入方法增益 |
| 选择器 | 已有固定prompt选择实验底座，未训练当前目标模型 | CPU轻量分类/回归起步，不为每题调用72B |
| 记忆归纳器 | 来源阶段用同一Qwen API提卡 | 离线使用，可与上述复用同一模型；不强制72B |
| 证据充分性judge | 当前单轮FRESH批次没有调用 | 两轮实验中需明确接入，可复用Qwen型号，独立调用仍收费 |

因此不是“需要五个大模型常驻”。这是五种职责，可以由一个API模型加一个本地轻量预测器承担。把改写器换成7B时，先保持Reader不变，只测这一项变化。

## TF-IDF是什么

全称Term Frequency–Inverse Document Frequency，词频—逆文档频率。它把文本转换成一张带权重的词表：在本句出现、且不是到处都出现的词更能区分文本。例如学校、人名可能权重大，普通连接词权重小。它不是LLM，也不需要显卡。

经典出处之一是Salton与Buckley的[Term-weighting approaches in automatic text retrieval，1988](https://doi.org/10.1016/0306-4573(88)90021-0)。这是经典检索工具，不是ReFormeR的新发明；我提出它作为廉价起点，不是在声称某篇近邻论文已用相同选择器。[实现说明](https://scikit-learn.org/stable/modules/feature_extraction.html#tfidf-term-weighting)

它的弱点也很明确：擅长识别词是否出现，未必理解关系方向、否定或同义表达；在人名上过拟合尤其容易。因此要与语义向量和固定prompt选择器比较，不预定它最好。

## 分类、回归、冻结分别是什么

- 分类：输出一个类别，如BASE/FRESH/某个模式，或“有害/无害”。
- 回归：预测一个数，例如某动作比强FRESH预计多0.08 F1。数值是预测，不是保证，也不是回到旧版本。
- 线性模型：对输入特征分别赋权后求和，很小且便于检查，不是一个能自由写答案的7B语言模型。
- 文本向量：用文本编码器把一句话转换为一组数字，语义相近的文本有机会更接近。
- 冻结编码器：保持编码器参数不变，只训练后面的决策小模块。不是所有问题得到同一个向量，而是不同时训练整套大模型；减少数据与显存要求、方便控制变量。

首版可以训练“每个固定动作各一组权重”，输入q预测各动作增益。若想支持动态模式库，使用q—规则的相似度、条件匹配/冲突/未知、约束保留信号、独立历史反馈等配对特征，再打分。

一个容易忽略的实现坑：只把q特征与模式特征并排拼接，直接用一个纯线性分数，q这一部分对所有候选都一样，可能只学出固定的模式偏好。需要每动作权重，或显式q×动作/条件交互特征，或小的非线性头；不能仅凭模型叫“context-aware”就说它真的依赖上下文。

## 分组验证与实体词

实体词就是具体人、地点、机构等名称。例如两道题都出现同一所大学，模型可能学到这所大学的特殊情况，而不是学到“什么时候该补建校时间”。

分组验证的第一层：同一问题的多个动作、改写版本必须放在同一折，不能一部分训练、一部分验证。第二层：另做共享实体/文档的分组压力测试，看换成陌生对象是否仍有效。若一题有多个实体，要检查重叠连通关系，不能给每题随便选一个实体就声称实体不重叠。

这种压力测试不能私自替代官方最终划分；先内部诊断，正式结果仍按公开协议。还要报告组数和组大小，过大的关联组会导致可用训练数据不足。[GroupKFold说明](https://scikit-learn.org/stable/modules/cross_validation.html#cross-validation-iterators-for-grouped-data)

TF-IDF词表、IDF值、标准化、阈值只能在训练/校准部分学习；测试部分只应用，不能把测试文本一起拟合后说没泄漏。模型的输入不能包含当前gold、题型标注或事后最好动作。

## EMA、回归和强化学习不是一回事

EMA把旧效用与新反馈加权平均：旧值占1−α，新反馈占α。它回答“这条经验最近表现怎样”，本身不会理解新问题。线性回归学习“输入特征→收益”；RL则涉及按回报改进选择/行动策略。MemRL有EMA形式的效用更新；Trainable Graph Memory、UMEM已有增量奖励学习，见同日文献核查。

## 7B / 72B 与电脑的关系

3090常见24GB显存，可作为7B BF16、短输入低并发的实用选择。4060 Laptop为8GB独立显存，不是24GB。如果你说的“8+8”是独立显存加共享内存，不能当作16GB高速显存；若是两条8GB系统内存，那是16GB RAM，显卡仍为8GB。[NVIDIA笔记本规格](https://www.nvidia.com/en-us/geforce/laptops/compare/)

BF16每个权重通常用16bit；4bit量化把主要权重压缩到更低精度，但仍有元数据、上下文缓存和运行缓冲。它不是整个进程恰好缩小到四分之一，也不保证完全不掉效果或必然更快。

[Qwen官方实测](https://qwen.readthedocs.io/en/v2.5/benchmark/speed_benchmark.html)在指定A100环境下，7B AWQ约5.39GB短输入、6.39GB于6144输入；7B BF16约14.38/15.38GB。你的8GB机器值得日后限长、单并发尝试，但不是本轮已经成功部署。模型加载还要系统内存余量。

72B不是只能API：可以租或使用服务器。BF16建议2×80GB起步；4bit在约40GB级权重和运行开销上，48GB紧凑，80GB更宽裕。这里是推理建议，训练和并发另算。当前不需要它，也没有租卡/下载权重。
