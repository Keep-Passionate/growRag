# A1 编号证据版：从哪里审查代码

## 这次只加什么

增加一个“执行前的适用性观察器”。它检查已经选好、填好参数的历史动作，不负责重新选卡，不修改查询，不训练路由。不是完整 GrowRAG 已经做完，也不是 S2G 原版复现。

当前 44 张卡和原历史 SELECT/FILL 保持不变。观察器只提供一个可被检验的判断；是否真的有用，要靠后续固定动作的实际检索结果回答。

## 文件职责

| 文件（均位于 `src/growrag/experiments/`） | 通俗理解 | 不允许做的事 |
|---|---|---|
| `a1_conditions.py` | 固定“看什么、什么算有效输出”的规则；本地算来源匹配 P0 | 读答案、改写动作、联网 |
| `a1_observer_refs.py` | 给证据编 `r1/r2/...`，把模型选的编号还原为实际来源 | 偷补模型没选的来源、改判定 |
| `a1_catalog_study.py` | 新版合成诊断：冻结 → 真调用 → 封存 → 原响应重放 → 评分 | 覆盖旧失败、失败后偷偷重试 |
| `a1_catalog_budget.py` | 把旧批次和新版费用累计到同一账本 | 重新把余额当成全额、漏计失败调用 |
| `prepare_a1_data.py` | 过门以后才从新 train 题准备 40 题，仅投影 ID/题文 | 使用答案挑题、覆盖旧样本、写经验 |
| `a1_fresh_shortrefs.py` | 后续自然题的原 FRESH 提示适配短证据 ID | 改旧实验结果、扩大证据窗口 |

旧 `a1_synthetic_study.py` 和旧 fixture 不变：它们解释首轮真实发生了什么。新结果与旧结果分目录保留，不重算旧成绩。

## 一次观察的顺序

当前问题 + 可见证据 + 已编译的历史动作
→ 本地不可变快照
→ 明确待观察项与证据编号目录
→ 一次真实模型调用
→ 严格检查编号、判定、理由与来源
→ 沿用原规则给出“放行 / 拒绝 / 不确定放行”
→ 保存原请求、原响应、解析结果、费用。

执行器以后仍只使用最初冻结的动作，不能执行模型观察阶段临时发明的动作。观察结果也不能根据最终答案倒着填写。

## T / R / P0 / P1 分别是什么

- **T：类型。** 动作需要的对象类型是否被当前证据支持？没有预先定义类型要求，就明确记未知，不凭变量名猜。
- **R：关系。** 这个查询针对原问题目标或合理的中间目标吗？这是语义判断，不是“检索一定没收益”的证明。
- **P0：来源。** 参数文字能否在当前问题/证据中找到？代码计算；找到字符串不等于该实体角色正确。
- **P1：角色。** 找到的实体确实是当前所需的作者、演员、地点等对象吗？只出现名字不能自动算支持。

明确矛盾才拒绝；未知先交给不确定放行政策。另有严格未知政策作对照，不在看到成绩后换主政策。

## 你审查时最重要的五件事

1. **输入有没有答案泄漏？** 请求只看当前问题、可见证据、已填动作及事先定义条件，不看 gold 或成败标签。
2. **有没有偷偷改模型输出？** 同时查看 raw-v3 与展开后的 v2；后者是代码映射，不是原模型响应。
3. **判断错了能否被发现？** 自然题阶段被拒绝的合法动作也要影子执行，才能量化误拒，不能只看放行成功率。
4. **失败和费用有没有消失？** 计划题数、完成、失败、未尝试分别报告；每次真实 HTTP 和 token 都归属到记录。
5. **实验有没有回答研究问题？** 32 行是接口开发诊断。只有新自然题比较证据、答案及成本，才触及“适用条件是否有价值”。
