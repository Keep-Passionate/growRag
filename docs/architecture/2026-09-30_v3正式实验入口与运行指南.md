# GrowRAG：当前架构与正式实验入口

这份短导读替代旧文档中的即时进度说明，不替代原始实验日志。项目目录：`D:\project\GrowRAG`。本文所说的 v3 是严格输出协议和贯通实验流程的版本，不是论文第三种方法。

## 1. 我们现在实现什么

研究问题：在相同检索器、模型和检索预算下，从别的题学来的查询动作，是否比本题现场构造动作带来额外收益？先跑通这个问题，再研究哪些适用条件帮助选择，不先训练复杂路由器。

当前不是一个纯检索前预测器：先有一次原问题检索，规划器能看到证据，然后决定是否补搜。以后检验“第一次检索也省掉”的前置选择器，需要另做实验，不能把目前结果当成其证据。

```text
                         在线解一道题
原问题 ──→ BM25 初检 ──→ 当前问题 + 已见证据 + 剩余预算
                                    │
                               Qwen 规划器
                          ┌─────────┼──────────┐
                         停止     现场创建     选择已有动作
                         STOP     CREATE       SELECT
                          │         └────┬─────┘
                          │              ▼
                          │        本地动作校验和展开
                          │        字段 / 条件 / 引用 / 预算
                          │              ▼
                          │        新 query → BM25
                          │              │
                          │     合并证据，预算内可再决策
                          └──────────────┤
                                         ▼
                              统一 Reader 回答原问题
                                         ▼
                              保存轨迹、引用和实际费用
```

- BASE：只用原问题检索一次，再回答。
- FRESH：不读历史库，现场构造动作。它与记忆分支使用同一个模型和动作语言，不故意采用弱提示。
- STATIC：只能选择固定的扩写、比较、桥接种子动作。
- MEMORY：看最多三个历史候选，可以选用，也可以现场创建或停止。选择器当前是模型规划器；候选初筛是词汇匹配，**尚不是学得的 QPP**。
- 所有修复分支最多三次实际检索（含初检），最多两次规划决策，每次取六段。一个动作展开两条 query 就花两次检索，不能按一次计费。
- 空的可见历史库严格退回 FRESH，连规划器输入也相同；缺失的库文件则报错，不能假装空库。

当前 FRESH 是本项目的同能力动态动作对照，不是未经改动的 S2G 论文复现。旧 S2G 迁移结果仍保留，但不与本轮结果混报。

## 2. 两类记录，各有用途

**本题轨迹**保留实际搜索 query、检索文档 ID、动作规格和绑定、拒绝/停止原因、答案及 API 用量。它用于检查“到底发生了什么”，不会在评价中直接改写长期库。

**跨题动作规格**保存动作标识/版本、支持的任务意图、所需缺口字段、执行条件、参数绑定和查询模板。来源题号、验证记录留在审计部分；模型不接收历史标准答案或事后评分。

算子的名称可新增，但程序只解释有限的声明式语法，不执行模型生成的任意 Python。合法不等于有效：字段都对，也可能只把原问题已有的词再写一遍，或者搜不到新证据。这些都保留为真实结果。

## 3. “训练历史”不是微调大模型

```text
官方 train 中独立来源 500 题
  → BASE / FRESH / STATIC 轨迹全部形成终态
  → 封存预测后，离线用来源标签评分
  → 分别先取前 50 / 100 / 250 / 500 题
  → 各自提取和去重，形成四个冻结库
                                      │
官方 train 中校准 100 题：开发检查      │  不向库写入
                                      ▼
官方 dev 中固定 500 题：七路同题评价，只读冻结库
  → 全部终态封存后才评分，不用评价题更新记忆或模型
```

四个规模指**来源题数**，不保证产生同样多的卡。空库也是结果，不补抽容易题凑卡。当前候选录入使用来源题整条 FRESH 轨迹相对 STATIC 的指标增量，并检查答案及规格风险；不是证明某一个动作有因果贡献，也不是跨题可信认证。真正的记忆额外收益要在独立题上算 MEMORY−FRESH，同时报告修复、损害、使用比例和成本。

这批是共享封闭语料上的诊断实验：76,691 段落、76,639 标题，不是官方 Fullwiki 全维基语料，也不是逐题十段 distractor 评测。不能与不同检索范围的论文表格直接排名。

## 4. 为什么本次更换来源，而不更换测试题

旧协议已经尝试过部分来源。新版不会重命名旧轨迹后混入四个库，而是单独选取新的 train 来源 500 题，排除旧清单与已登记历史题。

迁移工具保持原校准 100 题、评价 500 题及语料的**字节、顺序和指纹不变**；不因为观察到效果而换测试题。旧目录、失败记录、费用和占用记录全部保留。新目录只有显式创建模式才写入，默认预检。

这是一次方法版本迁移，不是获得重新尝试失败题或查看测试答案的许可。

## 6. 如何看到程序确实在运行

在项目根目录的 PowerShell 查看实际进程：

```powershell
Get-CimInstance Win32_Process |
  Where-Object { $_.Name -eq 'python.exe' -and $_.CommandLine -match 'run_operator_study' } |
  Select-Object ProcessId, CommandLine
```

运行目录为 `runs/2026-09-30_operator_v3_source_base_fresh_static_起点_终点/`。将下方路径替换成实际批次；`Ctrl+C` 只停止日志查看，不会停止另一进程中的实验：

```powershell
Get-Content -LiteralPath 'runs/实际批次/live.log' -Tail 10 -Wait
```

重点文件：`launch_plan.json` 是冻结配置；`checkpoint_*.json` 和 `predictions.json` 是实际结果；`live.log` 是简短滚动过程，`events.jsonl` 保留详细事件；`final_budget.json` 是用量/估费；`predictions_frozen.json` 是终态封存。失败也有记录，不把计划题数当完成数。

真实请求审计里有供应商请求 ID、模型返回信息和用量。不要将 API 密钥写入日志或 Git。

## 7. 与 PDF 的关系和下一步

用户 PDF 中的“先保留候选、再独立确认是否长期持有”值得保留。现阶段先完成一个有标签来源筛选的规模 pilot；PDF 中无标签保留、多状态独立确认、固定候选的经验表示消融、先产生多候选再统一选择，还没有全部接入这一条正式链路。

顺序：版本贯通验收 → 新来源冻结 → 来源分批采集 → 四库构建 → 冻结并跑 500 题评价 → 分析胜负题，再决定增加哪些适用条件。不给尚未运行的模块预填效果。

当前本地 16GB RAM 足以运行这套 API + CPU BM25 实验；无需 GPU 租赁。以后只有改成本地模型推理或训练权重时，才评估 24GB 显卡。租卡解决不了模型输出字段错误，也不是本轮启动前提。
