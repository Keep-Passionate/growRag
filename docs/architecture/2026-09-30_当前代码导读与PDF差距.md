## 2. 用一句话理解系统

系统不先训练一个新大模型，而是在既有 RAG 外面增加查询控制：**先搜原问题，读当前证据，决定停止、现场生成搜索动作或复用历史动作，补搜后再统一回答原问题。**

```text
只含题号和问题的 RuntimeQuestion
               │
               ▼
        CPU / SQLite BM25 初检
               │
               ▼
       当前问题 + 累积证据 + 剩余预算
               │
               ▼
         ModelOperatorPlanner
     ┌─────────┼──────────┐
     │         │          │
   STOP      CREATE     SELECT
  声明停止   现场新规格  固定种子 / 冻结历史规格
     │         └────┬─────┘
     │              ▼
     │      OperatorRegistry.plan
     │      检查字段 / 条件 / 证据绑定 / 预算
     │              │
     │              ▼
     │      追加 query → BM25 → 合并证据
     │              │
     │       还有预算时最多再决策一次
     └──────────────┤
                    ▼
              统一 Reader
           回答原问题并记录引用
                    │
                    ▼
          预测、动作、调用和费用封存
                    │
             满足全批封存门槛后
                    ▼
               离线读取 gold 评分
```

v1 最多 **3 次检索（含初检）、2 次决策、每次 top-6**；BASE 只做一次初检。一个宏算子发出两条查询，就扣两次检索预算，不因为包装成一个动作而免费。

`STOP` 是模型的停止声明，不是证据充分性的数学证明。字段合法、证据中出现过某个实体，也不保证实体关系或最终答案正确。

## 5. “训练历史经验”目前指什么

在本轮架构中，先做的是 **经验提炼与冻结**，不是微调 Qwen 权重：

```text
独立 train 来源 500
    → BASE / FRESH / STATIC 全部形成终态
    → 预测封存后离线评分
    → 分别先取前 50 / 100 / 250 / 500 道来源
    → 各自提取候选、去重、检查并冻库

独立 train 校准 100
    → 仅用于提示/阈值等开发选择，不向历史库写经验

独立 dev 评价 500
    → 只读冻结库，禁止改写模型/记忆/提示
    → 预测全部封存后评分与同题比较
```

50/100/250/500 是建库的**来源题数**，不保证得到相同数量的经验卡。各规模必须先切来源前缀再提炼，不能先看 500 题结果挑好卡，再伪称只用了 50 道来源。

已有旧版小样本 QPP 拟合模块，但当前动态算子规划器没有调用它，不能称作本轮已训练的经验路由器。当前优先检验：在相同动作表达能力与预算下，历史是否比强 FRESH 多提供有效机会。

数据隔离目前验证 ID 和规范化问题文本哈希；它不自动证明改写问题、共享实体、共享文档或语义完全独立。评测题也不是 500 道已经人工验收的新人工改写题。

## 6. PDF 建议与当前 v1 的差距

参考文档：[GrowRAG 最小实验与动态算子设计](D:/研究生/论文/grow-RAG/GrowRAG_最小实验与动态算子设计_20260930.pdf)。下列 PDF 要点用于下一版本实验设计；不能直接写进旧冻结批次造成方法混用。

| 维度 | 当前可运行 v1 / pilot | PDF 提议与待补工作 |
| --- | --- | --- |
| E1：表示/选择输入 | 词汇短名单 + 同一个 LLM planner；没有 E1 完整对照入口 | 固定同一 S0 与 H1–H3，候选采用同一规范方式执行，仅更换 M1/M2/M3/M5 的选择输入，隔离表示作用 |
| E3：历史与现场方案竞争 | MEMORY 可以 SELECT 或 CREATE，但不会先为所有选项形成可比计划再四选一 | plan-first：先有 FRESH 与 H1–H3 四个计划，再四选一；BASE 作为报告基线，不算进四个选择项 |
| repair 与晋升 | 保留函数和来源候选提取存在；没有独立 8 状态确认流水线 | 新 repair 固定单版本，在独立 8 个状态确认后再考察迁移；单例成功不能自动 ACTIVE |
| 入库反馈 | 来源预测先封存，再以来源 gold 得到整条 FRESH 相对 STATIC 的收益关联；不是运行期泄漏 | PDF 提议 gold-free 入库，需要独立实现/冻结；不得把 v1 的 gold-assisted 建库改口称无标签学习 |
| 检索配置 | 最多 3 次、top-6；BASE 1 次，最多 2 次决策 | PDF 建议 4 次检索、top-5。若采用，需要新签名/版本，不能与已采来源混算 |
| 数据规模 | source 500 / calibration 100 / evaluation 500 已冻结 | PDF 的 100 / 60 / 200 是提案，不替换用户要求的至少 500 道独立评测 |
| 指标 | Answer EM/F1、raw/visible support recall，修复/损害与成本 | 最终句级支持事实预测与 Joint 指标仍缺；support recall 不能改名叫 support F1 |
| 增益解释 | source 整题关联、跨题评价代码已备好，真实库/评价尚未跑 | 仍需证明历史额外机会、选择质量和适用条件作用，不能把多搜几次本身称为记忆贡献 |

因此，本轮已有 v1 应明确称为 **pilot / 先导实验**，不宣称“完整 PDF 方法已经实现”。PDF 新实验冻结之前，500 题评价继续封存。

## 7. 下一步与服务器判断

本轮先续独立来源的小批采集，保留此前失败和未知费用；先观察格式/网络/审计是否稳定，不重新跑失败原题来覆盖记录。随后按冻结协议完成来源封存、评分与候选检查。PDF 的 E1/E3/独立 repair 确认要另立实验版本并冻结，不通过修改旧结果完成。

用户本轮将付费授权提高到 200–300 元，先按 **200 元累计项目上限**执行；这是一项新的预算决定。已增加`--project-cap-cny`，默认50兼容旧命令；本轮显式200，所有guard/claim/launch/费用账均使用同一有效上限，旧授权/历史费用保留。全仓2852项测试通过（145.69秒），单题续跑离线预检通过；这些都不是新问答效果。

**当前不需要 GPU 服务器。** 已有方法是远端 Qwen API + 本地 CPU BM25/SQLite，当前模型见[固定模型配置](D:/project/GrowRAG/src/growrag/experiments/run_pilot.py:20)，运行预算与检索配置见[方法签名](D:/project/GrowRAG/src/growrag/experiments/operator_execution_signature.py:27)。当前阻塞点是调用错误/结构化输出与实验协议，不是本地缺显存。没有必要为尚未采用的 LoRA 或 GPU 推理预先付费。

若今后本地长时间运行不便，可以再考虑普通 CPU 远程机；若确实改做本地大模型微调/推理，再估算 GPU。届时需保留环境版本、日志、预测、费用账本和哈希，回传并验证结果后，才关闭用户指定的远程实例；关机与云平台停止计费并不总是同一件事。
