# A1代码导读：先判断动作是否适用，再检验这种判断有没有用

## 先读这几句

现在不是训练一个新的大模型，也不是已经实现了自动三路择优。A0已把BASE、FRESH和固定历史库分别跑完对照；A1新增的是**执行前观察器**，检查同一个已填好的历史动作。不让它改写动作、换卡或偷偷增加检索。

模型说“条件不符”，不代表检索一定无用。下一自然题阶段会把合法动作都执行一遍作为影子对照，包括被拒绝的动作，检验误拒。先32条合成诊断，再按门槛决定是否做40条新自然题；当前合成真实运行结果以独立runs反馈为准。

## 三个清晰边界

1. **本地合同**：输入是什么、引用能否找到、哪个条件由代码确定、失败怎么停。不能借模型自由发挥补字段。
2. **语义观察**：对象类型T、查询关系R、目标角色P1由固定提示一次判断；当前参数是否出现P0由代码判断。不把unknown当false，也不把机械格式失败当unknown。
3. **效果评价**：模型观察先封存，再运行固定动作，最后才用独立标签检查收益/损害。观察器不给自己的效果打分。

对应`tests/test_a1_*`是本地模拟/机械回归。测试通过不等于真实模型判断准确，不能写进论文当自然题成绩。

## 最小执行顺序

合成输入 → 冻结input/快照 → 本地P0＋单次模型T/R/P1 → 严格引用解析 → 封存报告和费用 → 全批终态 → 真实HTTP重放核对 → 才比较作者预期。

主政策：存在明确冲突才拒绝；没有冲突但有未知则不确定放行；全支持才普通放行。另离线比较单维、全维、严格拒未知及无条件放行，不重复请求模型。

自然题的后续顺序是：共享初检 → 旧选卡/填参一次 → 硬编译并冻结动作 → 上述观察封存 → BASE答案与固定动作真实影子结果 → 全批终态后标签评分。该自然题执行器尚须单独实现和冻结，本导读不声称已运行。

## 当前证据对方向的提醒

A0v2的99题主EM：61 BASE、74原FRESH、71聚焦FRESH、61历史。历史只有16题额外检索，相对BASE1修复/1损害；相对原FRESH少答对的13题里12题无历史执行。因而A1只能检验已选动作的适用性，不能被包装成已经解决了经验库覆盖和未选卡问题。

我们保留“跨题经验如何提供额外机会”这个科学问题；只有观测到可重复、有成本优势或更高质量的机会，才值得继续训练路由。不能仅靠画出了记忆结构，就预设论文贡献成立。
