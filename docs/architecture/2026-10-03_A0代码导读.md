# 当前A路线代码：先独立比较，再设计路由

目前主要验证的不是“多了一个记忆库能否涨分”，而是：**把现场修复做得足够强以后，历史动作还留下什么独有机会？** A0先回答这个问题，A1再检查是否能用适用条件减少误用，A2才比较同样信息的不同记法。

## 一眼看懂

```text
独立来源题 → 轨迹筛选 → 冻结历史库（10条规则＋34个模板）
                                      │只读
100道新开发题 → 同一BM25初检 → 四路独立运行
                              ├─ BASE：不修复
                              ├─ FRESH-original：原现场动作提示
                              ├─ FRESH-focused：允许聚焦有来源的中间实体/属性
                              └─ HISTORY-body8：召回8卡 → 选卡/不选 → 填参执行
                                       ↓
                   最多3次检索（含初检）、2次修复决定
                                       ↓
                   相同Reader，用E1/E2引用当前证据回答
                                       ↓
            原始请求/响应、query、卡片、证据、费用和终态封存
                                       ↓
            离线核对＋程序回放 → 此时才读标准答案 → 配对评分
```

BASE只检索1次。另三路可以提前停止，不必用满预算。四路是实验对照，不是系统知道哪路答对以后在线挑最好；当前没有训练好的三选一路由器，也没有额外QPP效果预测器。

建议按runtime → loop → data → feedback的顺序看。新增模块注释解释职责、失败边界和实验隔离；基础模块保持原样，避免新实验改变旧结果的含义。

## 本题记录与长期库

本题记录保存原问、每次当前证据、动作和参数、实际query、停止原因以及Reader输出。它是审计材料，不会自动进入长期库。Reader只看当前证据，没有历史答案通道。

长期库保存版本化的卡片外壳，正文可以是一般化改写规则，也可以是可编译查询模板；同时保留来源指针。当前44条可调用记录并没有丰富的显式适用条件，也没有已经学好的动态置信度。A1计划补充并验证类型、子目标关系、当前可见来源、目标角色关系；这些是待测试机制，不能描述成已得到效果。

## 当前运行规则

四路共用同一模型和检索索引。格式不合法不会人工补成正确结果：有完整计费记录的局部模型输出失败记失败臂，允许下一独立臂继续；连续3个失败臂、传输/账本异常或预算边界会停止。前5题四路不全通过就不扩批。

本系列100题按5/20/25/25/25分批。分批之间不打开答案、不调提示。全部计划题都有完成、失败或未执行状态，之后才加载共同完成题的金标；不能把缺失当0分。所有金钱值区分最坏情况预留和按tokens估费，两者都不是供应商账单。

## 本地查看与重现

代码在`D:\project\GrowRAG`。运行过程存入`runs\2026-10-02_a0_v1_*`，每批的`live.log`是简要滚动日志，`events.jsonl`是完整中间过程，`api_audit`与`request_journal`保留真实请求/响应和计费审计。总终态是`runs\a0_query_construction_v1\TERMINAL.json`；反馈只在审核成功后生成到`runs\a0_query_construction_feedback_v1`。

如第一批已经启动，可在PowerShell查看：

```powershell
Get-Content D:\project\GrowRAG\runs\2026-10-02_a0_v1_0000_0005\live.log -Tail 20 -Wait
```

这只查看日志，不发送模型请求。其他批次目录末尾对应`0005_0025`、`0025_0050`、`0050_0075`、`0075_0100`。带`--allow-network`的命令才会调用API；现有系列不支持隐式重跑，重复输出路径会拒绝。
